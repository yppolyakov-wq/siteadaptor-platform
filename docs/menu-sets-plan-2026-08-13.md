# План MEN — «Наборы меню с выбором» (Menü-Sets) + сбор в агрегаторе

Дата: 2026-08-13. Статус: план согласовывается. Ветка:
`claude/goodkarma-catering-analysis-fea071`. Разведка: воркфлоу 13 агентов
(10 областей кода → 2 варианта архитектуры → адверсариальный критик);
все утверждения ниже сверены с кодом.

## 0. Постановка (запрос владельца) и его решения

Кейс: кит catering «Grüne Tafel», направление (категория) «Hochzeitscatering»,
внутри — несколько продаваемых наборов меню. Три режима:

1. **Фикс-набор** — состав показан мини-плитками; клик по блюду → попап
   с крупным фото и описанием. Менять состав нельзя.
2. **Настраиваемый набор** — гость выбирает блюда внутри набора
   («выбери 1 закуску из 4»), цена пересчитывается.
3. **Свободный набор** — показаны ВСЕ блюда категории, сгруппированы по
   типу подачи (закуски/первые/вторые/десерты/напитки), гость собирает сам.
   Цена à la carte ≥ цены внутри набора (иногда равна).

**Решения владельца (2026-08-13):**
- «Не перемудрить и не перегрузить»: по возможности БЕЗ новых сущностей —
  «Combo с некой модификацией цены», «комплекты с возможностью выбора».
- Агрегатор: (1) набор фильтров согласован — тип события · число гостей ·
  цена с человека · диеты · радиус выезда · дата; (2) **каждый набор меню =
  отдельная карточка** агрегатора; (3) цена карточки = базовая сборка
  за человека, **мин. заказ показывать сразу в карточке**; (4) **блюда
  отдаём в поиск** агрегатора.

## 1. Вывод разведки: новые сущности НЕ нужны

- **Блюдо = `catalog.Product`.** Уже несёт: фото/галерею (`images`), описание,
  аллергены/диеты/Zusatzstoffe (`food.py`, LMIV), i18n-оверлеи, `base_price`.
  Заводить `Dish` — дублирование всего пищевого слоя. НЕ заводим.
- **Набор = `catalog.Combo` + `ComboGroup` (min/max выбор) + `ComboOption`
  (блюдо + `price_delta`)** — `apps/catalog/models.py:567+`. Расчёт цены,
  валидация выбора, сессионная корзина (`COMBO_SESSION_KEY`), снимок состава
  в `OrderItem.modifiers` — всё уже написано (`apps/catalog/combos.py`,
  `apps/orders/public_views.py:112-217`, `services.create_order(combos=)`).
- **Две цены блюда** получаются без трюков и без двойной семантики колонок:
  `Product.base_price` = цена à la carte (свободная сборка);
  цена в наборе = `Combo.price` + `ComboOption.price_delta`.
  Инвариант владельца «à la carte ≥ в наборе» выполняется естественно
  (в кабинете — подсказка, машинный constraint не нужен: величины разной
  природы, сравнивать нечего).
- Три режима = настройка групп ОДНОГО Combo (см. §2), не три механики.

Отвергнуто (вариант «чистая модель» MN, по критике): новый app
`menus.MenuSet/MenuSection/MenuSetLine` + `MenuCourse` + регистрация в
`DETAIL_SECTIONS` — это регенерация 4 golden-эталонов, пятый комплект
хардкод-блоков билдера (`_normalize_impl`/save-блоки/инспектор/site_home),
data-миграция Combo→MenuSet и двоемирие в кабинете. Против правила
«не перемудрить».

## 2. Модель — одна аддитивная миграция `catalog/0025`

На **`Combo`** (все поля опциональны, дефолты = прежнее поведение):

| Поле | Тип | Зачем |
|---|---|---|
| `images` | JSONField(list) | галерея набора (FileRef-конверт `catalog/images.py`, как у Product) |
| `category` | FK Category SET_NULL null | привязка к направлению: блок на лендинге DS-7, пул режима 3 |
| `price_per_person` | Bool default False | «Preis pro Person»; qty в корзине = число персон |
| `min_persons` | PositiveSmallInt default 0 | мин. гостей (0 = нет); кламп qty, показ в карточке и агрегаторе |
| `event_types` | JSONField(list) | поводы (строки; datalist из `site_config["anfrage"]["event_types"]` AF-1 — один словарь у формы заявки и наборов) |
| `free_pool` | Bool default False | режим 3: состав = все активные товары `category`, группы игнорируются, цены à la carte |

На **`ComboGroup`**:

| Поле | Тип | Зачем |
|---|---|---|
| `included` | Bool default False | режим 1: «входит в набор» — опции рендерятся фикс-плитками с попапом, в выборе/валидации/цене НЕ участвуют (их стоимость уже в `Combo.price`) |

На **`Product`**:

| Поле | Тип | Зачем |
|---|---|---|
| `course` | CharField(20) choices default "" | тип подачи (Gang): vorspeise/suppe/hauptgang/beilage/dessert/getraenk/snack — реестр `COURSES` в `food.py` (lazy, как DIETS). Группировка режима 3 и PDF-меню |

Почему `course`-поле, а НЕ подкатегории и НЕ Collection: фасет каталога
`?kategorie=` фильтрует по ТОЧНОМУ slug (не рекурсивно) — пересадка блюд в
подкатегории опустошила бы лендинги DS-7 (`Product.category=direction`) и
выдачу направления; Collection семантически «подборка/Lookbook» и M2M-оверкилл
для одноосевой группировки. Одна колонка — честный минимум.

Никаких новых ключей `site_config` → golden-фикстуры не трогаем вовсе.

## 3. Витрина

### 3.1 Починка конфигуратора (баг, найден ревью — чиним ПЕРВЫМ)
`combo_detail.html:30`: radio всех групп имеют ОДНО имя `name="opt"` —
браузер схлопывает их в одну группу, «выбери 1 закуску + 1 горячее»
неработоспособен сегодня. Фикс: radio → `name="opt-{{ g.pk }}"`,
`combo_add` собирает `opt` + все `opt-*` (валидация `validate_selection`
не меняется — она принимает список id). Замок ДО характеризационных
тестов остальной волны (иначе запиним баг эталоном).

### 3.2 Деталь набора (все режимы)
Остаётся своим шаблоном `combo_detail.html` (НЕ сводим на `detail.html` —
записи в `DETAIL_SECTIONS` нет, и не заводим: границa BUYBOX_CONFIGURABLE).
Дорабатываем:
- галерея из `Combo.images` (реюз `_media_gallery`-партиала);
- **мини-плитки блюд**: `included`-группы (режим 1) и опции выбора (режим 2)
  рендерятся плитками с фото (`option.product.primary_image`), названием и
  надбавкой; клик по плитке → **попап блюда**: существующая generic-модалка
  `[data-quick-url]`/`#quick-modal` (обработчик делегирован, нового JS ноль) +
  новый лёгкий фрагмент `GET /gericht/<pk>/info/` → `_dish_info.html`
  (фото крупно, описание, аллергены/диеты из `food.py`) — БЕЗ orders-гейта
  (read-only);
- **live-пересчёт цены**: инпуты несут `data-delta`, инлайн-скрипт считает
  сумму для отображения; сервер ВСЕГДА пересчитывает сам
  (`combo_price` в `combo_add`/`create_order`) — клиент цен не шлёт;
- при `price_per_person`: поле qty подписано «Personen», min=`min_persons`,
  строка «ab {min_persons} Personen» под ценой;
- **режим 3** (`free_pool`): вместо групп — блюда `category`, сгруппированные
  по `course` (порядок реестра), каждая позиция чекбоксом с ценой
  à la carte (`base_price`) и «+»-количеством; итог = Σ(выбранное × qty)
  × персоны. Валидация/цена — серверные (расширение `validate_selection`
  веткой pool);
- PAngV: при `menu_show_prices=False` (browse-only) цены скрыты и в
  конфигураторе — состав + «Unverbindlich anfragen» (осознанный сценарий).

### 3.3 Гейты и CTA (catering = browse-only, orders выключен)
Сегодня `/kombi/*` целиком за `_require_orders_active` → у кейтеринга наборы
невидимы. Меняем: **лист/деталь/попап доступны по видимости каталога**
(как Speisekarte), а ДЕЙСТВИЕ зависит от orders:
- orders on (ресторан): прежняя корзина `/kombi/add/` (остаётся за orders);
- orders off + jobs on (catering): CTA «Unverbindlich anfragen» →
  `GET /anfrage/?betreff=<набор: состав, N Personen>` — префилл AF-1;
  наследуем honeypot + rate-limit штатного приёмника, никаких новых
  анонимных POST-эндпоинтов. Черновик сметы (JobLine) — не в этой волне.
Меню-гейт `_PAGE_MODULE_GATES["combos"]` (жёстко «orders») → расширить
резолвером «orders или FOOD-browse с наборами».

### 3.4 Лендинг направления (DS-7) и листинг наборов
- `category_landing` += блок «Menü-Pakete»: наборы `category` картами
  (фото, «ab X €/Gast», «ab N Personen», бейдж режима «Wahlmenü»/«Freie
  Auswahl»). Выше «Beispiele aus der Küche».
- `/kombi/` листинг: карточки получают фото/цену-за-гостя/мин-гостей.

## 4. Заказ (orders on)
Существующий путь `create_order(combos=)` не трогаем: снимок состава уже
пишется в `OrderItem.modifiers` (label + delta). Дополняем снимок
`min_persons`/`per_person`-контекстом (подпись «22 Personen × 45 €»).
Известное ограничение (паритет с сегодняшним поведением, НЕ расширяем):
состав набора не резервирует склад блюд — для гастро/кейтеринга блюда
не складские (`stock=None`); v2 — строки состава через `custom_lines`.
Перепроверка состава/цены — внутри той же atomic, что и `create_order`
(замок).

## 5. Агрегатор — отдельный инкремент, SHARED-миграция `aggregator/0017`

По решениям владельца:
- `AggregatorListing.KINDS += "menu"`; поля (аддитивно): `price_per_person`
  Decimal null, `min_persons` SmallInt default 0, `event_types` JSON list,
  `diets` JSON list, `dish_names` JSON list (снимок названий блюд состава —
  ЭТИМ «отдаём блюда»: `?q=Rinderfilet` находит карточку набора без
  отдельного kind="dish").
- Карточка: «ab 45 €/Gast · ab 20 Personen» + чипы поводов/диет + «★ Anzeige»
  у featured (UWG §5a, существующие замки; featured НЕ поднимается).
- Синк tenant→public: по образцу `sync_stay_listing` — снапшот в задаче,
  **dedupe_key по id набора** (кабинетный CRUD состава гранулярный — иначе
  шторм задач), пересинк по сигналам Combo/ComboGroup/ComboOption + beat.
- Фильтры `/entdecken/`: повод, диета, гости (`min_persons <= guests`),
  цена/чел; город — существующий. Радиус выезда — v2 (у Tenant нет
  надёжных координат: lat/lon заполняются только демо/админкой) — фильтр
  по городу в v1, честно.
- **Семантика диет (нужно ваше слово при чекпоинте MEN-5):** рекомендую
  чип «Vegan möglich» = в наборе ЕСТЬ vegan-позиции (объединение по
  составу; для кейтеринга гость спрашивает именно «смогут ли веганское»).
  Альтернатива — строгое «набор целиком vegan» (пересечение; для
  свободного пула неопределимо).

## 6. Кабинет
`combo_form.html` += галерея (виджет как у товара), категория, «Preis pro
Person» + «ab N Personen», поводы (datalist из anfrage.event_types),
«Freie Auswahl aus Kategorie»; на группе — чекбокс «Im Set enthalten»
(included). У товара — селект «Gang» (course) в существующей вкладке
Kennzeichnung (гейт FOOD-типов, W0: поле в DOM всегда). Подсказка цен:
«Preis à la carte = Produktpreis; im Set gilt Set-Preis + Aufpreise».

## 7. Демо + i18n
Кит catering: «Hochzeitsmenü Klassik» (фикс, included-группы, 45 €/чел,
ab 20 Personen) · «Hochzeitsmenü Wahl» (выбор 1-из-N по курсам, 52 €/чел) ·
«Freie Auswahl Hochzeit» (free_pool на Hochzeitscatering). Блюдам
направлений проставить `course`. Кит restaurant: существующие наборы
получают фото. Переводы: спека `combos` уже i18n (name/description);
новые строки UI — msgid DE + 4 .po; названия блюд в переводах — по
конвенции demo_i18n (identity не заводим). PDF-Speisekarte (GK-13):
группировка по course внутри категории — приятный бесплатный бонус,
включить.

## 8. Замки и известные грабли
- Радио-фикс ДО характеризационных замков конфигуратора (§3.1).
- `test_sellable.py::test_combo_cart_mode_no_image` фиксирует
  `image_url==''` у адаптера `_combo` — переписываем ОСОЗНАННО
  (адаптер получает фото из `Combo.images`).
- Ни одного нового ключа site_config → golden целы; `menu_show_prices` уже
  нормализуется (DS-7).
- Гейт-замки: наборы видимы browse-only; `/kombi/add/` даёт 404 без orders;
  попап блюда без orders-гейта, но 404 на неактивном товаре.
- Серверная цена: тест «клиентские данные не влияют на сумму заказа».
- Agg-инкремент: dedupe синка (N правок опций → 1 задача), UWG-замки
  featured, кэш /entdecken/ только при пустом query (не кэшировать
  с фильтрами).
- CI-гигиена: `ruff format --check .` целиком, `npm run build:css` при новых
  Tailwind-классах, template_comments, i18n_gap, `--create-db` после
  миграции.
