поиск» (10.10.2026). ТЗ §2/§15 требует до изменений отчёт EXISTS / PARTIALLY EXISTS / MISSING и

## 2. Расхождения ТЗ с текущим решением — нужен выбор владельца

1. **Кто ведёт справочник категорий.** ТЗ §5: «администратор платформы управляет». Сейчас справочник
   — код (как районы): переводы, слаги и подсказки проверяются тестами, менять — коммитом.
   *Рекомендация:* оставить кодом до появления операторов порталов (T-8.12); тогда — таблица +
   админка с теми же слагами (данные не мигрируют).
2. **Несколько глобальных категорий у объекта** (ТЗ §4). Сейчас: одна категория + признаки.
   *Рекомендация:* так и оставить — вторая категория почти всегда признак («vegan», «regional»)
   или раздел-родитель (поиск по разделу уже находит все его категории). Добавим вторую, если
   встретится реальный случай.
3. **«Bio», «vegane Produkte» как подкатегории** (ТЗ §4) — у нас признаки, по ТЗ §3 же (свойства ≠
   категории). Фильтр `?merkmal=vegan` работает поперёк всех разделов.

## 4. Вопросы владельцу

- В1. Справочник категорий: код сейчас, таблица+админка с операторами (п. 2.1)? 
- В2. Одна категория + признаки достаточно (п. 2.2)?
- В3. Товары в каталог города: по умолчанию **все** активные товары бизнеса, согласившегося на
  каталог (можно исключить категорию/товар), или **только отмеченные** владельцем?
- В4. Порядок: T-8.19 (главная) и T-8.20 (поиск) — перед T-8.11 (товары) или после? Рекомендация:
  T-8.11 → T-8.19 → T-8.20 (сначала появляются товары, потом им есть что показывать и искать).
- В5. Популярные запросы видит владелец бизнеса только по своим объектам, а «ничего не найдено» —
  только платформа (спрос города)?

## 5. Решения владельца (2026-10-10)

- **В1** справочник — код сейчас, таблица + админка при операторах порталов: согласен.
- **В2** одна категория + признаки: пока согласен.
- **В3** какие товары попадают в каталог города — **согласовано владельцем (10.10)**: **все
  активные товары бизнеса, согласившегося на каталог (`in_city_catalog`), но только «годные к
  показу»** — есть фото, цена, категория города (своя или сопоставленная); владелец может
  исключить категорию целиком (переключатель в строке «Zuordnung zum Stadtkatalog») или товар
  (галочка «nicht im Stadtkatalog» в форме). Почему не «только отмеченные»: опыт городских
  маркетплейсов — ручную разметку никто не делает, каталог остаётся пустым. Почему фильтр
  «годности»: карточка без фото/цены портит выдачу всем. Распроданный товар остаётся с меткой
  «ausverkauft» только если включён склад, иначе — как есть.
- **В4** порядок: товары → главная → поиск, с демо под все разделы — да; последовательность —
  `t8-roadmap-2026-10-10.md`, этап 3.
- **В5** журнал запросов — пока только платформа: согласен; владельцу бизнеса остаются его
  собственные счётчики (просмотры, воронка по каналам T-8.6), запросы чужих людей ему не
  показываем, пока не появится понятная ценность и проверка на персональные данные.
