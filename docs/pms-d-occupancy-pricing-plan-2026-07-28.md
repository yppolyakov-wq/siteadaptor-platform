# PMS-D: occupancy-правила цены (ручной режим) — план v1

**Дата:** 2026-07-28 · **Статус:** очередь PMS-волн (рамка «остальное делай»);
анализ — Price Optimizer §6 в `docs/pms-gap-analysis-2026-07-27.md`.
**⚠️ Миграция `stays/0028`** (аддитив, JSON-поле на StaySettings).

## Идея (v1 = ручной, БЕЗ автопилота/AI)

Владелец задаёт правила «занятость ночи ≥ X % → цена этой ночи ±Y %»
(до 2–3 правил, строже = больше порог). Классика revenue-management руками:
последние номера дороже, пустой дом — дешевле (отрицательный Y). Никаких
рекомендаций/автопилота/цен конкурентов в формуле (CP-1 остаётся read-only).

## Модель

- `StaySettings.occupancy_rules` JSON list:
  `[{"occupancy": 80, "percent": 10}, {"occupancy": 50, "percent": -5}]`
  + `clean_occupancy_rules()` (кап 10 правил, percent −50..+50, occupancy
  1..100; мусор молча отбрасывается — паттерн G4/G12).
- Применение: из подходящих правил (occupancy ночи ≥ порога) берём правило с
  МАКСИМАЛЬНЫМ порогом (не суммируем — предсказуемо, паттерн G4).

## Применение в цене (pricing)

- Точка врезки: `quote_total_cents` — посуточный цикл. Новый опц. параметр
  `occupancy_by_day: dict[date, float] | None` (None = поведение байт-в-байт
  прежнее — все существующие вызовы не меняются).
- Занятость ночи = занято/quantity ЭТОГО юнита (не всего дома) — из
  `availability`-запроса ОДНИМ проходом на диапазон (без per-night запросов).
- Витрина: `_quote` (public_views) и страница юнита передают occupancy_by_day;
  кабинет walk-in/move — НЕТ (стойка бронирует по базовой цене; злая цена на
  стойке владельцу не нужна). reprice при update тоже без надбавки.
- Порядок формулы: сезон/выходные → rate_plan → **occupancy-надбавка** →
  ×rooms → auto_discount (G4) → ваучер → Kurtaxe. Надбавка входит в lodging
  (Kurtaxe не трогает).

## Кабинет + витрина

- Секция «Dynamische Preise» на units-странице (рядом с Verkaufsregeln G12):
  строки правил occupancy%+percent, add/delete (паттерн restriction_add).
- Витрина честна по PAngV: показывается уже итоговая цена ночи/итог — никаких
  зачёркиваний «было/стало» от occupancy-надбавки (это не скидка-акция).

## Тесты

- clean_occupancy_rules капы/мусор; выбор правила с max порогом.
- quote с occupancy_by_day: надбавка только на «горячие» ночи; None =
  байт-в-байт старый итог (характеризационный замок ДО врезки).
- Интеграция: заполненный юнит (n-1 из n) → витринная цена ночи +Y %;
  walk-in кабинета — без надбавки.

Инкременты: (1) модель+clean+миграция → (2) pricing с замком → (3) витрина
occupancy_by_day → (4) кабинет-секция → (5) демо-правило hotel-кита. Один батч.
