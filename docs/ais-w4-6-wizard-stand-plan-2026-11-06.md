# AIS W4-6 — сквозной стенд мастера v4 и решение о флагах (2026-11-06)

**Цель.** Прежде чем включать `SETUP_WIZARD_V4` (регистрация ведёт в мастер v4, сайт скрыт до
«Website veröffentlichen») и `READINESS_SELL_GATE` (продажа только при готовности), пройти
путь владельца ЦЕЛИКОМ так, как его пройдёт человек: от формы `/registrieren/` до опубликованного
сайта и карточек «Nächster Schritt». Отдельные стенды W4-1/W4-2 начинали с готового тенанта —
регистрацию, письмо, ожидание схемы и первый вход они не видели.

## 1. Путь (на каждый тип)

1. `/registrieren/` (публичный хост): тип бизнеса, имя, адрес, город, почта, пароль ×2.
2. «Prüfen Sie Ihre E-Mail» → прямая ссылка (console-бэкенд) → экран подтверждения с паролем.
3. Ожидание схемы (Celery `provision_business`) → вход на поддомене.
4. Кабинет уводит в мастер: **Firma** (адрес, телефон, часы сеткой) → **Angebot prüfen**
   (образцы типа → таблица → «Übernehmen») → **Rechtliches & Veröffentlichen** (сначала
   отказ со списком недостающего, затем Impressum → публикация) → **Fertig**.
5. Главная кабинета: карточки «Nächster Schritt» вместо чек-листа; «Verkauf öffnen» открывается.
6. Гость: до публикации витрина 503, после — 200.

Типы: bakery (Waren) · friseur (Termine) · hotel (Zimmer) · events (Tickets) · handwerker
(Anfragen). Телефон 390 px — все пять; десктоп 1440 px — bakery и hotel (самые широкие экраны).
На каждой странице: без JS-ошибок, без горизонтального скролла.

## 2. Решение о флагах (после стенда)

* `SETUP_WIZARD_V4` — включаем, если путь проходит у всех пяти без дефектов. Затрагивает
  только НОВЫЕ регистрации; существующие тенанты остаются в своём мастере.
* `READINESS_SELL_GATE` — НЕ включаем этим инкрементом: гейт ещё не вшит в чекауты (W4-5d).
  Включение без W4-5d ничего не закроет, а владелец решит, что продажа защищена.

## 3. ECC-прогоны

* Скиллы до кода: `e2e-testing` (Playwright-паттерны, ожидания), `accessibility` (фокус/имена на
  шагах мастера).
* Агенты: `e2e-runner` — не запускаем отдельно (стенд пишем сами, Python-Playwright по правилам
  проекта); `a11y-architect` — по снимкам шагов, если стенд найдёт новые элементы; найденные
  дефекты кода — `django-reviewer` на правках перед мержем.

## 4. Запуск

```bash
SETUP_WIZARD_V4=1 python manage.py runserver 0.0.0.0:8000 --settings=config.settings.stand
```

```bash
DJANGO_SETTINGS_MODULE=config.settings.stand SETUP_WIZARD_V4=1 uv run celery -A config worker -l warning
```

```bash
uv run --with playwright==1.55.0 python scripts/wizard_v4_e2e_stand.py
```

## 5. Результат стенда (2026-11-06)

`scripts/wizard_v4_e2e_stand.py` — 7 проходов (5 типов × 390 px + bakery/hotel × 1440 px),
**227 проверок, 0 провалов**: регистрация → письмо → пароль → схема (Celery, копия `_template`)
→ вход → Firma → Angebot prüfen → Recht (отказ без Impressum, затем публикация) → Fertig →
«Nächster Schritt» (1–3 карточки, без старого чек-листа) → «Verkauf öffnen» 200; гость 503 → 200;
ни на одной странице нет JS-ошибок и горизонтального скролла.

**Находка (продуктовая, не дефект кода).** У Handwerker шаг «Angebot» честно пишет «Für Ihr
Geschäft gibt es hier nichts einzutragen». Решение владельца W4-2 §10 п.3 («Anfragen как
`Product(primary_action="request")` без цены, если витрина не печатает 0,00 €, иначе — в W4-5»)
не исполнено ни в W4-2, ни в W4-5: витрина цену печатает везде (~250 шаблонов), отдельного
«Preis auf Anfrage» нет. Это отдельный инкремент (W4-6b), а не правка стенда. Затрагивает
handwerker; у catering/werkstatt/tour_operator есть и другие направления.

**Грабли стенда.** Лимит регистраций — 5 в час на сеть: стенд сбрасывает `rl:*` перед каждым
проходом. Локальной БД нужен public-тенант с Domain `siteadaptor.de` и шаблонная схема
(`ensure_template_schema`), иначе каждая регистрация строит схему ~100 с.

**CI нашёл:** таблица сравнения Google без `ui-table` (замок `test_design_guard`) — исправлено.

**Рекомендация по флагам.** `SETUP_WIZARD_V4` — можно включать (с оговоркой про Handwerker
выше). `READINESS_SELL_GATE` — не включать до W4-5d (гейт не вшит в чекауты).
