## 1. Принцип

Сначала ЗАМЕР (`CaptureQueriesContext` на демо-тенантах shop/hotel/catering: витрина аноним,
кабинет владелец), потом правка, потом ЗАМОК числа запросов, не зависящего от числа строк
(`django_assert_max_num_queries` при N и 3N строк — разница = 0). Вид страниц не меняется;
семантика каждого ключа контекста прежняя.

## 3. Замки

- `test_e10_speed.py`: число запросов кабинета «Sortiment» / «Offene Posten» / «Events» не
  растёт с числом строк (N vs 3N); витрина-аноним — без запросов сайдбара (запрос `Membership`
  не выполняется); кабинет — `resolve_menu` не зовётся (мок-счётчик); `Product.active_variants`
  с prefetch возвращает те же объекты, что без него (паритет `has_variants/price_from/in_stock`).
- Паритет разметки: существующие тесты списка «Sortiment», событий, Offene Posten, контекста
  (`test_cabinet_nav`, `test_live_preview`, `test_storefront_profile`) — без правок.

## 4. ECC-прогоны

- Скиллы до кода: `django-patterns` (prefetch/`to_attr`), `postgres-patterns`, `django-tdd`.
- Агенты: `django-reviewer` (всегда), `database-reviewer` (prefetch/агрегаты), `silent-failure-hunter`
  не нужен (нет денег/внешних вызовов); `e2e-runner` не нужен — JS-правка S-7 тривиальна,
  проверяется чтением + существующими замками бейджа.
