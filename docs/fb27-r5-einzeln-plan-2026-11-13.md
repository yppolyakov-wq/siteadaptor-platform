# FB-27 R5 — «Einzeln»: ручной выбор позиций блока «Liste»

Дата: 2026-11-13. Основание — `fb27-seitenaufbau-impl-plan-2026-11-11.md` §A.4, §C (R5).
Решение владельца: у блока три способа сказать «какие»: по правилу, из категории/подборки,
**вручную по одному с порядком** — для товаров, категорий, акций, услуг, номеров, событий,
туров. Первые два способа сделаны в R3b-2 (группа «Welche»), R5 — третий.

## 1. Что есть в коде

- Блок «Liste» выбирает позиции фетчерами `apps/core/list_blocks.py` (`_products`,
  `_promotions`, …) — фильтр и сортировка, ручного состава нет.
- Все семь сущностей — `TimestampedModel` с UUID-ключом; `str(obj)` даёт название.
- Данные блока чистит `siteconfig._clean_list_block` (поля только своего источника).
- Правки блока идут через черновик страницы (`aufbau_draft.op` → `site_schema.mutate`).

## 2. Решения

| № | Вопрос | Решение |
|---|---|---|
| E1 | Хранение | `data["pick"] = [uuid, …]`, не больше `LIST_LIMIT_MAX` (24), ключ только при непустом списке (presence-minimal, golden целы). В normalize — формат UUID и дедуп, без запросов в БД. |
| E2 | Режим | «Einzeln» действует, пока `pick` не пуст. Поля правила остаются в данных — «Zur Regel zurück» очищает `pick`, и блок снова показывает по правилу. Отдельного ключа режима нет. |
| E3 | Выборка | `pk__in=pick` поверх ТОЙ ЖЕ «живой» выборки, что у правила (активные товары, идущие акции, будущие опубликованные события…), порядок = порядок `pick`. Скрытая или удалённая позиция на сайте просто не показывается. |
| E4 | Смена источника | `pick` сбрасывается: ключи одного вида в другом ничего не значат. |
| E5 | «Alle N →», сортировка, «Höchstens» | При ручном составе не действуют: показано ровно выбранное. В панели поля сортировки и лимита скрыты. |
| E6 | Исчезнувшее | В панели строка «nicht mehr verfügbar» с кнопкой «Entfernen»; на сайте её нет. Само из данных не удаляется — владелец мог лишь временно скрыть товар. |
| E7 | Поиск | GET `?lookup=<текст>` на том же экране (без JS): до 8 живых позиций, не выбранных ранее; без запроса — первые 8 по порядку источника. У товаров — поиск провайдера каталога (название, марка, артикул), у остальных — по названию. |
| E8 | Операции | `pick_add`, `pick_remove`, `pick_up`, `pick_down`, `pick_clear` — через черновик, как остальные правки блока. Добавить можно только существующую живую позицию своего источника (проверка на сервере). |

## 3. Срезы

- **R5a — данные и выборка.** `LIST_PICK_SOURCES`, чистка `pick`, `list_blocks._picked`
  (одна выборка на блок), `resolve` использует её при непустом `pick`.
- **R5b — операции черновика.** Пять операций в `site_schema.mutate`.
- **R5c — панель.** В группе «Welche»: список выбранного (↑ ↓ ✕), поиск, «＋», «Zur Regel
  zurück»; строка результата считает показанное.

## 4. Замки (до кода)

- мусор в `pick` (не UUID, дубли, 100 штук) не попадает в конфиг и не роняет страницу;
- порядок на витрине = порядок `pick`; скрытый товар выпадает, остальные остаются;
- смена источника сбрасывает `pick`;
- добавить чужой/неживой/несуществующий ключ нельзя;
- вверх/вниз/убрать — через черновик, на сайте до «Speichern» ничего;
- панель: исчезнувшая позиция помечена; поиск не предлагает уже выбранное и скрытое;
- число запросов выборки блока не зависит от числа выбранных позиций;
- форма «Welche» без правок не меняет блок (замок W0 R3b-2 дополнен набором с `pick`).

## 5. ECC-прогоны

- До кода: `django-tdd`, `django-security`, `accessibility` (загружены в сессии).
- После R5c: `django-reviewer` + `security-reviewer` (ввод ключей, поиск), `database-reviewer`
  (запросы выборки и поиска), `a11y-architect` (список с кнопками порядка), стенд Playwright
  1440/390 с проверкой витрины.
