# T-8.26 п.4 — фолбэк опечаток по значимым словам + вкладки сохраняют `?kat=` (2026-10-16)

План агента planner по пункту 4 `docs/t8-26-audit-fixes-plan-2026-10-16.md` (аудит §7.2/§7.3);
факты сверены с `main`. Миграций и пересборки индекса нет. Цикл: замки ДО кода → три ревью →
зелёный CI → FF в `main`.

## Факты
- `search.tokenize` удаляет `-` ДО разбиения: «Solingen-Wald» → «solingenwald» → FTS 0.
- `_trigram_pks` склеивает все слова ≥4 букв в ОДНУ строку и сравнивает её целиком
  (`%>` + `TrigramWordSimilarity`, порог 0.3); стоп-слова здесь НЕ снимаются → длинное
  «solingen» тянет фразу выше порога, хотя «friseur» в тексте нет.
- `search_text` = название + бизнес + блюда (без города/района) → «solingen» на триграммах
  совпадает только с названиями вроде «Messer aus Solingen».
- Режим `SearchOutcome.mode ∈ none|fts|trigram|empty`; пометка `data-search-fuzzy` есть только
  в `portal_home.html`; `/entdecken/` (`views.py` search-ветка) `search_mode` в контекст не кладёт.
  Новое значение режима потребовало бы choices-миграции журнала поиска → не вводим.
- Вкладки портала: `broad` без kats/tags (режим и чипы), `carry` выбрасывает kat/merkmal →
  на `/?kat=X` вкладка «Alle» ведёт на `/`, «Produkte» — на `/?kind=product` без раздела.
- Плитка раздела уже ссылается на `?kind=alle&kat=X` и считает по всем видам → её число =
  её выдача. Расхождение аудита — у входа в раздел БЕЗ вида (`kind=""` → только предложения):
  чипы разделов и вкладки после фикса.
- Топонимы: `apps/core/districts.py` (`CITIES`, алиасы, `_key` ö→oe; `search.fold` ö→o).

## Решения
- **Р-1** `_fallback_terms(q, lang, city)`: разбиение без склейки дефиса → стоп-слова → fold →
  длина ≥ SUBSTRING_MIN, не цифры → минус `districts.toponym_tokens(city)` (город + районы +
  алиасы, обе свёртки; пустой city → объединение по всем городам); равенство слов, не подстрока.
  FTS-этап не меняем.
- **Р-2** если слова изменились (снят топоним / разрезан дефис) и что-то осталось — мягкий
  `_match_words` по ним ДО триграмм; режим остаётся `trigram` («не точно», без миграции).
  Р-2b (v2): район как подсказка фильтра — не делаем («Burg»/«Mitte»/«Wald» — обычные слова).
- **Р-3** `_trigram_pks(qs, terms)` одним запросом: OR по словам `%>`, `hits = Σ Case(sim_i ≥ thr)`,
  `hits ≥ need` (`need = n` при n ≤ 2, `n−1` при n ≥ 3), порядок `-hits, -Σsim`; пустые terms → `[]`.
- **Р-4** пометка «Keine genauen Treffer…» — общий партиал `_search_fuzzy_note.html` в
  `portal_home.html` и `search.html`; `views.py` кладёт `search_mode`. Новых msgid нет.
- **Р-5** вкладки несут `kat`/`merkmal` (`tab_carry` отдельно от carry чипов/формы); видимость
  вкладок — по пулу С разделом (`apply_filters(whole_pool, kats/tags)`); «Alle» → `?kind=alle&kat=X`.
- **Р-6** `kind = kind_key or ("alle" if q or kats or tags else "")` — вход в раздел без вида
  показывает все виды, ровно то, что посчитала плитка; ссылку плитки не трогаем.

## Инкременты
4a поиск (search.py, districts.py, `city=` в `broad`) · 4b пометка (партиал + views.py) ·
4c вкладки/раздел (portal_views.py).

## Замки ДО кода
`test_unified_search.py`: фолбэк игнорирует топонимы и требует предмет («Friseur in
Solingen-Wald» → только Herrenschnitt, mode trigram); только-топонимы → `[]`; порог на слово с
балластом («Mesesr Santoku Zzzz» → Messer Santoku; «Mesesr Zzzz» → `[]`); «E-Bike» FTS как прежде;
пометка на `/entdecken/?q=Mesesr` и её отсутствие при точном. `apps/core` `test_toponym_tokens`.
`test_portal_discover.py`: вкладки несут kat и «Alle» не ведёт на `/`; вкладка скрыта, когда в
разделе нет такого вида; число плитки == карточкам по её ссылке и по `/?kat=X` без вида.
Осознанно: ассерты состава `/?kat=…` (теперь все виды) в test_portal_discover/test_city_categories,
`kind` в журнале поиска при `?kat=` без вида → «alle». «mesesr» (строка ~71) остаётся зелёным
без правки — иначе дефект.

## Риски / Ops
Алиасы-слова снимаются только в фолбэке (точный FTS их учитывает); лента раздела без вида длиннее
(все виды — ровно то, что обещает плитка). Миграций нет, индекс не меняется.

## Ревью перед мержем (django · security · database) — блокеров нет
Взято: топонимы только для городов РЕЕСТРА (город вне реестра → пусто; «Burg»/«Wald» в Хильдене
не терялись бы) + `lru_cache`; триггер мягкого шага сравнивает составы по ОДНИМ правилам
значимости (цифра/короткое слово не «меняют состав» — «Messer 2000»); кэп 6 слов фолбэка и
`SET LOCAL statement_timeout` 2 с на его запрос (превысили → честный ноль; security-страховка);
баннер «ähnliche» только при непустой выдаче; три теста портала — на `isolated_ratelimit`;
+4 замка (граница `need`, город вне реестра, опечатка+топоним, режим у только-топонимов).
Принято без правки: float4/float8 на границе порога (measure-zero), префикс у последнего
оставшегося слова в мягком шаге, журнал поиска пишет `kind=alle` у входов в раздел (честно).
EXPLAIN для прода — в отчёте database-reviewer (BitmapOr по `agg_search_text_trgm`; индекс не
менять, при >200 мс — снижать кэп слов).
