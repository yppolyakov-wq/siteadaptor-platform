# KA-12 Волна 5 · E9.1 «библиотека деталей кабинета» (2026-10-30)

Источник: аудит `ka-8-visual-2026-10-23.md` (VI-1…VI-6), мастер-план `ka-12-master-plan-2026-10-23.md`
§E9. Макет утверждён владельцем 2026-10-30 (артефакт «Kabinett-Bausteine»): набор деталей — да,
цвет статуса по роли — да, SVG в меню — да (E9.3), тёмная тема — позже отдельным шагом.

Вид кабинета НЕ меняется: стиль B (2026-08-24) переезжает из скопированных строк утилит в один
набор классов. Этот инкремент — только библиотека + фильтр тона статуса + холст кабинета через
токен. Перевод экранов — следующими батчами в порядке аудита.

## 1. Решения

| # | Что | Как |
|---|---|---|
| D-1 | Префикс `ui-` у классов и `--ui-*` у переменных | `app.css` общий для кабинета, витрины, портала и Mini App: `.btn` уже занят в Mini App, `--accent` — акцент витрины. Без префикса деталь кабинета перекрасила бы витрину тенанта |
| D-2 | Классы в `@layer components` | утилиты Tailwind на конкретном элементе остаются сильнее детали — точечная правка не требует `!important` |
| D-3 | Тон бейджа = роль статуса из `status_registry` | intake → `new` (amber), active → `ok` (emerald), done → `done` (серый), cancelled → `bad` (rose). Кастом-статус владельца получает тон своей роли; неизвестный код — нейтральный `off` |
| D-4 | Тег `{% status_badge obj kind %}` | бейдж = тон по роли + подпись тем же путём, что `{% status_label %}` (имена владельца FB-4a, кастом-статусы). Одна точка для списков, доски и карточек |
| D-5 | Тёмная тема | токены готовы к ней, но значений для `.dark` в этом батче нет (решение владельца — позже) |

## 2. Состав библиотеки

- Токены `:root`: `--ui-canvas/surface/fg/muted/subtle/line/accent/accent-hover/accent-soft/focus`,
  пары `ok/warn/danger/info/off` (+ `-soft`), `--ui-r-card` 16px, `--ui-r-ctl` 10px, `--ui-shadow-card`.
- `.ui-canvas`, `.ui-topbar` (полупрозрачный холст шапки).
- `.ui-btn` + `-primary/-secondary/-ghost/-danger/-danger-outline`, `-sm/-lg`, `:focus-visible`,
  `[disabled]`; высота 40px (sm 32px, lg 48px).
- `.ui-card`, `.ui-card-row`.
- `.ui-badge` + `.ui-tone-new/ok/run/done/bad/off`.
- `.ui-tabs/.ui-tab` (`aria-selected`/`aria-current`), `.ui-tab-count`, `.ui-seg` (`aria-pressed`).
- `.ui-field/.ui-label/.ui-input/.ui-help/.ui-field-error` (`aria-invalid`), шрифт поля 16px.
- `.ui-empty`, `.ui-h1/.ui-h2/.ui-h3`, `.ui-muted` (контраст ≥ 7 : 1 на белом).

## 3. Первое применение в этом батче

`_base_dashboard.html`: `bg-[#F2F4F7]` холста и шапки → `.ui-canvas` / `.ui-topbar`. Больше
ничего на экранах не трогаем — переводы экранов отдельными батчами с паритет-замками разметки.

## 4. Замки (`apps/core/tests/test_ui_library.py`)

- `status_tone` для КАЖДОГО встроенного статуса каждого kind реестра → тон своей роли (полнота).
- Кастом-статус роли cancelled → `bad`; неизвестный код → `off`; мусорный kind → `off`, без 500.
- `status_badge` рендерит подпись владельца (FB-4a), а не код; HTML экранирован.
- Собранный `static/css/app.css` содержит каждый класс библиотеки (иначе purge/забытая сборка).
- В `static/src/app.css` у классов библиотеки нет префикса-коллизии: ни одного `.btn{`, `.card{`.

## 5. ECC-прогоны

- Скиллы до кода: `accessibility` (фокус, контраст, `aria-*` в селекторах), `django-patterns`
  (simple_tag, `format_html`), `django-tdd`.
- Агенты: `django-reviewer` (тег, экранирование) перед мержем; `a11y-architect` — контраст токенов
  и фокус-стили. `security-reviewer` не нужен: новых входов нет, вывод через `format_html`.
- Стенд: один Playwright-скриншот кабинета (холст/шапка не изменились) — по необходимости.
