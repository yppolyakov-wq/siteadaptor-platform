# T-8.6 «Чистый каталог города» — согласие, снятие, «Melden», атрибуция, воронка (2026-10-10)

Пункт 6 общего плана `t8-roadmap-2026-10-10.md` (этап 2: «можно пускать незнакомых людей»).
Источник — анализ лёгкой версии §5 (агрегатор: нет согласия, жалоб, атрибуции) и решение Р-3.

## 0. Факты (разведка 2026-10-10)

- Листинги агрегатора пишутся синками (`aggregator/tasks.py`), каждый upsert ставит
  `is_active=True`; единственный гейт тенанта — `_withheld` = `email_pending` (T-8.5).
- **Приостановленный бизнес остаётся на портале:** `SubscriptionSM` при `→suspended` только
  гасит `Tenant.is_active`, а `listings_for`/`finder` статус тенанта не читают вообще.
  Удаления тенанта как потока нет. `is_active` правится и прямо в админке (мимо FSM).
- **Мой дефект T-8.5:** подтверждение почты пересинхронизирует только АКЦИИ — номера/события/
  меню неподтверждённого тенанта не появились бы и после подтверждения.
- Жалоб/модерации листингов нет; единственный образец — `BusinessReview.status=hidden`.
- `?ch=` живёт в сессии витрины (`_capture_channel` → `session["src_ch"]`) и доезжает до
  `Reservation.source_channel`; у купона канала нет; `Promotion.views` — один счётчик без
  разбивки; ссылки портала канал не несут. Владелец видит лишь резервы по каналам.
- Переключателя «показывать в каталоге города» нет нигде.

## 1. Решение

**Согласие (⚠️ `tenants/0035`):** `Tenant.in_city_catalog` (default True — живые бизнесы не
выпадают из портала молча). Переключатель в «Mein Geschäft» (+ подсказка «erscheint nach
Bestätigung der E-Mail»), галочка на `/aktion-starten/` (включена). Действует только вместе с
подтверждённой почтой (Р-3).

**Кто попадает в каталог — одна точка истины** `aggregator.visibility`:
`listable(tenant)` = есть, `is_active`, не `suspended`, почта подтверждена, согласие дано.
Используется (а) синками при записи (вместо `_withheld`) и (б) ЧТЕНИЕМ портала:
`listings_for`/`finder`/клик-редирект отбрасывают листинги схем, которые сейчас не
`listable` (подзапрос к SHARED Tenant) — правка `is_active` в админке и любые обходы FSM
действуют сразу, без ресинка. `trial_expired` (льготная неделя) из каталога не убирает.

**Синхронизация состояния:** `apply_visibility(tenant)` — не listable → удалить все листинги
схемы; listable → Celery `reconcile_aggregator_schema` (все виды: акции/номера/события/меню).
Зовут: смена переключателя, подтверждение почты (фикс дефекта), `SubscriptionSM` при
`→suspended`/`→active`.

**Скрытие админом (⚠️ `aggregator/0020`):** `AggregatorListing.hidden_at`/`hidden_reason` —
синк поле не трогает (как `featured_until`), чтение портала скрытое отбрасывает.

**«Melden»:** модель `ListingReport` (SHARED): листинг, причина (falsch/abgelaufen/anstößig/
spam/sonstiges), текст, хэш IP, статус open/resolved. Ссылка «Melden» на карточке (вне ссылки
карточки), страница с причинами + honeypot + rate-limit, обе поверхности (`/entdecken/` и
портал — маршрут до catch-all). **Три жалобы с разных адресов → листинг скрыт автоматически**
до решения модератора. Админка: очередь жалоб (решить/скрыть/вернуть), у листинга —
действия «Verbergen/Wieder anzeigen» и счётчик жалоб.

**Атрибуция `?ch=portal`:** фильтр `with_channel` на всех ссылках карточек портала (обычных,
избранных — через клик-редирект, на карте, в шортлисте).

**Воронка по каналам (⚠️ `promotions/0029`, `loyalty/0007`):** `PromotionChannelView`
(акция × канал → просмотры, атомарный инкремент), канал = тот же, что пишется в резерв
(сессия, нормализация `[a-z0-9_-]`, пусто → «direkt»); `Voucher.source_channel` — купон
помнит, откуда пришли. Страница акции в кабинете: таблица «Kanal → Aufrufe → Zurückgelegt →
Abgeholt → Coupons → eingelöst».

## 2. Замки (до правок)

- `listable`: пять условий по одному; синк не создаёт листинг не-listable тенанта;
- чтение портала прячет листинги suspended/`is_active=False`/без согласия/скрытые без ресинка;
- `apply_visibility`: снятие удаляет все виды; возврат ставит реконсиляцию; подтверждение
  почты выкладывает и НЕ-акции (регресс-замок дефекта T-8.5);
- `SubscriptionSM →suspended` снимает листинги;
- «Melden»: жалоба сохраняется, honeypot/rate-limit без записи, три разных IP → скрыто, один IP
  трижды → не скрыто; маршрут портала не съеден catch-all;
- ссылки карточек несут `ch=portal`, клик-редирект тоже;
- просмотр акции увеличивает счётчик своего канала; купон помнит канал; воронка в кабинете.

## 3. Вне объёма

Уведомление владельцу о жалобе (письмо — после пилота), апелляция, модерация до публикации
(пилот небольшой — постмодерация с автоскрытием).
