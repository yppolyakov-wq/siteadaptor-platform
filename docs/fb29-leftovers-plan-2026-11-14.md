  `templates/events/tour_form.html`; права `events:edit`.
- **Уборка:** `drop_blocks` в рабочем коде не вызывается; чистит `purge_ghost_hosts`
  (обходит `_OBJECT_MODELS` — тур подхватит сама).

## 1. Срезы (один срез = ветка → CI → FF в `main`)

### T1 — своя структура и свои блоки у тура (размер M, миграция `events/0039`)

Макет не нужен: секция кабинета на существующем общем частичном.

1. Модель: `Tour.page_override = JSONField(default=dict, db_default={}, blank=True)`;
   миграция аддитивная; дописать в §3 `CLAUDE.md`.
2. Ядро: `object_structure.MODULES["tour"] = "events"`; шаблона страницы у тура нет (как у акции).
3. Хосты: `"tour"` в `OBJECT_HOST_KINDS`; `_OBJECT_HOST_RE` строить из этого списка.
4. Экран «Seitenaufbau» (`site_schema.py`): тур в `OBJECT_KINDS`, `_OBJECT_MODELS`,
   `_OBJECT_EDIT_URLS`; таблица «вид объекта → тип страницы» (`tour → event`) для `_page_type`
   и `resolve`; `host_for` — по виду из кода; превью тура — явный маршрут `storefront-tour` по slug.
5. Витрина: порядок секций через `object_structure.effective_order(…, "events", tour)`;
   в шаблоне `object_blocks "tour"` с обеих сторон от общих блоков.
6. Баннеры: в `place_banners` разделить «тип страницы» (`event_detail`) и «вид объекта» (`tour:<hex>`).
7. Кабинет: `apply_post(tour, "tour", POST)` в `tour_edit`, панель в контекст, секция
   `<details>` в форме тура до кнопки удаления.

**Замки до кода** (`test_fb29_tour_blocks.py` + расширение `test_fb29_object_kinds.py`):
реестры видов синхронны; код `tour@tour:<hex>` даёт хост, чужой/несуществующий pk — нет;
превью ведёт на `/tour/<slug>/`; тур без правок выглядит как раньше; скрытая секция не
выводится, показанная выводится; блок виден только на своём туре (не на другом туре и не на
событии); «свои блоки над общими»; блок-место в своих блоках глушит место по умолчанию;
форма без сентинела поле не трогает (W0), сброс очищает; уборка призраков берёт тур.

**Риски:** бизнес только с турами — тип «event» должен быть активен (проверить на мото-ките);
черновик тура в превью — 404, как у неопубликованного события.

### T0 — событийный блок: лишний запрос на карточку (S, вместе с T1)

`test_list_block_sources.py::test_event_block_queries_do_not_grow_with_cards` локально красный
и после починки окружения: 20 запросов на 6 карточек против 16 на 2 (по одному на карточку
сверх двух); на CI зелёный. Причина не найдена — похоже на зависимость от даты (события на
`days=5+i`). Найти запрос, сделать тест независимым от даты; если это настоящий N+1 на
витрине — чинить агрегатом. `database-reviewer`.

### T2 — Студия «Aufbau ändern» ведёт на строку объекта (S)

`site_schema.url_for_path`: у страницы объекта со своими блоками — строка «Nur diese Seite»,
иначе общая строка типа. Замки: со своими блоками → код объекта; без → код типа; битая ссылка → код типа.

### T3 — поиск страниц у баннера без чтения 2000 записей (S)

`banners.place_search`: фильтр по названию в базе (`icontains`, для JSON-названий — через
приведение к тексту), срез выборки, точная сверка подписи остаётся в Python. Замки: находится
запись за пределами первых 60; число запросов не растёт с числом записей; сбой базы → пустая группа и лог.

### T4 — примеры в предпросмотре дизайна на страницах-списках (M)

`design_samples.for_empty_section` — для списков услуг, номеров, событий. Замки: примеры
только в предпросмотре дизайна и только пока записей нет; в базу ничего не пишется; ссылки
примеров никуда не ведут. Категории и акции — по ответу на вопрос 4.

### T5 — мелочи вёрстки (S)

Колонки галереи и прочих блоков-сеток в узкой ширине — по правилу блока «Liste»; подсказка у
«Zurück zum Standard» говорит, что сбрасывается и положение своих блоков. Стенд 1440/390.

### T6 — чистка после переноса слайдов (ждёт сервера)

блоках «Banner», менеджер слайдов Студии и `undo`; решить про фото с чужих серверов.
Отдельным планом.
