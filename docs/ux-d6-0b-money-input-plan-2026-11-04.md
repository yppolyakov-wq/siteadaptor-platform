# UX-D D6.0b — один разбор сумм во всех формах кабинета (2026-11-04)

Хвост волны D6 (`ux-d6-lists-plan-2026-11-03.md` §D6.0b, найдено ревью). D6.0 перевёл допы и
финансы на `core.money.parse_amount`; остальные формы разбирают суммы по-своему. Без миграций.

## 1. Что не так (проверено чтением кода)

| Место | Сейчас | Что ломается |
|---|---|---|
| `_eur_to_cents` в `orders`, `stays/form_input`, `events/details`, `booking` (×2), `jobs._parse_deposit_cents` | `float(raw.replace(",", "."))`, мусор → 0 | «1.234,50» → **0 €** молча (немецкий формат с тысячами); «1,234» → 1,23 €; у части — `1e999` → 500 (OverflowError не ловится) |
| `loyalty/public_views` (витрина, сумма сертификата) | то же | «1.234,50» → 0 → «сумма вне диапазона» вместо 1234,50 |
| `orders/views` правка заказа (цена, скидка, доставка) | `Decimal(raw.replace(",", "."))` в общем `try` | «1.234,50» → ошибка вместо суммы; `NaN` проходит до `int()` |
| `catalog._parse_price`, `_parse_signed` | `Decimal(...)`, проверка `>= 0` | `NaN` → `InvalidOperation` на сравнении (500); `Infinity` проходит в запись |
| `inventory/views_purchasing` EK строки закупки | `Decimal(...)`, `except Exception` → None | `Infinity` уходит в сервис закупки |
| `core/views` скидка сделки, `core/inline_edit`, `core/setup_steps`, `events/views` | `Decimal(...)` | тысячи не понимаются; бесконечность/NaN — по месту |

## 2. Решение

В `core/money.py` — второй помощник рядом с `parse_amount`:

```python
def lenient_cents(raw, *, default=0, max_value=MAX_FORM_AMOUNT) -> int:
    """Старые формы, где пусто/мусор = «суммы нет» (депозит, скидка, надбавка → 0).
    Разбор тот же, что у parse_amount (тысячи, запятая, €), неконечное/отрицательное/больше
    потолка/3+ знака → default."""
```

- шесть `_eur_to_cents`-помощников и сумма сертификата → `lenient_cents` (семантика «мусор = 0»
  сохраняется; меняется только то, что «1.234,50» читается верно, а `inf`/`NaN` больше не роняют);
- места, где ошибка уже показывается человеку (`orders` правка заказа, скидка сделки,
  `catalog._parse_price/_parse_signed`, EK закупки, inline-правка) → `parse_amount`
  (`allow_negative` там, где знак законен: надбавка опции, скидочная строка) — ошибка остаётся
  ошибкой, но «1.234,50» и «12,50 €» принимаются, `NaN`/`Infinity` отклоняются;
- ставки НДС — не трогаем (уже `vat.parse_rate`, проверен D6.5).

## 3. Замки (до правок)
- параметризованный тест помощников: «1.234,50» → 123450, «12,50 €» → 1250, «NaN»/«inf»/«1e999»/
  «-5»/«abc» → default, потолок;
- по одному тесту на вьюху: депозит заявки, предоплата услуги/номера, скидка/доставка/цена
  заказа, сертификат на витрине (`1.234,50` не превращается в 0; `inf` не роняет страницу);
- скан-замок: в перечисленных модулях нет `float(` рядом с `.replace(",", ".")`.
