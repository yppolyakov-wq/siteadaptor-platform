# Pranasy: Seite `/sortiment/catering/` wie eine Startseite (2026-08-26)

**Фидбэк владельца (4 пункта):**

1. «Добавить в категории фото на странице `…/sortiment/catering/`».
2. «Для пакетов меню так же нужно применить функцию разного вида, как и для основных блюд».
3. «Сгенерируй недостающие изображения блюд».
4. «Добавь на эту же страницу галерею о кейтеринге, отзывы, команду и т. д. — как для
   полноценной главной страницы».

## 1. Разбор: что именно сломано/отсутствует

| # | Диагноз (проверено на коде и сиде) |
|---|---|
| 1 | Подкатегории на странице категории рисуются ТЕКСТОВЫМИ карточками при любом шаблоне, кроме `kopfbild` (`products.html`, ветка `{% else %}`). У `catering` шаблон `sets` → шесть Gänge без фото. Плюс: у «Beilagen» ключ `rice,bowl` своего файла не имеет и по префикс-группе забирает `rice-peas.webp` — фото БЛЮДА «Gemüsereis». |
| 2 | У наборов (`_combo_card.html`) вида один — карточка 4:3. У блюд посетитель переключает вид (MEN-22 class-swap на главной, MEN-24d `?ansicht=` на странице каталога). |
| 3 | 15 из 49 блюд без реального фото (тематический SVG), ещё два салата берут generic `salad-bowl.webp` (одна миска на двоих). |
| 4 | `{% page_blocks "catalog" %}` — ОДИН хост на весь каталог: блоки появились бы и на `/sortiment/`, и на всех 12 других страницах категорий pranasy. Точечного хоста «эта категория» нет. |

## 2. Решения

### P1 — фото у подкатегорий (generic)

Подкатегории рендерятся общим партиалом `_category_tile.html`, когда хотя бы у одной
есть фото (`subcategories_have_images`) — как уже сделано для верхнего списка категорий
(`categories_have_images`, фидбэк 2026-08-07). Нет фото ни у одной → прежняя текстовая
сетка байт-в-байт (у большинства тенантов `Category.images` пуст — иначе страница стала
бы хуже, чем была). `kopfbild` свою безусловную ветку сохраняет.

Плюс «Beilagen» получает СВОЙ файл — категория не должна носить фото своего же блюда.

### P2 — виды отображения наборов

Механика MEN-22 (class-swap + localStorage), НЕ серверный `?ansicht=`:

* полоса наборов живёт на странице каталога, где `?ansicht=` уже занят блюдами;
* набор не пагинируется (кап 6) — ре-рендер не нужен;
* DOM карточки не меняется → паритет-замки `_combo_card` целы.

Три вида: `kacheln` (как сейчас, дефолт) · `liste` (строка: фото слева, текст справа) ·
`kompakt` (строка без фото). Переключатель — рядом с заголовком «Menü-Pakete» и на
`/kombi/`; ключ localStorage свой (`combos`), поэтому вид наборов не связан с видом блюд.
Классы целевых видов — в `data-cls-*` (purge-safe, как в `_price_list.html`).

### P3 — недостающие фото

**Генерации изображений в этой среде нет** (нет ключа Replicate/OpenAI; прежние AI-наборы
делались отдельной сессией с доступом). Поэтому — тот же пайплайн, что дал 32 фото карты:
Openverse `license=cc0,pdm` → кандидаты → каждый кадр просматривается → webp ≤150 КБ →
`SOURCES.md`. Правило витрины прежнее: НИКАКОГО мяса/рыбы в кадре; чужое блюдо — брак.
Не нашлось честного кадра — остаётся SVG (неверная тарелка хуже отсутствия).

Цели: 15 блюд без фото + 2 салата с generic-миской + 1 фото категории «Beilagen».

### P4 — блоки страницы у КАЖДОЙ категории

`page_blocks` получает хосты вида `catalog:<slug>` рядом с фикс-whitelist'ом
`PAGE_BLOCK_HOSTS`. Это прямое продолжение KAT-1 («категория = страница»):

* `normalize_page_blocks` принимает `catalog:<slug>` (slug по строгому паттерну, кап
  числа таких хостов) — presence-minimal, golden целы;
* четыре гейта билдера (`add_block`, `use_block_template`, save-цикл `pb_present`,
  сборка `page_cblocks`) идут через ОДИН предикат `is_page_block_host`;
* страницы категорий попадают в `preview_pages` (группа `catalog`) — Studio их открывает,
  «+» на канве вставляет в правильный хост (`data-pb-host` уже несёт витрина);
* `products.html` на странице категории рендерит `{% page_blocks "catalog:<slug>" %}`
  ПОСЛЕ общего `{% page_blocks "catalog" %}`.

Тогда «галерея/отзывы/команда» — это ссылочные блоки `gallery_ref` / `testimonials_ref` /
`team_ref` / `faq_ref` / `anfrage_ref` (UC2-3b), то есть ГЛОБАЛЬНЫЙ контент сайта,
показанный и здесь. Своего дубля контента страница не заводит.

Демо pranasy: `DemoKit.page_blocks` = `{"catalog:catering": [gallery_ref, testimonials_ref,
team_ref, faq_ref, anfrage_ref]}`.

## 2b. Что получилось по P3 (фото)

Четыре раунда Openverse (`license=cc0,pdm`; точные названия блюд, транслитерации,
глубина 2 страницы, wikimedia-оригиналы отдают 429) на 15 блюд без фото дали
**два честных кадра**: `rice-plain.webp` (Reis) и `cucumber-raita.webp`
(Gurken-Raita). Остальные кандидаты отбракованы по правилам витрины: мясо/рыба в
кадре (Kohlroulade с шейкой, «green gazpacho soup **shrimp**», тушёная капуста с
свининой), узнаваемые лица (дети в школьной столовой, гость с ложкой), рекламные
плакаты 1910–50-х вместо еды и — чаще всего — ЧУЖОЕ блюдо (самосы вместо
Minzsauce, дал вместо Kitchari, красная подлива вместо БЕЛОГО Paneer-Ragouts).

Поэтому 13 блюд ОСОЗНАННО остаются на плейсхолдере, но сам плейсхолдер доведён:
реестр эмодзи знал только английские слова, так что немецкие ключи получали
общую «тарелку» 🍽️ или вовсе ✨. Добавлены темы (`ragout`→🍲, `kohl`→🥬,
`gurke`→🥒, `aubergine`/`brinjal`→🍆, `bulgur`/`groats`→🌾, `raita`/`joghurt`→🥛,
`bratling`→🥟, `kitchari`→🍛, `minz`→🌿, `suppe`→🍲, `reis`→🍚 …), а ключи блюд
переименованы так, чтобы подпись читалась как название («Gekochter» → «Reis»,
«Soy» → «Bolognese», «Mahabrinjal» → «Mahabridschal»). Два замка держат
результат: у каждого блюда своя тема (не 🍽️/✨) и подпись складывается из слов
его собственного названия.

**Генерации изображений моделью в этой среде нет** (ключа Replicate/OpenAI не
существует; прежние AI-наборы делались отдельной сессией с доступом). Если
владелец хочет фотореалистичные кадры для оставшихся 13 — это отдельный шаг с
внешним провайдером, как в `external-integrations-backlog.md`.

## 5. Второй заход по фидбэку (тот же день)

Три правки по странице направления:

* **Порядок блоков.** У шаблона «Sets & Menüs zuerst» полоса «Menü-Pakete» встала
  ПЕРЕД списком категорий: пакет и есть главное предложение направления, а
  категории ниже ведут к блюдам. Побочно тулбар (фильтр/сорт/плотность) оказался
  прямо над сеткой, которой управляет. У остальных шаблонов положение полосы
  прежнее — замки KAT-2 целы.
* **Подпись категорий.** У блока подкатегорий появился заголовок «Kategorien»:
  рядом с подписанной полосой пакетов он читался как её продолжение. msgid уже
  был в каталогах, новых строк не заводили.
* **Шесть столбцов.** `page_layouts["catalog"]` кита — `cols6`. Действует на все
  страницы каталога демо (у pranasy весь каталог — еда); посетитель по-прежнему
  меняет плотность контролом «− N +», на телефоне остаются две колонки.

### Дефект, который поймал стенд: «6 столбцов» рисовало три

Классы сетки собирает Python (`siteconfig.grid_class_string`), литералов в
шаблонах нет — значит Tailwind знает о них только из `safelist`. `lg:grid-cols-6`
туда не попал с волны DS-5, поэтому purge вырезал правило: вариант «6 столбцов»
стоял в пикере раскладок Studio у КАЖДОГО тенанта, а выбравший его молча получал
три колонки (побеждал sm-класс). Серверные тесты такое не видят — разметка-то
верная.

Замок `test_every_grid_class_the_layout_engine_emits_exists_in_the_built_css`
проверяет ВСЕ комбинации таблиц движка против собранного CSS: следующий пресет
без записи в safelist не пройдёт молча.

## 3. Границы v1

* Порядок/состав блоков категории правится в Studio, но отдельной кнопки «добавить
  секции как на главной» в кабинете категории нет (вход — канва/панель билдера).
* Вид наборов — посетительский; дефолта владельца в конфиге нет (у блюд он есть, у
  наборов v1 обходится: карточки остаются дефолтом).
* Генерация изображений моделью — вне среды; см. §2b.
* Попутно (видно ровно на этой полосе): карточка свободной сборки печатала
  «0,00 € / Person» — цены у неё нет, итог складывается из выбора. Цену такого
  набора больше не показываем; что это, говорит бейдж «Freie Auswahl».
