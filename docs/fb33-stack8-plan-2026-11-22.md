## 4. Ревью плана среза A (`planner`, 2026-11-22, до кода) — принято

Поправки к §1 A и §2 (каждая — замок первого коммита среза):
- **R1 (CRITICAL).** Django берёт `handler404` из `get_urlconf()`; до разбора адреса это ROOT_URLCONF =
  `urls_tenant`, поэтому `Http404` из middleware (неизвестный хост, `AdminGuardMiddleware`) попадёт в наш
  обработчик и на платформе, и на портале. Обработчик сам проверяет: тенант есть, схема не `public`,
  `request.portal is None` — иначе `django.views.defaults.page_not_found`.
- **R2.** Страница с блоками — только GET/HEAD, без `HX-Request`, вне `i18n_cabinet.CABINET_PREFIXES`, не у
  неподтверждённого бизнеса (`PendingStorefrontMiddleware`); иначе прежняя 404.
- **R3.** Блоки-формы на 404 запрещены (как у `confirmation`); «Liste» разрешён. Замок: страница по
  умолчанию не ставит НИКАКИХ cookie; с любыми блоками — не пишет сессию.
- **R4.** У блоков по умолчанию постоянные id (`nf-search`, `nf-popular`) — иначе черновик «меняется» сам.
- **R5.** Блоки по умолчанию не хранят текста: подписи — `gettext` при показе.
- **R6.** Пустой ключ `page_blocks["not_found"]` хранится (normalize и `page_presets` его не снимают):
  «задано пусто» ≠ «не задано». Умолчание считает `siteconfig.page_rows`; витрина читает через неё же.
- **R7.** `data-stu-page="not_found"` — Студия не показывает блоки главной.
- **R8.** При DEBUG=True обработчик не вызывается — стенд 404 идёт с DEBUG=False.
- Замок `test_custom_404_stays_standalone` НЕ переворачивается: `templates/404.html` остаётся запасной
  страницей (платформа, портал, сбой рендера). Строка «4» таблицы §2 заменяется замком «запасной путь жив».
- «Beliebt» — набор `"menu"` блока `quick_links` (`hero_tiles.QUICK_LINK_SETS`), плитки — верхний уровень
  `storefront_menu` из контекста (второй `resolve_menu` не звать).
- «Suche» — новый блок `site_search` (GET-форма `?q=` на `storefront_search_url`, единая точка
  `apps/core/context.py`); показывается, когда адрес поиска есть (каталог, запись, номера, события, акции —
  шире, чем «только каталог»); в «+ Block» предлагается только на хосте `not_found`.
- `detail_parts`, `aufbau_draft`, `block_window`, `block_i18n` — веток под `not_found` не нужно (своих
  разделов у хоста нет).
