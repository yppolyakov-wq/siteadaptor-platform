# KA-12 Волна 3 · батч 2 «Деньги с миграциями» — план (2026-10-24)

План — агент planner, сверка с кодом. Предыдущий шаг — батч 1
(`ka-12-w3-money-plan-2026-10-24.md`). Перенесены сюда из батча 1: MC-J1 и напоминание
об остатке билета.

## Принципы
1. **Фолио — денежная книга, не выручка.** `RevenueEntry` пишется при исполнении (MC-D1);
   строка `DealPayment` в журнал не проводится; частичный возврат после проводки — через
   `record_reversal` с уникальным `source_ref` на накопленную сумму.
2. **Двойная запись.** `payment_state` остаётся грубым состоянием (`open_q`/фильтры не меняются);
   суммы читаются из фолио, если строки есть, иначе — по-старому.
3. **Без бэкфилл-миграции.** Первая запись в легаси-сделку создаёт строку «Eröffnung» (сумма,
   уже полученная по старым правилам) под `select_for_update`, ДО записи полей — иначе сделка с
   депозитом до деплоя и остатком после недосчиталась бы.
4. Миграции только аддитивные; `finance/0016` — со сменой constraint (согласие владельца).

## Замки (пишутся первыми)
- B2-1: сделка с сертификатом → `voucher_paid_cents == discount`, с промокодом → 0; промокод с
  кодом, совпавшим с сертификатом, — `certificate_cents == 0` (сегодня красный).
- B2-2: accepted с неоплаченным депозитом — одна строка = депозит; quoted — нет; после счёта —
  строка счёта; после вебхука депозита — нет.
- B2-3: паритет всех сценариев `test_money_invariant`; легаси-депозит → «bezahlt» = opening +
  balance; повтор вебхука — одна строка; opening не дублируется при гонке; N+1 в `open_items`.
- B2-4: 10 € из 50 € → `refunded_cents=1000`; двойной клик — один вызов Stripe; две разные
  частичные — два ключа; больше оплаченного — отказ; отмена после частичного — возвращает остаток.
- B2-5: deposit-бронь → checkout на `due`; повтор вебхука — одна строка; чужая схема/сделка в
  metadata — ничего не пишется.

## Риски
Двойная выручка (фолио не проводит; корректура вне заявки журнал не трогает) · недосчёт оплаты у
легаси (opening под блокировкой) · идемпотентность возвратов (claim + ключ на накопленную сумму) ·
GoBD (выставленные счета не правим, корректура — свой номер) · N+1 (`folio.prefetch`) · частичный
возврат Stripe после полного и наоборот (всегда явный `amount`).
