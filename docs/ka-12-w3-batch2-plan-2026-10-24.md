# KA-12 Волна 3 · батч 2 «Деньги с миграциями» — план (2026-10-24)

План — агент planner, сверка с кодом. Предыдущий шаг — батч 1
(`ka-12-w3-money-plan-2026-10-24.md`). Перенесены сюда из батча 1: MC-J1 и напоминание
об остатке билета.

## Принципы
1. **Фолио — денежная книга, не выручка.** `RevenueEntry` пишется при исполнении (MC-D1);
   строка `DealPayment` в журнал не проводится; частичный возврат после проводки — через
   `record_reversal` с уникальным `source_ref` на накопленную сумму.
2. **Двойная запись.** `payment_state` остаётся грубым состоянием (`open_q`/фильтры не меняются);
   суммы читаются из фолио, если строки есть, иначе — по-старому.
3. **Без бэкфилл-миграции.** Первая запись в легаси-сделку создаёт строку «Eröffnung» (сумма,
   уже полученная по старым правилам) под `select_for_update`, ДО записи полей — иначе сделка с
   депозитом до деплоя и остатком после недосчиталась бы.
4. Миграции только аддитивные; `finance/0016` — со сменой constraint (согласие владельца).

## Риски
Двойная выручка (фолио не проводит; корректура вне заявки журнал не трогает) · недосчёт оплаты у
легаси (opening под блокировкой) · идемпотентность возвратов (claim + ключ на накопленную сумму) ·
GoBD (выставленные счета не правим, корректура — свой номер) · N+1 (`folio.prefetch`) · частичный
возврат Stripe после полного и наоборот (всегда явный `amount`).

## B2-4b Minderung — уточнённый план (2026-10-24, после B2-4a)
- Где: заказ, запись услуги, бронь номера (у них есть скидка владельца DC-5). У билета скидки нет —
  только возврат переплаты (B2-4a).
- Проверки ДО денег: сделка не отменена; нет выставленного счёта (иначе это Rechnungskorrektur,
  B2-7); сумма ≤ итог сделки и ≤ полученного; сертификат: скидка не опускается ниже его суммы.
- Порядок: захват возврата → Stripe → (успех или «неизвестно») снижение цены через
  `deal_discount.set_discount(discount + X, allow_closed=True)` → если выручка уже проведена —
  сторно `{id}:minderung:{новая скидка}` на X со ставкой проведённой записи.
- Двойное сторно: отмена записи/брони сторнирует ИСХОДНУЮ запись выручки — вычитаем уже сделанные
  сторно Minderung (`finance.services.minderung_total`). Заказ сторнирует `total` (уже сниженный).
- Отказ Stripe — цена не меняется. Только владелец.

## B2-7 Rechnungskorrektur — план (planner, 2026-10-24)
Делим на три шага.
- **B2-7a (без миграций):** возврат заказа (`returned`) возвращает сертификат ровно на
  `voucher_paid_cents` (легаси — `discount_cents`); то же в зеркале кастом-статусов.
- **B2-7b (⚠️ `finance/0016`, согласие M-1):** `kind += credit` (AlterField, только choices),
  FK `corrects` (PROTECT, related_name `corrections`), `correction_key` + частичный unique;
  замена проверки на `finance_invoice_kind_links` (invoice: без ссылок · storno: cancels ·
  credit: corrects) — существующие строки её проходят. `create_credit(original, gross, reason,
  key)`: под блокировкой, только issued/paid, сумма < остатка (иначе это Stornorechnung),
  строки по ставкам пропорционально оригиналу (сходится с `compute_totals`), номер из того же
  счётчика, отрицательные суммы, без срока оплаты. `open_amount` = брутто − корректуры −
  предоплата; Offene Posten аннотирует сумму корректур (без N+1); `invoice_for` берёт только
  `kind=invoice`. Minderung при выставленном счёте больше не отказ: выпускает корректуру в той
  же транзакции; выручку пишет только `record_minderung` (корректура журнал не трогает).
- **B2-7c:** ручная «Gutschrift erstellen» со страницы счёта (заказ/запись/номер — через
  Minderung без возврата денег; заявка — сторно журнала по ставкам; свободный счёт — только
  документ); Stornorechnung счёта с корректурами = минус ОСТАТОК; PDF «Rechnungskorrektur» +
  «Korrektur zu Rechnung RE-… vom …» (§ 31 UStDV), оригинал не меняется; подписи в кабинете
  «Gutschrift» (G-1).
