# План VF-13: резерв склада из сметы при «Beauftragt»

Дата: 2026-08-25. Решение владельца: «Делай по рекомендации» — товар из сметы
резервируется при принятии заявки (Beauftragt), чтобы витрина не продала больше,
чем есть. Разведка — воркфлоу 2026-08-25 (факты file:line проверены).

## 1. Сегодня

- Заказы (orders) режут `stock_quantity` при создании (`_reserve_stock`,
  OutOfStock блокирует покупку); возврат при отмене.
- Смета (jobs) списывает ТОЛЬКО при `done` — `services.commit_stock`
  (кламп в 0, идемпотентность через `Job.stock_committed`, леджер
  `kind="commit", source="job", source_ref=line.pk, note=reference_code`, FEFO).
- Возврата при отмене jobs нет вовсе (докстрока фиксирует: «cancelled достижим
  только до done» — уже неверно: ребро accepted→cancelled существует).
- `set_lines` пересоздаёт строки (delete+bulk_create) → PK строк нестабильны.
- Между accepted и done материал никак не удержан → витрина может продать
  зарезервированное под заявку.

## 2. Приём

**Резерв = уменьшение `stock_quantity`** (как заказы/Anprobe): витрина получает
«Ausverkauft» бесплатно (5 точек чтения счётчика не трогаем), реконсиляция
`счётчик == Σ леджера` сходится по построению. Отдельного счётчика «reserved»
и нового kind движения НЕ заводим — без миграций.

1. **Резерв при входе в `accepted`** — вызов существующего `commit_stock(job)`
   в `JobSM.on_transition` (кламп, не блокировка: принятие сметы клиентом/вебхуком
   Anzahlung нельзя валить OutOfStock — детали докупаются; философия jobs
   сохраняется). При `done` вызов остаётся — идемпотентный no-op
   (`stock_committed=True`). Вебхук Anzahlung идёт через `JobSM().apply` —
   покрыт автоматически.
2. **НОВОЕ `release_stock(job)`** — возврат при `cancelled`/`declined`:
   по ЛЕДЖЕРУ, не по строкам (строки могли пересоздаться/отвязаться):
   движения `source="job", kind="commit", note=reference_code`; на каждое —
   return-движение `source_ref=f"ret:{mv.pk}"` ПЕРВЫМ (дедуп конституционный
   через unique (source,ref,kind)); счётчик двигается conditional UPDATE (+F)
   только при созданном движении; `restore_fefo`. После — `stock_committed=False`
   под select_for_update. Возвращается ровно списанное (вкл. клампы).
   Re-accept после отмены невозможен (builtin-граф + правило «рёбер ИЗ
   cancelled не бывает») — двойной резерв исключён.
3. **Правка сметы при активном резерве** — в `set_lines`: если
   `stock_committed` и роль текущего статуса `active` → release + повторный
   commit в той же atomic (diff через полный цикл; net-эффект = дельта).
   После done/invoiced правка склад НЕ трогает (прежнее поведение — история).
4. **Кастом-статусы (зеркало)** — `status_effects`: kind=job, вход в роль
   `active` с `blocks_capacity` → `commit_stock_for` (для заявок «держит
   ёмкость» = держит детали; дефолт роли active — blocks_capacity=True,
   builtin `quoted` его не имеет → квота не резервирует); вход в роль
   `cancelled` → job-ветка в `restore_stock_for` (release_stock). Снять
   явный «паритет: не делаем» из докстроки.
5. **UI** — подсказка в конструкторе сметы («вычтены после выполнено») →
   «резервируются при Beauftragt, списываются при Erledigt»; msgid ×5 .po.

## 3. Замки (ДО правок)

- accept режет счётчик + леджер commit; done после accept — без двойного списания.
- accepted→cancelled возвращает ровно списанное (вкл. кейс клампа: было 2,
  в смете 5 → списали 2, вернули 2).
- quoted→declined — движений нет (резерва не было).
- Правка qty 2→5 при резерве двигает счётчик на 3; отвязка строки возвращает.
- Кастом-статус роли active резервирует один раз; кастом-отмена возвращает один раз.
- Правка сметы после done склад не трогает.
- FEFO: партии гасятся при резерве и восстанавливаются при отмене (smoke).

## 4. Границы v1

- Кламп, не блокировка (осознанно — ручной процесс, детали докупаются).
- Предупреждение «зарезервировано меньше сметы» на карточке — по спросу.
- Штучный diff вместо release+re-commit при правке — не нужен (net тот же,
  всё в одной atomic).
