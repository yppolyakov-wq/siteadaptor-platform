## 1. Что есть сегодня

### 1.1. Восемь списочных секций главной живут отдельно от блока «Liste»

| Ключ секции | Источник блока | Выборка во вьюхе главной (`promotions/public_views.py:158`) | Своё у секции |
|---|---|---|---|
| `promotions` | promotions | активные, `-created_at`, срез `limit` (9), §11 lowest_30d | стили spotlight / banner / rows, чипы «Ending soon» (≤3 дня), пустая секция пишет «No current offers.» |
| `products` | products | `source` featured_first / newest / featured_only, срез `limit`, промо-цены | 8 прайс-видов (`preisliste*`, кап строк `rows`, PDF), переключатель «список/плитка» |
| `categories` | categories | ВСЕ корневые активные, срез `limit` | стили square / tall / wide / compact, `img_h`, `tile_info` (ab-цена/число) |
| `services` | services | ВСЕ активные (без лимита) | горизонтальная карточка → выбор слота, бейдж Festpreis при jobs |
| `stay_rooms` | stays | ВСЕ активные (без лимита) | — |
| `events` | events | опубликованные будущие, `starts_at`, срез | своя карточка с правкой на канве (название/цена/фото) |
| `tours` | tours | опубликованные, порядок владельца, срез | — |
| `blog` | blog | опубликованные, срез | — |

У всех восьми: заголовок/интро (`section_titles[key]`/`section_intros[key]`, правка на
канве), ссылка «View all» (`show_all`, по умолчанию вкл), полный движок раскладки (пресет,
колонки по устройствам, лента, хвост, ряды, скорость), visual/hidden_on/width/font, якоря
меню по КЛЮЧУ (`siteui._BLOCK_ANCHOR_ID`: zimmer, leistungen, neuigkeiten, reisen; у акций
`id="aktionen"` в шаблоне).

Чего у секций **нет**, а у блока «Liste» есть: фильтр (тип/срок/скидка акций, категория/
подборка/«только…» товаров, подборка/видео услуг, подборка номеров, тема/«14 дней» событий,
страна туров, родитель категорий), сортировка провайдера фасетов, форма карточки, «Alle →»
с тем же фильтром. Чего у блока нет, а у секций есть: стили-композиции (прайс-лист,
spotlight/banner/rows, плитки категорий), полный движок раскладки по устройствам,
заголовок с правкой на канве, переключатель «список/плитка».

Итог: **одна и та же сущность «список товаров» на главной настраивается двумя разными
наборами контролов**, и ни один не умеет всего (именно это владелец называл «кашей»).

### 1.2. От ключей секций зависит многое

* `siteconfig.normalize_sections` (siteconfig.py:3603) материализует **все 25** фикс-секций —
  golden-эталоны содержат их все.
* Демо-киты: `demo_kits._kit_sections` (demo_kits.py:22502) — ряды по ключу + style/rows/
  layout/visual/sections_off; блоки кита ставятся «после секции <ключ>».
* Сборки дизайна (`sitetemplates.py`, ≈30 мест): `sections_order`, `section_styles`,
  `section_layouts`, `sections_on/off` — по ключу.
* Якоря меню/демо-меню — по ключу; переводы заголовков/интро — оверлеи `section_titles`/
  `section_intros` по ключу; Студия — имена полей `<поле>_<ключ>`; черновик — `collect()`
  по ключу; H0-гейт `archetypes.section_visible_for` — по ключу.
* CTA первого экрана ведёт по `primary_item.landing` (URL листинга), а не по якорю —
  его перевод на движок не задевает.

## 2. Центральное решение: «встроенный список»

**Списочная секция главной становится блоком «Liste» с закреплённым источником; ключ
секции остаётся её идентичностью.** У строки `products` появляются оси «ЧТО» блока
(фильтр, сортировка, форма карточки) в `row["data"]` (presence-minimal), выборку делает
движок блока (`core/list_blocks.py`), Студия показывает тот же набор контролов, что у
блока «Liste», а свободные блоки «Liste» получают все виды секций (прайс-лист, spotlight…).

Почему не «превратить в хранении в `{"key": "list"}`-блоки»:

* от ключа зависят golden, 19 китов, ~30 мест сборок, якоря меню, оверлеи переводов,
  H0-гейт, поля Студии и черновика — переписать всё ради невидимой владельцу разницы;
* единственная видимая разница — «удалить» против «скрыть», а скрытие встроенного списка
  ровно так же обратимо и сохраняет «палитру» (выключенная «Veranstaltungen» видна в
  списке и включается одной галкой);
* второй, третий… список того же источника на главной — обычный блок «Liste»
  («Neu im Sortiment», «Endet heute»), и встроенную строку можно скопировать в блок.

Так «секция товаров» и «блок Liste» перестают быть двумя механизмами: **один движок
выборки, один набор контролов, один реестр видов**. Хранение — прежнее, golden целы.

## 3. Модель данных

* `siteconfig.BUILTIN_LIST_SOURCES = {promotions: promotions, products: products,
  categories: categories, services: services, stay_rooms: stays, events: events,
  tours: tours, blog: blog}` — ключ секции → источник блока.
* `row["data"]` у этих восьми строк — ТОЛЬКО оси «ЧТО» источника + форма карточки
  (`_clean_list_block` с принудительным источником; поля вида — out/cols/rows/speed — НЕ
  хранятся: у строки остаётся её полный `layout`). Нет значений → ключа `data` нет
  (golden байт-в-байт).
* Легаси-поля строки не трогаются: `limit`, `source` (products), `rows`, `show_all`,
  `img_h`, `tile_info`, `layout`, `style`. Адаптер `list_blocks.section_data(row)`
  собирает из них данные блока:
  * products `source` → featured_first ≡ `sort=featured`, newest ≡ `sort=newest`,
    featured_only ≡ `only=featured` (+ newest); явные `data.sort/only` сильнее;
  * `limit` строки → лимит выборки; у `services`/`stay_rooms` лимита нет → «все» (как сейчас);
  * источник — по ключу (у строки его не выбрать).
* Заголовок/интро — прежние `section_titles`/`section_intros` (переводы и правка на канве
  целы).

## 4. Рендер

* Вьюха главной: для каждой включённой встроенной строки — `list_blocks.resolve_section`
  (фетчер источника + фильтры + сортировка + лимит) вместо своего запроса. Контекст
  шаблонов прежний (`products_preview`, `promotions`, …) — шаблоны секций не меняются,
  кроме ссылки «View all» (несёт фильтр: категория → `/sortiment/<slug>/`, тип акции →
  страница типа и т.п., `list_blocks._all_url`) и формы карточки строки.
* Особые данные секций сохраняются: `promo_ending_soon` (тот же фильтр), Festpreis,
  аспект плиток категорий, `has_products`.

### 4.1. Сознательные отличия (согласованность с листингами, а не регресс)

1. **События:** серия/заезды тура — одной карточкой («+N Termine»), как на `/veranstaltung/`.
2. **Категории:** направление без товаров в поддереве на главной не показывается (плитка вела
   на пустую страницу) — как на `/sortiment/` и в блоке «Liste».
3. **Блог:** статья без даты публикации — в конце, а не первой.
4. **Услуги/номера:** если владелец задал порядок листинга по умолчанию (STU-15c
   `services_sort`/`stays_sort`), главная следует ему — как «Alle →».

Каждое отличие — отдельный замок с комментарием (характеризация остального — байт-в-байт).

## 5. Студия

* Общий партиал полей «ЧТО» блока «Liste» (фильтры, сортировка, форма карточки),
  вынесенный из `_cb_row.html` (вывод строки C-блока — байт-в-байт, замок), с префиксом
  имён: у C-блока `cb_<id>_`, у встроенной строки `sl_<ключ>_`; источник у встроенной
  строки не выбирается (закреплён), видны только поля её источника.
* У products селект «Which items» (featured_first/newest/featured_only) заменяется
  общими «Auswahl» + «Sortierung» (одно место); легаси-значение предзаполняет их.
* Save: `sl_<ключ>_<поле>` → `entry["data"]` (normalize чистит); H0 carry-forward цел.
  Черновик: `collect()` шлёт `sec.data`. Сироты (подборка/категория/тип, которых нет в
  живых списках) остаются выбранными (W0) — как у блока.
* «Als eigenen Block kopieren»: копия встроенной строки в блок «Liste» (те же ЧТО +
  колонки/лента), чтобы получить второй список того же источника.

## 6. Одни виды везде

Блок «Liste» получает композиции встроенных секций — тот же реестр:
`LIST_STYLES[source] = SECTION_STYLES[ключ секции]` (products → 8 прайс-видов, promotions →
spotlight/banner/rows, categories → square/tall/wide/compact + img_h/tile_info). Разметка
композиций выносится из шаблонов секций в общие партиалы (сначала замки паритета секций),
`_block_list.html` и секции рисуют их одинаково. Прайс-лист блока учитывает его фильтр
(категория). В строке блока — селект «Darstellung» по источнику.

## 7. Адаптация под все архетипы

1. **Библиотека «＋»**: пресеты блока «Liste» для каждого источника (сейчас — только акции и
   товары): «Unsere Leistungen», «Video-Beratung» (услуги) · «Unsere Zimmer» лентой (номера) ·
   «Nächste Termine», «In den nächsten 14 Tagen» (события) · «Unsere Reisen» (туры) ·
   «Menü-Pakete / Sets» (наборы) · «Unsere Bereiche» (категории) · «Kundenstimmen ab 4 ★»
   (отзывы) · «Aus dem Blog» (блог). Инсертер показывает только пресеты источников с
   ВКЛЮЧЁННЫМ модулем (правило STU-9), главный архетип — первым.
2. **Фильтр «Ziel» у акций** (товары / услуги / номера / наборы — цели волны PL): «Angebote
   für Zimmer» у отеля, «Angebote für Leistungen» у салона. Дешёвый `filter(<fk>__isnull=False)`.
3. **Пресеты листингов по архетипу** (как «Prospekt (Blöcke)» у `/aktionen/`): `/sortiment/` —
   «Neuheiten + Sale über dem Katalog», `/termin/` — «Video-Beratung oben», `/unterkunft/` —
   «Angebote für Zimmer», `/veranstaltung/` — «In den nächsten 14 Tagen», `/touren/` — по
   странам. Пресет одноразово кладёт блоки над/под «Hauptliste» (LB-2).
4. **Демо-киты (все 19)**: встроенные списки с осмысленными «ЧТО» + блоки/пресеты там, где
   они показывают силу архетипа; замок «каждый блок «Liste» кита что-то показывает».

Тип бизнеса → главное на главной (по `archetypes.PRIMARY_SECTION` и китам):

| Тип | Главный список | Доп. списки (блоки/пресеты) |
|---|---|---|
| bakery, butcher, grocery, cafe, restaurant, catering | products (прайс-лист у гастро), categories | Endet heute / Neu im Sortiment, Menü-Pakete (наборы), отзывы о товарах |
| clothing, retail, online_shop | products, categories | Neu, Sale, Empfehlungen, подборки (лукбук) |
| hotel | stay_rooms | Angebote für Zimmer, отзывы о номерах |
| friseur, werkstatt | services | Video-Beratung, Angebote für Leistungen, отзывы об услугах |
| handwerker | (jobs: заявка) + services | отзывы, блог/референсы |
| events | events | In den nächsten 14 Tagen, по темам |
| tour_operator | tours | по странам, ближайшие заезды |

## 9. Риски

* Скорость главной: движок вызывается по разу на встроенную строку — те же запросы, что
  раньше (у товаров + рейтинги bulk, у событий + места). Замок числа запросов.
* Черновик Студии: новые поля обязаны доезжать в превью (класс дефекта PT-6) — замок.
* Сборки и киты продолжают писать ключи — их смысл не меняется.
