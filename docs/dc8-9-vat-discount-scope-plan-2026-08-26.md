заказа). Продолжение волны DC — оба пункта закрывают остаток утверждённых
макетов `docs/design/deal-card-2026-08-25/`.

## 2. DC-8 «честный НДС у брони, записи и билета»

Немецкие ставки (DE): проживание 7 % (§12 Abs. 2 Nr. 11 UStG), завтрак и прочие
допы в отеле 19 % (Aufteilungsgebot), Kurtaxe вне НДС, услуги 19 %, билеты 19 %
(культурные бывают 7 % — поэтому ставка настраивается, а не зашита).

**Ставка живёт на продаваемой сущности + СНИМОК на сделке** (как `OrderItem`):
- `StayUnit.vat_rate` (дефолт 7.00), `Service.vat_rate` (19.00), `Event.vat_rate` (19.00);
- снимок при создании: `StayBooking.vat_rate`, `Booking.vat_rate`, `Ticket.vat_rate`;
- допы: `extras.snapshot` кладёт `vat_rate` каждой позиции (старые снимки без
  ключа → ставка сделки, fail-safe);
- Kurtaxe — строка со ставкой 0.

**Единый калькулятор** `apps/core/vat.py::deal_vat_rows(kind, obj, small_business)`
→ `{"rows": [{rate, gross, net, vat}], "gross", "net", "vat"}` по образцу
`order_totals` (скидка режет базу ПРОПОРЦИОНАЛЬНО долям ставок — иначе НДС
считается с суммы, которую клиент не платил). Заказ остаётся на своём хелпере
(его разбивка уже честная), калькулятор зовёт его, чтобы точка входа была одна.

Потребители: секция «Summen» карточек (строки «davon X % MwSt.»), счета DC-6
(вместо фиксированных 7/19 — снимки), позже отчёты.

## 3. DC-9 «область действия скидки»

Поле `discount_scope` на четырёх моделях: `deal` (вся сделка, текущее
поведение и дефолт) · `position` (основная позиция: проживание / услуга / тир /
выбранная позиция заказа) · `delivery` (только доставка — есть у заказа).

Область меняет НЕ сумму скидки, а её РАСПРЕДЕЛЕНИЕ по ставкам НДС (и показ):
при `position` вычитается из базы ставки основной позиции, при `delivery` — из
доставки, при `deal` — пропорционально. Итог сделки одинаков во всех случаях,
поэтому движки оплаты и письма не трогаем.

UI — чипы в общем партиале `core/_deal_discount.html` (чип «Versand» только там,
где доставка есть). Приёмник тот же `deal-discount-edit`.

## 4. Миграции (все аддитивные)

`stays/0034` (StayUnit.vat_rate + StayBooking.vat_rate + discount_scope),
`booking/0026` (Service.vat_rate + Booking.vat_rate + discount_scope),
`events/0029` (Event.vat_rate + Ticket.vat_rate + discount_scope),
`orders/0021` (Order.discount_scope).

## 5. Инварианты

- Ставка — СНИМОК: смена ставки в каталоге не меняет прошлые сделки (GoBD).
- Итог сделки не меняется ни от НДС-разбивки, ни от области скидки — только
  показ и распределение базы; замок сравнивает итог до/после.
- §19 Kleinunternehmer обнуляет все ставки (общий флаг `small_business`).
- Замки-характеризации ДО правок: суммы сделок и счетов не двигаются.
