# Фидбэк владельца по отелю: 14 пунктов (2026-07-31)

Запрос владельца одним куском. Ниже — разбор по пунктам с результатом разведки
(что уже есть в коде, чего нет) и очередь инкрементов. ID волны — **HF**.

## 0. Что разведка изменила в оценке
- **Новости УЖЕ есть**: модуль `blog` (`apps/events/models.BlogPost`, кабинет
  `/dashboard/blog/`, витрина `/blog/` + `/blog/<slug>/`, обложка-фото, `excerpt`
  краткое + `body` полное). Писать функционал не нужно — нужно **подключить**:
  секция на главной, пункт меню, включение в архетипы (в т.ч. отель).
- **Закрытие дней и расписание услуг УЖЕ есть**: `AvailabilityRule` (недельные
  правила) + `ClosedDate` (точечные выходные, `resource=None` = весь бизнес), UI
  на `/dashboard/booking/` → «Ressourcen». Не хватает **визуального календаря** и
  **входа со страницы услуги** — владелец их не нашёл (это и есть жалоба).
- **Разных цен на разные даты у услуг НЕТ** (у номеров есть `SeasonRate`).
  Это новая модель → миграция.
- Детальная страница услуги есть (`service_detail.html`), листинг услуг есть
  (`/termin/`) — у отеля они просто не включены/не в меню.

## 3. Правила исполнения
Как в проекте: каждый инкремент — локальные гейты (ruff + затронутые тесты +
`i18n_gap` + `npm run build:css` при новых классах) → коммит → CI → FF-merge.
Новые строки сразу во все 5 `.po` (гейт I18N-9 иначе красный). Пункты с
миграциями (HF-5) в конце — их деплоит владелец.
