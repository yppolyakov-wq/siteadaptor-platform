# Грабли проекта и как их не повторять

Собрано 2026-10-24 по запросу владельца из уроков в `build-log.md` и `CLAUDE.md` §3.
**Правило:** перед инкрементом — просмотреть раздел своей темы. Наступил на новую граблю —
дописать сюда строку в том же коммите. **Грабля повторилась — превратить её в замок**
(тест, скрипт, проверка CI), а не во вторую строку.

| Миграции, тяжёлые запросы | `database-migrations`, `postgres-patterns` | `database-reviewer` |

| Celery / beat | `django-celery` | — |

Скиллы грузить В НАЧАЛЕ инкремента, а не после ревью: чек-лист дешевле найденного дефекта.

## 1. Деньги и Stripe

- **«Stripe не ответил» ≠ «Stripe отказал».** Таймаут/обрыв — деньги могли уйти: захват НЕ
  откатывать, владельцу «проверьте в Stripe». Откат — только при явном отказе
  (`InvalidRequestError`, `CardError`, `PermissionError`, `AuthenticationError`). (B2-4a)
- **Ключ идемпотентности = суть операции.** Полный возврат — ключ на платёж; частичный —
  на НАКОПЛЕННУЮ сумму (иначе Stripe «повторит» прежний частичный ответ). (B2-4a)
- **Повтор вебхука — не новое событие.** Сначала проверить, есть ли уже строка по intent;
  иначе «до» считается после записи и рождает ложную «переплату». (B2-5)
- **Метаданные вебхука подделываемы чужим connected account** — сверять `event.account`
  с аккаунтом бизнеса; деньги — только при `payment_status == "paid"`. (B2-5; старые ветки —
  roadmap §Отложено)
- **Состояние «возвращено» ставить, только когда вернули ВСЁ** — включая доплату остатка
  отдельным платежом; иначе повтор отмены ответит «уже возвращено» и остаток не вернётся.
- **Проверки — под блокировкой, а применение после внешнего вызова — снова под
  блокировкой с повторной проверкой** (отмена/счёт могли случиться между). (B2-4b)
- **Идемпотентны только «писатели» ≠ идемпотентна операция.** Сторно и документ по ключу
  пишутся один раз, а `скидка += X` — при каждом повторе. Проверять «уже применено с этим
  ключом» под блокировкой ДО изменения состояния. (B2-7c)
- **Пересчёт цены по сегодняшним тарифам ≠ цена сделки.** Снижение — от сохранённого итога.
- **Сторно при отмене читает исходную запись** — всё, что уже сторнировано раньше
  (Minderung, удержание), вычитать.
- **`discount_cents` ≠ сумма сертификата.** После DC-5/Minderung там и скидка владельца, и
  уступка; сертификату возвращать только `voucher_paid_cents` (`voucher_return_cents`). (B2-7a)
- **Выручка с несколькими ставками** (проживание 7 % + питание 19 %) — сторно по записям,
  каждая своей ставкой.

- **Дедуп вебхука ставить так, чтобы упавшая обработка снимала ключ** — иначе повтор Stripe
  глотается, а оплата не попадает в книгу никогда. (silent-failure, 2026-10-24)
- **Деньги пришли, а записать некуда** (нет сделки/тенанта) — не `return False` молча:
  `logger.error` + письмо владельцу, если источник доверенный.
- **Разные исходы — разные результаты.** «Деньги вернулись, цену не снизили» ≠ «Stripe не
  ответил»: общий текст толкает владельца вернуть второй раз.
- **`except Exception: return None` в UI без `logger.exception`** — ломающаяся форма
  денег исчезает бесследно. Каждый широкий except логирует.
- **Письмо об ошибке с ключом дедупа на сделку** глотает второй сбой — ключ на причину+сумму.
- **Срез за период из «всё время − всё время»** (разница журнала и полученного) повторяется в
  КАЖДОМ периоде, где у сделки есть проводка — относить один раз (день последней проводки).
  Сверять с полученным БЕЗ вычета возвратов: возврат уже учтён в своём месяце. (B2-8a)
- **«Первая проводка» = исполнение** — только положительные записи: сторно с ранней датой
  иначе сдвигает момент налога. (B2-8a)
- **Два документа/два объекта на одних деньгах — один порядок замков.** Вебхук шёл
  «сделка → счёт», кнопка «счёт → сделка» → взаимная блокировка. Правило: сначала сделка,
  потом документ, на ВСЕХ путях (`advance.lock_deal`). Синк вторичного документа после
  оплаты — fail-soft с логом: он не должен откатить уже записанный платёж. (B2-8b)
- **OR на каждую сделку** (`Q(kind, id) | …`, `startswith` на каждую) — план на тысячи веток
  и seq scan; группировать по виду `deal_id__in`, префикс — `Left(...)__in`. (ревью БД B2-8a)
- **Строка «для дат» рядом с денежной книгой** (заявка в `DealPayment`, но не в `FOLIO_KINDS`):
  все читатели денег обязаны гейтиться списком видов, а ручные строки — не метиться `stripe`
  (возврат картой без intent пометил бы их возвращёнными). Замок «деньги вида не изменились». (B2-8d)
- **Письмо «не платите» по сторно** — только для НЕоплаченного документа (`t.src == "issued"`) и
  только на адрес, куда документ реально ушёл (не текущий адрес клиента), с тем же лимитом. (B2-8d)
- **fail-soft лог читает `obj.pk`** — заглушка без pk роняет саму ветку «не падать»; в логах
  `getattr(obj, "pk", None)`. (CI B2-8c)

- **Повтор «отмены» не должен решать деньги заново.** Решение «вернуть / удержать»
  фиксировать В МОМЕНТ отмены (снимок на записи), повтор — только по нему; отменённое
  владельцем (no_show, «ohne Erstattung») гость не переигрывает. Удержание → выручка
  только при «keep»; «возврат положен, но не сделан» (NONE) — сигнал владельцу, не тишина;
  денежный шаг после коммита — в try (гостю не 500). (B6, 4 ревью сошлись)

- **Счёт из брутто-сделки нельзя считать «от нетто в центах».** Часть брутто-цен недостижима
  (45,00 € @19 %: 37,82 → 45,01; 37,81 → 44,99) — счёт расходится со сделкой на цент. Сделки уже
  считают через `orders/totals.split_gross`; счёт — тем же путём (план Bruttomethode). Найдено
  золотым путём E11.1 — сквозной тест «сделка → выручка → счёт» ловит то, что модульные не видят.
  Исправлено (`finance/0018`): счёт из сделки — `price_basis="gross"` + `finance.totals.gross_line`;
  суммы по ставкам считать ТОЛЬКО `finance.totals.rate_groups` — своя копия пересчёта групп
  (их было четыре) снова разведёт счёт, PDF, журнал и вычет предоплаты.

## 2. База и модели

- **`source_ref` и подобные — varchar(64): два UUID не влезают.** Ключ — короткий хэш
  (`md5(...)[:12]`). Повторилась: MX-2e → B2-4b. → кандидат в замок.
- **`values().annotate()` поверх queryset с `order_by`** тащит сортировку в GROUP BY. (VS-2c)
- **`update_or_create` на неизменённых строках сдвигает `updated_at`** — ломает lastmod/фид.
- **Схема public vs схема бизнеса**: Membership/данные бизнеса читать в `schema_context`
  бизнеса. (T-8.30f)
- **Миграции локально** — после правок миграций `--create-db`, иначе ложные падения.
- **«Индексная граница» без индекса.** Условие `end__gt=…` планировщик не использует, если
  индекса по `(resource, end)` нет — проверять Meta.indexes, а не верить названию. Потолок,
  на котором держится граница (буфер ≤ 480), закреплять валидатором И CheckConstraint, а не
  только клампом формы. Массовый `update()` пересчёта занятости — под блокировкой тех же
  строк, что берёт `book`, и с чтением свежего значения внутри блокировки. (KA-12 E4.4a)
- **Неявный дефолт выбора меняет цену у всех входов без параметра.** «Не выбрано → первый
  вариант» тихо меняет длину/цену для ссылок Finder/MCP/писем/акций, которые о вариантах не
  знают. Дефолт = базовая сущность, вариант — только явным выбором. (KA-12 E4.4b)
- **UUID-pk есть и у НЕсохранённой модели** (default в `__init__`): «сохранена ли» — только
  `obj._state.adding`, а не `obj.pk`. Хелперы, которые читают связи, должны молча отдавать
  пусто для несохранённых и для `SimpleNamespace`-заглушек (секции главной). Повтор урока
  CI 1145: контракт `sellable` гейтить ВКЛЮЧАЯ `apps/tenants`. (E4.4b)
- **После `obj.delete()` у объекта `pk is None`** — в тестах на «удалённую ссылку» сохранять
  `str(obj.pk)` ДО удаления. (E4.4b)
- **Снимок для учёта — база, не перевод.** `variant_label`/снимки пишем из базового поля
  (`name`), а не `name_localized()`: язык гостя не должен попадать в счёт/кабинет. (E4.4b)
- **pk моделей проекта — UUID, не int.** Парсер pk из формы через `int()`/`isdigit()` молча отверг бы
  ВСЕ настоящие значения (стойка перестала принимать тариф). Строго через `uuid.UUID` (`rate_plans.parse_uuid`);
  `get_object_or_404(pk=<мусор>)` на UUID-поле даёт 500, а не 404 — сначала парсить. (Z-4)
- **«Пустой набор M2M = для всех» — ловушка.** Каскад удаления последней категории молча расширяет
  тариф на все (пакетное удаление `pre_delete` не ловит). Явный флаг `applies_to_all`. (Z-4)

## 3. Вьюхи, формы, безопасность

- **`str.isdigit()` пропускает «²», а `int("²")` падает** — 500 на ручном POST. Числа из ввода — строгим
  regex `[0-9]{1,3}` (`night_rates.small_int`). (Z-3)
- **`audit_event` внутри `transaction.atomic` без своего savepoint**: он глотает исключение, но сбой INSERT
  помечает внешнюю транзакцию `needs_rollback` — бизнес-запись молча откатится при «успешном» ответе.
  Звать в `with transaction.atomic():`. (Z-3)
- **Писатели одной строки лочат в одном порядке** (`select_for_update().order_by("id")`) — иначе дедлок
  массовой правки с переносом брони. (Z-3)

- **Хелпер, вставленный между `@login_required` и вьюхой, «съедает» декоратор** — вьюха
  становится публичной. Замок `test_orphan_decorators`. (повторялась ≥3 раз)
- **`next=`**: проверять `url_has_allowed_host_and_scheme` с хостом запроса И отбивать `\`
  (`/\evil.com`).
- **Новый owner-only префикс** → записать в `EXPECTED_OWNER_ONLY_UNLISTED` замка
  `test_staff_walk`, если это приёмник, а не пункт меню.
- **Скрытие только CSS, все поля в DOM** (W0): невидимое поле, которого нет в DOM, стирается
  на Save.
- **Обязательное поле в скрытой вкладке** — Chrome молча отменяет отправку формы.
- **GET без побочных эффектов**: публичные GET, создающие сессию Stripe/запись — под
  лимит частоты.
- **Устаревшая ссылка ≠ подделка.** Выключенный/удалённый вариант своей сущности → возврат на
  выбор с сообщением; чужой/мусор → 404. После ошибки POST редирект несёт выбор гостя
  (вариант/мастер/длительность) — иначе повторная попытка молча бронирует другое. (E4.4b)
- **Депозит не больше цены.** Фиксированный депозит + скидочный вариант → гость платил бы
  больше брони: `min(deposit, price)`. (E4.4b)
- **Ролевой гейт — по всем писателям, а не по новым.** Закрыв тарифы для staff, оставили открытыми цену
  номера в `unit_settings`, Kurtaxe, авто-скидки, занятость, Lücken-Deal — обход одним POST (security-ревью
  Z-4). Гейт = константа действий + AST-замок «каждый писатель цен в константе»; смешанные формы гейтить по полям.
- **Подмена `roles.is_owner` в тестах перестаёт работать, когда место переводят на `has_perm`.** Тест
  молча проверяет «нет Membership → False» вместо «staff» (ревью E6.7a). Права в тестах — реальная
  Membership или `monkeypatch.setattr("apps.core.permissions.effective", …)`; функцию, импортированную
  по имени (`from … import has_perm`), подменить через модуль нельзя.
- **Декоратор права на вьюхе ломает тесты, которые зовут вьюху напрямую пользователем БЕЗ
  Membership** (CI #3266, E6.7c-4): раньше эти вьюхи закрывал только middleware по префиксу,
  тесты его обходили. Ставя `@perm_required` на вьюху — `grep -rn "views.<имя>(" apps/*/tests`
  и дать там реальное членство; локально гонять ВСЕ файлы с этими вызовами, а не только свой модуль.
- **Форма прав: «запертое» отмеченное право держит свои requires** (ревью E6.7d). Снять R, от
  которого зависит X вне области актора, — замыкание уронит X, и сервер ответит «scope» на
  чекбокс, который форма предлагала. Такие R тоже запирать (`needed`); замок — адверсариальный
  тест «каждый активный чекбокс снимается/ставится без отказа».
- **Меню прячет — не значит закрыто** (ревью E6.7e). Главная `/dashboard/` открыта всем (OPEN),
  но рисует петлю продаж и виджеты денег — без права раздела данные утекали мимо скрытого меню.
  Скрывая раздел, проверить каждую поверхность, где показаны ЕГО данные (главная, вкладки-query,
  поиск), и закрыть на сервере; замок «каждая видимая ссылка открывается» — по HTML страниц.
- **`str.isdigit()` пускает не-ASCII цифры** (Z-5, час заезда). `"٣".isdigit()` и `"²".isdigit()` —
  True, `int("٣") == 3`, а `int("²")` падает 500. Числа из формы — только `re.fullmatch(r"[0-9]{1,2}")`.
- **Мусор в pk → 500, а не 404** (Z-5). `get_object_or_404(Model, pk="1 OR 1")` при UUID-pk бросает
  ValidationError. pk из POST — через `rate_plans.parse_uuid` (None → 404/«не найдено»).
- **Новый модуль — проверить, что имя свободно** (E6.7g). `cat > apps/core/contacts.py` через
  shell затёр существующий модуль (лимиты по телефону E6.6) — тесты упали ImportError далеко от
  правки. Перед созданием файла: `ls`/`git ls-files <путь>`; файлы создавать инструментом Write
  (он требует прочитать существующий).
- **`next=` с «\\» и управляющими символами** (Z-5). Браузер читает `/\host` и `/<TAB>/host` как
  `//host`. Одна проверка на проект — `owner_login.safe_next`/`local_next`, своих не писать.

- **Контекст-процессор не должен падать на «ненастоящем» пользователе** (E6.7g, CI #3290).
  Новая проверка права в `modules_nav` упала на тестовом `SimpleNamespace(pk=1)` в рендере
  страницы middleware — `Membership.filter(user=stub)`. Проверки хрома в контекст-процессоре —
  в try/except с fail-closed значением. Смена дефолта права (staff теперь видит контакты) —
  `grep -rn 'PRESETS\["staff"\]' apps/*/tests` и переписать замки, кодировавшие старый дефолт.

- **Частичный возврат на отменённой сделке — цель от книги, не сумма** (T-4a, ревью). Если
  повторный вызов возвращает «ещё N», двойной POST/ретрай отдаёт удержанное. Считать
  «должно быть возвращено всего» от фолио и возвращать разницу; плюс блокировка сделки до
  перехода FSM (`TicketSM.apply` сам строку не блокирует, повторный `cancelled` не падает).

- **Перенос сделки на другую сущность — проверить ВСЁ, что привязано к старой** (T-4b, ревью).
  У билета к событию привязаны рассрочка (даты долей), Haftungserklärung, ответы анкеты, тариф,
  Extras, проживание. Перед переносом — список «что берётся у события» и решение по каждому:
  перенести / отказать / предупредить. Цель перепроверять ПОД блокировкой, а не по выборке.

- **`HttpResponse(charset="utf-8-sig")` + `csv.writer` = BOM в каждой строке** (T-5). Каждая запись
  кодируется отдельно. Правильно: `charset=utf-8` и один `response.write("\ufeff")` в начале.
- **Ссылка на анкету с данными о здоровье** (T-5, ревью): показывать данные только пока их можно
  править; потолок `max_age` у подписи; проверку «можно править» — под блокировкой; правка — только
  полей, пришедших в форме (иначе пустая форма гостя стирает введённое владельцем).

- **Серверный фолбэк «если поле пустое» при форме, которая это поле всегда шлёт, — мёртвый код.**
  Строка сметы рендерит `value="1"`, поэтому «пустое кол-во → гости» никогда не срабатывало, а тест,
  постящий пустое поле, проверял путь, которого нет в UI. Прежде чем писать фолбэк, посмотреть, что
  реально отправляет шаблон. (A-3)
- **Пресет «только если ключа нет» плюс presence-minimal «пусто = ключа нет» = пресет воскресает.**
  Владелец снял все поля, ключ удалён, и повтор шага мастера возвращал дефолт. Пресет — только при
  создании и СМЕНЕ типа. (A-3)

## 4. Переводы (i18n)

- **`i18n_quickcheck` не видит `.txt`-шаблоны писем и untracked-файлы** — `git add` до
  проверки; шаблоны писем сверять отдельно.
- **Своя сверка шаблонов: вывод `templatize` пишет `gettext(u'…')`** — регулярка обязана
  принимать `u`-префикс, иначе «0 пропусков» ложь. (B2-4a, 2026-10-24)
- **`gettext` внутри f-строки не извлекается**; псевдонимы `_t`/`_l` — тоже; `_(ПЕРЕМЕННАЯ)`/`_(name)` в цикле — тоже (дни недели брать из `django.utils.dates.WEEKDAYS_ABBR`). (Z-3)
- **Демо-словари `demo_i18n_<loc>.json` НЕ сортировать.** Их порядок — не `sorted()` Python:
  перезапись с сортировкой даёт дифф на тысячи строк. Новые ключи — `dict.update` + тот же
  `json.dumps(..., ensure_ascii=False, indent=1)`, проверка «перезапись без правок = файл байт-в-байт». (E4.4b)
- **Два pytest на одной `--reuse-db`** (в т.ч. свой забытый фоновый прогон) → ложные
  `relation ... already exists`. Перед локальным гейтом — `ps aux | grep pytest`. (E4.4b, повтор)
- **Дубли msgid в многострочной форме** — перед пушем .po-батча дуп-чек polib.
- **Локально нет gettext** — `.mo` собирать через polib, иначе тесты «немецкие».
- **`polib.save()` переписывает ВЕСЬ .po** (перенос строк, порядок — +8k/−23k строк диффа). Читать polib можно, ПИСАТЬ — только текстовым дописыванием в конец (`s += f'\n\nmsgid …'`), плюрал — `msgid_plural` + `msgstr[i]` по nplurals файла (B6).

## 5. Шаблоны, CSS, стенды

- **Многострочный `{# #}` утекает текстом** — гнать `test_template_comments`.
- **Новый Tailwind-класс** → `npm run build:css` и закоммитить `static/css/app.css`.
- **Django кэширует шаблоны и в DEBUG** — стенд врёт без рестарта runserver.
- **Скрипт внутри свапаемой зоны умирает после fetch** — обработчики делегировать на `document`.
- **Переменная контекст-процессора в аргументе фильтра** бросает VariableDoesNotExist.

## 6. Процесс и CI

- **`ruff format --check .` ЦЕЛИКОМ** перед пушем; по явному пути не форматировать миграции.
- **Два pytest на одной `--reuse-db` роняют друг друга** — гонять серийно.
- **`git stash` во время фонового pytest** подменяет файлы под идущим прогоном — его
  результат недостоверен. Пушить коммит без stash (`git push origin <sha>:<ветка>`). (B2-7b)
- **`pkill -f "<строка>"` убивает СВОЮ оболочку** (строка в её командной строке, exit 144) — останавливать сервер стенда по PID.
- **`while pgrep -f "<строка>"` находит СВОЮ же оболочку** (строка есть в её командной
  строке) — ожидание вечное, а нужная команда так и не запускается. Ждать по PID или
  `pgrep -f "[p]ytest …"`. (B2-7b)
- **Пуш отменяет идущий CI ветки** — пушить стопкой, проверять CI верхушки.
- **«Вчера» в тестах = `now() − 24 ч` ломается в ночь перевода часов** (сутки 25 ч: поздно
  вечером 25.10 это ещё СЕГОДНЯ по Берлину). Даты относительно локального дня строить от
  `timezone.localdate()` (полдень дня), а не вычитанием часов. Дважды: B6 `test_city_freshness`,
  T-6a `test_digest_promotions`.
- **`ruff format --check . | tail -1 && git commit` — гейт мёртвый**: код выхода берётся у `tail`, коммит
  проходит с неотформатированным файлом. Проверку не пропускать через пайп (или `set -o pipefail`). (A-2)
- **Лог CI сохранять в новый файл** — старый одноимённый из прошлой сессии выдаёт чужие падения.
- **Демо-сидер**: правка кода сидера → поднять `SEEDER_VERSION`.
- **Тест-строки уникальными** — негативный ассерт на голое слово ловит хром страницы.

- **Атрибут `hidden` не прячет элемент с классом `flex`/`grid`/`block`** — правило Tailwind
  preflight `[hidden]` слабее класса отображения. Прятать такие элементы классом `hidden`
  (переключать `hidden`↔`flex`), а не атрибутом. (KA-12 E2.1, стенд Playwright)
- **Тесты дат на стыке суток/перевода часов.** «`localdate() + N дней`» ≠
  «`localdate(now + N суток)`» в ночь перевода часов (25.10: сутки = 23 ч) и после
  22:00 UTC. Ожидание считать тем же путём, что код. (`test_city_freshness`, CI 3220)

- **(2026-10-25, E6.4c) `Tenant.objects.select_for_update().get()` + `save()` пытается создать схему.**
  Свежий экземпляр из БД несёт `auto_create_schema=True`, а django-tenants на `save()` проверяет/создаёт
  схему → в тестах (схемы нет) 135 с на клонирование, в проде — лишний запрос. На заблокированной копии
  ставить `tenant.auto_create_schema = False` (схема уже есть — по ней пришёл запрос).
- **(2026-10-25, E6.4c) Лимит частоты ТОЛЬКО по идентификатору жертвы = целевой DoS.** Лимит «N попыток
  на e-mail» позволяет любому, кто знает адрес, заблокировать человеку запись. Ключ — ящик + IP + схема;
  перебор адресов держит общий IP-лимит. И не голый 429 (в iframe — белый экран): сообщение + redirect.
- **(2026-10-25, E6.4c) Побочные эффекты сделки до возможного отката.** Аналитика «сделка» и DOI-письмо
  вызывались ДО ветки, которая может отменить бронь (сбой Stripe) — откат оставлял «сделку» и письмо.
  Внешние/учётные действия — после того, как исход сделки окончательный.
- **(2026-10-25, E6.7c-2) Журнал отказа внутри откатываемой транзакции исчезает.** `PermsDenied`,
  брошенный внутри `atomic()`, откатывает и запись `team.perms_denied` — отказ журналируется
  обёрткой ПОСЛЕ выхода из транзакции. И вставка новой функции ПОД декоратором `@_audited`
  повесила его на чужую функцию (повтор граблей «хелпер съел декоратор») — правку «заменить
  строку def» делать вместе с её декоратором.
- **(2026-10-25, E6.7c-2) Замыкание по `requires` маскирует тест и пропускает обход области.**
  Снять `kunden.view`, оставив `kunden.edit`, — ничего не снимет (`edit` тянет `view` обратно);
  а снятие базового ключа роняет зависимый ключ ВНЕ области актора → проверять `(old - new) -
  revoke_scope` после замыкания, не только запрошенное.
- **(2026-10-25, E6.7c-2) Случайное значение в `@pytest.mark.parametrize` роняет CI.** `str(uuid4())`
  в параметре даёт разный id теста у каждого воркера xdist → «Different tests were collected»,
  падает ВСЯ группа. Параметры — только константы (фиксированный UUID).
- **(2026-10-25, E6.7c-3) Ссылка-приглашение не должна входить в СУЩЕСТВУЮЩИЙ аккаунт.** Старый
  `team_join` логинил держателя ссылки в найденный по e-mail аккаунт и задавал пароль аккаунту без
  пароля — держатель (в т.ч. сам приглашающий, ему ссылка показывается) входил в чужой аккаунт.
  Правило: существующий аккаунт присоединяется только будучи залогиненным собой.
- **(2026-10-25, E6.7c-3) Инвайт = ВЫДАЧА, а не правка.** Семантика «ключи вне области сохраняются»
  годится для правки существующего участника; у нового участника прав нет, поэтому всё, что он
  получит, — только из области выдачи приглашающего (иначе пресет протаскивает чужие ключи).
- **(2026-10-25, E6.7g) Ключ в пресете меняет смысл тестов отзыва через `requires`.** Добавили
  `kunden.kontakte` в пресет staff — тест «снять kunden.view» перестал что-либо снимать: kontakte
  тянет view обратно. При расширении пресета искать тесты с `for_role(...) - {…}`.
- **(2026-10-25, E6.7g) Замороженные эталоны не дополнять.** `legacy_role_gates.py` — снимок до
  перехода на права; новый экран регистрируется только в `view_perms` (замок staff_walk краснеет).
- **(2026-10-25, Tickets T-2) pk из формы — не обязательно число.** `Lieferant.pk` — UUID; разбор
  через `_int_or_zero` молча превращал любой выбор поставщика в «без поставщика». Любой id из
  POST — через `parse_uuid`/модельный тип pk, и замок «выбранное значение сохраняется».
- **(2026-10-25, Tickets T-2) «мусорные поля без 500» — проверять и числа.** `Decimal("Infinity")`
  → OverflowError в `int()`, `1e30` → DataError в PositiveIntegerField, >32767 — в SmallInteger.
  Клампить к границе поля, `is_finite()` до `int()`.
- **(2026-10-25, Tickets T-3) pre-commit-хук проверяет только i18n.** `ruff check .` он не гоняет —
  неотсортированный импорт ушёл в коммит и в CI. Перед `git commit` — `ruff check .` и
  `ruff format --check .` целиком.
- **(2026-10-25, Tickets T-3) скрипт `.po` с `\n` в msgid.** Самописный дописыватель экранирует
  только кавычки — многострочный плейсхолдер сломал бы каталог. Такие записи — через `polib.POEntry`.
