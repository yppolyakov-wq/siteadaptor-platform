# ERP-гэп: что ещё нужно для «нормального ERP» (вопрос владельца 2026-08-21)

**Статус:** оценка на обсуждение (кода нет). Контекст: SME DACH, 39 €/мес,
анти-Битрикс простота. Цель — НЕ «настоящий ERP» (двойная запись, зарплаты,
Anlagen), а замкнутый цикл товара и денег с мостом к Steuerberater.

## §0. Что уже есть (после программ UD/Склад-2/SH/MX)

Склад: леджер, партии FEFO/MHD, мультисклад v1, инвентаризация, матрица осей,
себестоимость/маржа товара (T5), Meldebestand → Bestellvorschlag → закупка →
частичная приёмка (пишет расход), материалы заявок, опции с трекерами
(пул/склад/закупка/рецепт/FEFO). Деньги: журнал выручки (7 источников),
расходы + Ergebnis, НДС по товару со снимком в позиции, счета GoBD + PDF,
DATEV-экспорт выручки, маржа заезда, рассрочка/депозиты/способы оплаты.
Продажи: единая доска 6 kind, правка заказа, Zusatzverkäufe, DealLink.
CRM, аудит-лог, DSGVO-purge.

## §1. Разрывы (проверено по коду), по убыванию боли

### T1 — цикл денег не замкнут
1. **Offene Posten + сверка банка.** Оплата ставится руками или Stripe-вебхуком;
   Vorkasse сверяется глазами. Нет: списка «кто мне должен» по всем kind,
   импорта банковской выписки (CSV/camt), полуавтоматического сопоставления
   платёж↔сделка/счёт. Для DACH SME это разрыв №1.
2. **Входящие счета (Eingangsrechnung).** `ExpenseEntry` — журнальная строка,
   не документ: нет файла/фото чека, поставщика-FK у ручной записи, Zahlungsziel,
   статуса «оплачен/просрочен», Skonto. Кредиторки нет вообще.
3. **Vorsteuer / UStVA-срез.** `vat_rate` у расходов существует и всегда 0;
   Ergebnis = брутто − брутто. Нужен срез «USt по выручке − Vorsteuer по
   расходам = к уплате» за период (без Elster-передачи — цифры бухгалтеру).
4. **DATEV-экспорт расходов.** Экспортируется только выручка (Kasse an
   Erlöskonto); расходная сторона бухгалтеру не отдаётся.
5. **COGS-снимок в позиции заказа.** Маржа считается по ТЕКУЩЕМУ cost_price —
   history дрейфует после смены закупочной цены. Нужен снимок себестоимости
   в OrderItem на момент продажи (как уже снимаются цена/НДС/артикул).

### T2 — операционные дыры
6. **Mahnwesen.** Напоминания о неоплате есть (B2), но нет ступеней
   (Zahlungserinnerung → Mahnung 1/2), фристов и статуса по счёту.
7. **Возврат поставщику / рекламация** (Rücksendung): приёмка есть, обратного
   пути нет (сейчас — ручная корректировка без документа).
8. **Себестоимость Работы.** Часы в смете — свободные строки; учёта времени
   нет → маржа Werkstatt/Handwerker не считается. Минимум: плановые часы ×
   ставка на строке сметы.
9. **Рецепт/BOM производства.** Опция-рецепт v2 = одна Вещь. Пекарня
   «мука→хлеб» (Produktionsauftrag со списанием сырья и приходом готового) —
   нет. v1 = простой акт производства.
10. **Права по направлениям.** Роли admin/staff идентичны (решение «пока так»);
    ось готова (вкладка = направление) — гейт по ролям, когда понадобится.

### T3 — осознанно НЕ делать
Двойная запись/SKR03 (мост = DATEV), зарплаты (лоно бухгалтера), Anlagen/
амортизация, полноценный MRP. Банковские API (FinTS/GoCardless) — external;
сначала CSV-импорт.

## §2. Предлагаемая очередь (ERP-волна, если владелец скажет «делай»)

| ID | Шаг | Миграции |
|---|---|---|
| ERP-1 | COGS-снимок в OrderItem + честная маржа по заказу/направлению в Ergebnis | аддитивная |
| ERP-2 | Offene Posten: список должников по всем kind + CSV-импорт выписки + сопоставление (по Verwendungszweck/сумме, подтверждение кликом) | без/аддитивная |
| ERP-3 | Eingangsrechnung: документ поверх ExpenseEntry (файл, поставщик, Zahlungsziel, статус, Skonto) + Mahn-статусы своих счетов | аддитивная |
| ERP-4 | UStVA/EÜR-срез в Ergebnis + DATEV-экспорт расходов | без |
| ERP-5 | Возврат поставщику (документ + движение) | аддитивная |
| ERP-6 | Часы/ставка в строке сметы → маржа Работы | аддитивная |
| ERP-7 | Производственный акт v1 (BOM: сырьё − / готовое +, одной операцией) | аддитивная |

Порядок: ERP-1 (дёшево, чинит дрейф маржи) → ERP-2 (боль №1) → ERP-3 → ERP-4;
5–7 по спросу архетипов.
