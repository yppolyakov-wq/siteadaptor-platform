# STU-14 — «на каждом типе страниц всё редактируемо» (закрытие дыр реестра)

**Дата:** 2026-09-09 · **Ветка:** `claude/aktionsmarkt-analysis-45t2vu`
**Повод:** третий пункт фидбэка владельца — «проверь, чтоб на каждом типе страниц каждый
тип был редактируемый и имел свои типы оформления». Проверка сделана в STU-13 (§4 того
плана); здесь — закрытие найденных дыр.

## 1. Что закрываем в этой волне (БЕЗ миграций)

| # | Дыра | Правка |
|---|---|---|
| 14a-1 | `tours` — панель ПУСТА (0 настроек, 0 блоков) | хост `tours` + `{% page_blocks %}` в `tour_index.html` + `text_width` |
| 14a-2 | `checkout` — панель ПУСТА, при этом «Kasse» есть в меню «Seite ▾» | хост `checkout` + вызов в шаблоне корзины-чекаута |
| 14a-3 | `promos` (обзор акций) — единственный листинг без C-блоков | хост `promos` + вызов в `promotions_list.html` |
| 14a-4 | `legal` — правовые страницы нельзя дополнить блоком | хост `legal` + вызов в правовом каркасе |
| 14a-5 | `text` — ОДИН хост `info` на 4 страницы, рендерится только на `/ueber-uns/` | свои хосты `team` / `gallery` / `reviews` + вызовы в их шаблонах |
| 14a-6 | `blog` — блоки только на индексе | хост `blog_post` + вызов в `blog_detail.html` |
| 14b | Четыре архетип-лендинга (`/treue/`, `/gutschein/`, `/anfrage/`, `/nachricht/`) попадают в «Seite ▾», но типа не имеют → пустая панель | свои типы страниц + хосты блоков |
| 14c | `/merkzettel/`, `/kombi/`, `/finder/`, `/lookbook/` вне реестра | типы страниц (ширина текста + блоки там, где шаблон это выводит) |

## 2. Что НЕ в этой волне (нужны поля на сущностях → миграции)

* шаблон страницы у детали акции (`Promotion.page_style`) и у деталей услуги/номера/события;
* сортировка/фильтры у листингов услуг/номеров/событий (нужны фасет-провайдеры на витрине).

Эти пункты — отдельным решением владельца: они меняют схему и требуют деплоя.

## 3. Инварианты
* Добавление хоста в `PAGE_BLOCK_HOSTS` не материализует ключей в конфиге —
  golden-эталоны `normalize` обязаны остаться байт-в-байт (замок).
* Новый тип страницы обязан РЕАЛЬНО узнаваться резолвером по своему url_name
  (замок STU-6 «каждый тип узнаётся по адресу, собранному реверсом»).
* Пустых обещаний не даём: настройку объявляем типу только если шаблон её ЧИТАЕТ
  (правило STU-9 — иначе панель предлагает неработающее).
