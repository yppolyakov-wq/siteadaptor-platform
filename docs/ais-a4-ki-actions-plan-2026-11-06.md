# AIS A-4 — «KI-Aktionen: объект × действие» (план, 2026-11-06)

План — агент ECC `planner` (сверен с кодом), принят ведущим. Источник правды —
`docs/ai-strategy-2026-11-06.md` §2–§4, §7 (В-1…В-5) и `ais-a3-assistant-panel-plan-2026-11-06.md`.
Решения владельца: первый набор — категории, товары, услуги + шаблон/сетка/карточка страницы;
затем цена/скрыть/переместить; предпросмотр с правкой → «Alles übernehmen»; «Rückgängig» 10 мин,
пока не менялось; без права — предложение без кнопки; массовые ≤ 50 с предпросмотром; названия
магазина в промпт можно, клиенты/заказы — никогда; запретный список.

## 0. Суть
Уровень 2 стратегии: фраза → пакет «объект · действие · поля» → правка в предпросмотре →
«Alles übernehmen» → запись ТЕМИ ЖЕ писателями, что экраны кабинета → «Rückgängig» 10 минут.
Новое: реестр действий `apps/core/assistant_actions.py` и модель `core.AssistantChange` (журнал
применённого пакета — для отката и журнала A-6).

## 1. Развилки (принято)
1. Предложение до клика — в кэше задачи (TTL 30 мин); в базе до клика ничего; истёк → «Vorschlag
   abgelaufen, bitte neu fragen».
2. `AssistantChange` (TENANT): user · job unique (идемпотентность) · items JSON (action, kind, pk,
   before, after, created) · applied_at · undone_at · undo_until; срок 90 дней тем же beat.
3. «Rückgängig» по снимку полей, а НЕ по `updated_at` (его двигают продажи/склад): пункт
   откатывается, если текущее значение каждого поля == `after` (под `select_for_update`), иначе
   «inzwischen geändert — nicht zurückgesetzt». Созданное: товар/категория — мягкое удаление,
   услуга — без броней; только если без ссылок (заказы, склад, брони). Откат своего создания в окне —
   не «удаление данных» из запретного списка.
4. Идемпотентность: `AssistantChange.create(job=…)` первым в atomic + claim в кэше.
5. Всё или ничего: одна транзакция, `select_for_update`, оптимистичная проверка `before`.
6. **Право цены — `preise.edit`** (как массовая правка цен), строже формы товара (`sortiment.edit`).
   ⚠️ развилка владельцу: рекомендация — `preise.edit`.

## 3. Разбор фраз
Детектор без ИИ (создание ИЛИ «имя существующего объекта + глагол изменения» на 5 языках) →
`put_actions` (обобщение `put_plan`: те же лимиты, замок). Правила — запасной путь. ИИ — новая
задача `assistant_actions` (fast, свой тумблер, абзац Datenschutz), схема с enum действий;
контекст — только названия (категории ≤ 60, товары ≤ 150, услуги ≤ 60, ≤ 3500 символов), рамка
DATA; примеры на 5 языках. ≤ 10 пунктов, массовые разворачиваются сервером до ≤ 50.

## 4. UX
`outcome="actions"` → партиал предпросмотра: карточка на пункт (fieldset/legend, «vorher →
nachher», правимые поля, галочка «übernehmen», «Im Formular öffnen»), без права — причина без
контролов. POST меняет только значения полей и галочки по индексу; action/kind/pk — из кэша.
Успех → «Erledigt: N angelegt, M geändert» + ссылки + «Rückgängig (bis HH:MM)». Без JS —
полная страница. Аудит `assistant.apply|assistant.undo` без текста фраз. ⚠️ Снижение цены
попадает в PriceLog (§ 11 PAngV, «низшая цена 30 дней») — предупреждение в превью; скрытие
категории не скрывает товары — честная подпись, без авто-каскада.

## 8. Правки архитектора (агент `architect`, 2026-11-06) — обязательны до кода

1. **История до клика.** `_put` готовой записи пишет её в `AssistantTurn` (A-3d) — пакет попал бы в
   базу до клика. В историю — только сводка без items; `AssistantTurn.KINDS` += "actions".
   Apply читает пакет ТОЛЬКО из job-кэша (не из истории, не из POST); карточка из истории — без
   кнопки. Свой TTL у `put_actions` (30 мин), сейчас `RESULT_TTL` = 10 мин.
2. **`AssistantChange`:** unique `job` в схеме; откат — только автор + перепроверка права в момент
   отката; в JSON канонические значения (Decimal строкой, FK — pk).
3. **Откат:**
   - цена товара: `PriceLog` пишет post_save и он append-only — откат снижения НЕ убирает его из
     минимума 30 дней (§ 11 PAngV) → предупреждение в превью И в тексте отката;
   - у услуг PriceLog нет; товар/услуга с вариантами или сезонными ценами — `price` отказом
     «Im Formular öffnen»;
   - удаление созданного товара: исключить собственные строки (стартовое движение склада
     `source="catalog"`, первая запись PriceLog), иначе откат невозможен всегда; мягкое удаление;
   - категория — только без живых товаров/детей; пункты пакета откатывать в ОБРАТНОМ порядке;
   - услуга (жёсткое удаление, `Booking.service` SET_NULL): ссылки проверять самим (брони,
     `Promotion.service`, generic `Extra`/`Review`/`DealLink`, M2M collections) — есть ссылки →
     `is_active=False` с честным сообщением;
   - откат создания — право `sortiment.edit` (отмена своего действия, не удаление чужих данных).
4. **Идемпотентность:** истина — unique-индекс; `IntegrityError` ловить снаружи atomic, перечитать и
   отдать прежний отчёт (паттерн `offer_batch.confirm`); claim в кэше — только UX.
5. **Блокировки (главный риск):** checkout/правка заказа/jobs блокируют Product/Variant по одной
   строке в порядке корзины, склад — Tenant→Product. Поэтому: (а) первым `Tenant
   select_for_update` (сериализует applies тенанта), затем все целевые строки ОДНИМ запросом
   `filter(pk__in=…).order_by("pk").select_for_update()`; (б) `SET LOCAL lock_timeout '3s'` →
   «gerade in Benutzung, bitte erneut» (владелец не ждёт за покупателем и наоборот); (в) в
   транзакции ничего внешнего — gate и проверка фактов ДО atomic, `page_settings.write` получает
   `gate=` заранее; после отката транзакции — `tenant.refresh_from_db(fields=["site_config"])`.
   CAS через `update()` нельзя: обходит post_save (PriceLog, листинг города).
6. **Право цены `preise.edit`** — эшелон для ИИ и массовых правок, не реальная граница: форма
   товара/услуги (`sortiment.edit`) цену тоже меняет — закрыть это или нет, решает владелец
   отдельно. Цена при `*.create` — `sortiment.edit`, как экран создания.
7. **Писатели «создать» — обёртка над Form-классами экранов** (`create_product(tenant, data,
   actor)` = `ProductForm` → `is_valid` → `save` → `log_catalog_change`; вьюха зовёт ту же
   функцию — паритет по построению). `_service_from_post` → dict данных, единственный путь
   `service_new`. Свести на них же `offer_batch._create` (сейчас третий путь мимо форм со своей
   логикой НДС). Для правок (price/visibility/move) формы НЕ использовать (ModelForm с частичными
   данными обнулит поля — класс W0): узкие `save(update_fields)` на заблокированной строке;
   `set_category_active` — новый; `toggle_visibility` — версия на заблокированном экземпляре с
   доменной ошибкой вместо `Http404`.
8. **Замки (+ к §5):** «lock_timeout/deadlock с параллельным checkout»; «откат товара со стартовым
   остатком»; «откат в обратном порядке»; «пакет из истории не применяется».

- Форма товара/услуги (`sortiment.edit` меняет цену) — оставляем как есть.

## 10. Исполнение A-4a (2026-11-06)
- Шаг 1 (писатели) и шаг 2 (пакет, предпросмотр, применение, откат, журнал) — в ветке, §1–§2/§8 соблюдены.
- Отступления от плана, принятые по ревью: гейт пункта = гейт экрана создания (`setup_assistant.reachable`:

  (решение архитектора §8.3 — отмена своего действия, не удаление чужих данных).

## 11. A-4b — цена · скрыть/показать · переместить (план исполнения, 2026-11-06)
**Без миграций кроме choices** (`AssistantTurn.KINDS += "actions"` — `core/0017`, choices-only).
- **Детектор без ИИ** `apps/core/assistant_changes.py`: глагол изменения на 5 языках (цена: Preis/kostet/
  price/цена/стоит/ціна/fiyat; скрыть: ausblenden/verstecken/hide/скрой/спрячь/выключи/сховай/gizle; показать:
  einblenden/anzeigen/show/покажи/включи/покажи/göster; переместить: verschieb/move/перенеси/перемести/taşı)
  + имя СУЩЕСТВУЮЩЕГО объекта (самое длинное совпадение имени товара/услуги/категории как целых слов,
  casefold; капы 500/200/200 строк). Глагол создания (neu/anlegen/добавь/создай/new/add/ekle) — не наше,
  уходит в A-4a. Неоднозначно (два объекта с одним именем) — пункт без кнопки «Mehrere Einträge heißen so».
- **Факты сервером:** цена — `setup_assistant._price_in` (только число с €/евро из текста); переместить —
  категория-цель по имени после «nach/in/в/у/до/to/into» (только существующая, одна).
- **Реестр** += `product.price`, `service.price` (`preise.edit`), `product/service/category.visibility`,
  `product.move` (`sortiment.edit`); гейт — экран правки объекта (`reachable`). Цена товара с вариантами
  и услуги с вариантами/сезонными ценами — отказ «Im Formular öffnen» (одна цена тут не правда).
- **Предпросмотр:** «vorher → nachher», цена и категория правятся, видимость — только галочкой;
  снижение цены товара — предупреждение § 11 PAngV (журнал цен не чистится, минимум 30 дней).
- **Применение:** тот же apply: Tenant → цели `pk__in order_by pk FOR UPDATE`, текущее значение == `before`
  предпросмотра (иначе «inzwischen geändert»), узкий `save(update_fields)` (post_save → PriceLog/листинг
  города; не `update()`), видимость — семантика `sellable_manage.toggle_visibility` (включение = Г3-штамп).
- **Откат:** текущее == `after` → вернуть `before`; для цены товара — та же оговорка PAngV в отчёте.
- **ИИ** (`assistant_actions` задача) — отдельным инкрементом A-4b-2 после правил: схема с enum действий,
  контекст только названий (≤ 3500 символов), рамка DATA, проверка фактов той же функцией.
- Замки: детектор ×5 языков, неоднозначность, вариантный товар, право `preise.edit`, оптимистичная
  проверка, откат, PAngV-предупреждение, история с пакетом изменений не применяется.
- **Исполнение A-4b (2026-11-06):** по ревью ECC (django + security) детектор доведён: глагол рядом с
  именем (≤ 40 символов), вопрос с вопросительным словом — вопрос даже с суммой, «Preis … ausblenden»
  без суммы — скрыть, «Käsekuchen Mini kostet 4 €» (имя длиннее существующего) — создание, относительное
  («um 2 € erhöhen», «на 10 %») и несколько сумм — цена не угадывается, «1.250 €» — тысячи; детектор
  только при праве видеть ассортимент, пункт без права действия — без текущих значений; аудит с
  «до/после»; цена услуги не ниже предоплаты; цель «переместить» перепроверяется в транзакции;
  откат скрытия не ставит штамп свежести Г3; предупреждение у скрытия категории. Цена 0 € — осознанно
  разрешена (владелец видит её в предпросмотре и подтверждает).

## 12. A-4c — шаблон / сетка / карточка страницы (план исполнения, 2026-11-06)
**Без миграций.** Один исполнитель — `page_settings` (STU-19: тот же писатель, что экран
«Seitenvorlage»; никакого второго списка шаблонов).
- **Детектор без ИИ** (`apps/core/assistant_pages.py`): слово типа страницы на 5 языках (Sortiment/
  Katalog/Produkte · Aktionen · Leistungen/Termine · Zimmer · Veranstaltungen · Startseite) + подпись
  варианта из `page_settings.schema(tenant, types=(тип,))` в тексте (на языке кабинета И по-немецки,
  целыми словами) или «N pro Reihe / N в ряд / N per row» → пресет `colsN` сетки. Ровно одна пара
  «настройка → значение» → пункт; несколько — пункт без кнопки «Bitte genauer»; ничего — не наше.
  Глагол создания/вопрос «как/где» — не наше (как A-4b).
- **Реестр** += `page.setting` (`website.edit`, гейт — экран кабинета типа `page_templates.cabinet_url`
  через `reachable`); значение правится в предпросмотре селектом из ДОСТУПНЫХ вариантов схемы
  (недоступные — нет); «vorher → nachher» подписями вариантов; ссылка «Im Formular öffnen» = экран
  кабинета; превью страницы — `?preview=1&tpl=<code>:<value>` (STU-19b, ничего не пишет).
- **Применение:** после Tenant-лока — `page_settings.validate` по сохранённому конфигу + проверка
  «текущее значение == увиденному» → `apply_override` → один `update(site_config=…)` (тот же путь, что
  `write`, но внутри общей транзакции пакета) + `bump_storefront_cache` on_commit.
- **Откат:** текущее == `after` → вернуть `before` (для `""` — удаление ключа, presence-minimal).
- Замки: детектор ×5 языков, неоднозначность, недоступный вариант не предлагается, оптимистичная
  проверка, откат, право `website.edit`, гейт Mini App (экран кабинета).

## 13. A-4d — массовые изменения ≤ 50 (план исполнения, 2026-11-06)
**Без миграций.** Массовое = развёртка СЕРВЕРОМ в обычные пункты A-4b (`product.price` /
`product.visibility`): применение, блокировки, оптимистичная проверка, журнал, аудит и
«Rückgängig» — те же, второй машинерии нет.
- **Детектор без ИИ** (`apps/core/assistant_bulk.py`): слово «все» на 5 языках (alle/sämtliche ·
  all/every · все/всех/весь · усі/всі · tüm/bütün/hepsi) рядом (≤ 60 символов, с любой стороны —
  tr ставит его после имени) с именем ровно одной СУЩЕСТВУЮЩЕЙ категории + действие: цена
  (± N %, ± X €, «auf X €»), скрыть, показать. Создание/перенос/вопрос — не наше. Без слова «все»
  («blende Kuchen aus») — сама категория (A-4b). «Покажи все товары … 4 в ряд» — вид страницы
  (A-4c) и в массовое не уходит. Маршрут: массовое → A-4b → A-4c → создание.
- **Факты сервером:** процент — число с %/Prozent/процент/yüzde (tr «%10»); направление — знаком
  или словом (teurer/erhöhen · billiger/senken · дороже/подними · дешевле/снизь · artır/indir);
  нет направления у процента или «um/на N €» — не угадываем (пункт без кнопки с подсказкой);
  несколько сумм — отказ. Пределы — общие с экраном «Sortiment»: процент −90…500, сумма ≤ 100 000.
- **Одна формула** `apps/catalog/bulk_price.py` (`valid`, `new_price`: не ниже нуля, до цента,
  половина вверх) — её же зовёт массовая правка WR-6 (поведение экрана байт-в-байт).
- **Развёртка:** товары категории и её ПРЯМЫХ подкатегорий (страница категории KAT-1), живые;
  > 50 — пункт без кнопки «Das sind N Produkte … im Sortiment auswählen»; товар с вариантами —
  пропускается с подсказкой (одна цена тут не правда); уже такие — пропускаются со счётчиком.
- **Предпросмотр:** шапка «Alle Produkte in „Kuchen“: +10 %» + таблица (галочка с именем ·
  Bisher · Neu), полей ввода нет; одно предупреждение § 11 PAngV на пакет; в историю — одна строка.
- Замки: ×5 языков, общая формула, без направления, без «все», скрыть+откат (категория видима),
  снятая галочка, вариантный товар, > 50, право `preise.edit`, без `sortiment.view` — тишина,
  вопрос, одна строка истории, одно предупреждение, изменённый после предпросмотра — отказ.

## 14. A-4e — ИИ-задача `assistant_actions`: фраза мимо правил → пакет (план, 2026-11-06)
План — агент ECC `planner`, сверен с кодом. Решения владельца: в проде пока прямой Claude API (США)
с пометкой «Daten werden in den USA verarbeitet» (`{% ai_notice %}`); Bedrock EU позже — только маршрут.
**Без миграций.** ИИ понимает формулировку и выбирает из ЗАКРЫТОГО реестра; каждый факт проверяет
сервер теми же функциями, что у правил; дальше — существующая цепочка `put_actions`-запись →
`_present_actions` → `apply`/`undo`.

### 14.1 Маршрут (`assistant_views.assistant_ask`)
bulk → changes → pages → create_intent → **НОВОЕ** `assistant_ai_actions.wants(request, q)` → `ask`.
`wants()` без ИИ: задача включена; `out_of_scope(q) == ""`; не вопрос (`_looks_like_question`);
`sortiment.view` + активен catalog или booking; индекс не пуст. Правила всегда приоритетнее; ИИ не
переписывает пункт правил. Модель «не действие» → fallback со статьями A-1 без второго вызова.

### 14.2 Контекст (`apps/core/assistant_ai_actions.py::build_context`)
Индекс `assistant_changes._index` по `_kinds_for`: категории → товары → услуги; строка `{i, kind, name}`
(имя + i18n через « / », ≤ 80, без переводов строк и маркеров); кап 3500 символов, хвост режется,
«Liste unvollständig». **Никогда:** цены, pk, описания, клиенты, заказы, брони. `ctx["objects"]` =
`[(kind, pk)]` — только в кэше задачи. Фраза — `prepare_question` (scrub ПД); рамки REQ/DATA с
маркером `token_hex(6)` (вырезается из данных); SYSTEM — каталог действий + примеры структуры на 5 языках.

### 14.3 Схема (`schema_for(ctx)`)
`{not_action, items[≤10]: {action: enum, ref: int|null, category_ref: int|null, scope: one|category_all,
name_text ≤120, price_text ≤20, duration_text ≤20, visible: bool|null, in_category_text ≤60}}`. Enum —
из `ACTIONS` ∩ виды `_kinds_for` × активные модули; `page.setting` в v1 исключён; ref — 0…len−1.

### 14.4 Проверка фактов (`check_actions`)
1. ref в пределах и вид совпадает со спекой, иначе пункт отброшен. 2. Объект назван во фразе (слово
имени ≥ 3, casefold, префикс 5 — склонения), иначе отброшен. 3. Два объекта с тем же именем → blocked.
4. Цена: `setup_assistant._ai_price(q, price_text)` (число буквально в тексте, не вес/время/валюта);
относительное — `assistant_bulk.price_change` + `bulk_price.new_price`, `fixed`; несколько сумм при
нескольких ценах → пусто + подсказка; `_price_blocked`. 5. Видимость из модели; `want == before` →
blocked. 6. Перенос — только в существующую названную категорию. 7. `category_all` разворачивает
СЕРВЕР (`assistant_bulk.expand`, ≤ 50), в пакете не больше одного массового пункта. 8. `*.create` →
`setup_assistant._from_ai` → `from_plan` (создание первым). 9. Пункт — тот же dict, что у правил
(`assistant_changes.item_for`); права — в `present`/`apply`. 10. Отброшенные — сводка в шапке; ничего
не осталось → fallback `unclear`.

### 14.5 Задача, кэш, лимиты
`TaskSpec(tier="fast", max_tokens=800, timeout_s=20, max_input_chars=6000)`; `ask()` по образцу
`assistant_ai.ask` (лимиты, замок, pending, Celery `assistant_actions_job`); `run_actions_job` →
generate → check_actions → `_put(outcome="actions", source="ai")`; SYSTEM_CODES → refund; finally —
release. Кэш хранит ПРОВЕРЕННЫЙ ответ модели (не пункты): пункты пересобираются, `before` свежий;
ключ включает хэш списка объектов. Таймаут — общий `job_state`.

### 14.6 Отказы
AIError/невалидный JSON → «nicht verfügbar» + статьи, refund; выдуманный индекс → пункт отброшен;
всё отброшено → fallback; Redis/очередь → `unavailable`; исключение проверки → fallback, без записи.

### 14.11 Правки архитектора (агент `architect`, 2026-11-06) — обязательны до кода
1. `wants()` — только при СИГНАЛЕ действия: глагол (общий `_ACTION_VERB_RE` = `assistant_changes._VERB_RE`
   + глаголы создания + «все») ИЛИ имя существующего объекта во фразе (`_matches`). Без сигнала — прямо в
   `ask` (иначе регрессия A-2: «Mein Shop wird nicht angezeigt» потерял бы диагноз).
2. `not_action` от модели → воркер ставит в ту же задачу запись `assistant_answer` (второй вызов только
   в этом редком случае; попытки считаются по задаче). Вопрос — `assistant_changes._looks_like_question`.
3. Индекс строится один раз: `wants(request, q) -> ctx | None` → `ask(request, q, ctx)`; fail-closed.
4. `check_actions(tenant, user, q, ctx, data, lang)` — без request и `reachable()`; воркер:
   `schema_context` + Tenant/User по pk + `translation.override(lang)`. Права воркера — только «что
   предлагать»; гейты экрана/Mini App — в `present`/`apply` (инвариант A-4a).
5. Пользователь удалён/потерял членство до воркера → `unavailable` + refund.
6. Кэш — только ответ модели после проверки схемы; ключ: TASK, CHECK_VERSION, lang, q, упорядоченный
   список `(kind, pk, names)`, enum схемы, версия ACTIONS. Попаданий мало (индекс по `-updated_at`) — честно.
7. На попадании `check_actions` выполняется синхронно в запросе тем же кодом.
8. Не дублировать: `_put`, `_release`, `_refund`, `_lock_key`, `job_state`, `JOB_RE`, `ENTRY_V`,
   `DEADLINE_S` из `assistant_ai`; один `run_job` с диспетчером по `entry["task"]`; в ctx действий —
   `article_keys` для fallback по таймауту.
9. `assistant_history._DROP` += `objects`, `source`, сырые данные модели; замок «из истории не применяется».
10. Видимость — только при глаголе скрыть/показать во фразе. 11. `in_category_text`/`name_text` —
   должны встречаться во фразе. 12. Неоднозначность — по индексу (тот же casefold-ключ), не по выбору модели.
13. Пакет с `category_all` — только массовый, прочие пункты отброшены со сводкой; две цены при
   относительном изменении — отказ (замок).
14. Смешанный create + change — `outcome="actions"`, `present` рисует create-пункты; замок на шаблон и
   `actions_change`. 15. `_from_ai(..., allowed)` — по правам пользователя в воркере; цена при create —
   `sortiment.edit`, при изменении — `preise.edit`.
16. Проверка короче `DEADLINE_S`; поздний `_put` воркера не перезаписывает timeout.
17. Тумблер `wants()` — задача `assistant_actions` из AI-CFG (`apps/ai/config.py`), не `assistant_ai.enabled()`.
18. pk из `ctx["objects"]` перепроверяются перед `item_for` (удалён → пункт отброшен).

### 14.12 Исполнение A-4e-2 (2026-11-06) и правки ревью ECC
**Как сделано:** запрос (`wants` → `ask`) строит список названий и ставит задачу в общий канал
`assistant_answer_job`; `assistant_ai.run_job` диспетчеризует по `entry["task"]`; воркер только зовёт
модель и кладёт ответ (`state: raw`, без базы); пункты собирает СЛЕДУЮЩИЙ опрос (`job_state` →
`finish` → `check_actions`) — права, язык и «vorher» берутся из запроса; кэш хранит ответ модели.
Создание (A-4e-3) и шаблоны страниц (A-4e-4) — не в этом инкременте.
**Сознательные отклонения:** видимость берётся у модели без глагола из словаря (понять «nicht mehr
anbieten / raus» — смысл задачи; владелец подтверждает в предпросмотре) — против §14.11 п. 10;
`not_action` → статьи A-1 (без второго вызова модели) — против §14.11 п. 2, т.к. `wants` и так требует
сигнал действия, а вопросы («Wie…») отсекаются раньше.
**Ревью (django · security · silent-failure, 0 критичных):** «назван во фразе» — без служебных слов,
склонение только при общем начале почти во всё слово («Apfelkuchen» ≠ «Apfelstrudel»), хвост сложного
слова («Strudel» → «Apfelstrudel»), другая азбука («штрудель»); названные — первыми в списке (срез
3500 их не отрежет); `category_all` — только со словом «все» рядом с категорией (как A-4d); относительная
цена при двух ценовых пунктах — не угадываем; «понял, но однозначного нет» — свой текст (не «nicht
verfügbar») со счётчиком отброшенного; итог задачи пишет ровно один — воркер или таймаут опроса
(`assistant_ai.finalize`, и в A-2), попытки не возвращаются дважды; два опроса не собирают пакет
дважды; «Alles übernehmen» не превращает непоказанный ответ в пакет (`job_state(convert=False)`);
пустой ответ модели не кэшируется; невалидный — лог + возврат попытки; ошибка проверки —
`check_failed`, `logger.exception`, попытка назад; без лимита помощника создания (`setup-plan`).
