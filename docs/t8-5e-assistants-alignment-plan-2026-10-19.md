# T-8.5e «Выровнять два ассистента акции» — план (2026-10-19)

План — агент planner (сверено с кодом). Миграций нет. Решение владельца: одна схема шагов
в обоих потоках; в регистрацию добавить количество, описание, проверку текста, «скоропортящееся»
(только еда); ИИ — только после регистрации.

## 0. Факты
- `QuickStartForm` (`tenants/quickstart.py`) наследует `QuickPromotionForm` — поля `description`/
  `quantity` уже объявлены, но `promo_payload()` передаёт в Celery только title/description/term/
  response/city/цены/until → **`quantity` и `perishable` теряются**; поля описания нет в шаблоне.
- `perishable` выкидывается при `tenant=None` (регистрация); в задаче `provision_quick_logic`
  форма валидируется повторно с тенантом и при ошибке **молча** возвращает None — акция пропадает.
- Шаблон регистрации: 2 шага, JS знает ровно два; форма `novalidate` (страховка от ошибки Chrome
  со скрытыми обязательными полями — держать).
- Проверка текста: партиал `_text_check.html` берёт URL кабинета (на публичной схеме —
  NoReverseMatch), эндпоинт под логином; `promotions/text_check._product()` ходит в каталог
  (на public-схеме таблицы нет). Движок правил `core/text_check.py` без БД — годится.
- Маршрут `aktion-starten/<slug>/` перехватит `/aktion-starten/pruefen/` → новый маршрут выше +
  `pruefen` в резерв имён.

## 1. Инкременты
- **E1 данные** — `quantity`/`description`/`perishable` (еда + исключение включено) доезжают до
  акции; лимит описания 1000 на анонимном вводе; лог `form.errors` перед `return None`.
  Замки: payload несёт поля; акция получает количество/описание; perishable только у еды;
  **класс «поле теряется по дороге»** — каждое поле ассистента либо в payload, либо в явном
  `CABINET_ONLY`.
- **E2 одна схема шагов** — регистрация: 1 Was gibt es? · 2 Preis und Dauer · 3 Reaktion ·
  4 Wer sind Sie? → Fertig; кабинет 1·2·3 → Fertig; общий партиал точек `_quick_steps.html`;
  JS на N шагов, «Zurück»; ошибка сервера открывает свой шаг; флажок perishable на шаге 4 под
  типом (CSS-скрытие, сервер решает сам). Замки: 4 шага, все поля в DOM (W0), поле в своём шаге,
  `novalidate`.
- **E3 проверка текста без входа** — `POST /aktion-starten/pruefen/`: лимит по IP, whitelist
  полей (без `product`), тенант-заглушка по типу, без БД каталога и без ИИ, без cookie/кэша.
- **E4 стенд** 390 px оба потока + ревью django/security (новый анонимный POST).

## 2. Риски
Молчаливая потеря акции в задаче (замок E1-4 + лог) · скрытые шаги и `novalidate` · анонимный
эндпоинт (лимит/whitelist/без БД) · конфликт `pruefen` с поддоменом.
