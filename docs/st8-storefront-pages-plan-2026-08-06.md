# ST-8 — отдельные страницы витрины: Галерея · Отзывы · Мастера (план-док)

Дата: 2026-08-06. Запрос владельца: «страницы галереи, отзывов, мастеров, о нас —
**не разделы на главной, а отдельные страницы**»; объём — «в нужных китах, типа
отели или ресторан»; набор — **Отзывы, Галерея, Мастера/Команда** (FAQ/Контакты
владелец не выбрал — остаются секциями).

## §1. Что показал аудит (факты по коду)

**Отдельных страниц галереи/отзывов/команды в проекте нет вообще.** Существуют
только `/ueber-uns/` (about) и `/blog/`; остальное — секции главной (`gallery`,
`testimonials`, `reviews`, `team` в `siteconfig.SECTIONS`).

**Корень жалобы:** у отеля и ресторана пункты меню «Galerie» и «Bewertungen» —
это ЯКОРЯ на секции главной (`demo_kits.py:1606-1619`: `{"type": "anchor",
"target": "/#galerie"}`), то есть клик прокручивает главную, а не открывает
страницу.

**Механика для решения уже есть:** `apps/tenants/menu.py` резолвит узел типа
`page` через карту `_PAGE_URL_NAMES = {home, offers, about}`; узел без ссылки
гаснет сам. Подписи «Galerie»/«Bewertungen» уже в `_MENU_LABEL_ANCHORS` и
переведены на 5 языков.

**Наполнение демо-китов (все 14):** галерея — 6 фото у каждого; команда — у 12
из 14 (нет у `aktionsmarkt` и `shop`); отзывы — 2–3 у каждого; about — у всех.
То есть контент для страниц есть, показывать нечего только «команду» у двух
розничных китов.

**Побочно найдено (в объём не входит, вынести в roadmap):** в меню нельзя
вывести существующие страницы `/treue/` (лояльность), `/kombi/` (наборы),
`/karten/` (подарочные карты), `/finder/`, `/merkzettel/`, `/lookbook/<slug>/`
— в `NAV_ITEMS`/`_PAGE_URL_NAMES` их нет.

## §2. Решения

1. **Три страницы:** `/galerie/`, `/bewertungen/`, `/team/`. Каждая
   переиспользует партиал соответствующей секции (полный список вместо тизера)
   и общий каркас витрины.
2. **Гейт — по наличию контента, а не по архетипу.** Пустая галерея/команда/
   отзывы → 404, пункт меню гаснет (как `agb_present` и `finder`). Так «нужные
   разделы для нужных китов» получаются сами: у розничных китов без команды
   страницы «Мастера» просто не будет, а у отеля/ресторана/парикмахерской — будет.
   Архетип-whitelist не заводим: он врал бы при пустом контенте и мешал бы
   владельцу, который наполнил раздел вручную.
3. **Меню:** `_PAGE_URL_NAMES` += `gallery`/`reviews`/`team`; в демо-китах
   якоря `/#galerie` и `/#bewertungen` заменяются на `page`-узлы, где страницы
   осмысленны; где пункта не было — добавляется.
4. **Секции главной остаются** тизерами и получают ссылку «Все …» на страницу
   (если она доступна) — дублирования смысла нет: секция знакомит, страница
   показывает всё.
5. **Отзывы на странице** — те же generic-отзывы (`reviews.Review`), что и в
   карточках сущностей, плюс отзывы о бизнесе; сортировка новые-первыми.

## §3. Инкременты

- **SP1** роуты + вьюхи + шаблоны трёх страниц (404 при пустоте), i18n заголовков.
- **SP2** меню: `_PAGE_URL_NAMES`, узлы в китах, ссылка «Все …» из секций главной.
- **SP3** демо: проверить наполнение всех 14 китов; где команда пуста и уместна —
  добавить (решение по каждому киту в ходе работы, по смыслу архетипа).
- **SP4** замки: доступность/404 по каждому гейту, пункт меню появляется и гаснет,
  паритет главной (секции не тронуты); стенд Playwright по 5 языкам.

## §4. Риски

| Риск | Митигция |
|---|---|
| Пустые страницы в меню | гейт по контенту: 404 + узел меню гаснет (замок) |
| Дубль с секцией главной | секция = тизер + ссылка «Все …», страница = полный список |
| Ломается меню отеля/ресторана (якоря) | замена якоря на page-узел покрыта замком меню демо-китов |
| Перевод заголовков | msgid «Galerie»/«Bewertungen» уже есть; новые — сразу в 5 .po (гейт I18N-9) |

## §5. Гейт

`ruff` + `pytest` затронутых модулей + `test_template_comments` + `npm run
build:css` при новых классах; стенд по языкам (de/en/ru/tr/uk) на демо `hotel`
и `friseur`. CI на ветке → FF-мерж в `main` по зелёному.
