# AIS-0 — замер «время до живого сайта» (2026-11-05)

Первый инкремент программы AIS (`ais-modules-directions-assistant-plan-2026-11-05.md §5.5`):
без базовой линии на текущем мастере улучшение v4 не доказать. Без миграций.

## Что меряем

- **Старт** — `Tenant.created_at`: бизнес создаётся после подтверждения почты (AB5.1).
- **Финиш** — метка `completed` мастера. На v3 это «прошёл мастер»; на v4 станет «Website
  veröffentlichen» (та же метка ставится публикацией).
- **Шаги** — первая метка каждого шага (Weiter или Überspringen) → время на шаге и доля пропусков.

## Как храним

В состоянии мастера `site_config["onboarding"]` (его `normalize` пропускает дословно):
- `times` — `{ключ: ISO-время}` для ключей реестра + `start` (первый показ) + `completed`;
  пишется только ПЕРВЫЙ раз, мусор при чтении отбрасывается;
- `source` — `wizard` (прошёл сам) / `quick` / `demo` / `import` (мастер помечен пройденным за
  владельца). В замер идут только `wizard` и незавершённые.

`touch_start` пишет БД один раз на тенанта (повторные заходы — без записи).

## Отчёт

`python manage.py onboarding_report [--days 30] [--type bakery] [--json]` — по всем и по типам:
число бизнесов, завершили, медиана и p75 минут, доля «≤ 24 ч», по шагам — медиана, сколько видели,
сколько пропустили (сортировка: самые долгие шаги сверху). Исключены демо, внутренние, быстрый
старт, импорт и тенанты без меток (созданные до AIS-0).

Пороги v4 — `ais-modules-directions-assistant-plan-2026-11-05.md §5.4`. Замер на v3 — ≥ 2 недели
после деплоя, затем первый отчёт.

## ECC-прогоны

`django-reviewer` перед мержем (состояние мастера — общий ключ site_config, гонки записи).
`security-reviewer` не нужен: только чтение и служебные метки без персональных данных.
