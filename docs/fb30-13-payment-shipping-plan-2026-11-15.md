# FB-30.13 — оплата видна всегда; зависимость «оплата ↔ доставка»

Дата: 2026-11-15. Фидбэк владельца: «В корзине не нашёл выбора оплаты. Так же нужно
предусмотреть зависимость оплаты от доставки и наоборот». Решения владельца (ответы на вопросы):

1. Блок «Wie möchten Sie bezahlen?» в корзине — **всегда**; один способ — строкой без выбора.
2. Правило задаётся **в способе доставки**: «Welche Zahlungsarten bei dieser Versandart»
   (галочки; ни одной — все). Нужна аддитивная миграция `orders/0030`.
3. Галочка «Auch bei Lieferung anbieten» у «Vor Ort» **уходит в доставку** (одно место правила).

## Причина «не нашёл»
Пикер рисуется при `len(methods) > 1` (E7-2). Без Stripe Connect и без IBAN у бизнеса один
способ — «на месте» — и блока нет совсем.

## Модель и правило (одна точка истины — `apps/core/payment_methods.py`)
- `ShippingMethod.payment_methods = JSONField(default=list, blank=True)` — коды из
  `METHODS`; пусто — все. Прежние способы из полей `Tenant` (`legacy_methods`) — без правила.
- `pm.allowed_with(method, tenant) -> set|None` (None — без ограничений). Совместимость
  наследства: `site_config["payment_on_site"]["delivery"] is False` (30.12, мог быть сохранён) →
  у курьера/посылки без своего списка «Vor Ort» не допускается. Галочка с экрана убрана.
- `pm.pair_refused(tenant, code, kind, *, method)` — текст ошибки или "". Заменяет
  `on_site_refused`; зовут чекаут, акция, принятие предложения (ошибка, заказ не создаётся).
- Ноль способов — никогда: способ доставки, у которого нет ни одного *доступного частному лицу*
  способа оплаты, покупателю не предлагается (как тяжёлая посылка); в кабинете у такого
  способа — предупреждение. Сохранить список только из недоступных нельзя? — можно (Stripe
  подключат позже), но с предупреждением.

## Витрина (обе стороны, без JS — сервер)
- Опция доставки несёт `data-pays="stripe vorkasse"` (пусто — все), строка оплаты — `data-pay`.
- Выбрана доставка → прячутся несовместимые способы оплаты (выбор переносится, объявление в
  live region). Выбрана оплата → прячутся несовместимые способы доставки (тот же перенос).
  Последний видимый вариант не прячется никогда.
- Один способ оплаты — строка «Zahlung bei Abholung …» + скрытое поле `payment`.

## Кабинет
- Форма способа доставки: fieldset «Zahlungsarten bei dieser Versandart» — 4 галочки с
  подписью по заказу; подсказка «Keine Auswahl = alle». Сентинел `sec_payments` (W0).
- Карточка «Vor Ort»: галочка «bei Lieferung» снята, вместо неё — ссылка «Welche Zahlungsart
  bei welcher Versandart — in den Versandarten».
- Список способов доставки: строка «Zahlung: alle / Vorkasse, Online».

## Замки до кода
- корзина с одним способом показывает блок оплаты строкой и скрытое поле;
- `allowed_with`: пусто → None; список → множество; наследство `delivery=False` → без on_site
  у курьера/посылки, у самовывоза — все;
- чекаут/акция/предложение: несовместимая пара → ошибка, заказа нет; совместимая — заказ;
- способ доставки без доступной оплаты не предлагается; ноль способов оплаты — никогда;
- форма способа: сохраняет только известные коды, без сентинела не трогает, «все» = [];
- экран оплаты больше не рисует `on_site_delivery`.
