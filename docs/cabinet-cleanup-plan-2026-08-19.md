## §1. Порядок волн и правила исполнения

**Порядок: X0+X7 → X1 → X2 → X3 → X4 → X5 → X6 → X8.**
Язык (X1) — рано, потому что .po-файлы меняются каждым инкрементом и
cherry-pick дорожает с каждой неделей.

Правила (конвенции проекта, без изменений):
- Одна волна = один инкремент: ветка `claude/x<N>-…` → локальный гейт
  (ruff+pytest затронутых модулей) → push → **CI зелёный** → **чекпоинт с
  владельцем** → merge в main.
- Все волны БЕЗ миграций. Характеризационные замки — ДО правок (прецедент UB1-3).
- Каждая волна с UI-изменениями — Playwright-стенд до чекпоинта (урок: JS/навигация
  серверными тестами не ловятся).
- Убираемый экран = редирект с GET-carry, не 404 (прецедент W10-6/W11-5).
- Новые/изменённые msgid — сразу ×5 .po (гейт i18n_gap).

### X3 — Главная = вертикальный кокпит (вариант B)

Первый экран после логина = рабочая петля архетипа (паттерн
Fresha/TravelLine/Smoobu/GloriaFood):

1. **Полоса «Heute»** (одна строка сверху): presence-пилюля (компакт) ·
   Umsatz с «vs прошлая неделя» (RevenueEntry есть; при выключенном finance —
   карточка «Finanzen aktivieren» вместо пустоты) · 2–3 операционных числа
   (Abholbereit/Anreisen/Termine) · бейдж Nachrichten.
2. **Тело = петля primary-kind**, встроенная теми же партиалами, что в
   Verkäufe (V-волна: `stays/_belegungsplan_body`, booking-Tagesplan,
   `core/_board_body`, order-Liste): отель → Belegungsplan · салон/werkstatt →
   Tagesplan · магазин/гастро → очередь заказов · Handwerker/кейтеринг →
   доска заявок · туры/события → расписание заездов. Уважает выбор вида
   (`sales_views`); «Verkäufe →» — ссылка на полную страницу.
3. Setup-карточка (X2.4) показывается до завершения мастера; блоки
   «Heute»-колонок и отдельный канбан «Tasks» уходят (петля их поглощает —
   они показывали те же сделки).
4. Пустая петля — не мёртвый экран: демо-подсказка/CTA «＋» (у китов
   демо-сделки уже сеются).
5. Мобайл: полоса Heute + петля; таб-бар без изменений.
   Замки: рендер петли по архетипу (5 параметризаций), «Heute»-полоса
   гейтится модулями, характеризация партиалов не дублируется (реюз).

### X4 — Подпункты по смыслу + сироты + глоссарий

1. **Подпункты «Sortiment»** (бывш. Angebote, §0.7) — сущности архетипа по
   активным модулям: Produkte [catalog] · Leistungen (`booking:services`)
   [booking] · Zimmer & Preise (`stays:units`) [stays] · Tickets & Reisen
   [events] · Kategorien · Kollektionen. Складская группа
   (Lager/Einkauf/Kombi/Import) уходит из подпунктов сайдбара в ящик
   «Erweitert» каталожного хаба (достижимость та же, шум — нет).
2. **Подпункты «Verkäufe»** — рабочие входы: Öffnungszeiten & Ressourcen
   (`booking:resources`) [booking] · Tage blockieren (`booking:availability`)
   [booking] · Check-ins (`stays:checkins`) [stays] · Kitchen Display
   [orders, только FOOD_BUSINESS_TYPES] · Abläufe; отчётная группа
   (Auswertungen/Finanzen/Berichte) остаётся, но ПОСЛЕ рабочих входов.
3. **Все сироты — в реестр/палитру** (новый флаг `palette_only`, чтобы не
   раздувать таб-бары): booking:services/resources/availability, stays:units/
   checkins/channels, status-manager, KDS, Table-QR, events:teacher-list/
   logistics/documents, crm:company-list, promotions:reservation-list.
   Расширенный замок X7.3 начинает ловить класс навсегда.
4. **Глоссарий-переименования** (только подписи, URL целы): якорь/хаб
   «Angebote»→«Sortiment»; в модуле jobs подписи «Angebote»→
   «Kostenvoranschläge»; «Tasks»→уходит с X3; плитка «Bestellungen» умерла в
   X2. Файл-глоссарий `docs/cabinet-glossary.md` (одно слово = одна сущность).
5. Гастро-шум: KDS/Table-QR гейтятся FOOD_BUSINESS_TYPES (сейчас — только
   модулем orders, видны парикмахеру).

### X5 — Настройки

1. **Таб-бар без горизонтального скролла:** табы в два подписанных ряда —
   «Basis» (Mein Geschäft · Sprachen · Zahlung & Lieferung · Benachrichtigungen)
   и «Verwaltung» (Recht & Steuern · Abläufe · Integrationen · Abo & Rechnung ·
   Team) + ящик Erweitert как есть; flex-wrap, «Abo/Team» видимы всегда.
2. **Google Bewertungen** — из main-табов внутрь Integrationen (карточка →
   экран остаётся, запись становится palette_only). Дубль-подсветка nav_key
   уходит сама.
3. **Abläufe без телепорта:** при заходе из подпункта Verkäufe — `?from=board`:
   back-ссылка «← Verkäufe» и подсветка якоря Verkäufe (nav-параметр), из
   настроек — как сейчас. Одна страница, один источник правды.
4. **«Mein Geschäft»** — секции с якорь-навигацией (Kontakt · Öffnungszeiten ·
   Social · Betrieb) + sticky-Save; инвариант W0 (все поля в DOM, скрытие CSS).
   Взаимные прокси-ссылки «часы бизнеса ↔ расписание слотов записи» (X6.4).

### X6 — Консистентные механики

1. **Конвенция «＋»:** «＋» ВСЕГДА открывает форму создания. Для Leistung/
   Zimmer — экран-обёртка с существующей формой (сейчас — список с формой в
   подвале); на Verkäufe «＋» появляется у order (ручной заказ — если движок
   не поддерживает, честно не показываем) — минимум: паритет stay/booking.
2. **Поиск:** `?q=` на «Sortiment»-обзоре (имя по всем kind через
   `ManagedSellable`) и в generic-Liste Verkäufe (имя/email клиента +
   reference_code через реестр transactions).
3. **Draft-ловушка акций:** после Save — редирект с явным primary-CTA
   «Jetzt aktivieren» + человеческий статус (`status_label`) вместо сырого
   кода; на списке акций у draft — бейдж «nicht sichtbar».
4. **Часы ×1 (честно):** движки не сливаем (расписания booking — per-resource
   by design); в обоих местах — взаимные плашки-ссылки, из настроек часов
   видно «Termin-Slots: Öffnungszeiten & Ressourcen →».
5. **Порядок видов фиксированный:** Kalender · Board · Liste на всех вкладках
   (меняется только доступность); дефолты не трогаем.
6. **Таб «Price & stock»** формы товара действительно содержит цену (перенос
   поля из Basics; W0-инвариант, W2-замок обновляется осознанно).

### X8 — Ctrl+K по данным

Эндпоинт `/dashboard/palette-search/?q=` (login_required, гейты модулей):
заказы/брони по reference_code и имени клиента (реестр transactions),
клиенты [crm], товары/услуги/номера по названию (`ManagedSellable`), лимит
5/тип; палитра показывает секцию «Gefunden» под пунктами меню (debounce 250мс,
fetch — паттерн живых панелей MEN). Замки: гейты модулей, аноним 302,
кросс-тенант изоляция (схема и так тенантная).

## §4. Что НЕ делаем (зафиксировано)

- Вариант C — никакой новой перегруппировки якорей.
- Никаких новых «режимов» (урок SM-1) и вторых IA (урок W-CL).

- Изменение движков продаж/FSM/anti-oversell — только навигация/UX-слой.
