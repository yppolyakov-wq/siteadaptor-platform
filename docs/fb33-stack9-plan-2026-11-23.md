### C. M5a-2 — 404 и поиск
1. **Кэш 404.**
   - В `apps/core/pagecache.py`: `_nf_key(request, schema, lang, host) =
     "sfnf1:{host}:{schema}:{lang}:v{_sf_version}"` (без пути), `not_found_hit(request)`,
     `not_found_store(request, response)`. Проверка на персональное — из `_cacheable` (параметр `status=404`;
     сейчас `:86` пропускает только 200). Мимо кэша: TTL 0, не GET, `request.GET`, непустая сессия, нет хоста.
   - Вызов в `storefront_404` (`not_found_views.py:101–111`) — только после `_wants_blocks`: платформа, портал
     и закрытая витрина в кэш не попадают.
   - На хите — код 404, `X-Robots-Tag: noindex`, `Vary: Cookie`; TTL — `PUBLIC_PAGE_CACHE_TTL` (120 с); сброс —
     `bump_storefront_cache`.
   - **Риск:** без пути в ключе путь одного посетителя попал бы в страницу другого: тело зависит от пути
     через `next` у смены языка (`_header_icons.html:30`) и у демо-плашки (`_demo_banner.html:12,15`) — утечка
     пути с токеном (`/angebot/<token>x/`). Поэтому на 404 в контексте `storefront_self_path="/"`, в шаблонах —
     `|default:` (на остальных страницах вывод тот же; решение §4 №3).
2. **noindex при `?q=`.** Одно место — `{% block robots %}` в `templates/storefront/listing.html` (его
   наследуют все 11 листингов, своих `robots` у них нет): мета при непустом `request.GET.q` после strip и не у
   демо (у демо уже есть мета `_base.html:25`). Маршруты поиска — `context.py:225–230`, `:537–560`. Листинги с
   `?q=` и так мимо кэша; canonical без query (`seo.py:284`) остаётся.

**Замки:** два разных битых пути дают байт-в-байт одно тело, пути в нём нет; второй битый адрес не рендерит
шаблон (сигнал `template_rendered` = 0) и укладывается в потолок запросов; страница по умолчанию
действительно попадает в кэш; сессия, cookie, сообщение — мимо кэша; публикация сбрасывает; на хите 404 и
`noindex`; сбой Redis — всё равно 404; `?q=x` на каждом маршруте поиска и `/aktionen/` — `noindex,follow`,
пустой `q` и без `q` — как было, у демо одна мета. Тесты кэша — с `override_settings(PUBLIC_PAGE_CACHE_TTL=60)`,
locmem и настоящим хостом.
