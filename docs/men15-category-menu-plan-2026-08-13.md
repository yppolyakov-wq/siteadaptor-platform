# MEN-15 — категории вторым уровнем меню, с картинками

**Запрос владельца (2026-08-13):** «нужно добавить в меню сайта сверху настройку
выводить категории — или у нас это для кейтеринга „Was wir für Sie kochen“ — во
2-й уровень меню с картинками, нужно настроить управление этим красиво».

Разведка по коду выполнена 2026-08-13 (карта файлов и рисков — §5). Кода до
согласования этого документа не пишем.

## 1. Что уже есть (факты, не предположения)

- **Меню хранится в `site_config["menus"]`** = `{top: {style, sticky, items[]},
  bottom: {...}}` (`apps/tenants/siteconfig.py:1615`). Узел —
  `{label, type, target, enabled, icon, children}` (+ опциональный `label_i18n`),
  `_clean_menu_node` — `siteconfig.py:1550`.
- **Дети уже поддерживаются**, ровно один уровень: `_MENU_MAX_DEPTH = 2`
  (`siteconfig.py:1525`), залочено тестом `apps/tenants/tests/test_menu.py:65`.
- **Выпадающая панель уже есть** и открывается тапом (фидбэк 2026-08-07):
  `templates/storefront/_header_nav.html:14-20`. Панель — один столбец
  текстовых ссылок; `icon` узла в шапке НЕ рендерится (только в нижнем меню,
  `apps/core/context.py:258`).
- **У категории есть фото** — `Category.images` (FB-6), `image_url`,
  `primary_image`, а также `parent`/`children` и `slug`
  (`apps/catalog/models.py:25-101`). Управление фото в кабинете готово
  (`apps/catalog/views.py:605`, `:710`, `:730`). **Миграции не нужны.**
- **Плитка категории — общий партиал** `templates/storefront/_category_tile.html`
  с обязательным текстовым фолбэком (у большинства тенантов фото нет).
- **Узлы `type: "category"` уже используются китами** как обычные текстовые
  пункты (`apps/tenants/demo_kits.py:1060`, `:4199`).
- **Мега-меню/подменю с картинками в проекте нет** (grep по mega/submenu — 0).

## 2. Развилка, которую нужно закрыть до кода

Владелец говорит «настройка выводить категории». Два принципиально разных
прочтения:

- **(A) Авто-узел.** Один пункт меню типа `categories`: дети собираются на
  рендере из живых категорий. Владелец не ведёт список руками — добавил
  категорию, она появилась в меню. Порядок/состав = `sort_order`/`is_active`.
- **(B) Ручные дети.** Владелец сам кладёт нужные категории детьми пункта
  (это МОЖНО уже сегодня, тип `category`), а нового — только картинки в панели.

**Рекомендация: (A) + картинки.** Кейтеринговое «Was wir für Sie kochen» — это
именно «покажи мои направления», список которых меняется вместе с каталогом;
ручное ведение обоих списков разъезжается. (B) остаётся доступным как было.

## 3. Предлагаемое решение (v1)

### 3.1. Данные — БЕЗ новых ключей и миграций

Новый тип узла `"categories"` в `MENU_NODE_TYPES` (`siteconfig.py:1523`).
Хранится обычным узлом: `{label: "Speisekarte", type: "categories", target: ""}`.

- `target` пуст → дети = активные КОРНЕВЫЕ категории;
- `target = "<slug>"` → дети = подкатегории этой категории (тот самый «2-й
  уровень»).

Golden-фикстуры не трогаются: набор ключей узла прежний (риск §5.1 снят).

### 3.2. Резолв — ОДИН запрос вместо N

В `apps/tenants/menu.py` ветка `categories` в `_resolve` строит детей одним
queryset'ом (`is_active=True`, `parent__isnull=True` либо `parent__slug=target`,
`order_by("sort_order","slug")`, кап 12) и отдаёт
`{"label", "url", "image", "children": []}`.

Два обязательства:
1. **Ссылка та же, что у плитки категории** — `/bereich/<slug>/` при
   `category_landings` и `landing_ready`, иначе `?kategorie=<slug>` (сейчас меню
   и плитки расходятся: `menu.py:178` против `_category_tile.html:34`).
2. **Мемоизация на объекте тенанта** (как `_page_has_content`,
   `menu.py:121`) — шапка резолвится трижды за рендер.

### 3.3. Рендер

- `_header_nav.html`: если у детей есть `image` — панель становится сеткой
  плиток (фото 96px + подпись, 2 колонки, `min-w-[380px]`); если фото нет ни у
  кого — прежний текстовый столбец. Фолбэк обязателен (§5.5).
- Панель «Mehr» (`_header_nav.html:36`) и мобильное меню (`_base.html:114`) —
  текстовый список с мини-фото 32px; большие плитки там не помещаются.
- Пустой список категорий → узел не рендерится вовсе (правило `menu.py:312`).

### 3.4. Управление в кабинете

- `site_menu.html`: тип «Kategorien» в селекте + для него селект `target`
  («Alle Hauptkategorien» / конкретная категория). Попутно чинится
  `core/views.py:2797` — `label` берётся из `get_i18n("name")`, а не сырого
  dict, и список отдаётся деревом (родители/дети).
- Кнопка-подсказка «Fotos für Kategorien pflegen» → `/catalog/categories/`
  (фото уже редактируются там, дублировать загрузку не надо).
- Studio, область «Menu»: пресет «＋ Kategorien ins Menü» — добавляет узел
  одним кликом (это и есть «настройка выводить категории»).

## 5. Риски (из разведки)

1. **N+1**: `_category_url` бьёт `exists()` на каждый узел (`menu.py:176`), а
   `normalize()` вызывается 2–3 раза за рендер шапки и не кэширована. Новый тип
   ОБЯЗАН быть однозапросным и мемоизированным.
2. **Golden-замки** (4 фикстуры × 2 теста): любой безусловный новый ключ узла их
   валит. Обход — presence-minimal; в v1 новых ключей нет вовсе.
3. **Глубина 2** залочена (`test_menu.py:65`): «категория → подкатегория» внутри
   панели — это 3-й уровень, в v1 не делаем.
4. **Бюджет ширины шапки** `≤ 788px` по всем 15 китам (`test_demo_menus.py:229`)
   — новый пункт в демо может его превысить.
5. **Фото есть не у всех**: `Category.images` пуст у большинства; без текстового
   фолбэка панель выродится в серые прямоугольники.
6. **Три поверхности рендера** (десктоп-панель, «Mehr», мобильное меню) —
   пропустишь одну, пункт исчезнет при overflow или на телефоне.
7. **Save билдера заменяет `menus` целиком** клиентским JSON
   (`core/views.py:2775`); ключи, которых нет в JS-модели, выживают только у
   существующих узлов (`site_menu.html:205`), у нового из `blankNode()` — нет.
