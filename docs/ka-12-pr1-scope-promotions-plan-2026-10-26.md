# KA-12 PR-1 (= WR-9, E3.5) · Aktion auf Kategorie / ganzen Shop (2026-10-26)

Из разбора CS-Cart (`cs-cart-promotions-analysis-2026-10-26.md` §4 п.1): «−20 % auf alle
Brote», «Sale −10 % auf alles» — сегодня акция живёт только на ОДНОМ товаре.

## Решение
- `Promotion.category` (FK catalog.Category, SET_NULL) + `Promotion.whole_shop` — ⚠️
  `promotions/0032`, аддитивная. `scope_kind` = «category»/«shop»/''.
- Область — **только процент**: «новая/старая цена», условие цены и mystery — свойства
  одного товара (форма отклоняет, резолвер отфильтровывает).
- Резолвер — единственный (`price_layer.product_promo_map`; `promo_for_product` делегирует
  ему): своя акция товара · акция категории товара или её предков · весь магазин; правило
  прежнее — лучшая цена клиенту, без суммирования. Акции области — тем же запросом (число
  запросов фида/каталога прежнее, замок `test_promo_feed_constant_queries`).
- Цена считается свойствами модели от ЭТОГО товара: резолвер подставляет виртуальную копию
  акции (`scope_copy`: свой `_state` и кэш связей, `save()` запрещён). Поэтому §11 PAngV,
  бейдж, «Sie sparen», Merchant-фид, корзина, `create_order` (снимок, лимит, маркер возврата)
  работают без правок.
- Вариант со своей ценой — без скидки (прежнее правило `promo_line_price`).
- Страница акции: отклик «Nur zeigen» (или Coupon/Anfrage по выбору), карточка «Gilt für» →
  страница категории / весь каталог.

## Не делаем (v1)
«−X €» на всю область (PR-2), «ab Bestellwert» (PR-4), исключения товаров из области.

## ECC-прогоны
Скиллы: database-migrations, django-patterns, django-tdd. Агенты после кода: django-reviewer,
database-reviewer (запрос/цепочка категорий), security-reviewer + silent-failure-hunter (деньги).

## Ревью (django-reviewer, 2026-10-26) — исправлено
- POST `/p/<uuid>/kaufen/` и резерв принимали акцию области (цена None → 500 в create_order):
  гард во вьюхах и в сервисах `purchase()`/`reserve()` (будущие каналы — бот/MCP).
- §11 PAngV: прошлая акция категории/магазина входит в 30-дневный минимум товара (тем же
  запросом, что прошлые акции товара — число запросов прежнее).
- Виртуальная копия помнит область (`scope_kind` = область оригинала, `target_kind` = product).

## PR-2 «−X € pro Stück» (2026-10-26, ⚠️ `promotions/0033`)
- `Promotion.discount_off` — третий вид выгоды (рядом с % и новой ценой), один на акцию (форма).
- `new_price` = обычная − X (не ниже 0); бейдж — «−1,00 €» (процент от суммы в евро вводил бы в
  заблуждение); работает и для области PR-1 («−1 € auf alle Brote»), и в §11-минимуме.

## PR-5 «Nur für Neukunden / einmal pro Kunde» (2026-10-26, без миграций)
- `metadata["customer_rule"]` ("" / new / once), поле формы с presence-guard.
- `apps/promotions/eligibility.check` в `create_order` ДО списания лимита: клиент — по e-mail
  (без регистра), иначе телефону; «new» — у клиента нет живых заказов; «once» — нет живой
  строки с этой акцией (отменённые/возвращённые не считаются). Неизвестный адрес = новый.
- Отказ — `PromoNotEligible` (подкласс промо-OutOfStock: все чекауты ловят без 500), корзина
  объясняет правило. Запрос/предложение (quote/offer) не проверяются.

## Ревью PR-2/PR-5 (security-reviewer, 2026-10-26) — исправлено
- Прямая покупка `/p/<uuid>/kaufen/` (и бот/MCP через `purchase`) обходила правило клиента →
  проверка в `purchase()` до списания лимита; отказ — свой обработчик, не «ausverkauft».
- Гонка «once»: транзакционная advisory-блокировка на (акция, клиент) внутри `check()`.
- Оракул «есть ли у адреса заказы»: одна нейтральная фраза вместо двух разных.
- Телефон сравнивается по цифрам (0171… ≡ +49 171…).
- Правило клиента запрещено у услуг/номеров (их брони не проходят через `create_order`).
- «−X €» не дороже цены товара (форма); у области — товар дешевле скидки пропускается.
- Инлайн-правка процента на канве закрыта у акции с «−X €» (два вида выгоды в обход формы).
Остаётся (осознанно): правило проверяется по контакту, новый адрес = новый клиент.

## PR-4 «Gratis-Artikel ab Bestellwert» (2026-10-26, без миграций)
- Акция-подарок: цель — товар-подарок, порог `metadata["gift_min_order"]`; цену товара НЕ
  меняет (исключена из `price_layer`), продать её страницей нельзя (отклик «Nur zeigen»,
  гард в `purchase`/вьюхах).
- `gifts.pick(subtotal)` — одна функция корзины («Gratis dazu …» / «Noch X € bis zum Geschenk»)
  и `create_order` (строка 0 € после всех позиций, до промокода: лимит кампании + склад в
  savepoint; кончился подарок — заказ без него). Возврат лимита/склада при отмене — штатно
  по маркеру {"promo": id}. Правка заказа не размножает подарок.
- v1: порог — сумма товаров до промокода; «−X % ab Bestellwert» не делаем (по спросу).
