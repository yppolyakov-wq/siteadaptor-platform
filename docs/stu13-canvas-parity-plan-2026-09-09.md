**Дата:** 2026-09-09 · **Ветка:** `claude/aktionsmarkt-analysis-45t2vu`
**Повод:** фидбэк владельца по скриншоту Студии (демо `aktionsmarkt`, локаль витрины ru):
«не соответствует твоему дизайну: было больше выделено, подписи, попап был шире» ·
«стоит русский, а правое меню не переведено и пункты в попапе тоже» ·
«проверь, чтобы на каждом типе страниц каждый тип был редактируемый и имел свои типы оформления».

**Эталон:** канвас `docs/design/studio-2026-09-07/` — артборды **P3** (панель блока + плашка),
**P4** (быстрый поповер), **F1** (панель страницы), **F2** (шапка/подвал), карта **P1**.
Волна STU-12 (12a–12j) реализовала ПОВЕДЕНИЕ; этот инкремент закрывает ВИД и находимость.

**Диагноз по переводу (F).** Панель переводится корректно: при `cabinet_lang=ru` стенд
показывает «Шапка и подвал», «Стиль заголовка», «Пункты меню». Немецкий текст на скриншоте
владельца — потому что язык КАБИНЕТА остался `de` (T1-a: язык витрины ≠ язык кабинета), а
переключателя в полноэкранной Студии нет. Значит правка — не в `.po`, а в находимости.

## 2. Инкременты

* **13a — плашка по макету** (A1–A3): тёмная пилюля, имя блока, порядок кнопок, центрирование.
* **13b — выделение выбранного блока** (B): рамка на канве, снимается при закрытии панели.
* **13c — панель по макету** (C1–C4): карточки-группы + сводка значений + бейдж «Эксперт»,
  обычный регистр подписей, крошка сверху, дубли ▲▼⚙ из шапки убрать → подсказка внизу.
* **13d — поповер по макету** (D1): шапка с именем и ✕, плитки сеткой, ширина под 3 плитки.
* **13e — топбар компактный** (E): устройства иконками, 🔗 иконкой, статус не обрезан.
* **13f — язык кабинета из Студии** (F): селектор в топбаре Студии (тот же endpoint
  `set-cabinet-lang`), возврат на ту же страницу канвы.
* **13g — сверка «каждый тип страниц редактируем»**: обход всех типов реестра стендом +
  замок; дыры реестра закрываем по отчёту разведки.

## 3. Инварианты
* W0 — контролы остаются в `#home-form`; поповер по-прежнему ПРИНИМАЕТ настоящий контрол.
* Замки STU-12 (`test_stu12_*`, `test_registry_and_panel_agree`) обязаны остаться зелёными;

* Новые строки — в 5 каталогов `.po` (гейт `i18n_gap`), новые Tailwind-классы → `npm run build:css`.
* Проверка каждого инкремента — Playwright на демо `aktionsmarkt` (JS-фичи серверные тесты не видят).

## 4. Пункт 3 владельца: «каждый тип страниц редактируем и имеет свои типы оформления»

Сверка реестра `studio_pages.PAGE_TYPES` (20 типов) с разметкой панели, `PAGE_BLOCK_HOSTS`
и реестрами оформления (разведка 2026-09-09; все факты — из кода).

**Полностью укомплектованы** (шаблон страницы + раскладка + форма карточки + C-блоки +
сортировка/фильтры): `catalog` (7 настроек), `category` (8). Хорошо покрыты: `product`,
`promos`, `promo_group`, `services`, `stays`, `events`, детали `service`/`stay`/`event`.

**Дыры (панель пуста или почти пуста):**

| тип | что не так | где чинить |
|---|---|---|
| `tours` | **0 настроек, 0 блоков, 0 шаблонов** — панель пуста | SETTINGS += раскладка/шаблон; хост `tours` в PAGE_BLOCK_HOSTS + `{% page_blocks %}` в `tour_index.html` |
| `checkout` | **0 настроек**, хоста нет, при этом пункт «Kasse» есть в меню «Seite ▾» | хост `checkout` + настройки по образцу `cart` |
| `promo` (деталь акции) | 1 настройка, нет шаблона и блоков | `PROMOTION_DETAIL_STYLES` + `Promotion.page_style` (⚠️ миграция) |
| `promos` / `promo_group` | единственные листинги без C-блоков | хосты `promos`/`promo_group` |
| `legal` | 1 настройка, блоков нет | хост `legal` + вызов в правовых шаблонах |
| `text` | ОДИН хост `info` на 4 страницы, а рендерится только на `/ueber-uns/` | свои хосты `team`/`gallery`/`reviews` |
| `blog` | блоки только на индексе, деталь без вызова | хост `blog_post` |
| детали `service`/`stay`/`event` | нет шаблона страницы (только скрытие секций) | реестры `*_DETAIL_STYLES` (⚠️ поля на сущностях) |
| листинги `services`/`stays`/`events` | нет сортировки/фильтров и шаблона | по образцу `catalog_sort` |

**Страниц витрины ВНЕ реестра** (панель «Diese Seite» пуста): `/merkzettel/`, `/kombi/`,
`/finder/`, `/lookbook/<slug>/`, `/karten/`, `/lehrer/`, `/hausordnung/`, страницы
подтверждений и публичные оффер/смета. Самое болезненное: **четыре архетип-лендинга**
(`/treue/`, `/gutschein/`, `/anfrage/`, `/nachricht/`) попадают в переключатель «Seite ▾»
через `modules.storefront_landing`, но типа не имеют — владелец переходит и видит пустоту.

**Объём:** часть закрывается без миграций (хосты блоков, настройки листингов, типы
лендингов), часть требует полей на сущностях. Волна **STU-14** — отдельным планом.
