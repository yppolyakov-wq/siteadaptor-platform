# FB-27 R8 — граница со Студией

Дата: 2026-11-13. Основание — `fb27-seitenaufbau-impl-plan-2026-11-11.md` §A.6, §C (R8), §D.6;
решения владельца — `fb27-website-pages-ia-plan-2026-11-11.md` («Studio: пункт меню убрать;
открывается кнопкой „Auf der Seite bearbeiten“; структура — только в Seitenaufbau»). План
составлен агентом `planner` по разведке кода (карта точек — §1).

## 1. Что есть в коде (разведка)

Вьюха Студии — `home_builder_view` (`apps/core/views.py`), url `site-home`. Её «Speichern»
пересобирает структуру из формы:

- фикс-секции главной: `order_<key>`, `enabled_<key>` (секции нет в форме → выключена),
  `hide_*`, `width_`, оси вида и списков;
- свои блоки главной: цикл по `cb_id`; блок, которого нет в форме, **удаляется**;
- `page_blocks` (при `pb_present=1`): **все** хосты пересобираются, хост или блок вне формы
  теряется;
- в том же Save: настройки типов (`*_page_style`, `*_detail`, `storefront_root`…);
- отдельные действия: `add_block`, `copy_builtin:`, `use_/save_/delete_block_template:`,
  `use_page_template:`, `use_page_preset:`, `add_type_block:`, `restore_version:`;
- живой черновик `site_preview_draft` принимает `sections` и `page_blocks` целиком;
- только содержимое пишут `site_inline_edit` и `site_cblock_photo_edit`.

Предохранитель R0: Save сверяет `structure_hash` и при расхождении отказывает (с потерей
набранного текста).

## 2. Решения

| № | Вопрос | Решение |
|---|---|---|
| S1 | Принцип Save | Структура (порядок, состав, `enabled`, `width`/`pos`/`newline`, хосты) берётся из **свежей строки БД** под `select_for_update`; из формы — только содержимое и вид блоков, найденных по `key` (фикс-секции) и `id` (свои блоки). Блок из формы, которого нет в БД, игнорируется; блок БД, которого нет в форме, остаётся как был; хост без строк в форме — как был. |
| S2 | Один писатель | Новая функция `site_schema.merge_content(fresh, posted)` — её зовут и Save, и живой черновик: «превью = результат Save». |
| S3 | Что такое структура | `site_schema._STRUCT_FIELDS` + поля, которые правит панель «Seitenaufbau» (оси блока «Liste» и встроенных списков, `limit`, `source`). Второго списка не заводим. |
| S4 | Что остаётся Студии | Тексты и фото блоков, стиль/шрифт/оформление (`style_`, `font_`, `visual_*`), раскладка секции (`layout_*`, `cols`, `tile_*`), скрытие на устройстве (`hide_*`) — пока в «Seitenaufbau» нет своего контрола. |
| S5 | Настройки типов страниц | Уже принадлежат «Seitenaufbau» (R4): набор `page_settings.protect_owned` расширяется на оставшиеся ключи Save. |
| S6 | Действия, меняющие структуру | `add_block`, `copy_builtin`, `use_block_template`, `use_page_preset`, `add_type_block`, удаление, порядок, видимость, ширина: из интерфейса Студии убираются (R8b), на их месте — ссылка «Aufbau ändern» на «Seitenaufbau» этой страницы; на сервере — 302 туда же с сообщением (R8d). |
| S7 | Библиотека | `save_/delete_block_template` остаются (это библиотека, не структура). Вставка шаблона блока из Студии уходит; группа «Vorlagen» в «+ Block» — отдельной записью в roadmap. |
| S8 | Версии | `restore_version` откатывает весь конфиг, включая структуру — остаётся явным действием с предупреждением в подтверждении. |
| S9 | Предохранитель R0 | После R8a устаревшая вкладка безопасна: в R8d отказ заменяется слиянием и сообщением (текст не теряется). |
| S10 | Меню | Якорь «Website» ведёт на «Design» (`targets=("design",)`), `site-home` — в `EXPECTED_UNLISTED`; Студия открывается кнопкой «Auf der Seite bearbeiten» из «Seitenaufbau» и с витрины. |

Вопросы владельцу (работаем по рекомендации, пока не сказано иное): скрытие на устройстве
остаётся в Студии (S4); восстановление версии остаётся (S8); вставка сохранённых шаблонов
блоков временно пропадает (S7).

## 3. Срезы

- **R8a — сервер.** `merge_content`, Save под блокировкой строки, живой черновик,
  `protect_owned`. Тесты, где Save Студии только готовил структуру, переводятся на хелпер
  `seed_blocks()` (прямая запись конфига или `site_schema.apply`); тесты «Save переставил» —
  в замки «не переставил». Действия `add_block`/`add_type_block` пока живы.
- **R8b — шаблоны и JS.** Контролы структуры в `site_home.html`, `_cb_row.html`,
  `_builtin_list_fields.html` → ссылка; `collect()` структуру не шлёт. Выкладывается вместе с
  R8a (иначе контролы молча ничего не делают).
- **R8c — меню и ссылки.** Якорь, кнопки, ссылки «менять порядок» → «Seitenaufbau»; замки
  меню переписываются осознанно (`test_sidebar_st4b`, `test_x0_x7_locks`,
  `test_ka_w2_nav_locks`, `test_menu_label_equals_h1`, `test_w11_5_redirect`).
- **R8d — уборка.** Серверные 302 для действий S6, перенос `test_lb3_overview_blocks` на
  `site_schema.apply`, снос мёртвых шаблонов страниц, ослабление R0 (S9).

## 4. Замки (до кода) — `apps/core/tests/test_fb27_r8_studio_boundary.py`

- Save с обратным порядком, выключенной секцией и другой шириной: схема как в БД, текст новый;
- `pos`/`newline`/оси списка из формы не применяются;
- блок, которого нет в форме, не удаляется (главная и хост страницы); галочка удаления
  игнорируется; хост без строк в форме сохраняется;
- устаревшая вкладка не возвращает удалённый блок; Save после записи «Seitenaufbau» хранит
  новый порядок;
- перевод (ru): оверлей идёт за порядком БД;
- живой черновик не может переставить или убрать блок;
- инлайн-правка и замена фото по-прежнему пишут;
- частичная форма не стирает содержимое (W0);
- настройки типа страницы Save Студии не меняет;
- `site-home` открывается; кнопка есть в «Seitenaufbau» и на витрине; экраны кабинета без
  `NoReverseMatch`; якорь «Website» ведёт на «Design».

## 5. Риски и откат

- Сдвиг переводов блоков → порядок из БД + `realign_block_overlays`, отдельный замок.
- Массовая переписка тестов (≈200) → хелпер и перевод группами.
- Пропущенное семейство полей формы → `silent-failure-hunter`.
- Откат: R8a — один коммит с `merge_content`; миграций нет.
