## 1. Как это сделано на рынке (ECC market-research, 7 платформ)

| Платформа | Список | Правовые страницы | Защита от удаления | Кто правит | Шаблон |
|---|---|---|---|---|---|
| Jimdo | один список | созданы заранее, Datenschutz в подвале | системные (вывод) | владелец | один редактор |
| IONOS MyWebsite | один список «Seiten» | созданы заранее, ссылки в подвале | частично (вывод) | владелец | один редактор |
| WordPress / Woo | один список Pages | обычная страница с меткой «— Privacy Policy Page» | нет | правку Privacy Page — только Admin (`manage_privacy_options`); частая жалоба, обходят плагином | один шаблон |
| Wix | один список «Pages & Menu» | обычные страницы + генератор | нет | роли Admin / Website Manager | один редактор |

| Shopware 6 | нет экрана страниц: «Erlebniswelten» по типам | привязка в настройках | — | ACL-роли | **шаблоны по типам — пользователи путаются** (форум) |

«Вывод» — это не подтверждено найденными источниками.

**Выводы:**
1. **Один плоский список — норма.** Так у Jimdo, IONOS, WordPress, Wix и CS-Cart. Предложение владельца совпадает с рынком.
2. **Правовые страницы почти везде отмечены**, но не отдельной группой, а меткой в строке и защитой от удаления.
3. **Отдельные шаблоны по типу страницы (Shopware) путают** — микробизнесу нужен один тип «Seite». Это совпадает со вторым пунктом владельца.
4. **«Правит только владелец»** — так устроены WordPress и Shopify. Однако там же жалобы: помощник или Steuerberater не может поправить текст. Поэтому на рынке это право, которое владелец может выдать, а не жёсткий запрет.

Источники — в отчёте исследования (сохранён в §8).

## 2. Решения (предлагаю, нужен «ок»)

- **Р-1. Один список «Seiten» без групп.** В одной таблице: Über uns, Versand (пока магазин принимает заказы), Impressum, Datenschutz, Widerruf, AGB и свои страницы. Сортировка: сначала страницы из меню и подвала, затем остальные по названию.
  - **Колонка «Art»** — метка: Impressum / Datenschutz / Widerruf / AGB / Versand / Über uns. У своих страниц метки нет.
  - **Колонка «Status»:** «Eigener Text», «Automatisch» (у правовых без своего текста), «Entwurf», «⚠ fehlt» (AGB без текста при онлайн-оплате — подсказка, не запрет).
  - **Колонка «Sichtbar»:** «im Menü» / «im Footer» / «nicht verlinkt».
- **Р-2. Защита от удаления.** У Impressum и Datenschutz кнопки «Löschen» нет (§ 5 DDG). У Widerruf, AGB, Versand и Über uns вместо «Löschen» стоит «Eigenen Text entfernen» — возвращает автоматический или стандартный вид. Свои страницы удаляются с подтверждением.
- **Р-3. Правка — только владелец.** Сейчас тексты страниц может править сотрудник с правом «Website», а правовые — только владелец. Вариант на выбор:
  - **(а) по рекомендации рынка:** новое право «Seiten bearbeiten», по умолчанию только у владельца. Владелец может выдать его помощнику в «Team & Zugriff» (механика E6.7 готова). Правовые тексты входят в это же право.
  - **(б) жёстко:** только владелец, без возможности выдать.

  В обоих вариантах сотрудник видит список только для чтения: без «Bearbeiten», «＋» и «Löschen».
- **Р-4. Одна форма правки для всех страниц.** Правовая страница открывается той же формой, что своя:
  - заголовок, текст и языки;
  - у Versand — галочка «Versandarten»;
  - у правовых — «Automatischen Text übernehmen».

  Отдельная форма `legal-page-edit` растворяется в общей. Хранение прежнее: свои и системные страницы — `ContentPage`, правовые — `LegalDoc`. Миграций нет.
- **Р-5. «Seitenaufbau» и «Studio»: один тип «Seite» вместо трёх.** Сейчас в реестре типов страниц три отдельных типа: «Über uns» (блоки хоста `info`), «Eigene Seite» и «Rechtliches» (хост `legal`). Предлагаю свести их в один тип «Seite» с ОДНИМ общим набором блоков — блоки показываются под текстом любой текстовой страницы.
  - Блоки, стоящие сейчас на «Über uns» (`info`) и на правовых (`legal`), переносятся в общий набор без потерь. Конфиг читается по-старому, миграций нет.
  - Вопрос В-2: нужны ли блоки на правовых страницах вообще (галерея под Impressum странна)? Рекомендация — общий набор блоков на всех текстовых страницах, кроме правовых.
- **Р-6. Заготовки при «＋ Neue Seite»:** «Leer», «FAQ», «Öffnungszeiten & Anfahrt», «Zahlungsarten». Это префилл текста, а не новые типы (как макеты Squarespace).

## 3. Все возможные варианты для текстового редактора

Обозначения:
- ✅ уже есть (M21.10);
- 🟢 рекомендую;
- 🟡 по желанию;
- 🔴 не советую (с причиной).

Граница безопасности — серверный белый список. Любая новая функция = новые теги и классы в `richtext.PAGE_RULES` + замок.

## 7. Риски
- **Удаление Impressum или Datenschutz** ведёт к Abmahnung. Поэтому жёсткая защита без кнопки, а не просто подтверждение.
- **«Только владелец» и Steuerberater или агентство:** без возможности выдать право люди передают пароль. Это довод за В-1 (а).
- **Плоский список прячет обязательность.** Компенсируют метка «Art» и статус «⚠ fehlt».

## 10. Фидбэк владельца после P5 (2026-11-11) — решения и исполнение
Решения: фото «тянуть за угол» · у каждой страницы свои блоки · короткие адреса · кадрирование.
- **Лишние блоки в «Seitenaufbau»** — превью читало черновик Студии из сессии; теперь
  `?preview=1&stand=saved` (сохранённое), тег `page_blocks` читает общий `page_settings.raw_config`.
- **Свои блоки у каждой страницы:** хосты `info` (Über uns) · `versand` · `seite:<slug>` (только
  существующей страницы; при смене адреса блоки переезжают, при удалении — убираются,
