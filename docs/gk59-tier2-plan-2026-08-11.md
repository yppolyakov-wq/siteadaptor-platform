## GK-9 — соцссылки с иконками в футере (⚠️ миграция `tenants/0029`, аддитивная)

Решение по прецеденту LS-1 (`ls1-video-beratung-plan §`): «обычный контакт бизнеса
живёт колонкой Tenant, НЕ site_config» → 5 колонок `instagram/facebook/linkedin/
tiktok/youtube` CharField(120, blank), «handle или URL» (идиома
`events.Teacher.instagram_url`). Хелпер `Tenant.social_links()` → [(key, url,
label)]; форма BusinessSettingsForm (+help_texts, W0: все поля в DOM) в фиелдсете
контактов settings.html; НОВЫЙ партиал `storefront/_social_icons.html` — inline
mono-SVG (self-hosted, GDPR-safe; спрайта на витрине нет — пути инлайном), слот
в футере между часами и правовой строкой, `target="_blank" rel="noopener"`
(замок frame_escape не матчит внешние, но идиома футера); JSON-LD `sameAs` =
website + соцссылки (замок test_seo:93 обновить осознанно). Тест test_socials.py.

## GK-8 — инлайн-блок подписки newsletter (без миграций)

C-блок `newsletter` в REPEATABLE_BLOCKS (валиден на главной И страницах): данные
{title, text, button_label} все опциональны, `{}` → на публике пусто/placeholder
в превью — но РЕНДЕР формы не зависит от данных (заголовок дефолтный msgid);
партиал `_block_newsletter.html`: форма POST → `{% url 'storefront-newsletter' %}`
(роут безусловный, DOI-флоу серверный; honeypot `website`, email required,
privacy-примечание как на /newsletter/). Осознанное ограничение v1: сабмит
уводит на /newsletter/ (PRG/`next` в signup-вьюхе нет — отдельный скоуп).
Редактор: 3 инпута + visual-гейт + collect()-поля + variantThumb (✉️+кнопка) +
block_types. Тесты по образцу test_stats_block.

## GK-5 — usp-столпы с описанием (без миграций)

`clean_usp` += optional `text` presence-minimal (≤200; golden целы — паттерн
_text_style); textarea → 3-part «icon | label | text» (`split("|", 2)`;
2-part строки round-trip байт-в-байт — замок test_usp_bar:30 цел); стиль
`pillars` в SECTION_STYLES["usp_bar"] + label + .po; ветка в _usp_bar.html
(грид 3 колонки, крупная иконка + h3 + абзац; прочие ветки рендерят только
label — классы-замки целы). Демо: catering-кит получает тексты столпов +
section_styles={"usp_bar": "pillars"} (витрина «3 столпа философии» из
референса). Известный краевой случай: легаси-label с «|» внутри теперь
режется на 3 части — реально в демо/конфиге таких нет (double-pipe не
встречается), фиксируем в тесте поведение 3-части.

## GK-6 — testimonials: рейтинг + фото + аватар-ряд trust (без миграций)

НЕ трогаем общие `_clean_pairs`/`pairs_to_text` (их делят faq/process):
отдельный `clean_testimonials` — {name, text} + presence-minimal `stars`
(int 1..5, кламп как events) и `photo` (URL-строка, как team.photo);
textarea 4-part «Name | Text | Sterne | Foto-URL» (прецедент —
events.details._records, форма events.forms:98); сериализатор
`testimonials_to_text`. Рендер: звёзды через НОВЫЙ фильтр siteui `stars`
(конфиг не раздуваем — golden целы), аватар/инициал-фолбэк (паттерн
_team.html) во всех 5 стилях. Trust: аватар-ряд перекрывающихся кружков из
testimonials[].photo (фолбэк — инициалы), рядом с рейтингом; классы
литеральные (прецедента -space-x нет — проверить в собранном CSS, при
отсутствии npm run build:css). Демо: catering/friseur testimonials
дополняются stars+photo (словари i18n не трогаются — фото/цифры не текст).
Тесты: test_testimonials_media.py + осознанная проверка классов-замков
test_cblocks:359-397.
