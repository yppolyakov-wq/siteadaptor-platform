# ERP-5..7: возврат поставщику · маржа Работы · производственный акт (план)

Дата: 2026-08-21. Отмашка владельца «Делай» на остаток гэп-анализа
(`erp-gap-analysis-2026-08-21.md §2`, строки ERP-5..7). Разведка — 3 агента
(закупки / сметы / склад), факты сверены с кодом.

Инварианты всей тройки: счётчик двигается ТОЛЬКО существующими путями
(`apply_manual_movement` / `receive_lot`), движение и счётчик в одной atomic
(D1/UD3-2), партии следуют за остатком (FEFO-зеркало), деньги — только через
`ExpenseEntry`/снимки. `reconciliation_rows` (счётчик ↔ леджер) обязан
оставаться чистым после каждой операции — это встроенный тест корректности.

## ERP-5 — Rücksendung an Lieferant (возврат поставщику)

Сегодня: приёмка есть (`receive_po_line`), обратного пути нет — ни движения,
ни сторно расхода (подтверждено grep'ом). Откат статуса PO ничего не
компенсирует.

- **Модель (⚠️ миграция `inventory/0005`, аддитивная):**
  `BestellPosition.qty_returned` (PositiveInt, default 0) + property
  `qty_returnable = qty_received − qty_returned`; `StockMovement.KINDS +=
  ("return_supplier", "Rücksendung Lieferant")` и `("production",
  "Produktion")` — ОБА новых kind одной choices-миграцией (прецедент 0004).
- **Сервис `return_po_line(position, *, qty, actor, note, location)`**
  (рядом с `receive_po_line`, та же atomic-схема): take = min(qty,
  qty_returnable), ≤0 → 0; `apply_manual_movement(kind=KIND_RETURN_SUPPLIER,
  delta=−take, source="purchase", note="Rücksendung <BE-код>")` — счётчик
  клампится в ≥0, фактический объём = |mv.delta| (нехватка остатка → честно
  вернётся меньше, предупреждение); `consume_fefo` при партиях в той же
  atomic; `qty_returned += actual`.
- **Деньги — сторно-запись** `ExpenseEntry` с ОТРИЦАТЕЛЬНОЙ суммой
  (Gutschrift): `get_or_create(source=SOURCE_PURCHASE,
  source_ref=f"{position.pk}:ret:{qty_returned}", amount=−unit_cost×actual,
  category=goods, supplier=po.supplier, note="Rücksendung <BE-код>")` —
  зеркало идемпотентности приёмки (`<pk>:<накопленный qty>`); суммы
  Ausgaben/Ergebnis уменьшаются сложением, удалять записи приёмки не надо
  (жёсткое удаление = паттерн туров, здесь НЕ подходит: частичные приёмки
  уже разнесены по своим записям). Модель отрицательную сумму допускает
  (валидатор только в UI-вводе ручной формы).
- **Кабинет:** action `return_line` в `views_purchasing._handle_post`;
  в таблице строк PO (status ordered|received, qty_returnable > 0) —
  инлайн-форма «↩ Rücksendung» (qty, локация при >1); колонка приёмки
  показывает «↩ N» при qty_returned > 0.
- **НЕ делаем (v1):** отдельный документ RS-* (движение+сторно+счётчик на
  строке PO достаточны — история видна в леджере и Ausgaben), возврат ДО
  приёмки (нечего возвращать), Skonto.

## ERP-6 — часы × ставка на строке сметы → плановая маржа Работы

Сегодня: ставки/себестоимости часа нет нигде; `JobLine.qty` уже Decimal
(«3,5 Std»); EK есть только у товаров. Выручку Job журнал не пишет
(invoice-флоу) — Ergebnis НЕ трогаем, маржа живёт на карточке заявки.

- **Модель (⚠️ миграция `jobs/0015`, аддитивная):** `JobLine.cost_rate`
  (Decimal 8,2, null) — ПЛАНОВАЯ себестоимость за единицу строки: для
  работ = внутренняя ставка €/Std., для Teile — авто-снимок EK детали.
- **Приёмник `_save_lines`:** читает `line_cost_{i}` (DE-запятая, как цена);
  пусто + выбран Part → снимок `cost_value` детали (философия снимков
  ERP-1: смета помнит EK на момент составления); пусто без Part → None.
- **Карточка Job (только кабинет!):** блок «Kalkulation (intern)» —
  Plan-Kosten = Σ(qty × cost_rate по строкам с известной ставкой),
  Plan-Marge = netto − Plan-Kosten (+%), пометка «ohne …» если часть строк
  без ставки. В ПУБЛИЧНУЮ смету и PDF cost_rate НЕ попадает (проверить
  оба рендера — они идут по своим полям, замок).
- **Форма строк:** узкий инпут «EK» в expert-строке за существующей
  механикой строк (12 строк, скрытые пустые); JS-пересчёт не трогаем
  (Summe считает продажу).
- **НЕ делаем (v1):** учёт фактического времени, RevenueEntry.SOURCE_JOB
  (выручка Job через счёт — отдельное решение), ставка в Sofort-Angebot
  (OfferLine qty целое, композер из чата — не место калькуляции).

## ERP-7 — Produktion buchen (акт производства v1)

Сегодня: BOM/рецепта нет; ближайший прецедент «списать состав одной
операцией» — `jobs.commit_stock`; отчёты (Warenwert/Bestellvorschlag)
стоят на СЧЁТЧИКЕ; расход при производстве НЕ пишется (мука уже оплачена
закупкой — иначе двойной учёт).

- **Без новой модели:** документ = общий код `PR-XXXXXX` (генератор —
  паттерн BE-кода) в `note` всех движений акта; kind="production" (обе
  стороны, знак дельты различает), source="production", source_ref=""
  (ручная семантика, как приёмка формой). История — существующий
  drill-down `?history=` и CSV.
- **Сервис `produce(*, output, output_variant, qty, inputs, actor, mhd,
  lot_code, set_cost)`** в `apps/inventory/services.py`: одна atomic;
  сырьё — `apply_manual_movement(delta=−qty_i)` + `consume_fefo`; нехватка
  (|mv.delta| < qty_i или None) → `ProductionError` → откат ВСЕГО акта
  (fail-closed, частичного производства нет); готовое — `receive_lot`
  (при включённых партиях; MHD хлеба!) либо `apply_manual_movement(+qty)`.
  Локации v1 не участвуют (всё на основном складе) — объявленное
  ограничение.
- **EK готового:** unit_cost = Σ(qty_i × EK сырья) / qty, пишется в
  `cost_price` готового при чекбоксе «EK aus Zutaten berechnen» (default
  on) и только если EK всех строк сырья известен — иначе Warenwert молча
  терял бы готовое (`stock_value=None` → continue). Средневзвешенного с
  существующим остатком v1 нет (объявлено).
- **Кабинет:** секция «🏭 Produktion buchen» на `/dashboard/stock/` —
  выход (пикер entities + qty + MHD/Charge при lots_on) + до 4 строк
  сырья (пикер + qty) + чекбокс EK; action `production` в `_handle_post`
  (до резолва entity — у акта своя пара полей).
- **НЕ делаем (v1):** сохранённые рецепты на товаре, Produktionsauftrag
  со статусами, локации, полуфабрикаты в несколько переделов.

## Порядок и гейты

ERP-5 → ERP-6 → ERP-7, по коммиту на шаг; обе новые kind-choices — в
`inventory/0005` (первый коммит). Локальные гейты каждого шага: ruff
check+format ЦЕЛИКОМ, pytest затронутых модулей (--create-db на шаге с
миграцией), msgfmt --check-format всех локалей + polib-дуп-чек (урок
ERP-волны), i18n_gap, template_comments при правке шаблонов, app.css при
новых Tailwind-классах. Пуш стопкой → зелёный CI → FF в main.

Тест-замки: сервисы (движение+счётчик+FEFO+деньги, идемпотентность,
клампы, откат акта при нехватке), reconciliation чист после каждой
операции, cost_rate не течёт в публичную смету/PDF, view-POSTы.
