# T-8.11 «Товары, услуги и предприятия в каталоге города» (2026-10-10)

Пункт 9 этапа 3 `t8-roadmap-2026-10-10.md`; фаза 2 ТЗ «Siteadaptor 2.0» (`tz-siteadaptor-2-0-
phase0-2026-10-10.md`). Правило попадания — В3 (предложение владельцу): все активные позиции
бизнеса, согласившегося на каталог, если карточка годится к показу; владелец исключает
категорию или позицию.

## 0. Факты (разведка 2026-10-10)

- Пул города = `AggregatorListing`, видов 4 (promotion/stay/event/menu); ключ
  `(tenant_schema, listing_kind, source_ref)`; все чтения — `objects.public()`.
- Образец синка — меню (`_menu_snapshot`/`sync_menu_listing` + хуки post_save/post_delete в
  `aggregator/apps.py` + блок в `reconcile_schema`).
- `Product`: soft-delete, `images`, `base_price`, `list_price` (UVP), `stock_quantity` (NULL =
  без учёта), `primary_action="request"` = «auf Anfrage», `badge="neu"`, `diets`, относительный
  `get_absolute_url()`. `Service`: без slug, деталь `/leistung/<uuid>/`, `price_cents`,
  `pricing_mode`, `image`. Категории города товара — `catalog/city.py::resolve` (T-8.13b).

## 1. Решение

**Новые виды листинга** `product`, `service`, `business` (⚠️ `aggregator/0022`: choices +
поле `availability` — "" | `sold_out` | `on_request`; бейдж «Neu» — из `badge` товара или
«создан ≤ 14 дней»: поле `is_new`).

**Исключение владельцем** (⚠️ `catalog/0036`, `booking/0028`): `Product.hide_in_city`,
`Category.hide_in_city` (действует на всю ветку дерева), `Service.hide_in_city`. В кабинете:
галочка «Nicht im Stadtkatalog zeigen» в формах товара/услуги/категории и колонка-переключатель
в блоке «Zuordnung zum Stadtkatalog».

**Годность к показу:** товар — активен, не удалён, есть фото и цена > 0 (вариант: цена «ab»
минимальной), не скрыт сам и не скрыт веткой категории. Услуга — активна, модуль `booking`
включён, не скрыта; без фото — логотип бизнеса, без цены — «Preis auf Anfrage». Предприятие —
одна карточка на бизнес (название, описание, логотип/обложка, ссылка на главную сайта).

**Категория города:** товар — `city.resolve(категория)` → иначе подсказка по типу бизнеса;
признаки — диеты товара. Услуга и предприятие — подсказка по типу бизнеса.

**Синк:** снимки в схеме тенанта, `update_or_create` по ключу, удаление при негодности или
`_withheld`; хуки post_save/post_delete Product/ProductVariant/Service (on_commit + dedupe),
предприятие — при реконсиляции (её же зовут смена согласия/подтверждение почты/сопоставление
категорий). `reconcile_schema` получает три новых блока с чисткой «сирот».

**Показ:** бейджи вида на карточке (🛍 Produkt · 🛠 Leistung · 🏪 Unternehmen), «Neu»,
«Auf Bestellung», «Ausverkauft», цена «ab …» у вариантов. Главная портала по умолчанию остаётся
лентой предложений (акции/номера/события/меню) — иначе 200 товаров одного магазина вытеснят
акции; виды переключаются чипами «Angebote · Produkte · Dienstleistungen · Unternehmen»
(`?kind=`). Полная главная «Entdecke Solingen» с блоками — T-8.19. Поиск `/entdecken/` ищет
по всем видам. Карточка ведёт на сайт бизнеса (`?ch=portal`), корзина/оплата — у бизнеса.

## 2. Замки (до правок)

- товар с фото и ценой → листинг product с абсолютной ссылкой, категорией по сопоставлению,
  UVP как старой ценой; без фото / без цены / неактивный / удалённый / скрытый / скрытая
  категория-предок → листинга нет;
- `primary_action=request` → `availability=on_request`; учёт склада и 0 → `sold_out`;
  без учёта склада → "";
- услуга: модуль выключен → нет; без цены → цена пусто;
- предприятие: одна карточка, ссылка на главную; бизнес не в каталоге → ни одного листинга
  новых видов;
- реконсиляция удаляет «сирот» трёх видов; хуки сохранения ставят синк;
- портал: по умолчанию товары не в ленте, `?kind=product` — только они; чипы видов только
  непустые; `/entdecken/?q=` находит товар.
