# FB-32 — «Seitenaufbau»: одни блоки на всех страницах (план, 2026-11-17)

Фидбэк владельца от 2026-11-17 (скриншоты «Главная», «Корзина», «Startseite › Kategorien»).
Принцип владельца: **основная единица структуры страницы — блок**. Настройки типового блока
(акция, баннер, продукт, категории, страница…) одинаковы на всех типах страниц; особый тип
страницы (товары в категории) лишь добавляет свою группу (фильтр, сортировка). Всё содержимое
страниц разбито на блоки.

Продолжение FB-31 (`docs/fb31-block-strategy-2026-11-15.md`: §3 «cart», §4 `cart_upsell`).

## Ответы на вопросы владельца (по коду)
- **Полоса доверия (`usp_bar`).** Содержимое (пункты «иконка | заголовок | текст») сейчас правится
  только в Студии одним текстовым полем (`templates/tenant/_section_fields.html`), вид — там же.
  В «Seitenaufbau» у блока только ширина. → **S2**.
- **Приветственный баннер.** В панели можно выбрать баннеры из библиотеки и менять их порядок.
  Создать новый или загрузить фото, не уходя со страницы, нельзя: ссылка «Neuer Banner» есть только
  при пустой библиотеке и после создания уводит в список баннеров. → **S3**.
- **Слайдер или один баннер.** Отдельного переключателя нет. Два и больше выбранных баннера —
  слайдер, один — обычный показ выбранным видом (`templates/storefront/sections/_hero.html`).
  Чтобы показать один баннер, лишние снимают крестиком. → **S3**: явный переключатель
  «Ein Banner / Slider».
- **Вид блока категорий на главной пропал.** Поле вида плиток (square/tall/wide/compact) убрали из
  панели коммитом `1a21263c` (`list_panel.py`, строка с `f["name"] != "style"`). Осталось только
  в Студии обычным списком. → **S1**.

  для «Aktuelle Angebote», «Produkte», «Kategorien» (и прочих секций с `SECTION_STYLES`).
  Миниатюры видов — новые.
- **S2 «Полоса доверия» в панели** — пункты (до 6) с выбором иконки кнопками, вид — общим
  выбором S1; писатель — тот же `clean_usp`.
- **S3 баннер в панели** — «+ Neuer Banner» (создание с `next=` обратно в «Seitenaufbau», новый

- **S5 один реестр настроек блока** — «тип блока → оси (Welche · Wie · Breite) + миниатюры»,

  «Kategorien»: главная и каталог на одном наборе значений вида (сейчас `SECTION_STYLES` против
  `CATALOG_PART_STYLES`/`CATEGORY_VIEW_CHOICES`). Перенос сохранённых значений — шагом
  `deploy.sh` по образцу FB-31.7.
- **S6 остальные страницы** — пройти типы страниц: всё содержимое — строки-блоки (как детали
  и корзина).

## План S4 и S5 (planner, 2026-11-17)
**S4 — корзина блоками.** Хост `cart` с одним разделом `upsell` (узкий реестр
`PAGE_SECTIONS = {"cart": ("upsell",)}` рядом с `detail_parts`); видимость — тот же ключ
`cart_show_upsell` (второго хранения нет), позиция — якорь в `page_blocks["cart"]`
(пишется, только когда свой блок стоит выше). Настройки на строке: `SETTING_ROWS["cart"] =
{"cart_upsell": "upsell"}`, новый `cart_upsell_layout` как у «Ähnliche» (Wie · Spalten ·
Höchstens ≤ 12); без значения — прежние 4 товара в 4 колонки. `cart.html` рисует поток
«блоки → полоса → блоки» (`detail_parts.flow`), без якоря разметка прежняя. Тайл «Passt dazu»
из Студии убрать (как P6). Замки до кода: golden корзины (пустая, со своими блоками и без,
превью), «без якоря — байт-в-байт».

**S5 — один реестр, «Kategorien».** 9 видов: square, tall, wide, compact + regale, tabs, index,
side, wegweiser; `auto` → «Standard». Модуль `apps/core/block_settings.py`: тип блока → оси и
виды с миниатюрами и хостами, где вид доступен; `SECTION_STYLES["categories"]` и виды
каталога выводятся из него. Один построитель панели для главной и каталога; каталог
добавляет группу «Diese Seite». На главной `tabs` и `side` недоступны с причиной («nur auf
Katalogseiten»). Перенос значений — шагом `deploy.sh` после прогона FB-31.7 на сервере.

Вопросы владельцу (рекомендации): tabs/side на главной — недоступны с причиной (да);
`auto` = `square` байт-в-байт — слить, иначе «Standard» десятым (да); перенос S5 после
FB-31.7, реестр и панель — сразу (да); «Passt dazu» — до 12 и вид как у «Ähnliche» (да);
тайл «Passt dazu» из Студии убрать (да).

## S5b — «Regale», «Index», «Wegweiser» на главной (planner, 2026-11-18)
Данные этих видов считает корень каталога (`apps/promotions/public_views.py`: полки ~1785,
Wegweiser ~1713/2216, `side_entries` ~2229; `apps/catalog/wegweiser.py`). Порядок:
1. **Замки до кода:** golden секции «Kategorien» главной (`""`, square, tall, wide, compact) и
   число запросов главной при виде `""`; новые виды не трогают БД, пока не выбраны.
2. **Общий построитель** `apps/catalog/category_views.py` (`entries`, `departments`, `shelves`
   без N+1: дети одним prefetch, товары одним оконным запросом ≤ 8 на полку, `total` одним
   агрегатом, `attach_promos` разом); каталог переходит на него с паритетом
   (`test_composition_parity`) и замком числа запросов.
3. **Реестры:** `SECTION_STYLES["categories"]` + regale/index/wegweiser; `LIST_STYLES` —
   прежние 4 явным кортежем (блок «Liste» — отдельным шагом); `block_views` — `home` у трёх.
4. **Секция:** ветки в `sections/_categories.html` по `style`; данные — только при выбранном
   виде; пусто → прежняя сетка; `heading_id` у `_wegweiser_departments.html` (дубль id);
   «Im Fokus»/guides на главную не переносим; полок на главной не больше 6.
5. **Панель:** для трёх видов скрыть «Spalten»/вывод, «Höchstens» — число направлений.
ECC: django-reviewer, database-reviewer (оконный запрос, замки запросов), silent-failure-hunter
(fail-safe), a11y-architect (id, фокус), Playwright 1440/390 de/ru (слайдер полок).
- **S5b ✅ (код)** (2026-11-18): построитель `apps/catalog/category_views.py` (полки — дети одним
  prefetch, промо-цены одним проходом; `entries`; `departments`), каталог перешёл на него

## S6 — остальные страницы строками (planner, 2026-11-18)
