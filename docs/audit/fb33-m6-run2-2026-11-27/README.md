## 2. Что нашёл только второй прогон (выборка главного)
- Полный `save()` формы объекта перетирает поле структуры (ловушка 6) → охрана `save`.
- «Version wiederherstellen» Студии и `_pin_own_categories` заново создают хосты объектов (ловушки 5, 20).
- Потолки `normalize` молча режут хосты и блоки (60 → 30) на пути копии.
- Превью общего типа берёт первый объект — если у него своя структура, превью врёт.
- Сохранение акции/номера/события шлёт пересинхронизацию портала — перенос через `.save()` дал бы шторм задач.
- Раздел, появившийся в общей структуре после копии (LMIV, нескрываемые): правила нет.
- a11y: с JS первая правка идёт в модальном окне с инертным фоном — объявление A2 в области схемы не прозвучит; в окне блока не сказано, для какой страницы правка; список потерь не включает правленые тексты скопированных блоков.
- Страница объекта по прямому коду при одном `website.view` раскрывает имя и тексты; право объекта нужно на КАЖДОЙ операции (матрица op × вид).

## 3. Что нашёл только первый прогон
- NFC и управляющие символы в ключе группы; `follow_group_rename` и его блокировки.
- Имя 🔒 «Reihenfolge fest», рамки `#6b7280`, страница сброса без JS (`<title>`, крошки, `h1`).
- Отпечаток общей в черновике A2 (устаревшая копия при правке общей до «Speichern»).
- Процессные кэши между схемами в команде (во втором — тоже, совпало).

## 4. Где прогоны совпали
Один писатель; копия сохраняет `id` блоков общей; A2 через одну функцию с переносом; старые данные не
удалять до стопки 20; права `website.edit` + право объекта, акция и группа — `marketing.edit`; Студия
отклоняет хосты объектов; запись без пользователя — отказ; номера миграций; сброс кэша за писателем.
