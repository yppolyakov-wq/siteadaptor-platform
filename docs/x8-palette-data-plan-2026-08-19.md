# X8 — Ctrl+K по ДАННЫМ (последняя волна программы «Кабинет-X»)

Дата: 2026-08-19. Волна X8 плана `docs/cabinet-cleanup-plan-2026-08-19.md` §6.A8
(решение владельца №6: «ДА, волной X8, последней»). Без миграций.

## 1. Зачем

Сценарий №1 микро-владельца — «найти заказ фрау Мюллер», а не «открыть раздел».
Палитра Ctrl+K (W8) сегодня ищет ТОЛЬКО по названиям разделов и настроек; данные
ищутся по трём разным экранам (список заказов, Sortiment, контакты) — при этом
поиск по каждому из них уже есть (X6-2 закрыл последний пробел).

## 2. Что делаем

**Эндпоинт** `/dashboard/palette-search/?q=` (`login_required`, кабинет-гейт
middleware; тенантная схема изолирует данные по построению):

| Секция | Источник | Гейт |
|---|---|---|
| Сделки | `transactions._managed_queryset(kind, q=…)` по видимым kind (`sales_page.visible_kinds`) | модуль kind |
| Клиенты | `crm.Customer` (имя/e-mail/телефон) | модуль `crm` |
| Предложения | `sellable_manage.sellable_manage_sections_for(q=…)` | модуль kind |

Лимит 5 на секцию, общий кап 20; ответ — JSON `{"sections": [{label, items:
[{label, sub, url}]}]}`. Никаких новых способов ЧТЕНИЯ данных не вводим —
переиспользуем ровно те функции, что уже гейтят и фильтруют (X6-2/X2c).

**Клиент:** палитра `_nav_palette.html` — секция «Gefunden» НАД пунктами меню,
запрос debounce 250 мс от 2 символов, отмена предыдущего запроса (AbortController),
fail-safe: сеть упала → остаётся прежний навигационный поиск.

## 3. Замки

- аноним → 302 (не 200 с данными) и не-член тенанта → 403 (класс дефектов X0);
- выключенный модуль не отдаёт свою секцию (гейты) — по одному тесту на kind;
- лимиты соблюдаются; пустой `q` (<2 символов) → пустой ответ без запросов в БД;
- палитра остаётся рабочей без JS-ответа (навигационная часть — серверная).

## 4. Готовность после X6/X2c

Поисковые функции уже есть и покрыты замками: `_managed_queryset(..., q=)`
(X6-2), `sellable_manage_sections_for(q=)` (X6-2), CRM-поиск `?q=` (ST-5c).
X8 — тонкий слой поверх них.
