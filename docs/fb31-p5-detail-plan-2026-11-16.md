# FB-31 P5 — детальные страницы из блоков (разделы — строки схемы)

образцы — P3/P4. Разведка — `planner` (ECC). Кода нет.

## 0. Сегодня
- `site_config["<kind>_detail"] = {hidden, order (только события), layout}` (`normalize_detail_sections`,
  реестр `apps/core/detail_sections.py`); у товара/услуги/номера порядок задан шаблоном.
- Объект: `page_override = {hidden, shown, layout, blocks_first}` (`object_structure.py`), свои
  блоки `page_blocks["<kind>:<hex>"]` — одним куском до/после общих.
- Свои блоки НИКОГДА не стоят между разделами: `{% page_blocks "<kind>_detail" %}` — один хвост.
- Студия пишет порядок/видимость (`ed_order_*`, `*_visible_*`); кабинет — только строка «Seite»
  (`*_detail_layout`, `product_related`, `cart_upsell`); разделы в кабинете не правятся.
- Тур — без раскладки (нет в `LAYOUT_KINDS`).

## 1. Цель
- Строки разделов — позиции на хостах `<kind>_detail` и `<kind>:<hex>` (`{"key": "<раздел>"}`
  без id); видимость и раскладка остаются в прежних ключах (один писатель на факт).
- «Kauf» — закреплённая строка там, где страница её рисует (товар/услуга/номер — первой;
  событие/тур — форма записи после разделов).
- Разделы первого экрана (описание/сведения товара, описание/удобства номера в Standard) —
  внутри области покупки: скрыть можно, двигать нельзя.
- Чтение без миграции; каноническая форма не хранится → сайт байт-в-байт, пока владелец не
  двинул. Два пути рендера: прежняя разметка и новый поток `_detail_flow.html`.

## 2. Срезы
R0 эталоны (до кода) · R1 `apps/core/detail_parts.py` · R2 хранение · R3 витрина (поток) ·

## 3. Риски
Байт-в-байт (перенос разделов товара в партиалы, обёртки `data-ed-section`, гейты «пусто»,
превью); две зоны (первый экран / тело); старые писатели Студии; ширина блоков между разделами;
смена вида туров у тех, у кого задана раскладка событий; у объектов видимость и порядок в двух
местах, потолок 120 хостов.

## 4. Вопросы владельцу (рекомендация)
1. Разделы — в любом порядке, «Kauf» закреплён на своём месте. [Да]
2. Описание/сведения товара (и описание/удобства номера) в Standard остаются в области покупки:
   скрыть — да, двигать — нет; в Tabs/Breit — в теле. [Да]
3. Блоки между разделами — ширины текста; после последнего раздела — как сейчас. [Да]
4. В Tabs блоки между разделами рисуются под вкладками, с подсказкой в панели. [Да]
5. «Wie» — только у «Ähnliche» товара; у «Ähnliche Zimmer» и «Passt dazu» услуги — показ. [Да]
6. Своя схема объекта: порядок «nur hier» и блоки между разделами (R8, нужен макет). [Да]
7. Тур берёт общую раскладку «Veranstaltungsseite» (после подсчёта затронутых бизнесов). [Да]
8. Студия правит порядок/видимость до P6 через синхронизацию. [Да]
