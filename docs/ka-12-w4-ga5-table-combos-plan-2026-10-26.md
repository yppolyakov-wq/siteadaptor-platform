# KA-12 GA-5 · Объединение столов «Tisch 3+4» (2026-10-26, ⚠️ `booking/0042`)

Продолжение `ka-12-w4-gastro-plan-2026-10-26.md` (решение Р-3: объединение — в v1).

## 1. Модель
Комбинация — обычный ресурс-стол с M2M `Resource.parts` (self, несимметричная, `related_name
="combinations"`). Свои места (по умолчанию — сумма частей), своё правило онлайн, свой порядок —
поэтому автоподбор GA-4 берёт её сам, когда ни один одиночный стол не подходит (сортировка по местам).
Один уровень: часть не бывает комбинацией, комбинация — частью. Только столы «1 бронь = 1 стол»
(`capacity == 1`, не пул) — у пула мест и ресурса на N броней область = он сам (поведение прежнее).

## 2. Область занятости — одна точка `apps/booking/occupancy.py`
- `scope_ids(r)` = r ∪ части r ∪ все комбинации, где есть r или его часть.
- Пересечения: `services.overlapping` и слоты `availability.free_slots_with_spots` фильтруют
  `resource_id__in=scope_ids(...)` — отсюда берут book/book_many/move/самоперенос/create_manual/
  resync_occupancy.
- Блокировки: `lock_scope(*resources)` — `select_for_update` всей области одним запросом в
  порядке pk (book, move, самоперенос, resync_occupancy). Без этого брони «стол 3» и «3+4» прошли
  бы проверку одновременно; разный порядок дал бы встречный дедлок.
- Писатель состава — `occupancy.set_parts` (валидация + места по умолчанию); экран ресурсов,
  action `resource_parts`.

## 3. Замки
part ↔ combo взаимно блокируют (book и слоты), две комбинации с общим столом, перенос в занятую
область, автоподбор: одиночный стол раньше комбинации, неверные составы, пул = сам; текстовый замок
«проверки занятости с active_statuses идут не по `resource=resource`».
