# HF-6: несколько периодов в одной брони (план, 2026-07-31)

Пункт 3 фидбэка владельца: «на сайте нельзя выбрать сразу несколько периодов по
часам». Уточнение владельца («первое»): речь именно о том, что **гость выбирает
несколько периодов в ОДНОЙ брони** — например две смежные пары часов или два
визита подряд, — а не о том, чтобы владелец продавал абонемент.

Самый рискованный пункт волны: трогает anti-double-book, письма и отмену.
Поэтому — отдельным планом, ДО кода.

## 1. Что есть сейчас
- `/termin/leistung/<pk>/` — пикер: день → один старт → POST `start` → одна
  `Booking` (`apps/booking/public_views.py::service_book`).
- Гонку закрывает `services.book` (атомарная проверка пересечений), витринная
  сетка `availability.service_slots` — лишь подсказка.
- `Booking` — плоская запись: `resource`, `start`, `end`, `reference_code`
  (`T-XXXXXX`), FSM `BookingSM`, письма по `reference_code`.

## 2. Развилка хранения (решение: A)
**A. N записей `Booking` + общий код группы.** Каждый период — своя `Booking`
(как сейчас), плюс поле `group_code` (индексируемое, пустое = одиночная бронь).
Anti-oversell, календарь кабинета, перенос, FSM — работают БЕЗ изменений, потому
что сущность «занятый интервал» остаётся прежней.

**B. Одна `Booking` со списком интервалов в JSON.** Отвергнуто: ломает всё, что
считает занятость по `start`/`end` (сетка слотов, Belegung, перенос, отчёты) —
это переписывание движка ради формы ввода.

## 3. Инкременты
- **HF-6a (миграция `booking/00XX`, аддитив):** `Booking.group_code`
  (`CharField(max_length=12, blank=True, db_index=True)`) — общий код на все
  периоды одной брони. Пусто = сегодняшнее поведение байт-в-байт.
- **HF-6b (сервис):** `services.book_many(service, starts, …)` — в ОДНОЙ
  транзакции создаёт N броней с общим `group_code`; при занятости любого из
  периодов откатывает всё (гость не получает половину брони). Переиспользует
  `services.book` (не дублирует anti-oversell).
- **HF-6c (витрина):** мультивыбор на странице услуги — чекбоксы стартов вместо
  радио, счётчик «выбрано N · итого X €», кап (напр. 6 периодов). Цена — сумма
  `pricing.price_cents_for` по датам каждого периода (HF-5 уже даёт резолвер).
- **HF-6d (подтверждение/письма/кабинет):** страница `/t/<code>/` показывает все
  периоды группы; письмо — списком; в кабинете карточка брони показывает
  «часть группы» и отмена предлагает отменить всю группу.

## 4. Замки (пишем ДО кода каждого инкремента)
- Паритет: одиночный выбор даёт РОВНО прежний результат (одна бронь, `group_code`
  пуст) — иначе мы сломали обычный сценарий ради редкого.
- Атомарность: если второй период занят — не создаётся НИ ОДНОЙ брони.
- Ёмкость: два гостя одновременно выбирают пересекающиеся наборы → выигрывает
  один, второй получает честный отказ (тот же путь, что сейчас).
- Цена: сумма по датам с учётом сезонных цен услуги (HF-5).

## 5. Что НЕ делаем в v1
- Не объединяем смежные периоды в один интервал (две пары часов подряд остаются
  двумя записями — так календарь владельца честнее).
- Не переносим группу целиком одним действием (перенос — по одному периоду).
- Мультивыбор ДАТ для номеров (stays) не трогаем: там своя воронка.
