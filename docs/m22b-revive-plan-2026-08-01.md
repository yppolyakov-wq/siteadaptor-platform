# План: оживление M22b — «печатает» и «бизнес на связи» в чате (2026-08-01)

Аудит июня нашёл единственную реально потерянную работу: два коммита от 25.06 на
`claude/m20-retreat-pages` (`628f13b1`, `29e02155`) так и не долетели до `main`.
Проверено адверсариально: `thread_typing`, `inbox_typing`, `open_status` в
`apps/inbox` и `templates/storefront/message_thread.html` отсутствуют — фича не
переизобреталась. Владелец: «давай отдельным инкрементом и проверим».

## 1. Что переносим

**«Бизнес на связи»** (`628f13b1`): в публичном треде — статус по часам работы
(`tenant.open_status()`), серверный рендер, без поллинга.

**«Печатает»** (`29e02155`): флаг в кэше с TTL 6 секунд, без БД и без миграций.
Клиент пингует `…/nachricht/<token>/typing/`, владелец — `…/inbox/<pk>/typing/`;
противоположная сторона забирает флаг своим существующим поллингом (`thread_poll`
отдаёт `typing: bool`).

Третий коммит ветки (`4c27921f`) — запись в roadmap «SSE отложен»; переносим
отдельной строкой, если её там ещё нет.

## 2. Почему не cherry-pick

Пробный мерж даёт ~7 конфликтных мест: с 25.06 `apps/inbox` вырос на +868 строк
(LS-3 композер оффера, LS-6 «прямая линия», FSM-переходы), `config/urls_tenant.py`
— на +208. Конфликты пришлись бы на соседние строки, а не на смысл. Кода в
переносе всего ~60 строк без тестов, поэтому **применяем вручную по диффу** —
чище и позволяет вписать в текущий код, а не в код пятинедельной давности.

## 3. Точки врезки (текущий main)

| Файл | Что добавляем |
|---|---|
| `apps/inbox/public_views.py` | `TYPING_TTL`, `_typing_key`, `open_status` в контекст `thread`, `typing` в ответ `thread_poll`, вьюха `thread_typing` |
| `apps/inbox/views.py` | `typing` в ответ кабинетного `thread_poll`, вьюха `thread_typing` |
| `apps/inbox/urls.py` | маршрут `<uuid:pk>/typing/` |
| `config/urls_tenant.py` | маршрут `nachricht/<uuid:token>/typing/` |
| `templates/storefront/message_thread.html` | плашка статуса + «печатает» + пинг на `input` |
| `templates/inbox/thread.html` | то же со стороны кабинета |

Импорт `_typing_key`/`TYPING_TTL` в `views.py` из `public_views` в оригинале был
локальным (внутри функций) — переносим **на уровень модуля**: циклического
импорта нет (`public_views` не импортирует `views`), а локальный импорт в
горячем поллинге — лишняя работа на каждый запрос.

## 4. Чего НЕ делаем

* Не трогаем сам механизм поллинга и его интервалы — фича встраивается в
  существующий ответ, новых запросов на чтение не появляется (пинг «печатает»
  шлётся только пока пользователь реально печатает, с троттлингом).
* Не заводим модель/миграцию: состояние живёт в кэше и обязано теряться.
* SSE не делаем — остаётся отложенным (та самая запись из `4c27921f`).

## 5. Риски и как снимаем

* **Утечка приватности:** флаг «печатает» доступен только внутри треда, который и
  так гейтится `public_token` / логином владельца. Ключ кэша содержит pk треда —
  чужой тред не прочитать, не зная его.
* **Redis-префикс между тенантами:** ключ `inbox_typing:<conv_pk>:<role>`, где
  `conv_pk` — UUID, поэтому коллизий между схемами нет по построению.
* **Гейт модуля:** обе вьюхи проходят `_require_inbox` / `login_required`, как
  соседние.
* **Кэш недоступен** (Redis лёг): `cache.get` вернёт None → «печатает» просто не
  показывается; тред работает. Проверить, что исключение не всплывает.

## 6. Проверка

1. `pytest apps/inbox` — переносим и оригинальные тесты (`test_inbox`,
   `test_public`), они и есть замок.
2. Новый замок: `thread_poll` без активности возвращает `typing: false`; после
   пинга — `true`; через TTL — снова `false`.
3. Стенд: два окна (витринный тред + кабинет), проверить обе стороны вживую.
4. Гейты батча: `ruff check .` + `ruff format --check .` целиком,
   `test_template_comments`, `i18n_gap`, `npm run build:css` при новых классах.

Миграций нет.
