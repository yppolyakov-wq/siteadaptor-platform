# DL-20 — шаблоны страницы категории товаров и страницы группы акций

**Запрос владельца (2026-09-03):** «Посмотри ещё макеты категорий товара и категорий
акций. Нужны так же макеты 5 шт и такая же механика выбора шаблона и наследования
если нужно через общие настройки.»

Канвас на согласование — **«Kategorie-Vorlagen»** (11 артбордов), исходники
`docs/design/kategorie-vorlagen-2026-09-03/` (правки — в `_generate.py`).

---

## 1. Что показала разведка (2 агента, факты с путями)

### 1.1 Страница категории товаров

* Рендерит **не** `apps/catalog/views.py` (та вьюха мертва с SR-1 и делает 302), а
  `apps/promotions/public_views.py:843 product_list(request, slug=None)` — одна вьюха
  на `/sortiment/` и `/sortiment/<slug>/`.
* Реестр стилей уже есть: `apps/catalog/category_styles.py` —
  `CATEGORY_PAGE_STYLES` (3-кортежи) + `VALID_PAGE_STYLES` + резолвер `page_style(category)`.
  Сейчас **шесть** записей: `"" | kopfbild | sets | preisliste | regale | tabs`.
* Хранение — `Category.page_style` (`CharField(max_length=20)`, **без `choices`** — реестр
  растёт без миграций; choices наполняет форма `apps/catalog/forms.py:59`).
* **Общего дефолта нет.** Шаблон задаётся только поштучно: владелец обязан выставить его
  в каждой категории вручную. Это и есть «наследование», которого просит владелец.
* Ветвление сегодня — `{% if category_page_style == ... %}` внутри
  `templates/storefront/products.html` (365 строк, уже 4 точки ветвления).

### 1.2 Страница группы акций

* **Модели категории акций нет.** Группа — плоское `Promotion.group`
  (`CharField(max_length=50)`, свободный текст) + `group_i18n` (переводится только метка,
  ключ фасета остаётся базовым).
* **Страницы группы фактически нет.** Единственный вход — `/aktionen/?gruppe=<group>`;
  при активном фильтре `has_filters=True` → секции глушатся → **плоская сетка** под общим
  H1 «Aktuelle Angebote». Названия группы на странице не видно, «Endet bald» и Vorschau
  выключены (`apps/promotions/public_views.py:553`, `:565`).
* Существующие оси вывода акций: `promo_layout` (`("slider",)`), `promo_grouping`
  (`("time",)`) — обе top-level presence-minimal; `SECTION_STYLES["promotions"]`
  (spotlight/rows/banner) — **только секция главной**, на `/aktionen/` не применяется.

### 1.3 Механика DL-19, которую надо повторить

`apps/core/card_forms.py`: реестр (единственный источник значений) + резолвер
`card_form(entity, site_default, kind)` — «своё бьёт дефолт сайта, мусор → прежний вид».
Плитки с мини-макетом — `templates/tenant/_cardform_picker.html` (+ `_cardform_thumb.html`),
значение держит hidden-инпут прежнего имени, `change` кормит живой черновик билдера.

## 2. Решения этапа

| # | Развилка | Решение | Почему |
|---|---|---|---|
| Р-1 | 5 шаблонов — вместо существующих или сверх? | **Сверх.** Standard/Kopfbild/Sets/Preisliste/Regale/Tabs остаются | сносить рабочие стили = регрессия у живых тенантов; новые пять с ними не пересекаются (проверено при выборе композиций) |
| Р-2 | Где хранить общий дефолт | `site_defaults["category_page_style"]` и `["promo_group_style"]` | `site_defaults` presence-minimal (`siteconfig.normalize_site_defaults:1255`) → **golden-эталоны целы**, миграции не нужны |
| Р-3 | Где хранить выбор для ОДНОЙ группы акций (модели нет) | `site_config["promo_groups"] = {<группа>: <стиль>}`, presence-minimal | завести модель группы = миграция + перенос свободного текста; ключ по имени группы совпадает с ключом фасета `?gruppe=` |
| Р-4 | Заголовок группы на странице | Делаем **всегда**, не только под новые шаблоны | это не украшение, а починка: сегодня посетитель по ссылке из меню попадает на страницу без имени того, что он открыл |
| Р-5 | Куда ветвить рендер | Отдельные партиалы `templates/storefront/category/_*.html` и `promo_group/_*.html` | прецедент `cards/` (DL-19); `products.html` уже 365 строк с 4 ветками — пятая пачка `{% if %}` его добьёт |
| Р-6 | Новые top-level ключи siteconfig | Только `promo_groups` (presence-minimal) | golden-снапшоты падают на любом безусловном ключе; presence-minimal их не трогает |

**Инвариант волны:** пустое значение в обоих слоях = **прежняя разметка байт-в-байт**
(замки `test_listing_parity`, `test_promotions_parity`, `test_dl16_*`).

## 5. Замки, которые писать ДО кода

1. `page_style("")` и `promo_group_style("")` → разметка страницы **байт-в-байт** прежняя
   (характеризационный снапшот до правок).
2. Приоритет: значение у категории/группы бьёт `site_defaults`; мусор в любом слое → `""`.
3. presence-minimal: `normalize` не материализует ни `category_page_style`, ни
   `promo_group_style`, ни `promo_groups` при пустых значениях → golden целы.
4. Каждый ключ реестра рендерится без ошибки на пустой категории/группе (нет товаров,
   нет фото, одна акция) — класс «шаблон разваливается на реальных данных».
5. `?ansicht=liste` продолжает глушить секции на `/aktionen/` при любом шаблоне группы.
6. Внутри `data-listing-root` — никаких инлайн-скриптов с прямым биндингом
   (замок `test_density_view`, урок Ф1/HF).

## 6. Известные риски

* **Дублирование смыслов.** `Regale` (полки по подкатегориям) и `Magazin`; `?ansicht=liste`
  и «список условий». Урок DL-9: шаблон, который повторяет уже существующий контрол, — это
  пятый переключатель с тем же результатом. Проверка при рендере: у каждой пары шаблонов
  должен отличаться **набор или порядок блоков**, а не только классы.
* **Mosaik на слабых фото** выглядит хуже ровной сетки — подпись в кабинете это называет.
* **`Navigator` на мобильном** обязан схлопываться в существующую кнопку «Фильтры», а не
  рисовать вторую колонку.
* **Имя группы как ключ** (`promo_groups`): переименование группы в форме акции осиротит
  запись. Решение: при чтении неизвестный ключ игнорируется (fail-safe → общий дефолт),
  чистка — при сохранении панели.
