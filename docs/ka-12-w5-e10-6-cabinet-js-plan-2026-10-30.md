**E10.6 (инлайн-JS → файл) — делаем.** Страница кабинета 175 КБ (27,7 КБ gzip), из них инлайн-JS
35 КБ (10,4 КБ gzip); хромовые скрипты, одинаковые на каждой странице, ≈ 26 КБ (≈ 7–8 КБ gzip)
отдаются заново при КАЖДОМ переходе. Вынос в кэшируемый файл снимает ~¼ трафика навигации.

## Что делаем
- `static/js/cabinet.js` — ОДИН файл из хромовых скриптов `tenant/_base_dashboard.html`
  (бейдж непрочитанных, сайдбар/меню-диалог, палитра Ctrl+K и т.д.) и партиалов
  `core/_confirm_tap`, `core/_danger_confirm` (только скрипт — `<dialog>` с переводами остаётся
  в партиале), `core/_sheet_js`, `core/_photo_shrink`, `core/_list_kb`.
- Подключение — `<script src="{% static 'js/cabinet.js' %}">` на ТОМ ЖЕ месте (конец body), без
  `defer`: порядок исполнения прежний (страничные скрипты, рассчитывающие на хром, не ломаются).
  Имя файла хэшируется ManifestStaticFilesStorage → кэш навсегда, обновление — новым именем.
- Остаются инлайн: строка `sb-min` в начале body (без мигания свёрнутого сайдбара), тост
  триала (условный, 6 строк), `tenant/_tg_shim.html` (в нём `{% trans %}`).
- Шаблонных тегов в переносимом JS нет (проверено скриптом) — перенос без data-атрибутов.

## Замки
- Замки, читавшие JS из `_base_dashboard.html`/партиалов (a11y хрома, таб-бар, карточки, телефон,
  фото, таблицы), читают `static/js/cabinet.js`; проверка подключения — `{% static 'js/cabinet.js' %}`

- Новый: в базе кабинета нет инлайн-скрипта длиннее N строк, кроме разрешённых (`sb-min`, тост).
