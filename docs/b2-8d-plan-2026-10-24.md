# KA-12 B2-8d — Mindest-Ist заявок + авто-Anzahlungsrechnung B2B + письмо о сторно

Дата: 2026-10-24. Основа: `docs/b2-8-advance-invoices-plan-2026-10-24.md` §2/§5, B2-8a/b/c в коде.
Действующие решения владельца: Q-1 (билет — v2), Q-2 (автосторно), Q-3, Q-5. Флаг 8d-2/8d-3 —
`ADVANCE_INVOICES_ENABLED`; 8d-1 без флага (налоговый срез, не документ). Миграций нет.

## 0. Факты (сверено с кодом)
- Фолио `DealPayment` ведётся только для order/booking/stay/ticket (`core/folio.py FOLIO_KINDS`);
  деньги заявки читаются через `prepaid_cents`. Все читатели денег гейтятся `FOLIO_KINDS`
  (`money_contract._folio_totals`, deal_card, bank prefetch, `refunds.refund_partial`); без гейта —
  только `folio.mark_refunded` и `refunds._refund_other_card_rows` (фильтруют по сделке).
  `DealPayment.deal_kind` — свободная строка: вид `"job"` пишется без миграции.
- Пути оплаты заявки: вебхук `jobs/payments.mark_deposit_paid` (ставит `payment_state` напрямую) и
  всё остальное через `money_contract._settle_payment` (кнопка, банк, оплата Anzahlungsrechnung
  `deposit_only`, оплата итогового счёта неоплаченной заявки). Уже `paid` → `_settle_payment` выходит.
- Выручка заявки в журнале — при выставлении счёта: `source="job"`, `source_ref="inv:<pk>:<ставка>"`,
  дата = `issued_at`. Срез `ustva.py` эти записи к заявке не привязывает (`_deal_ref` их не знает).
- Авто-счёт B2B уже есть: `finance/auto_invoice.on_confirmed` (CO-2d) — образец для 8d-2.
  Письмо со счётом и PDF — `finance/services._send_invoice_email` (дедуп, троттлинг, `sent_at`).
  Письма о сторно нет нигде.

## 1. Решение: A′ — датированные строки `DealPayment(deal_kind="job")`, `FOLIO_KINDS` не трогаем
| | A: `FOLIO_KINDS += job` | B: `Invoice.paid_at` | **A′** |
|---|---|---|---|
| Охват | все пути | только с Anzahlungsrechnung | все пути |
| Деньги заявки | меняются (большой радиус) | не меняются | **не меняются** |
| Возвраты | `refund_partial` откроется | без даты | `mark_refunded("job", intent)` ставит `refunded_at` |
| Миграция | нет | да | **нет** |
Риск A′: кто-то добавит `job` в `FOLIO_KINDS` и деньги молча переключатся на книгу → охранный замок T6.

## 2. Инкременты
### 8d-1 — даты платежей заявки и Mindest-Ist
- `folio.DATED_KINDS = FOLIO_KINDS + ("job",)` — виды с датами для УСт, деньги по ним не читаются.
- `folio.record_job_payment(job, amount_cents, purpose, method, source, intent="")`: под блокировкой
  заявки; без строки `opening` (легаси не получает сегодняшнюю дату); повтор intent → прежняя
  строка; кламп `amount ≤ payable − Σ(amount − refunded)`; Gutschein не считается деньгами.
- Запись ДО смены `payment_state`: `mark_deposit_paid` (deposit/full, stripe, intent) и ветка
  `job` в `_settle_payment` (deposit_only → deposit, иначе payable_gross, `full`).
- 8d-1b: оплата итогового счёта заявки с уже пришедшим депозитом — строка `balance` на
  `open_amount`, только если у заявки уже есть датированные строки (иначе легаси).
- `ustva`: `_rows_with_events_in` по `DATED_KINDS`; `_job_ref_map` (inv-pk → Invoice.deal_id → Job);
  `_journal_of` ветка заявки; `_job_advance_note` — только для заявок без датированных строк.
Замки T1–T8 (`test_b2_8d_job_mindest_ist.py`): Soll депозит/счёт по месяцам, вебхук без дубля,
оплата Anzahlungsrechnung снимает пометку, Ist депозит+остаток, возврат по месяцу возврата,
**T6 охранный** (деньги заявки и `FOLIO_KINDS` прежние), легаси без строки, Gutschein не в сумме.

### 8d-2 — авто-Anzahlungsrechnung юрлицу с письмом и PDF
- `advance.auto_for_confirmed(kind, deal)` по образцу `auto_invoice.on_confirmed` (on_commit →
  реальный тенант → atomic → блокировка): флаг, kind ∈ KINDS, покупатель = фирма, депозит > 0,
  способ ≠ invoice, статус активен. Ошибки → warning, подтверждение не откатывается.
- Вызов рядом с `on_confirmed` (stays/booking SM и services, status_effects) + `jobs` при accepted.
- Письмо: обобщённый `_send_invoice_email(template=, dedupe_prefix=)`, шаблоны
  `advance_invoice_issued*`, вариант «уже оплачено» (Q-6 — да, документ нужен для Vorsteuerabzug).
Замки A1–A6.

### 8d-3 — письмо о сторно отправленной Anzahlungsrechnung
- `InvoiceSM` cancelled, `kind=advance`, `sent_at` → on_commit письмо «nicht mehr zahlen» + PDF
  Stornorechnung; дедуп; покрывает оба пути автосторно. Не отправленный документ — без письма.
Замки S1–S4.
