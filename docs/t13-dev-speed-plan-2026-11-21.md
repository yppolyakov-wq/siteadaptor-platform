### T-13.1 — `scripts/preflight.sh`: один финальный гейт перед пушем
Читает `git diff --name-only origin/main...HEAD` (+ незакоммиченное) и гоняет:
1. `ruff check .` и `ruff format --check .` (целиком, с exclude миграций);
2. при `*.html` в diff — `test_template_comments.py` и `scripts/i18n_quickcheck.py`;
3. при `templates/**` или `static/src/**` — `npm run build:css` и проверка, что
   `static/css/app.css` не изменился (иначе — «закоммить»);
4. pytest по затронутым приложениям `--reuse-db` (`--create-db`, если в diff есть
   `migrations/`); `apps/core/sellable.py` → добавить `apps/tenants`; `apps/core/**` → добавить
   `apps/tenants`; всегда `--ignore=apps/billing/tests/test_tasks.py`; без `-x`;
5. `test_claude_md_budget.py` при правке `CLAUDE.md`.
Вывод — короткая сводка «шаг ✓/✗». Замок: тест на таблицу «путь → набор проверок» (чистая
функция выбора вынесена в `scripts/preflight_plan.py`, её и тестируем).
CLAUDE.md §5: абзац «Финальный гейт» сжимается до «`bash scripts/preflight.sh`» (минус ~1 КБ).

### T-13.7 — скиллы, которые учатся: петля обратной связи
Скилл сам себя не меняет — меняем его мы, но по правилу и по данным, а не по настроению.
1. **Журнал находок** `docs/skill-feedback.md` (таблица, одна строка на находку): дата · шаг ·
   кто нашёл (агент ревью / CI / стенд / владелец) · класс · какой скилл был загружен ·
   **покрывал ли скилл это** (нет правила / правило было, не сработало / правило неверное).
   Строка пишется в том же коммите, что и правка по находке — как сейчас грабля в `pitfalls.md`.
2. **Правило правки в том же коммите:** «нет правила» → строка в скилл; «правило неверное» →
   исправить; «было, не сработало» → не дописывать текст, а превратить в замок или хук
   (текст, который не помог один раз, не поможет и во второй).
3. **Ретро раз в стопку** (шаг `sa-increment`, 5 минут): сколько находок на шаг, какие классы
   повторились, какие правила скиллов ни разу не понадобились за 5 стопок → удалить.
   Скилл обязан оставаться ≤ 200 строк: новое правило вытесняет наименее полезное.
4. **Счётчик пользы** в самом скилле: у каждой граблы — дата последнего срабатывания
   (`· посл. 2026-11-21`). Без срабатываний 2 месяца → кандидат на удаление или уже замок.
5. **Проверка описаний:** раз в месяц — список шагов, где скилл по теме НЕ был загружен
   (по журналу); если такое есть — править `description` скилла (по нему он и выбирается).
6. **Замок** `test_project_skills.py` дополняется: размер ≤ 200 строк, пути существуют,
   в журнале нет строк без заполненной колонки «покрывал ли».
Мерило то же: находок ревью на шаг и красных CI на стопку — колонка в ретро, тренд виден
через 3–4 стопки.

- Скилл устаревает и начинает врать → замок на существование упомянутых путей + правило:
  новая единая точка пишется в скилл в том же коммите, что и в `project-memory.md`.
- Скиллы дублируют память → в скилле только «что звать и чего не делать», история и
  обоснования остаются в `project-memory.md`/`pitfalls.md` ссылкой.
- preflight медленный → pytest только по затронутым приложениям; флаг `--fast` (без pytest).
- Бюджет CLAUDE.md 45 КБ (сейчас 32 КБ) — T-13 его уменьшает, не увеличивает.
