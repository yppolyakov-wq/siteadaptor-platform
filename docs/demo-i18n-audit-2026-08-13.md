# Аудит переводов демо-сайтов + доперевод (2026-08-13)

Запрос владельца: «анализ демо-сайтов и процент перевода на основные языки; параллельно
идёт разработка — не помешать деплою; после анализа выполнить перевод».

Языки демо-витрин: база **de** + **en / ru / uk / tr** (`demo_i18n.DEMO_LOCALES`,
`DemoKit.enabled_locales` по умолчанию все пять).

## 1. Как измерялось

Демо-контент переводится НЕ через gettext, а двумя обходами из `apps/tenants/demo_i18n.py`:

* `overlay_config` — тексты `site_config` → `cfg["i18n"][loc]` (накладывается `siteconfig.localize`);
* `translate_tenant_content` — модельные поля (`*_i18n` / full-JSON) после сидинга.

Источник переводов — словари `apps/tenants/demo_i18n_<loc>.json` (`{немецкая строка: перевод}`),
поиск по ТОЧНОМУ совпадению строки. Отсюда три независимых класса дефектов:

| класс | симптом | чем лечится |
|---|---|---|
| **A. нет записи в словаре** | строка немецкая на всех локалях | добавить перевод |
| **B. нет пути перевода** | запись в словаре не помогает — обход строку не берёт | доработка обхода/модели |
| **C. перевод не доезжает** | перевод в БД есть, шаблон печатает базовое поле | правка шаблона |

Инструмент измерения — **`scripts/demo_i18n_gap.py`** (создан этим аудитом):
`uv run python scripts/demo_i18n_gap.py [--missing ru]`. Он раскладывает немецкие строки
всех 15 китов на ROUTED (путь есть) / GAP (пути нет) / не требует перевода (имена
собственные, коды размеров) и печатает покрытие по китам и группам контента.

## 3. Что сделано

### 3.1 Переводы (класс A)

294 строки батчем 1 + 35 строк батчем 2 (ставшие переводимыми после правок пайплайна),
на 4 локали = **~1150 новых записей** в `demo_i18n_{en,ru,uk,tr}.json`.

Правила, по которым переводили: цены/проценты/единицы переносятся как есть (en — десятичная
точка, ru/uk/tr — запятая); имена людей, названия заведений и брендов не переводятся;
интернациональные термины (Espresso, Aperol Spritz, Bio-Box) НЕ добавляются в словарь вовсе —
замок `test_demo_i18n_maps_have_no_identity_entries` запрещает identity-записи.

Валидация при слиянии (`scratchpad/merge_translations.py`): ключ обязан существовать во входе
байт-в-байт, перевод непустой и ≠ оригинала, деньги и проценты сохранены, существующие записи
не перезаписываются. Побочно устранён дубль ключа `"Hochzeits-Catering"` в `demo_i18n_uk.json`.

### 3.2 Пайплайн (класс B) — БЕЗ миграций

* `_TRANSLATABLE_CONFIG_KEYS` += `anfrage` (виды мероприятия формы заявки) и `before_after`.
* C-блоки главной (`sections`) и страниц (`page_blocks`) — новый точечный обход
  `_tr_cblock_data` / `_tr_blocks` / `_tr_page_blocks`: переводятся ТОЛЬКО текстовые поля
  данных (`title/body/caption/label/button_label`, `rows[].label|value`, `items[].*`),
  служебные токены (ключ блока, стиль, выравнивание) не трогаются.
  **Важно:** оверлей мерджится ПОЗИЦИОННО, а витрина рендерит нормализованный конфиг
  (`normalize_sections` дедупит фикс-секции и дописывает недостающие в конец) — поэтому
  индексы и значения берутся из НОРМАЛИЗОВАННОЙ формы, иначе перевод сел бы на чужой блок.
* `Category.description` — описание направления (лендинг `/bereich/<slug>/`, DS-7a): поле
  полноценно i18n, но обход его не брал → добавлено в `translate_tenant_content`.
* `templatetags/siteui.py::page_blocks` читал блоки из голого `normalize()` — теперь из
  локализованного конфига (без этого перевод C-блоков страниц не доехал бы даже с оверлеем).
* Новый тег `siteui::anfrage_event_choices` → пары `(value, подпись)`: **value остаётся
  немецким** (вьюха `/anfrage/` валидирует его fail-closed и пишет в `Job.event_type` —
  запись бизнеса живёт на базовом языке, как снимок заказа в I18N-10), переводится только показ.

### 3.3 Рендер (класс C) — переводы лежали мёртвым грузом

`Combo` переводился обоими обходами, но **все** его поверхности печатали плоские немецкие поля.
Исправлено на `*_localized` (аксессоры уже существовали):

`combos.html`, `combo_detail.html`, тизер в `products.html`, `_buybox_service_form.html`
(имя услуги под локализованным H1), `sections/detail/_stay_similar.html`,
`stay_confirmation/stay_cancel/stay_checkin`, `booking_confirmation`, `passes`,
`event_confirmation/event_cancel`.

### 3.4 Замки

`apps/tenants/tests/test_demo_i18n_pipeline.py` (6 тестов): оверлей C-блоков переводит только
текст и садится на правильный блок ПОСЛЕ normalize; page_blocks получают оверлей по хосту;
виды мероприятия переводятся в показе, а база (DE) остаётся ключом; описание категории
переводится.

|---|---|---|
| en | 77.8 % | **96.2 %** |

Все 15 китов ≥ 86 % на каждом языке; 11 из 15 — 100 % на ru/uk/tr.
Остаток (en 51, tr 26, ru 2, uk 3 строки) — это ровно то, что переводить нельзя:
`Espresso`, `Tiramisu`, `Aperol Spritz`, `S/M/L/XL`, `150 g`, названия заведений
(`Bella Vista`, `Backhaus Krume`). В словарь они не пишутся принципиально — замок
`test_demo_i18n_maps_have_no_identity_entries` запрещает identity-записи.

Проверка качества (автоматическая, `scratchpad/qa_translations.py`): 1048 новых записей,
0 проблем по эвристикам — нет пустых и identity, в ru/uk есть кириллица, немецкие служебные
слова не протекли, длина в норме, кавычки/скобки парные, ни одна украинская строка не
является копией русской.

## 5. Проверка на стенде

Локальный стенд (`seed_demo_tenants --kit catering --recreate`, dev-БД, Django test client),
страницы `/`, `/anfrage/`, `/ueber-uns/`, `/galerie/`, `/aktionen/`, `/bereich/<slug>/` на ru:

* доля кириллицы в видимом тексте 74–85 % (остальное — название заведения, город, адрес,
  имена, названия блюд и переключатель языка — так и должно быть);
* подписи полосы цифр (C-блок `stats`), hero, описания направлений — переведены;
* `<option value="Hochzeit">Свадьба</option>` — value немецкий, подпись русская.

Детектор «немецких остатков» (латинские слова из DE-версии, дожившие до ru) на главной
даёт 13 слов, и все, кроме `seit` (исправлено) и `Umgebung/deutschlandweit`
(`Tenant.service_area_note`, см. §6) — имена собственные.

⚠️ Локально `.mo` не компилируются (нет gettext) — до `polib`-компиляции стенд показывает
немецкий ХРОМ и это ложная тревога, а не дефект перевода.

## 6. Что осталось — требует решения владельца

**Класс B, нужны МИГРАЦИИ** (поля `*_i18n` у моделей, которых их не имеют). Не делалось
намеренно: параллельно идёт разработка, а новые миграции — главный источник конфликтов на
деплое. ~287 уникальных строк:

| контент | строк | модель |
|---|---|---|
| лендинг ретрита (`Event.details`) + program/questions | ~110 | `events.Event` (JSON без i18n) |
| отзывы демо (`BusinessReview`, `reviews.Review`) | 77 | по проектному правилу тексты отзывов не переводились |
| демо-заявки/сметы кабинета (`Job`, `JobLine`) | 46 | `jobs.Job` |
| блог | 21 | `events.BlogPost` |
| лояльность (`Stempelkarte`, «1 Gratis-Pizza») | 18 | `loyalty.LoyaltyProgram` |
| часы работы текстом | 14 | `Tenant.opening_hours_text` |
| ведущие/мастера/ресурсы | 21 | `events.Teacher`, `booking.Resource` |
| Extras, ваучеры, абонементы, группы комбо | 17 | `core.Extra`, `loyalty.Voucher`, `booking.PassPlan`, `catalog.ComboGroup` |

**Прочее, найденное попутно (не трогал):**

* **de.po**: 137 английских msgid без немецкого перевода, из них ~36 — реальная проза UI
  («Extras (optional)», «Details (optional)»), причём 32 из них переведены в ru/tr/uk. То есть
  на НЕМЕЦКОЙ витрине местами английский. Правится точечно в `locale/de/LC_MESSAGES/django.po`.
* **SEO-мета** (`apps/core/seo_meta.py` DEFAULTS) — немецкие литералы без gettext: `<title>`
  и `description` всех страниц демо остаются немецкими на любой локали.
* **`/branchen/*`** — 224 строки маркетинговой копии в осознанном allowlist гейта
  `scripts/i18n_gap.py`; перевод — отдельное решение (рекомендация: начать с en).
* `label_i18n` узлов меню обрезается normalize до `de/en` (`siteconfig.py`) — явные переводы
  подписей для ru/uk/tr сохранить нельзя; сейчас не мешает (работают gettext-якоря).

## 7. Ops

Изменения **без миграций**. Чтобы переводы появились на живых демо, после деплоя:

```
./scripts/deploy.sh single
python manage.py seed_demo_tenants --recreate    # или --kit <ключ> --recreate
```

Без пересева демо-тенанты сохранят прежние (немецкие) оверлеи: перевод накладывается на
этапе сидинга, а не на рендере.
