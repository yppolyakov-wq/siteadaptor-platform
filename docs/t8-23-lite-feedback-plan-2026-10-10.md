# T-8.23 «Лёгкий кабинет по фидбэку владельца» — разбор и предложения (2026-10-10)

Вход: проверка владельцем быстрого магазина `koernerstrasse-64` (скриншот /aktionen/ в Studio) +
3 разведки по коду. Сделано сразу (баги): дубль «Maus» (полоса «Endet bald» повторяла весь
список) и ожидание создания (перезагрузка каждые 3 с → тихий опрос + выход по таймауту).
Остальное — на обсуждение, кода нет.

## 1. Факты

- **«Nur Aktionen» меняет только витрину.** Кабинет профиль не читает: лёгкий магазин получает
  полный кабинет своего типа — ~45 пунктов меню, главная = доска заказов (у булочной — пустые
  «Bestellungen», хотя корзины на витрине нет), акций на главной нет.
- **Адрес/телефон/часы** при быстром старте не спрашиваются; вводятся только в «Einstellungen →
  Mein Geschäft» (форма на 21 поле). Карточка «So finden Sie uns» без адреса и телефона не
  показывается вовсе — отклик «Nur zeigen» у свежего магазина пустой. Экран «Fertig» об этом
  не говорит; чек-лист считает шаги «Firma/Kontakt» выполненными (мастер помечен пройденным).
- **Баг:** у типа «hotel» модуль акций выключен пресетом → после быстрого старта 404 на
  `/promotions/…`. Исправить в первом же инкременте.
- **Товар → акция.** Ассистент акции всегда создаёт свободную акцию без товара. Вход «% Aktion» с
  карточки товара есть (W11-4), но ведёт в полную форму (4 вкладки, ~28 полей). Модель уже
  умеет: у акции с товаром старая цена и фото берутся из товара.
- **Список акций на телефоне** — таблица `min-w-[640px]` со скроллом вбок + настройки витрины
  (раскладка, форма карточки) прямо в фильтре.
- **Merkmale** — один общий список из 14 на все разделы (у «Mode» предлагаются «vegan», «yoga»);
  на портале чипы признаков считаются по всему пулу, а не по выбранному разделу.
- **Портал** — карточка ведёт сразу на сайт бизнеса; страницы предложения внутри портала нет.
  Всё нужное для неё уже лежит в снимке листинга (название, описание, фото, цены, срок, район,
  координаты, бизнес); полное описание есть только у акций (у прочих видов — 300 символов).

## 2. Предложения

**А. Лёгкий кабинет = 4 экрана** (гейт — тот же профиль «Nur Aktionen», новых моделей нет):
Aktionen · Produkte · Geschäft · Teilen. Главная кабинета = список акций с большой «＋»;
нижнее меню на телефоне — эти же 4 пункта. Список акций на телефоне — карточками (фото, цена,
«bis …», счётчики, «Teilen / ↻ / Bearbeiten»); «Bearbeiten» открывает тот же короткий ассистент,
полная форма остаётся ссылкой «Alle Felder». Всё остальное — за «Funktion hinzufügen» (переход на
ступень 1–2), а не в меню. Модули при быстром старте: только акции + каталог (+ фикс отеля).

**Б. «Geschäft»** — короткая форма на телефон: адрес, телефон, WhatsApp, часы работы (7 строк).
Адрес и телефон — по желанию сразу на втором экране «Aktion in 3 Klicks». На «Fertig» и в списке
акций, пока адреса нет: «Damit Kunden Sie finden: Adresse & Öffnungszeiten ergänzen →».

**В. Товар — основа акции.** «Produkte» — быстрая форма: название, цена, артикул, категория
(с «＋ neue Kategorie»), фото. У каждого товара «% Aktion» → короткий ассистент с привязкой к
товару (цена «statt» и фото подставляются). В самом ассистенте шаг 1: «Für welches Produkt?» —
выбор из своих или «＋ Neues Produkt» (создаётся тут же). Свободная акция без товара остаётся
возможной («Sonstiges/Dienstleistung»), но по умолчанию — от товара. В каталог города товар
попадает сам (T-8.11), акция ссылается на него — данные не дублируются.

**Г. Merkmale по разделу.** К справочнику добавить `TAGS_BY_SECTION` (какие признаки уместны в
каком разделе, при необходимости — уточнение по категории); в форме при выборе категории
показываются только её признаки, сервер отбрасывает чужие; на портале чипы признаков считаются
внутри выбранного раздела. Хранимые слаги не меняются — миграций нет. Списки признаков по
разделам — на согласование (черновик в §3).

**Д. Предложение внутри портала.** Страница `/<город>/angebot/<id>/` на портале, собранная из
снимка листинга (без копирования данных): большое фото, описание, цена/старая цена, срок,
бизнес + район + мини-карта + часы «открыто сейчас», кнопки «Zum Angebot beim Geschäft»
(сайт бизнеса, `?ch=portal`) и «Alle Angebote von …», «← Zurück» с сохранением фильтров.
Карточки портала ведут сюда, а не наружу. SEO: canonical — на страницу бизнеса (портал не
конкурирует с сайтом владельца). Для витрины бизнеса в обратную сторону — ссылка «← Zurück zum
Stadtportal», когда посетитель пришёл с `?ch=portal`. Позже — несколько фото и полное описание
у товаров/услуг (сейчас 300 символов).

## 5. Ответы владельца (2026-10-11) и стратегия «товар — основа акции»

Ответы: Q1 — связан с Q2; **Q2 — акция всегда от товара**; **Q3 — адрес и телефон
спрашиваются при «Aktion in 3 Klicks», обязательно**; **Q4 — черновик признаков принят**;
**Q5 — отдельная страница** (вопрос о нагрузке — §5.4).

### 5.1 Факт из кода, на котором строится решение

Резерв по акции (`promotions.services.reserve`) списывает **только счётчик акции**
`Promotion.available_quantity` (conditional UPDATE, без перепродажи), возвращает его при отмене/
просрочке и **не создаёт заказ и не трогает склад товара**. Склад товара включается сам по себе:
`Product.stock_quantity = NULL` значит «учёт не ведётся». То есть «товар без склада + штуки в
акции» — уже рабочая комбинация, ничего не ломая.

### 5.2 Стратегия: один и тот же товар, разная глубина по ступеням

- **Ступень 0 (лёгкий портал).** Товар — это **карточка**, а не складская позиция: название,
  цена, артикул (необязательно), категория, фото. Остатки по умолчанию **не ведутся**.
  Акция всегда от товара; количество живёт **в акции** («Wie viele Stück?», пусто = без
  ограничения) — это и есть привязка к наличию, которой не было у конкурентов: «noch 3 Stück»,
  автоматически «ausverkauft», автоснятие из каталога города.
  Отклики: **Zurücklegen** (резерв на движке выше, без заказа), **Coupon**, **Nur zeigen**.
  «Kaufen» (корзина/оплата) на ступени 0 не показывается.
- **Ступень 3 (Verkaufen) — тот же товар, без переноса данных.** Владелец включает «Lagerbestand
  führen» → у товара появляется остаток; резерв по акции тогда ограничен меньшим из «штук в
  акции» и «на складе», а выдача резерва («Ausgegeben») пишет складское движение. Включает
  модуль заказов → у той же акции становится доступен «Kaufen». Категории, характеристики,
  варианты — уже есть в полной форме товара, в лёгкой просто скрыты («Mehr Felder»).
- **«Nur zeigen»** остаётся, но тоже от товара: информативная акция с ценой, сроком и
  карточкой «So finden Sie uns» (адрес/телефон теперь обязательны — пустой не будет).

### 5.3 Порядок (предложение)

1. **T-8.23a** баг отеля (акции выключены пресетом) + модули быстрого старта = акции+каталог.
2. **T-8.23b** адрес и телефон обязательными на втором экране «Aktion in 3 Klicks»; экран
   «Geschäft» (адрес, телефон, WhatsApp, часы); подсказка про часы на «Fertig».
3. **T-8.23d** товар → акция: «Aktion in 3 Klicks» и ассистент создают **товар** (название,
   цена, фото, категория) и акцию на него; «% Aktion» у товара → короткий ассистент; поле
   «Wie viele Stück?» в ассистенте. Существующие свободные акции лёгких магазинов —
   одноразовой командой превращаются в товар + акцию.
4. **T-8.23c** лёгкий кабинет: Aktionen · Produkte · Geschäft · Teilen, главная = акции.
5. **T-8.23e** Merkmale по разделам (черновик Q4).
6. **T-8.23f** мост к складу: резерв учитывает остаток товара, выдача пишет движение — только
   когда у товара включён учёт.
7. **T-8.24** страница предложения в портале.

### 5.4 Нагрузка страницы предложения в портале

Нового хранения нет: страница читает **ту же строку** `AggregatorListing`, которая уже есть для
карточки в ленте (один запрос по первичному ключу), и кэшируется так же, как главная портала.
Дублирования для поисковиков нет: canonical указывает на страницу бизнеса. Нагрузка — одна
выборка по индексу на просмотр (и ноль при попадании в кэш), меньше, чем лента.

- **S2.** При включённом учёте склада резерв ограничен складом, а выдача списывает остаток —

- **S3.** Существующие свободные акции лёгких магазинов превратить в товары автоматически?

### 5.6 Решения владельца (2026-10-11)

- **S1 да** — на ступени 0 остатки выключены, количество — в акции.
- **S2 да** — при включённом учёте склада резерв ограничен складом, выдача списывает остаток.
- **S3 да** — существующие свободные акции лёгких магазинов превращаются в товар + акцию.
- **SEO страницы предложения в портале (T-8.24)** — вопрос владельца «как получать клиентов,
  если основная — страница бизнеса, и как это сочетается с идеей хаба для поисковиков и ИИ».
  Рекомендация **А**: в выдаче хаб входит страницами-списками (раздел × город × район, «heute»,
  «neu») — их нет ни у одного бизнеса; страница одного предложения — промежуточный шаг,
  canonical на страницу бизнеса (тоже наша платформа, с возвратом в портал); ИИ получает данные
  напрямую (Offer JSON-LD, llms.txt, sitemap портала — T-8.8; MCP — T-8.10f), canonical там не
  играет роли. Вариант **Б** — страница в портале основная с добавочным содержимым (похожие
  рядом, район, «сейчас открыто»). Выбор нужен к T-8.24; пересмотр по данным поиска через 2–3
  месяца пилота — одной настройкой.

## 6. T-8.23d «Товар → акция» — проект (2026-10-11)

- **Ассистент** (`promotions/quick.py`, тот же для «Aktion in 3 Klicks»): шаг 1 получает
  «Für welches Produkt?» (свои товары + «＋ Neues Produkt aus diesen Angaben»), а для нового
  товара — «Artikelnummer» и «Kategorie» (свои + «neue Kategorie»), всё необязательно.
  `?product=<pk>` — вход «% Aktion» с карточки товара: товар выбран, заголовок и цена «statt»
  подставлены.
- **Общая функция** `quick.attach_product(form, promo, images)` — и во вьюхе ассистента, и в
  задаче быстрого старта: выбранный товар → `promo.product`, фото ассистента остаются у акции;
  товара нет → создаётся `Product` (название = заголовок, описание, цена = «statt», иначе
  акционная; артикул; категория; фото ассистента переезжают в товар, у акции пусто — фото и
  старая цена берутся у товара, файлы не копируются). Остатки не ведутся (`stock_quantity`
  NULL, решение S1); количество — «Stückzahl» акции (`available_quantity`).
- **Без товара** остаётся только «−N % auf alles» (ни акционной цены, ни «statt»): такую
  акцию товаром не сделать честно.
- **«Wiederholen»** переносит товар; собственные фото акции копируются как раньше.
- **Конвертация (S3):** команда `convert_lite_promotions` (dry-run → `--apply`) по магазинам
  «Nur Aktionen»: свободная акция с ценой → товар + привязка (фото переходят в товар), заодно
  включает модуль акций, если пресет его выключил (T-8.23a). Идемпотентно.

## 7. Свой домен бизнеса и хаб (вопрос владельца 2026-10-11) → T-8.25

Факты из кода: свой домен подключается как ещё один `Domain` (`tenants/domains.py`,
`is_primary=False`); сайт отвечает и на поддомене, и на своём домене — без редиректа и без
canonical на витрине. Ссылки каталога города, писем, QR строятся от поддомена
(`aggregator.tasks._site`, `services.site_url_for`) даже при подключённом домене.

Позиция: свой домен — только адрес; витрина, кабинет, акции, синк в каталог города, письма
и QR остаются нашим сервисом. Хаб держится не на адресе витрины, а на (1) страницах-списках
портала, (2) данных для ИИ (T-8.8/T-8.10f), (3) измеримом трафике, который портал приводит
бизнесу (`?ch=portal`, воронка T-8.6) — это аргумент подписки; деньги платформы — подписка и
продвижение в портале, не трафик чужих доменов.

**T-8.25 «Основной адрес»:** проверенный свой домен становится основным — ссылки портала,
писем, QR и флаеров, canonical витрины и sitemap указывают на него; поддомен 301-редиректит
на него (вход в кабинет остаётся). Взаимная ссылка: в подвале витрины «Auch im Stadtportal
<Stadt>» (у бизнесов в каталоге города) — бизнесу полезно, порталу даёт обратную ссылку.
Вопрос владельцу: поддомен при своём домене — 301 на свой домен (рекомендация: один адрес
для поисковиков) или оставить оба?

**Решение владельца (2026-10-11):** T-8.25 поддержан; при своём домене поддомен **301 на свой
домен**. Ориентир по агрегаторам техники (idealo/Geizhals): у них свои страницы ранжируются,
потому что это СРАВНЕНИЕ одного товара у многих магазинов (цены, история цены, отзывы) — такой
страницы нет ни у одного магазина. У нас тот же принцип: страница одного предложения одного
бизнеса → canonical на бизнес; страницы сравнения/подборки (раздел × район, «где в Золингене
есть X» по GTIN — T-8.11/T-8.20) → наши собственные, основные.
