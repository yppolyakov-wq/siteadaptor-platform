# План: общение с клиентом из сделки + беседы на странице клиента (VF-17/VF-18)

Дата: 2026-08-25. Статус: **черновик на решение владельца** (код не начат).
Запросы владельца (2026-08-25): «Было бы удобно прямо с заказа общаться с клиентом…
через канал на сайте или внешние каналы. Что для этого нужно?» и «Страница клиента
в CRM: кликабельные заказы + блок общения в виде тикетов по каждому заказу; если
был запрос с сайта и потом заказ — хранить в том же чате».

## 1. Что уже есть (разведка 2026-08-25, факты проверены по коду)

- **Треды `inbox.Conversation`** уже несут мягкую ссылку на сделку
  (`ref_kind`/`ref_id`/`ref_label`, ref_id = reference_code) и клиента (FK на общую
  карточку `Customer`; матчинг по e-mail). Канал у треда есть (`web/email/whatsapp`).
- **Витрина уже создаёт** треды с привязкой к сделке: «⚠️ Etwas stimmt nicht?» (LS-6)
  на 6 поверхностях сделок → high-тред с ref; форма контакта.
- **Ответ владельца в треде** уже уходит клиенту e-mail'ом со ссылкой на публичный тред;
  из треда есть «💶 Angebot senden» (LS-3).
- **Внешние каналы**: e-mail (штатно), Telegram клиенту (если он привязал бота —
  событийные пуши есть, свободного сообщения нет), WhatsApp — только wa.me-ссылки
  (клиент пишет бизнесу; писать клиенту через API — external, платный Business API).
- **Чего нет**: владелец НЕ может начать тред сам (роут «нового диалога» отсутствует);
  на карточках сделок нет кнопки «Написать клиенту»; на странице клиента в CRM треды
  видны списком (customer360), но не сгруппированы по сделкам.

## 2. Предложение (3 инкремента, БЕЗ миграций — всё уже в модели)

**C1 — «✉️ Nachricht an den Kunden» на карточках сделок** (order/job/booking/stay):
кнопка в блоке клиента. Если тред с этим `ref_kind+reference_code` уже есть —
открываем его; нет — создаём (`services.start_conversation` + owner-first сообщение
формой на карточке) и шлём клиенту штатное письмо со ссылкой на публичный тред.
Клиент отвечает по ссылке (или из ЛК) — переписка в одном месте, вся история у сделки.
Нужен новый маленький роут «start-thread-for-deal» + гейт inbox-модуля.

**C2 — беседы по сделкам на странице клиента в CRM**: секция «Gespräche» группируется
по `ref_label` (тред без ref — «Allgemein»); каждая строка кликабельна в тред.
Плюс правило «запрос с сайта → заказ»: когда сделка создаётся для клиента, у которого
уже есть ОТКРЫТЫЙ тред-запрос без ref (обычный вопрос с сайта), привязываем свежую
сделку к этому треду (`ref_*`), — история «спросил → купил» остаётся одной беседой.
Привязка только fail-soft и только при однозначности (один открытый тред).

**C3 — внешние каналы из того же треда**: рядом с полем ответа — кнопки
«per Telegram» (если у клиента есть привязка — шлём то же сообщение пушем) и
«per WhatsApp» (wa.me-ссылка с текстом — открывает чат в приложении владельца;
API-отправка = external-backlog). E-mail остаётся дефолтом.

## 3. Решения владельца

1. C1: кнопку ставим на все 4 карточки сделок сразу? (рекомендация — да)

   только вручную кнопкой «привязать к беседе»?
3. C3-Telegram: свободное сообщение клиенту через бота — ок по UWG, если тред начат
   клиентом/сделкой (сервисная коммуникация)? (рекомендация — да, только в тредах)
4. WhatsApp Business API (писать первым в WhatsApp) — оставить в external-backlog?

## 4. Порядок

C1 → C2 → C3, каждый — отдельный инкремент с замками; ни один не требует миграций.
