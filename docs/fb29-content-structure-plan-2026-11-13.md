## 3. Вопросы владельцу

- **В-1. Баннер и несколько категорий — что это значит?** (а) баннер ВЕДЁТ на цель (одна
  ссылка), а «несколько категорий» — где он ПОКАЗЫВАЕТСЯ (на страницах этих категорий);
  (б) баннер показывает товары нескольких категорий. Рекомендация — (а): библиотека баннеров,
  у каждого одна ссылка и список мест показа («Startseite», категории, акции).
- **В-2. Своя структура объекта (29.4b) — с чего начать?** Рекомендация: сначала категории
  (у них уже есть своя схема блоков с R7 и поля вида) и товары; услуги, номера, события —
  вторым шагом, им нужны миграции.
- **В-3. Хранение баннеров.** Рекомендация: отдельная модель в схеме бизнеса (миграция), а не
  `site_config` — десятки баннеров с фото и сроками в JSON настроек не место; слайдер главной
  хранит ссылки на записи. Существующие слайды переносятся миграцией данных.
- **В-4. Порядок.** Рекомендация: 29.5 + 29.3 + 29.4a (один макет «Seitenaufbau») → 29.7 →
  29.6 → 29.2a–c → 29.4b → 29.8b.

## 4. Замки (до кода, по срезам)

- 29.5: ширина встроенной секции переживает «Speichern» Студии; нетронутая панель ничего не
  меняет (W0); перетаскивание даёт тот же результат, что «выше/ниже»; без скриптов всё доступно.
- 29.4a: пикер пишет ту же настройку, что прежняя строка (один писатель `page_settings`).
- 29.4b: объект без своих правок рендерится байт-в-байт как сейчас; своя правка не трогает
  общую схему; удаление объекта убирает его переопределение.
- 29.2: старые слайды после переноса показываются так же и в том же порядке; баннер вне срока
  не показывается; удаление баннера, стоящего в слайдере, требует подтверждения; права —
  как у экрана сайта.
- 29.6: разметка с px/высотой проходит `richtext` и не даёт XSS; старые фото без новых
  атрибутов выглядят как раньше.
