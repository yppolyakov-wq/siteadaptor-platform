# STU-18 — панель Студии: дизайн области настроек + карта «что должно быть на каждой странице»

**Дата:** 2026-09-10 · **Повод:** фидбэк владельца (2 скриншота панели + таблица трёх осей
из плана LAY): «проверь панель настроек, вывод информации тут ужасен, сделай дизайн этой
области и на согласование разведай, какие блоки и настройки в студии должны быть на каждой
странице… Композиция · Сетка · Форма карточки… Так же настройки шрифтов и тд. Всё должно
быть согласовано с дизайнами сайтов и палитр».

**Статус:** РАЗВЕДКА + ДИЗАЙН НА СОГЛАСОВАНИЕ. Кода нет. Решения владельца — §7.

## 1. Замер, а не мнение

Панель снята в браузере на живом стенде (демо `aktionsmarkt`, Chromium 1440×900, панель
в ширине по умолчанию 380 px), **в двух локалях кабинета**: немецкой и русской (у владельца
кабинет русский — это оказалось важно).

Скрипты замера: `scratchpad/measure.py`, `widths.py`, `ru.py`. Скоуп панели работает
корректно — первый прогон показал «все строки на всех страницах», но это была **ошибка
замера**: кадру канвы не хватило времени инструментироваться, и `applyStuPageScope` ещё
не отработал. С ожиданием по факту (`[data-stu-setting].hidden` появился) картина честная:

| страница | строк в панели | какие |
|---|---|---|
| `/aktionen/` | 4 | promo_page_style · promo_grouping · promo_index_layout · promo_card_form |
| `/sortiment/` | 6 | product_card_form · catalog_menu_labels · catalog_layout · catalog_sort · catalog_filters · catalog_page_style |
| `/ueber-uns/` | 1 | text_width |

### 1.1 Что намерено: высоты строк (панель 380 px, локаль RU)

| страница | строка | высота |
|---|---|---|
| `/aktionen/` | `promo_page_style` (плитки композиции) | **289 px** |
| | `promo_grouping` | 56 px |
| | `promo_index_layout` (сетка: плитки + 5 полей) | **296 px** |
| | `promo_card_form` (плитки) | **332 px** |
| | **итого 4 настройки** | **≈ 973 px** |
| `/sortiment/` | `product_card_form` | 319 px |
| | `catalog_menu_labels` | 40 px |

| | `catalog_sort` | **24 px** |
| | `catalog_filters` | **16 px** |
| | `catalog_page_style` | 302 px |
| | **итого 6 настроек** | **≈ 1106 px** |

**Четыре настройки не помещаются в три экрана панели.** При этом «Сортировка» — 24 px,
«Показать фильтры» — 16 px: настройки, к которым владелец обращается чаще всего, выглядят
как случайные строчки между тремя простынями плиток.

### 1.2 Что обрезано (RU) — и чего нет в DE

На `/sortiment/` в русской локали панель **переливается по горизонтали на 30 px**
(в немецкой — 0). Это и есть полоса прокрутки со второго скриншота владельца.

Обрезанные подписи (RU, ширина по умолчанию 380 px):

* «Полки (подкатегории лентами)» → «Полки (подкатегор…»
* «Вкладки (подкатегориями вкладками)» → «Вкладки (подкатегор…»
* «Плитка предложения» → «Плитка предложен…»
* «Стандартный» (плейсхолдер поля «На странице»)
* «▾ 3 в строке» (выбранная опция селекта пресета)

Причина не в переводе: **плитка имеет фиксированную ширину подписи `w-16` (64 px) и
`line-clamp-2`** (`templates/tenant/_cardform_picker.html:14`). Немецкие подписи в неё
попадают, русские — нет. То есть вёрстка панели рассчитана на длину одного языка.

## 2. Диагноз: почему «вывод информации ужасен»

Семь причин, все проверены по коду и видны на снимках `scratchpad/panel-ru-*.png`.

**П-1. Заголовки карточек не описывают содержимое.** На `/sortiment/` карточка называется
**«Шаблон страницы»**, а внутри неё — **форма карточки** (`site_home.html:574` legend +
строка `product_card_form` на `:674`). Настоящий шаблон страницы (`catalog_page_style`,
`:798`) лежит в ДРУГОЙ карточке — «Целевые страницы». Владелец читает заголовок и получает
не то, что он обещает.

**П-2. Одна ось разорвана на два непохожих блока.** Сетка `/aktionen/` — это плитки
«Акции: сетка» (пресет) **и** пять полей «Вывод · Последний ряд · Рядов · На странице ·
Скорость» (`_output_axis.html`). Это одна ось, но плитки крупные и цветные, а поля —
мелкие серые в две колонки. Выглядит как два разных раздела.

**П-3. Два набора плиток с одинаковым визуальным языком означают разное.** Композиция
(`_pagelayout_thumb.html`) и пресет сетки (`data-thumb` → `.bld-thumbs`) рисуются
одинаковыми серыми мини-макетами 56×40. На `/aktionen/` они идут подряд.

**П-4. Пять конкурирующих шаблонов строки.** Разведка markup нашла в одной панели:
(а) подпись сверху + полноширинный контрол; (б) горизонтальный флекс «подпись — селект»;
(в) мелкая инлайн-подпись + узкий селект; (г) чекбокс-строка; (д) плитки. Размеры полей —
`px-3 py-2 text-sm`, `px-2 py-1.5 text-sm`, `px-1.5 py-1 text-xs` — три разных.

**П-5. Значение по умолчанию выглядит выключенным.** «Рядов: *все*», «На странице:
*Стандартный*», «Скорость: *выкл*» — это `placeholder` пустых `input[type=number]`
(`_output_axis.html:31-44`). Серый текст в пустом поле читается как «недоступно», а не
как «сейчас так».

**П-6. У панели два визуальных языка, и лучший используется только для блоков.**
Настройки БЛОКА канвы уже свёрстаны хорошо: группы `.bld-grp` — свёрнутые карточки со
сводкой значения в заголовке (`site_home.html:1858-1878`). Настройки СТРАНИЦЫ этой
механики не получили: у `.stu-page-row` и `.page-block` **нет ни одного собственного
CSS-правила** — весь вид собран из утилит Tailwind на месте.

**П-7. Подписи повторяются дословно.** «Aufbau» — на 4 строках, «Sortierung» — на 3;
различаются только тем, какая страница открыта. Строка `catalog_layout` вообще не имеет
своей подписи — берёт её у соседнего `<div>`-обёртки (`:763`).

## 3. Ответ на главный вопрос: что должно быть на каждой странице

### 3.1 Целевая структура панели — одна и та же на всех 30 типах

```
Эта страница: <Имя>                              [🌐 ru] [✕]
──────────────────────────────────────────────────────────
① ШАБЛОН СТРАНИЦЫ      (ось A · композиция)   ▾ «С обложкой»
② ВЫВОД                (ось B · сетка)        ▾ «Сетка, 3 в строке»
③ КАРТОЧКА             (ось C · форма)        ▾ «Полочный ценник»
④ СОДЕРЖАНИЕ СТРАНИЦЫ  (сорт/фильтры/секции)  ▾ «3 настройки»
──────────────────────────────────────────────────────────
🎨 Оформление сайта →   Look «Prospekt» · Barlow · ●accent
```

Правила:
1. **Порядок групп неизменен** — от «что вокруг» к «как одна плитка», затем содержание.
2. **Группа без применимых настроек не рисуется** (не пустая рамка).
3. Где ось честно отсутствует — **одна строка-объяснение**, а не контрол-обманка
   (прецедент уже есть: `team`/`gallery`, `site_home.html:737`).
4. Группы свёрнуты, в заголовке — **текущее значение**; открыта та, которую владелец
   трогал последней. Это снимает П-1/П-2/П-5 и режет 1106 px до ~5 строк.

## 5. «Согласовано с дизайнами сайтов и палитрами»

Сегодня **не согласовано**, и в двух разных смыслах.

**5.1 Панель не показывает палитру сайта.** Мини-макеты плиток нарисованы фиксированными
цветами Tailwind (Д-9). Владелец выбирает «как будет выглядеть мой сайт» по картинке,
которая нарисована не его цветами и не его шрифтом.
→ Предложение: мини-макеты рисуются переменными витрины (`--sf-primary`, `--sf-card-radius`,
`card_chrome`, `media_shape`), а подпись плитки — шрифтом сайта. Механизм уже есть: эти
переменные эмитятся на витрине, панель может подмешать их в свой scope.

**5.2 Оси пишутся из двух мест, и второе сильнее.** Экран `/dashboard/design/` («Оформление
сайта») содержит **сборки** (`BUNDLES`, 27 штук). Сборка одним кликом переписывает не
только кожу, но и **композицию** (состав/порядок/стиль секций), **сетку**
(`catalog_layout`, `section_layouts`) и **форму карточки** (`card_style`, `promo_card`)
— `sitetemplates.py:2020-2102`. То есть настройки, которые владелец выставил в панели
Студии, молча переписываются кнопкой на другом экране.
→ Предложение: оставить сборку как «стартовую точку», но а) честно предупреждать, что
она перезапишет (список — из `_apply_bundle_axes`), б) показывать в панели Студии, какой
Look/сборка сейчас применены (ключ `config["design"]` для этого уже пишется).

**5.3 Где живут шрифты — и надо ли их возвращать в Студию.** Сегодня шрифт, цвет,
типографика, тёмная тема, радиус/тень/фон карточек, `card_chrome`, `media_shape` живут на
`/dashboard/design/` — вынесены туда осознанно волной STU-12g (решение владельца 1B),
и это закреплено замком `test_stu12_theme_moved.py:35`.

Возвращать их в панель страницы **не рекомендую**: это глобальные настройки, а панель — про
одну страницу; смешение глобального с постраничным и породило исходную кашу. Но нынешняя
ссылка — просто текст в верхней строке. Предлагаю **группу ⑤ внизу панели**: живая сводка
(имя Look, шрифт, кружок акцента) + переход. Владелец видит, чем сейчас оформлен сайт, не
уходя со страницы. Если нужен именно ввод шрифта в Студии — это решение Р-3.

## 7. Задачи

Сквозные инварианты волны (нарушение любого — красный замок, не «мелочь»):

* **И-1.** Ключей хранения не добавляем нигде, кроме 18d (там — `<kind>_page_style`,
  presence-minimal). Миграций нет ни в одной задаче.
* **И-2 (W0).** Скрытие контролов — только CSS; поля остаются в форме, иначе Save с одной
  страницы стирает настройки других.
* **И-3.** `test_registry_and_panel_agree` остаётся зелёным на каждом шаге: коды
  `data-stu-setting` и наборы `data-stu-page` не меняются от перестановки.
* **И-4.** Пилюля охвата остаётся ВНУТРИ своей строки (`test_scope_pills_stand_next_to_their_control`).
* **И-5.** Замки пишутся ДО правок и обязаны краснеть.
* **И-6.** Перед каждым пушем: `ruff check .` + `ruff format --check .` ЦЕЛИКОМ,
  `scripts/i18n_quickcheck.py`, `apps/core/tests/test_template_comments.py`,
  пересборка `app.css` при новых Tailwind-классах.

Порядок: **18a → 18b → 18c → 18e → 18d**. 18d — отдельной волной последней: она
единственная объёмная и единственная, что трогает витрину.

### STU-18a — компоненты панели (вид, без перестановки)

Цель: убрать пять конкурирующих шаблонов строки и обрезку. Строки остаются на местах,
меняется только их вёрстка — поэтому шаг безопасен и виден владельцу сразу.
