# PMS: корпоративный контур (CO) + цены конкурентов (CP) — планы v1

**Дата:** 2026-07-28 · **Статус:** обе развилки одобрены владельцем
(«корпоративный контур — да», «показывать цены конкурентов — да»).

## CP — «Marktposition»: цены отелей города (дешёвая, первой)

Данные УЖЕ есть в public-схеме: `AggregatorListing` (city, business_type,
new_price «ab €», is_active) — это публичные цены витрин платформы.

- **CP-1:** карточка «📊 Marktposition» на странице отчётов stays
  (`stays:reports`): все активные отели того же города (min 3, иначе карточка
  скрыта — на пустом рынке сравнение бессмысленно), отсортированы по «ab €»;
  своя строка подсвечена + позиция «N из M», min/median/max. Read-only,
  подпись-дисклеймер «базовые цены отелей платформы в вашем городе».
- **Осознанно НЕ делаем:** рекомендации «подтянуть цену к соседям» (картельный
  риск — только факт позиции), живые цены по датам (кросс-схемный обход дорог;
  v2 по спросу), внешние источники (Booking-скрейпинг — ToS).
- Без миграций; гейт: модуль stays + business_type hotel/pension.

## CO — корпоративный контур v1 (справочник компаний)

Скоуп v1 — «справочник + привязка + документы», без биллинг-автоматики:

- **CO-1 (⚠️ миграции crm/000X + promotions/000X):** TENANT-модель
  `crm.Company` (name, vat_id, street/postal/city, email, phone, note,
  discount_percent 0..50 — задел) + `Customer.company FK null` (SET_NULL).
  Кабинет: `/dashboard/kunden/firmen/` (CRUD по образцу CRM), селект компании
  в карточке клиента; чип компании в списке/360°.
- **CO-2:** счёт из брони корпоративного гостя — `Invoice.recipient`
  префилится реквизитами компании (name + адрес + USt-IdNr), не свободным
  текстом клиента; фильтр CRM `?firma=`.
- **CO-3 (v2, по спросу):** корпоративный тариф (RatePlan, видимый компании),
  безнал «на счёт компании», отчёт продаж по компании. Не в этом заходе.

Порядок: CP-1 → CO-1 → CO-2. Каждый — отдельный батч с замками.
