# T-8.2 «Zurücklegen» — план (2026-10-10)

Пункт 1 общего плана `t8-roadmap-2026-10-10.md`. Решение владельца Р-1: «отложить» делаем
старым механизмом резерва (срок, код+QR, автоснятие, сканер, уведомления). Разведка —
отчёт агента 2026-10-10 (ниже — только выводы с местами в коде).

## 0. Факты

- Движок резерва жив целиком: `services.reserve` (:64), `/p/<uuid>/reserve/`
  (`reservation_create`), `/r/<code>/` с QR, beat `expire-reservations` (5 мин), сканер
  `promotions:redeem`, письма клиенту и владельцу. На витрине на него не ведёт ничего.
- Кнопка «Reserve now» открывает попап, где форма «Jetzt kaufen» шлёт на `/kaufen/` →
  обычный заказ. Модуль заказов не проверяется нигде → у кафе/парикмахерской/событий/
  кейтеринга клиент получает 404 на подтверждении (лёгкие демо обходят это включением
  `orders`).
- Дыры движка, которые станут видны клиенту:
  - R1 скан «Ausgeben» у неподтверждённого резерва падает (нет перехода pending→fulfilled);
  - R2 лимит «N pro Kunde» обходится без e-mail (клиент ищется только по почте, почта
    необязательна);
  - R4 срок удержания нигде не показан клиенту и не ограничен концом акции;
  - вкладка продаж подписана «Aktions-Reservierungen (alt)», а у лёгких демо это
    главная вкладка.
- Анкета «Anfragen» из акции не существует (есть модальное окно заявки `?betreff=`,
  модуль `jobs`).

## 1. Решение: отклик акции

Новый модуль `apps/promotions/response.py` — одна точка истины «что делает кнопка акции»:

| Отклик | Когда | Что видит клиент |
|---|---|---|
| `booking` | цель акции — услуга или номер | как сейчас: «Termin wählen» / «Zimmer buchen» |
| `buy` | можно продавать онлайн: модуль заказов включён **и** витрина не «Nur Aktionen» | как сейчас: форма заказа |
| `reserve` | иначе (или явно выбрано) | «Zurücklegen lassen»: имя + e-mail или телефон + количество → код и QR |
| `inquire` | явно выбрано **и** модуль заявок включён | кнопка «Anfragen» → окно заявки с темой акции |
| `show` | явно выбрано | без кнопки; карточка «So finden Sie uns» |

Явный выбор владельца — `Promotion.metadata["response"]` (без миграции): поле
«Reaktion der Kundschaft» в форме акции (по умолчанию «Automatisch»), ключ `response` в
спеке демо-китов. Невыполнимый выбор (купить без модуля заказов, заявка без модуля
заявок) падает на автоматику. **Нет тенанта в запросе → `buy`** (прежнее поведение;
на этом держатся замки разметки buy-box, рендерящие страницу без тенанта).

## 2. Изменения

1. `response.py` + `_detail_ctx` кладёт `promo_response`; buy-box (`_buybox.html`,
   ветка `reserve`) получает ветки reserve/inquire/show; кнопка и нижняя панель
   страницы подписываются по отклику («Zurücklegen lassen» / прежняя / «Anfragen»).
2. Форма «отложить» шлёт в живой `storefront-reserve`; без доставки и способа оплаты.
   Вьюха: требует e-mail **или** телефон; не принимает цель-услугу/номер (как покупка).
3. **Фикс 404:** `promotion_purchase` при невозможности продать онлайн возвращает на
   акцию с сообщением, заказ не создаётся.
4. Движок: клиент ищется и по телефону (R2); `fulfill` неподтверждённого резерва сначала
   подтверждает (R1); срок удержания ≤ конца акции (R4); срок «bis …» на странице
   подтверждения и в письме клиенту (существующий msgid «Wir halten die Reservierung bis
   %(until)s für Sie bereit.»).
5. Условия акции («max. N pro Kunde», «Reservierung N h gültig») показываются при
   отклике `reserve`, а не только при `promo_type=reservation`.
6. Вкладка продаж: «Aktions-Reservierungen (alt)» → «Reservierungen».
7. Демо: лёгкие киты больше не включают модуль заказов — их акции откладываются;
   пансион — «Anfragen» (модуль заявок + поля «дата/гости» анкеты).

## 3. Замки (до правок)

- резолвер: матрица целей × модулей × явного выбора, нет тенанта → `buy`;
- витрина: при `reserve` форма шлёт на `/reserve/`, ровно поля
  name/email/phone/quantity + служебные, нет полей доставки/оплаты; при `buy` — прежняя
  форма (существующие замки остаются зелёными без правок);
- `/kaufen/` без модуля заказов не создаёт заказ и не ведёт в 404;
- резерв без контакта отклоняется; повтор по тому же телефону упирается в лимит;
- скан неподтверждённого резерва выдаёт его; срок не позже конца акции; «bis …» на
  странице подтверждения;
- `inquire` без модуля заявок → автоматика; `show` → без формы;
- лёгкие киты: без модуля заказов, отклик `reserve` (пансион — `inquire`).

## 4. Вне объёма

Списание складского остатка при «отложить» (сейчас держится только лимит акции —
владелец откладывает товар руками; решение позже), напоминание клиенту перед концом
срока, купон (T-8.3), выбор отклика в мобильном ассистенте (T-8.4).
