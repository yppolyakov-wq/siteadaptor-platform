# AIS-5 «🌐 Übersetzen» в переключателе языка ввода — план (2026-11-06)

Источник: анализ AIS (строка AIS-5), план агента `planner`, сверен с кодом.

## Суть
Кнопка рядом с выпадашкой языка ввода (`_i18n_switch.html`, тег `lang_switch`) переводит
базовый текст в ПУСТЫЕ поля выбранного языка. Чужой текст не трогает, в базу ничего —
сохраняет штатный Save формы.

## Сервер (AIS-5a)
- `apps/core/i18n_translate.py`: задача `i18n_translate` (fast, pii_scrub), Celery + опрос
  (паттерн `promotions/ai_text_check.py`), кэш по хэшу 24 ч, замок одной задачи на
  пользователя, задача принадлежит пользователю (чужой job → 404).
- `POST /dashboard/uebersetzen/` (`core:i18n-translate`) + `GET …/<job>/`
  (`core:i18n-translate-result`), generic и без чтения объектов: экран ∈ белого списка и
  у пользователя право POST на этот экран; target ∈ дополнительных локалей тенанта; капы
  60 элементов / 2000 знаков / 6000 всего (отказ, не обрезка); лимиты на пользователя и
  тенанта с `refund` при сбое очереди.
- Защита токенов до модели: URL, e-mail, телефоны, @handle, HTML-теги, плейсхолдеры →
  `⟦n⟧`. Пост-проверка по элементу: маркеры, числа/деньги/проценты, нет новых ссылок/
  контактов, число строк, отношение длины, maxlength, HTML только у rich-базы (через
  `richtext.sanitize`), алфавит, identity не применяется.
- TASK_DATA в `disclosure.py`, плашка «ИИ в США» у кнопки; ИИ выключен → кнопки нет.

## Клиент (AIS-5b)
- Кнопка видна при выбранном не-базовом языке; блок JS в `cabinet.js` с делегированием;
  база поля: `data-i18n-of` → соглашение `<stem>_<base>`/`<stem>` в той же форме →
  `data-i18n-base`; правовые тексты `data-i18n-notranslate`.
- Заполнение только пустых на момент применения полей, пометка `data-ai-filled`, синк
  rich-редактора, live region, `aria-busy`.

## Стенд (AIS-5c)
`scripts/ais5_translate_stand.py`: товар, rich-описание, услуга (строки/FAQ), строка extra,
отказ пост-проверки, гонка с вводом, ИИ выкл./нет права, скрытая группа, 390 px.

## ECC-прогоны
Скиллы: django-security, django-tdd, django-celery, error-handling, e2e-testing,
accessibility. Агенты: security-reviewer и silent-failure-hunter после 5a; django-reviewer
перед мержем; a11y-architect после 5b; стенд Playwright. database-reviewer не нужен.

## Риски
Перевод уходит в США (плашка/TASK_DATA); rich-редактор перетирает textarea на submit;
нестандартные имена полей (замок разметки); злоупотребление как переводчиком (связка
экран+право, капы, лимиты); формат чисел; гонка с вводом; мини-формы строк.
