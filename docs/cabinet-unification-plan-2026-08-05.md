# План «Кабинет v3»: единый реестр навигации + Settings-хаб + честные режимы (W7–W12)

Дата: 2026-08-05. Семейство задач: **W-v3** (продолжение семейства W —
admin-global-audit 2026-07-09 закрыл W0–W6). Факты — `docs/cabinet-audit-2026-08-05.md`
(+ полные отчёты в `docs/cabinet-audit-2026-08-05/`). Все правки опираются ТОЛЬКО на
CONFIRMED/ADJUSTED-факты аудита.

**Цель (формулировка владельца):** «проверить весь функционал, оптимизировать и сделать
единые разделы; выделить базовые настройки, а дополнительные по типам разделить и
поместить в табы; красиво снаружи И порядок под капотом».

---

## §1. Принципы (выведены из аудита + конкурентов)

1. **Один источник правды навигации.** Каждый вход в кабинет описан РОВНО ОДИН раз в
   одном реестре; сайдбар, хаб-табы, плитки, мобильный бар, подсветка и поиск —
   производные. «Сайдбар говорит одно, хаб другое» становится невозможным по конструкции.
2. **Один вход на сущность** (урок Битрикса). Дубль-вход допустим только как явная
   ссылка-мостик, не как второй параллельный экран.
3. **Настройка живёт там, где её эффект**, а всё «настроил раз в месяц» — в едином
   Settings-хабе (правило Shopify: меняется реже раза в неделю → в Settings).
4. **Режим меняет видимость, не семантику** (инвариант W0 остаётся железным); осей
   скрытия ровно две: активность модуля (по архетипу, с возможностью включить) и
   уровень Einfach/Experte. «Erweitert»-ящики и ui_mode — ОДИН механизм, не четыре.
5. **Лендинг оправдан только состоянием.** Страница-прихожая из ссылок, дублирующих
   таб-бар, удаляется; остаётся то, что показывает статус (напоминания, результаты,
   подключения).
6. **Переезд с маппингом.** Каждый убираемый экран = редирект на новое место +
   (временно) подсказка; ничего не «исчезает» (урок Squarespace «Where did everything go»).
7. **Замки до правок.** Характеризационные тесты на текущее поведение ДО каждого свода;
   инвариант-тест достижимости всех вьюх из хрома.

## §2. Целевая структура

### §2.1 Сайдбар (состав почти не меняется — он уже канон)
```
🏠 Übersicht        (главная «что сегодня»: виджеты + плитки + канбан)
🗂 Verkäufe         (ЕДИНСТВЕННАЯ поверхность продаж, §2.4)
📦 Angebote         (всё продаваемое: Angebote-обзор + Produkte/Kategorien/Lager/…)
📣 Marketing        (= Marketing + Kunden, слиты; бейдж inbox, §2.5)
✏️ Website          (Studio — единственный вход, §2.6)
⚙️ Einstellungen    (Settings-хаб, §2.3)
➕ Funktion hinzufügen
```
Судьба якоря «Integrationen» — развилка Р-3 (рекомендация: вкладка «Integrationen» в
Einstellungen со СТАТУСАМИ подключений; уникальная ссылка stays:channels переезжает туда
и в хаб Verkäufe).

### §2.2 Единый реестр навигации (ядро всей программы, W8)
`apps/core/nav_registry.py` — записи вида:
```
NavEntry(url_name, label, anchor,      # к какому из 7 якорей относится (подсветка!)
         hub, tab_group,               # таб-бар и смысловая группа внутри хаба
         module_key, archetypes,       # гейт активности / релевантности
         level,                        # "basic" | "advanced"  (= Einfach/Experte)
         search, badge, icon)
```
Из реестра генерируются: `sidebar_nav` (якоря+бейджи), `hub_tabs` (включая ящик
Erweitert = level:"advanced"), `hub_tiles`, `nav_primary` (мобайл), карта
`nav_key → anchor` (чинит подсветку на ~37 экранах одним словарём), поисковый индекс.
NAV_TASK_LABELS/NAV_GROUPS/HUB_TABS сводятся В реестр (classic-ветка — по решению Р-1).
Инвариант-замок: «каждая кабинет-вьюха достижима ≥1 переходом из хрома при своих гейтах»
— ловит сирот класса billing/newsletter навсегда.

### §2.3 Settings-хаб «Einstellungen»: базовые + по типам в табах
Владелец просил именно это. Структура «раздел → табы» (паттерн CS-Cart/Shopify):

**Базовые (видны всем, всегда):**
1. **Mein Geschäft** — имя/лого/адрес/контакты/WhatsApp + часы работы (структурные И
   текстовые СЛИТЫ в один блок; мастер пишет туда же) + presence («Jetzt erreichbar»).
2. **Sprachen** — языки витрины + язык кабинета + пояснение про переводы контента:
   три «глобуса» объяснены на ОДНОМ экране (сейчас 5 понятий, 3 иконки без подписей).
3. **Recht & Steuern** — LegalDoc per-locale как ЕДИНСТВЕННЫЙ редактор (плоские поля
   Tenant → read-only плашка «управляется здесь»), vat_id/small_business, Zusatzstoffe-гейт.
4. **Zahlung & Lieferung** — существующий экран W4-3 + статус Stripe-Connect;
   /dashboard/billing/payments/ схлопывается в read-only статус.

**По типам (гейт по модулям):**
5. **Benachrichtigungen & Kanäle** — матрица уведомлений с 3 пресетами («Alles / Nur
   Wichtiges / Eigene Auswahl» вместо 54 чекбоксов), owner-каналы, **Telegram одним
   экраном** (бот+Mini App / канал публикаций / owner-уведомления — 3 блока, токен один раз).
6. **Abläufe** — ВСЕ настройки процессов в одном месте с селектором вида
   (Bestellung/Termin/Übernachtung): колонки доски, имена статусов, правила переходов,
   свои статусы. На операционных экранах — только ссылка «⚙️ Abläufe anpassen».
7. **Website & Domains** — домены + SEO + мостики «Farbe & Schrift → Studio».
8. **Abo & Rechnung** — подписка/счета (сейчас — сирота без единого входа!).

**Erweitert (ящик, = level advanced):** Funktionen (модули), Medien, Extras, Finder,
Ansicht (режимы, §2.7), Hilfe. Кандидат «Team & Zugriff» поверх готовой
`core.Membership` — отдельная развилка Р-7.

Единая механика Save на всех табах: targeted-write / сентинелы `sec_*` (паттерн W4-3),
запрет `normalize(полный конфиг)` в save-путях настроек; общий партиал
`_settings_page.html` (шапка+messages+Save) вместо 8 копий.

### §2.4 Verkäufe — единственная операционная поверхность продаж (W10)
- Вкладки по kind как сейчас + **Reservierungen** (появляются при primary promotions
  ИЛИ активных резервах — сейчас заявки клиентов спрятаны в Marketing/Erweitert).
- Виды: **Heute** (НОВЫЙ, kind-агностичный: заезды/выезды/записи/заказы к выдаче —
  поглощает stays:today и виджеты «Abholbereit»/«Anreisen heute») · Kalender · Board · Liste.
- Liste становится честной: сортировка по дате СОБЫТИЯ (не created_at), фильтр статуса,
  поиск — паритет с /dashboard/orders/.
- «＋» (создать бронь/запись/заказ) доступен из ЛЮБОГО вида, не только Kalender.
- Действия встроенных тел не выбрасывают наружу: `next=` во всех формах,
  kanban_action non-fetch уважает next.
- Ссылка «⚙️» на Abläufe (§2.3-6) и вход в KDS/Table-QR из вкладки order.
- events:list / jobs:list получают вкладки внутри Verkäufe; hub_tabs["board"]-огрызок
  и orders_view-сегмент умирают; легаси-страницы → редиректы С СОХРАНЕНИЕМ GET-параметров
  (строго ПОСЛЕ достижения паритета функций, иначе не схлопывать — список паритета в
  audit-sales «Развилка одна поверхность»).
- Единый `transactions.apply_action(kind, obj, target, actor, extra)` для ВСЕХ
  поверхностей — закрывает расхождения писем/таймстемпов/блокировок (трек-номер,
  is_delivery, reservation-таймстемпы, кастом-статусы с карточки).

### §2.5 Marketing (= Kunden влит) (W11)
- Хаб один, табы в 3 смысловых группах: «Angebote & Aktionen» (Aktionen, Gutscheine,
  Treuepunkte, Einlösen) · «Kunden erreichen» (Kampagnen, Newsletter, Kanäle/Beiträge,
  Care-Zyklus→ссылка в Einstellungen) · «Ruf & Dialog» (Bewertungen, Kontakte,
  Nachrichten, Telegram→ссылка, Finder).
- HUB_TABS["kunden"] удаляется, страницы crm/inbox/telegram переходят на marketing-хаб —
  ловушка «молчаливой подмены таб-бара» исчезает.
- Лендинг marketing_home: карточки-дубли убрать, оставить ТОЛЬКО состояние (обзор
  авто-касаний + панель результатов) — по правилу §1.5 он единственный из лендингов
  проходит критерий.
- Отзывы: кабинет Bewertungen начинает показывать и BusinessReview (отзывы о бизнесе,
  которые витрина УЖЕ рендерит, а владелец не может ни увидеть, ни ответить) — вторая
  вкладка «Über den Betrieb».
- /promotions/newsletter/: вход табом ИЛИ удаление — развилка Р-5.
- Акция на услугу/номер/комби из UI: PromotionForm += service/stay_unit/combo (+кнопка
  «Aktion erstellen» со строки сущности в Angebote) — закрывает дыру «движок PL готов,
  UI нет».

### §2.6 Website (W11, малый объём)
Studio — единственный вход; лендинг site.html слить в Studio (карточки → уровни рейки,
SEO-вход в рейку), «Website»-ярлык ведёт в одно место; back-ссылка чинится; вторая
копия галереи удаляется. Медиатека — из Erweitert Settings в Website-рейку («Galerie» ≠
«Medien» разводятся именами).

### §2.7 Режимы: одна честная ось (W12)
- **Einfach/Experte = level реестра.** Простой прячет level:"advanced" ВЕЗДЕ (сайдбар,
  табы=ящик Erweitert, плитки, поля форм по CSS) — тумблер наконец делает то, что обещает
  тултип.
- **Архетип-скрытие — автоматика, не ручная карта:** выводится из
  primary_module/recommended_for (ARCHETYPE_SIMPLE_HIDDEN на 4 из 15 типов удаляется);
  «нерелевантный модуль» = выключен по архетипу с возможностью включить (урок Битрикса),
  а не «скрыт в Простом».
- Страница **«Ansicht»** в Erweitert: уровень + classic_ui + список «что именно скрыто»
  (сейчас настройка вида размазана по шапке/Funktionen/ящику).
- **classic_ui — развилка Р-1** (рекомендация: заморозка немедленно → удаление после
  стабилизации W8–W10; сейчас это вторая IA с ~21 веткой и двумя неполными кабинетами).
- Матрица тестов (simple|expert)×(classic|new) — или удаление classic-ветки вместо неё.

## §5. Ограничения и риски

- Аудит нашёл и ПОВЕДЕНЧЕСКИЕ дефекты (письма/таймстемпы/склад заявок) — W7c чинит их
  до любых перестановок навигации, чтобы «переезд» не смешался с «изменением поведения».
- Редиректы легаси-страниц продаж — только после паритета функций (список потерь —
  audit-sales, GROUPING «Развилка одна поверхность»); до того легаси живёт с меткой.
- Golden-тесты normalize: ключи `notify` и пр. добавлять по паттерну
  onboarding/demo (passthrough), НЕ материализуя — golden целы.
- i18n: все новые лейблы — немецкие msgid + переводы en/tr/ru/uk в том же батче
  (урок Finder-трека), гейт `scripts/i18n_gap.py`.
- classic_ui-замки (Р7-правило Studio-трека) уважаются до решения Р-1.
