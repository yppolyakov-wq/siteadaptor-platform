# AIS A-3 — плавающая панель «✨ Assistent» (KI · Support · Kunden) + маршрут «создать X» (план, 2026-11-06)

План — агент ECC `planner` (сверен с кодом), доработан ведущим. Запрос владельца: «плавающая
кнопка KI-Assistent справа снизу: переписка с ИИ, чат техподдержки, вход в чат с клиентами» +
«на „добавь товар Колбаса … 50 евро как услугу“ ответ „Я не уверен“ — так не должно быть».
Решения владельца: «по рекомендации, делать сейчас» (Support — админка платформы + уведомление;
история ИИ — в БД со сроком; телефон — над таб-баром, не перекрывая «＋»). Открытые вопросы
О-1…О-4 — по рекомендации (§1).

## 0. Суть

Одна плавающая кнопка справа снизу открывает **существующую** шторку помощника
(`<dialog id="sf-drawer">`, `templates/core/_drawer.html`) — вкладки **KI** (A-0/A-1/A-2 +
план «anlegen» + история), **Support** (тикеты M22c `apps/support` + «An den Support»),
**Kunden** (непрочитанные беседы inbox → «Nachrichten»). Второго диалога и нового чат-движка
нет; новая сущность одна — история ИИ (`core.AssistantTurn`). Фраза «создать X» уходит в
помощник `setup_assistant` (STU-19c): план с кнопкой «Formular öffnen» и предзаполнением.

## 1. Решения

- **Р-1** одна шторка (контракт `docs/references/patterns/drawer.md`); вкладки — ссылки
  `a[data-drawer]` (`<nav>` + `aria-current`), без JS — полная страница `/dashboard/assistent/?tab=`.
- **Р-2** плавающая кнопка ЗАМЕНЯЕТ ссылку ✨ топбара (`_base_dashboard.html`), атрибуты
  `data-drawer data-drawer-key="assistant" data-assistant-open` переезжают (стенды целы).
- **Р-3** уведомление платформе о новом тикете — `notifications.services.notify()`: e-mail на
  `SUPPORT_NOTIFY_EMAIL` (по умолчанию `PLATFORM_CONTACT_EMAIL`); Telegram общим ботом — только при
  `SUPPORT_TELEGRAM_CHAT_ID`. Текст «Neue Support-Anfrage: <Firma> — <Betreff>» + ссылка в
  админку, **тело тикета наружу не уходит**; дедуп по треду и окну.
- **Р-4 (дефект)** ответ платформы из админки сохранялся инлайном мимо `services.add_message` →
  `unread_for_owner` не ставился, владелец ответа не видел. Чиним `save_formset` + письмо владельцу.
- **Р-5** история ИИ — TENANT-модель, только своему пользователю: вопрос (после `pii.scrub`) и
  ТОЛЬКО прошедший `check_answer` ответ; ссылки — идентификаторами (URL при показе заново); 90 дней
  (`ASSISTANT_HISTORY_DAYS`), ≤ 200 строк на пользователя, «Verlauf löschen».
- **Р-6** маршрут «создать» — во вьюхе `assistant_ask` ДО `assistant_ai.ask` (создание обязано
  работать без ИИ; модель A-2 его не вызывает — она ничего не создаёт и выбросила бы «50 €»).
- **Р-7 / О-1** Support видят все члены команды, как сейчас (паритет; сузить до owner+admin —
  отдельное решение владельца).
- **Р-8 / О-2** Support в лёгком пакете и Mini App — да (малому владельцу поддержка нужнее всего).
- **О-3 (ops)** env `SUPPORT_NOTIFY_EMAIL`, `SUPPORT_TELEGRAM_CHAT_ID` на проде.
- **О-4 (юр.)** строка в Datenschutz/AVV о хранении вопросов к ассистенту 90 дней.

## 2. Модель (одна, аддитивная) — `core.AssistantTurn`, миграция `core/0015`

`user` FK · `job` CharField(32) unique (идемпотентность) · `kind` answer/plan/fallback/scope ·
`seite` · `question` (≤ 500, после scrub) · `answer` (только проверенный текст) · `refs` JSON
(идентификаторы) · `articles` JSON (ключи A-1) · `created_at` (индекс `(user, -created_at)`).
Пишет один хелпер `apps/core/assistant_history.record()` — из `ask()` (мгновенные исходы), из
`run_job` (рядом с `on_outcome`) и из маршрута «plan»; сбой записи не роняет ответ. Purge — beat
по схемам пачками.

## 3. Маршрут «создать X» (факты пробника на фразе владельца)

`out_of_scope=''`; `_entity_of` → product (`товар` найден раньше `услугу`); `_price_in` → ''
(«евро» не знает). Правки правил:
1. явная сущность сильнее: `als/as/как/в виде/як <X>`, `<X> olarak`;
2. явная недоступна (модуль выключен) → следующая найденная + пометка «Leistungen sind bei Ihnen
   nicht eingeschaltet — als Produkt angelegt»;
3. цена: `евро|євро|avro`, символ до числа (`€ 50`, `EUR 50`); «200 гр» ценой не становится;
4. `_FILLER` += глаголы/служебные слова ru/uk/tr/de/en; основы uk (`послуг`, `акці`, `знижк`).
Маршрут: `create_intent()` (тот же детектор, что палитра) → запись `outcome=plan` через тот же
job-кэш → `_assistant_answer.html` рендерит план партиалом `tenant/_setup_plan.html`.
Вопрос не попадает ни в URL, ни в HTML вне ответа.

## 4. UX панели

Кнопка 56×56, `aria-label`, бейджи с `sr-only`; десктоп `right-6 bottom-6`; телефон над
FAB «＋» продаж, таб-баром и липкими Save (`bottom-[10rem]`); скрыта, пока шторка открыта.
KI: поле вопроса видно ВСЕГДА (без ИИ — статьи A-1 и план «создать»), «Wo stelle ich das ein?»,
«Verlauf». Support: треды с точкой непрочитанного, «Neue Anfrage», эскалация из ответа ИИ
(сервер берёт вопрос из своей записи, ответ ИИ в тикет не идёт). Kunden: гейт inbox +
`nachrichten.view`, 5 бесед без e-mail/телефона (право `kunden.kontakte`), открытие — полная
страница. a11y: фокус-трап `<dialog>`, фокус на заголовок при смене вкладки, цели ≥ 44 px.

## 6. ECC-прогоны

Скиллы до кода: django-patterns, django-security, django-tdd, database-migrations,
accessibility, e2e-testing, django-celery. Агенты: `django-reviewer` — каждый батч;
`security-reviewer` — a (ввод), b/c (тикет, Telegram, эскалация), d (изоляция истории);
`database-reviewer` — d; `silent-failure-hunter` — b, d; `a11y-architect` — c. Стенд Playwright
390/1440 de+ru: кнопка не перекрывает «＋»/Save/таб-бар; вкладки клавиатурой; фраза владельца →
план → форма с «50,00»; эскалация → ответ из админки → бейдж; Kunden → тред.

## 7. Риски

Перекрытие на низком телефоне (стенд 390×667); `exists()` Support на каждой странице (мемо на
запросе); ПД в вопросе (scrub + 90 дней + удаление); оператор Telegram должен один раз нажать
`/start` у общего бота; синхронный `build_plan` с ИИ в рендере ответа (лимит `setup-plan`).

## 8. Инкременты

- **a** «создать X» (без миграций): правила §3, `create_intent`, маршрут plan, форма KI без ИИ.
- **b** Support-трубы (без миграций): фикс админки, уведомления, env, `drawer_aware`, пакет/Mini App.
- **c** панель (без миграций): плавающая кнопка, вкладки, тег `support_unread`, эскалация.
- **d** история (⚠️ `core/0015`): модель, запись в трёх точках, «Verlauf», clear, purge.
- Затем **A-4** «KI-Aktionen» — пакет изменений с подтверждением (решения владельца: каталог/
  категории/услуги + шаблон/сетка/карточка; «Rückgängig» 10 мин, пока не менялось; без права —
  предложение без кнопки) — отдельным план-доком.
