## 0. Решения владельца (2026-11-24) и что из них следует
- **D6.** Значение select принимается только из списка вариантов. Иначе — ошибка поля и возврат введённого. CSV — экранирование `= + - @ \t \r` для всех полей.
- **D4.** Оба среза в этой стопке: D4a — заказ; D4b — запись, номер, билет.
- **Второй платёж к оплаченному неотменённому заказу** записывается в книгу и сразу возвращается, как поздняя оплата отменённого. Повтор — `retry_late_refunds`, пометка «Rückerstattung offen».

Поэтому для «второго» нужен возврат одного intent (`refunds.refund_intent`), а не `refund_payment` (тот возвращает главный плюс прочие).

**Решение владельца (2026-11-24) — вариант A: ответ хранится с пометкой.** Поэтому `answers_for_deal` после `snapshot` дописывает «осиротевшие» ответы:
- ключ POST `q<n>` (`fullmatch` `_ID`, без вопроса в текущем списке, непустой) → строка снимка `{"label": "", "value": <текст ≤ LABEL_MAX*2, через clean_text>, "type": "text", "stale": "removed"}`;
- ответ choice вне текущих `options` у существующего вопроса → `{"label": <подпись вопроса>, "value": <текст ≤ LABEL_MAX*2>, "type": "text", "stale": "changed"}`;
- битые number/date — по-прежнему не ответ (ошибка ввода гостя, не правка владельца), только лог;
- потолок осиротевших — `STALE_MAX = 10` на сделку (POST не раздувает зашифрованное поле), лишнее — в лог;
- лог INFO — только id и число, без значений.

Показ — единый `rows`: `stale == "removed"` → подпись «Entfernte Frage»; `stale == "changed"` → подпись вопроса и к значению «(nicht mehr in der Liste)». Карточка, письмо владельцу, KDS, ЛК и PDF берут `rows` — второго пути показа нет. Подпись из POST не берём: имя удалённого вопроса неизвестно, в снимке — пустая подпись и признак. `validate`/`form_spec.missing` не трогаем.
