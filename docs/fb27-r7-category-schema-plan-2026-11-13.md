# FB-27 R7 — своя схема у категории

Дата: 2026-11-13. Основание — `fb27-seitenaufbau-impl-plan-2026-11-11.md` §A.7, §C (R7), Q2.
Решение владельца: у категории может быть своя схема; она **заменяет** блоки каталога на
странице этой категории; кнопка «Aufbau vom Katalog übernehmen».

## 1. Что есть в коде (разведка)

- Хосты `catalog:<slug>` уже существуют (`siteconfig.category_host`, `_CATEGORY_HOST_RE`,
  основной список с маркером — `has_main_list`). Студия умеет в них писать.
- Витрина сегодня **складывает** блоки: `products.html:310, 336-340` рисует `catalog`, затем
  `category_block_host` (над списком и под ним).
- Потолок хостов общий: `_page_block_hosts` сортирует `catalog:*` и `seite:*` вместе и режет
  по 40 — `catalog:` раньше по алфавиту, поэтому первыми вытесняются блоки текстовых страниц.
- Смена адреса категории (`CategoryForm.save`, три точки вызова) блоки не переносит;
  удаление (`category_delete`) хост не убирает. `content_pages.move_page_blocks` делает это
  для `seite:` — префикс зашит.
- В «Seitenaufbau» под-страницы есть только у типа `text` (`text@<хост>`); `category`
  схлопнут в строку каталога (один `block_host`).
- Slug категории — до 100 знаков, хост принимает до 60.

## 2. Решения

| № | Вопрос | Решение |
|---|---|---|
| C1 | Код строки | `category@catalog:<slug>` — та же схема, что `text@seite:<slug>`; хост принимается только у существующей категории. |
| C2 | Что значит «своя схема» | У хоста категории есть хотя бы один свой блок или сохранённый маркер основного списка. Нет — страница категории показывает блоки каталога, как сегодня у всех, кто категории не настраивал. |
| C3 | Замена | При своей схеме блоки `catalog` на странице категории не рисуются (решение Q2). Существующие сайты, где в хосте категории уже лежат блоки из Студии: поведение меняется — блоки каталога с этой страницы исчезнут. Смягчение: миграции данных нет, но в записи build-log и в чекпоинте владельцу — явно; на демо-китах проверить, у кого такие хосты есть. |
| C4 | «Aufbau vom Katalog übernehmen» | Операция черновика `adopt`: блоки каталога копируются в схему категории (новые id, данные и ширины те же), маркер основного списка — на своём месте; свои блоки категории остаются ниже. Переводы блоков не копируются (v1; тексты основного языка). |
| C5 | «Zurück zum Katalog-Aufbau» | Операция `reset`: схема категории очищается (в черновик; на сайте — после «Speichern»), страница снова показывает блоки каталога. С подтверждением. |
| C6 | Список в селекте | Категории — в группе «Sortiment» под «Katalog»: сначала с собственной схемой, затем остальные; не больше 200, одним запросом. |
| C7 | Потолки | Раздельно: 40 хостов категорий и 40 хостов страниц (`_MAX_CATEGORY_HOSTS`, новый `_MAX_CONTENT_PAGE_HOSTS`). |
| C8 | Смена адреса и удаление | `move_page_blocks(old, new, prefix=…)` — общий; зовётся из `CategoryForm.save` (смена slug) и `category_delete`. Slug длиннее 60 — своей схемы нет (строка в селекте не предлагается). |
| C9 | Настройки типа | Строка категории показывает настройки типа `category` (общие для всех категорий, с подписью «gilt für alle Kategorien») — на строке «★ Hauptliste». |

## 3. Срезы

- **R7a — данные.** Раздельные потолки; `move_page_blocks` с префиксом; вызовы при смене
  адреса и удалении категории.
- **R7b — витрина.** `category_has_schema`; `products.html` рисует либо каталог, либо
  категорию.
- **R7c — экран.** `category_pages()`, `host_for`, `type_groups`, операции `adopt`/`reset`,
  подсказка в панели («Diese Kategorie zeigt den Aufbau des Katalogs»).

## 4. Замки (до кода)

- 41-я категория со схемой не вытесняет блоки текстовых страниц, и наоборот;
- смена адреса категории переносит блоки и переводы; удаление — убирает хост;
- категория без своей схемы показывает блоки каталога; со своей — только свои;
- `adopt` копирует блоки с новыми id, исходные блоки каталога не меняются;
- `reset` возвращает показ блоков каталога; обе операции — через черновик;
- POST с несуществующей категорией отклоняется (хосты-призраки);
- список категорий в селекте — без запроса на строку;
- W0: открытие и «Speichern» без правок не создают хост категории.

## 5. ECC-прогоны

- До кода: `django-tdd`, `django-patterns`, `database-migrations` (миграций схемы нет, но
  меняется смысл сохранённых данных — раздел про обратимость).
- После R7a: `database-reviewer` (запросы списка, блокировка строки тенанта при переносе).
- После R7c: `django-reviewer`, `security-reviewer` (ввод хоста), стенд Playwright 1440/390.
