# План SF: ТЗ «UX/UI Sparfuchs» ↔ платформа — волны SF-1..SF-4 (2026-08-31)

Источник: внешнее UX-ТЗ по демо-сайту `aktionsmarkt.siteadaptor.de` (PDF владельца,
80 разделов, P0/P1/P2). ТЗ писалось в предположении standalone-проекта; фактически
это демо-кит `AKTIONSMARKT` (business_type=grocery, бандл `fokus_angebote`,
`apps/tenants/demo_kits.py:3596+`) мультитенантной платформы. Сверка каждого
кластера ТЗ с кодом выполнена воркфлоу (12 разведчиков + адверсариальная
перепроверка ключевых вердиктов вручную, file:line). Итог сверки — в чате сессии
2026-08-31; здесь — только то, что ДЕЛАЕМ. Отмашка владельца: «Давай все
последовательно» (2026-08-31).

### SF-4b — план-раздел (к чекпоинту)

**Сегодня** (волна PL, осознанный дизайн): карточка товара в каталоге при
активной акции-цели показывает БАЗОВУЮ цену + rose-бейдж «−N %»; промо-цена и
чекаут по ней живут только на странице акции (`/p/<uuid>/kaufen/` →
`promotions.services.purchase` → custom-строка Order c маркером `{"promo": id}`
и списанием лимита кампании). Quick-add с карточки кладёт товар в корзину по
ПОЛНОЙ цене — обмана в цифрах нет (что показано, то списано), но путь к скидке
трёхшаговый, и для «магазина акций» это главный разрыв воронки (вывод сверки
Sparfuchs-ТЗ).

**Предложение (вариант A, рекомендую):**
1. Карточка каталога и деталь товара показывают ПРОМО-ЦЕНУ (крупно) +
   зачёркнутую базовую + бейдж; PAngV-строка уже есть (SF-3). festpreis-бейдж
   «%» → человеческий («Aktion»).
2. Quick-add/добавление в корзину товара с активной акцией-целью кладёт в
   корзину ПРОМО-строку: `create_order` при сборке позиций спрашивает
   `promo_for_product` и, если акция жива, применяет `new_price` + маркер
   `{"promo": id}` в modifiers-снимке + **атомарное списание лимита кампании**
   (conditional UPDATE как в `purchase`; OutOfStock лимита → позиция по полной
   цене ИЛИ отказ? — предлагаю честный отказ с сообщением «Aktionslimit
   erreicht», по образцу OutOfStock).
3. Возврат лимита при отмене заказа — уже работает по маркеру (FSM-хук волны
   PL) — переиспользуется без правок.
4. Паритет-замки «карточка = корзина = подтверждение = заказ» ДО правок;
   гонка: два посетителя с последней единицей лимита в корзинах — лимит
   списывается на ЧЕКАУТЕ (не при добавлении в корзину), проигравший получает
   пересчёт с сообщением.
5. Фасет цены каталога и сортировка price_asc/desc остаются по base_price
   (v1; аннотация промо-цены в фасеты — отдельный инкремент по спросу).

**Риски:** смешанная корзина (обычные + промо-строки) — снимок цены обязан
замораживаться на момент чекаута; повторное добавление того же товара —
количество промо-строки капится остатком лимита; издержки: ERP-1 COGS-снимок
не зависит от промо-цены (cost_price из каталога — корректно).

**Альтернатива (вариант B, дешевле):** только пункт 1 (показ промо-цены на
карточке/детали), покупка по акции остаётся на странице акции; quick-add у
акционного товара заменяется кнопкой «Zum Angebot». Без изменений денежного
пути. Если сомнения — начать с B, A отдельным инкрементом.

**РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-08-31): Вариант A.** Дизайн после разведки (3 агента,
карты в чате сессии):

- **Единый источник промо-цены строки** — `apps/promotions/price_layer.py`:
  `attach_promos(products)` (bulk-атрибуты promo/promo_price/promo_badge/
  promo_lowest на карточные поверхности) + `promo_line_price(promo, product,
  variant)` → Decimal|None. **Применимость**: промо действует только на строку,
  чья база = `product.base_price` (variant is None или без своей цены) —
  `new_price` выводится из базовой цены, вариант с надбавкой едет по полной;
  модификаторы добавляются ПОВЕРХ промо-цены.
- **Деньги**: врезка в `create_order` (items-путь; @transaction.atomic уже
  есть): батч `product_promo_map` по позициям → для применимых строк
  `claim_units` (conditional UPDATE, суммарный qty по акции) + `unit_price =
  new_price + options_delta` + маркер `{"promo": str(pk), "label": "Aktion"}`
  элементом в `OrderItem.modifiers` РЯДОМ со снимком опций — возврат лимита
  (`_restore_promo_limits`) и аналитика (`deal_counts`,
  `modifiers__contains`) подхватывают без правок. Исчерпанный лимит →
  промо-OutOfStock, checkout ловит и показывает «Aktionslimit erreicht…»
  (лимит клеймится на чекауте, не при добавлении в корзину — проигравший
  гонку получает честное сообщение). Параметр `apply_promotions=True`
  (custom_lines-пути не задеты; `promotions.purchase` живёт как жил).
- **Витрина корзины/чекаута**: `_line_price` остаётся базой; строки корзины и
  пересчёт subtotal чекаута (минимумы доставки!) берут промо-цену тем же
  `promo_line_price` — «показано = списано».
- **Правка заказа (editing.py, найденные дыры)**: `set_item_qty` двигает лимит
  кампании зеркально складу (qty↑ → claim, qty↓/delete → return по маркеру);
  `add_item` кабинета промо НЕ применяет (владелец задаёт цену сам — граница v1).
- **Показ**: `attach_promos` на каталоге, главной, related, upsell корзины,
  wishlist, quick-add модалке; карточка: промо-цена крупно + зачёркнутая база
  (data-price-edit ОСТАЁТСЯ на элементе только с базовой ценой, data-price =
  base — иначе канва-правка писала бы базу под видом промо); деталь: buy-box
  промо + зачёркнутая, rose-баннер остаётся; sticky-buybar — промо; товары С
  вариантами: промо-цена на карточке НЕ показывается (только бейдж, как
  сейчас) — «from …» с промо врал бы. Прайс-виды (_price_list): показывают
  просто актуальную (промо) цену БЕЗ зачёркнутой — нет анонса снижения, PAngV-
  референс не требуется. Карточка товара с промо получает PAngV-строку
  lowest_30d (батч уже есть).
- **Границы v1** (зафиксировано): max_per_customer на корзинном пути не
  проверяется (как и в purchase — существующее); фасет цены/сортировка

- **Замки ДО правок**: паритет «карточка = деталь = quick-add = корзина =

## Порядок и правила

SF-1 → SF-2 → SF-3 → SF-4a → SF-4b. Каждый инкремент: локальный гейт
(`ruff format --check .` целиком, pytest затронутых модулей `--reuse-db`,
i18n_quickcheck, при шаблонах — test_template_comments, при новых Tailwind-классах
— пересборка app.css) → пуш стопкой → зелёный CI → чекпоинт. Без миграций во всех
волнах, кроме возможной SF-4a (generic-ключ Merkzettel — сессия, миграция не
нужна). ⚠️ ops после SF-1: `seed_demo_tenants --kit aktionsmarkt --recreate`.
