## 4. Грабли процесса (держать; механизмы — в скиллах `sa-*` и замках)
1. **Лимит сессии обрывает всех исполнителей разом.** Каждый законченный коммит исполнителя — сразу cherry-pick в ветку
   стопки и пуш; незакоммиченное — `git diff > docs/wip/fb33-stackNN-<срез>-wip.patch`; после лимита возобновлять ТЕХ ЖЕ
   исполнителей (`SendMessage`), а не новых; патч снимать коммитом, когда код закоммичен.
2. **Своя тест-БД и стенд-БД у каждого** (`DB_NAME=platform_<срез>`, стенд — `CREATE DATABASE … TEMPLATE platform_m39_stand`,
   свой порт). Координатор — свой worktree и своя `DB_NAME`. Не править worktree во время своего pytest; конец прогона — по
   ` in [0-9.]+s`. Шаблон стенд-БД занят, пока на нём сервер обхода — копию делать до запуска обхода.
3. **Сервер стенда — с `DB_CONN_MAX_AGE=0`** (параллельные стенды исчерпывают `max_connections` Postgres: «too many
   clients», ложные ✗ входа). Инвентарь и стенд — по очереди (общий Redis → ложные «302»). Вход стенда упирается в лимит
   429 — один ✗ «вход» на тысячи проверок не дефект, но перепроверить.
4. **Своя подпапка scratchpad у исполнителя** (одноимённые логи и скрипты перезаписывают друг друга).
5. **Свежие `.mo` перед стендом и обходом** (polib `save_as_mofile`; стенд владельца сам отказывает при устаревших).
   `polib.save()` `.po` НЕ вызывать — переписывает переносы всего файла; правки `.po` — текстом, после записи-якоря среза.
6. **Параллельные срезы одного реестра** — разные кортежи с якорями-комментариями модулей; генератор раскрыть в P0; якоря
   `.po` — записями (`msgid "fb33-stack-anchor-<срез>"`) заранее в P0. Общие тесты (`test_fb33_m5d1_inhalt.py`,
   `test_fb33_m5d_inventory.py`) и эталон реестра правят все — при своде брать одну правку.
7. **Правка ядра после старта срезов** ломает ожидания срезов (стопка 12: `lang`) — при своде гонять тесты ВСЕХ срезов
   на верхушке, не только своего.
8. **Общие эталоны окна** (`FB33_M3_REGEN`, `FB33_M32_REGEN`, `FB33_M35C_REGEN`) — только координатор, только на верхушке,
   со свежими `.mo`, сверка списка изменившихся с прогнозом плана; прогноз учитывает и неэталонные замки окна
   (`test_fb33_m37_preview`, `test_fb33_m3_window`) и эталон реестра `golden_fb33m5d2/registry.json`.
9. **`static/css/app.css`** — пересобрать (`npm run build:css`) и закоммитить вместе с шаблоном (pre-commit хук), на
   верхушке — пересборка и сверка «без изменений».
10. **Бриф исполнителю:** цитаты артборда — дословно и целиком (не «…»); список файлов «не трогать»; свой порт и БД; ветка
    для пуша `claude/fb33-stack-NN-<срез>`; отчёт — что было красным до кода, итог preflight и стенда, что не проверено.
11. **Тексты артборда о поведении** («берёт товары с галочкой», «рисуется у тура») сверять с кодом витрины ДО утверждения.
12. **Фокус окна:** адрес несёт `#schema-panel` — браузер ставит фокус на якорь ПОСЛЕ скрипта; `aufbau.js::hold` держит
    фокус до `load` (стенд `focus-open`).
13. **`lang` у имени** — только когда язык имени ≠ язык окна; имя системной страницы — строка интерфейса (без `lang`).
14. **Подпись в `inline-flex`-ссылке** — одним `<span>` с `min-width:0; overflow-wrap:anywhere`.
15. **`view_perms.url_allowed` пускает к цели без правила** — проверять через `nav_registry.screen_closed(…, target_url=)`.
16. **select по реестру вариантов** показывает сохранённое значение вне реестра; варианты, которые сохраняются, — пары
    `(value, label)`.
17. Перед пушем — `uv run python scripts/preflight.py` со своей `DB_NAME`; новые строки — во все пять `.po` парой
    (msgctxt, msgid), дуп-чек polib-ом; `i18n_gap`/`msgfmt` — только на CI.
18. Хотфиксы в `main` запрещены; FF в `main` — только по «делай» владельца, после зелёного CI верхушки.
