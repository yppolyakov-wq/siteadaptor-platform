# PT — «типы акций»: разделить, выводить по отдельности, настраивать вывод

**Дата:** 2026-09-11 · **Повод:** запрос владельца: «у нас есть раздел акции и разные
типы акции. Нужно разделить типы один от другого, чтобы можно было выводить только
определённый тип акции, выбирать для неё шаблон, раскладку. И тип отображения, сетка
или слайдер, и далее управлять ими».

**Статус:** РЕШЕНИЯ ПРИНЯТЫ (владелец, 2026-09-11) — см. §5. Исполнение — §4.

## 1. Что сегодня есть (замер, не мнение)

Три разведки по коду. Факты с путями.

### 1.1 Сколько «типов» у акции на самом деле — четыре независимых оси

| Ось | Поле | Значения | Что это семантически |
|---|---|---|---|
| **Механика брони** | `Promotion.promo_type` `models.py:213` | `discount` \| `reservation` | единственное поле, которое в форме называется «Art der Aktion» (`forms.py:75`) |
| **Стиль показа цены** | `Promotion.discount_style` `models.py:257` | 9 кодов: `""`, `percent`, `badge`, `strikethrough`, `festpreis`, `ab`, `countdown`, `surprise`, `mystery` | **чистая презентация**, не механика (`_discount_display.html`) |
| **Цель** | `product` / `service` / `stay_unit` / `combo` `models.py:177-201` | + `target_kind` `models.py:420` | на что действует ценовой слой (волна PL) |
| **Рубрика** | `Promotion.group` `models.py:282` | свободный текст, `max_length=50` | то, что владелец видит на витрине как раздел |

Плюс флаги, которые читаются как «тип» глазами посетителя: `is_surprise` `:238`,
`recurrence` `:275`, `is_new` `:452`, `available_quantity` `:225`.

**Вывод:** поля «тип акции» в полном смысле нет. Чипы механики
(`_discount_display.html:97-119`, part `flags`) собираются из четырёх разных признаков —
и комментарий на `:98` прямо ссылается на прошлый фидбэк «не понимаю, какие типы акций».

### 1.2 Рубрики (`group`) — де-факто уже «типы»

В демо `aktionsmarkt` это ровно типы, а не произвольные ярлыки
(`demo_kits.py:3846+`): **Wochenangebote · Dauertiefpreis · Anti-Food-Waste · Räumung**.
У других китов — «Mittagstisch», «Happy Hour», «Kombi-Menüs», «Limitierte Angebote».

Что рубрика уже умеет:

* **страница только этого типа** — `?gruppe=<имя>` (фасет `facets.py:50,60`), это
  отдельная поверхность `promo_group` (`compositions.py:69-80`);
* **свой шаблон страницы** — 11 композиций, выбор на группу:
  `site_config["promo_groups"][<группа>] = <код>` → дефолт `site_defaults.promo_group_style`
  (резолвер `group_styles.py:32-43`);
* **пункт меню на тип** — цель `promo_group` уже в реестре (`tenants/menu.py:607`);
* **секции по типам на `/aktionen/`** — `public_views.py:589-649`, порог 2 карточки,
  ссылка «Alle …» при обрезке;
* **панель настройки в кабинете** — «Vorlagen der Gruppenseiten»
  (`promotion_list.html:70-81`, запись `views.py:283-300`), строки строятся по ЖИВЫМ
  акциям, а не по словарю.

### 1.3 Чего нет — ровно то, что просит владелец

| Просьба | Статус | Причина |
|---|---|---|
| «выводить только определённый тип» | **частично** | по рубрике — да (страница + меню). По механике (Mystery, Überraschung, Vorbestellung, Countdown) — нет: из механик фильтруется только `Reservierbar` (`facets.py:53`) |
| «выбирать для неё шаблон» | **есть** | композиция страницы группы (DL-20) |
| «…раскладку. И тип отображения, сетка или слайдер» | **НЕТ** | сетка у обзора и у страницы группы — **один общий ключ** `promo_index_layout` (`studio_pages.py:492-508`, `siteconfig.py:1806`). Своей раскладки у типа быть не может по построению |
| «форма карточки под тип» | **НЕТ** | `card_style` есть у акции и у сайта, у рубрики — нет (`card_forms.py:79`) |
| «выводить тип отдельной секцией на главной» | **НЕТ** | секция `promotions` одна и без скоупа (`sections/_promotions.html`), лимит 9 |
| «управлять ими» | **частично** | списка типов как объекта нет: рубрика набирается текстом в форме каждой акции (`forms.py:166`), переименование в одной акции осиротит запись словаря (это уже учтено fail-safe `group_styles.py:38`) |

## 2. Диагноз

Ось рубрикации в системе **уже есть и работает** — ей не хватает трёх вещей:
статуса объекта (список, порядок, переименование), **собственных осей вывода**
(сетка/слайдер — сегодня глобальные) и **второй поверхности** (секция главной).

Поэтому правильный ход — не заводить новую сущность рядом с рубрикой (это дало бы
пятую ось в системе, из которой волна LAY только что вычищала «кашу»), а **достроить
рубрику до полноценного «типа акции»**.

Отдельный вопрос — **механики** (Mystery / Überraschung / Vorbestellung / Countdown /
Dauerangebot). Они выводятся из полей и не требуют ручной разметки. Их честное место —
**встроенные типы** в том же списке: владелец не заводит их руками, но может дать им
шаблон, раскладку и вывести отдельной страницей/секцией.

## 3. Предлагаемая архитектура (ноль миграций)

### 3.1 Модель «тип акции»

Единый реестр `apps/promotions/promo_types.py`:

* **Свои типы владельца** — значения `Promotion.group` (как сегодня). Поле не трогаем,
  меняем только подпись в кабинете на «Typ / Rubrik».
* **Встроенные типы** — производные от полей, ключ с префиксом `sys:`:
  `sys:mystery` (`discount_style="mystery"`), `sys:surprise` (`is_surprise`),
  `sys:reservation` (`promo_type="reservation"`), `sys:countdown`
  (`show_countdown` или `discount_style="countdown"`), `sys:dauer` (`recurrence`).
  Предлагаются владельцу только те, у кого есть хотя бы одна живая акция
  (правило STU-9: не обещать пустое).

Каждый тип — это **ключ**, по которому работают фильтр, настройки и поверхности.

### 3.2 Настройки типа: расширяем `promo_groups`

Сегодня `{<тип>: "<код композиции>"}`. Расширяем значение до словаря, строку читаем
как раньше (back-compat без миграции конфигов):

```
promo_groups: {
  "Anti-Food-Waste": {
     "style":  "schaufenster",     # композиция (есть сегодня, как строка)
     "layout": {...},              # НОВОЕ: своя сетка/слайдер (normalize_layout)
     "card":   "coupon",           # НОВОЕ: форма карточки типа
     "label":  "...",              # НОВОЕ (опц.): подпись, не ломая ключ фасета
  }
}
```

Всё presence-minimal → golden-эталоны `normalize` целы (`test_normalize_golden.py`).
Капы прежние: ключ ≤ 50, типов ≤ 60 (`siteconfig.py:3479-3480`).

### 3.3 Где тип выводится

1. **Страница типа** — `?gruppe=` (есть) + `?typ=sys:mystery` для встроенных (новое,
   тем же провайдером `PromoFacets`).
2. **Секция главной на тип** — параметризованная секция акций со скоупом
   (`sections[i].scope`), можно несколько.
3. **Пункт меню** — цель `promo_group` (есть) + встроенные типы в тот же селект.
4. **Секции на `/aktionen/`** — как сегодня, но каждая секция берёт раскладку своего
   типа (сегодня — общую).

### 3.4 Управление

Экран **«Aktionstypen»** (вкладка Marketing рядом с акциями): список типов с числом
акций, порядок (drag), подпись и переводы, видимость в меню/на главной, и три оси
вывода на каждый — шаблон · сетка/слайдер · форма карточки. Панель
«Vorlagen der Gruppenseiten» становится входом на этот экран.

## 5. Решения владельца (2026-09-11)

* **Р-1 = (a).** Тип — ОДНА ось: свои рубрики владельца (сегодняшний `group`) **плюс
  встроенные механики** (`sys:mystery`, `sys:surprise`, `sys:reservation`,
  `sys:countdown`, `sys:dauer`) в том же списке. Встроенные выводятся из полей —
  руками размечать не нужно. Миграций нет.
* **Р-2 = да.** На главной можно вывести **несколько секций акций разных типов**,
  каждая со своим шаблоном и раскладкой.
* **Р-3 = полный набор.** На тип настраиваются **шаблон · раскладка · сетка/слайдер ·
  форма карточки**.
