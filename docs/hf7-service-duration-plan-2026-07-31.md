# HF-7: длительность услуги, календарь сразу, ярлык украинского (план, 2026-07-31)

Три пункта фидбэка владельца после HF-6.

## 1. Бронь услуги на несколько единиц времени подряд («с 8:30 до 12:30»)

**Что не так.** HF-6c дал мультивыбор РАЗНЫХ времён (два-три отдельных визита) —
это не то же самое, что один непрерывный отрезок. Хуже: когда услуга длиннее
шага сетки (90 мин при шаге 30), соседние старты пересекаются и как набор
отвергаются, поэтому «8:30–12:30» одним куском собрать было нельзя в принципе.

**Решение — «сколько единиц».** Гость выбирает, сколько подряд идущих единиц
услуги берёт: `?dauer=N` (1 = сегодняшнее поведение байт-в-байт). Сетка стартов
считается на суммарную длительность `N × duration_minutes`; бронь — ОДНА запись
`Booking` с `end = start + N × duration`, цена = N × цена дня (HF-5 сезонность
считается по дате старта).

Почему не «клик заезд → клик выезд», как у номеров: у услуги единица неделима
(мойка 60 мин нельзя взять на 90), поэтому честный ввод — количество единиц, а
не произвольные границы. Подпись показывает получившийся отрезок («08:30–12:30 ·
4 Std.»), так что неоднозначности нет.

Движок это уже умеет: `free_slots(resource, day, duration_minutes=…)` принимает
произвольную длину. Дополняем сквозным параметром:
- `availability.service_slots(service, day, resource=None, duration_minutes=None)`
- `availability.assign_resource(service, start, resource=None, duration_minutes=None)`

Мультивыбор HF-6c остаётся: каждый выбранный старт = блок из N единиц; блокировка
пересечений считается по суммарной длительности.

**Кап.** N ≤ 8 единиц (больше — это уже аренда на день, отдельный сценарий) и
физически не больше окна расписания: недостижимые N в сетке просто не дают стартов.

**Замки.** `dauer=1` — прежний результат байт-в-байт (одна бронь, та же цена);
`dauer=4` даёт одну бронь 4×duration и цену ×4; занятая середина отрезка убирает
старт из сетки; мусор в `?dauer=` → 1.

## 2. Календарь сразу открыт, кнопка «забронировать» — после выбора

**Что не так.** Страница-деталь услуги (`/leistung/<pk>/`) — SEO-страница с
кнопкой, которая ПЕРЕЗАГРУЖАЕТ витрину на отдельный слот-пикер
(`/termin/leistung/<pk>/`). Гость жмёт «Termin buchen» → перезагрузка → и только
там календарь.

**Решение.** Слот-пикер (`#svc-box`: мастера → календарь → времена → buy-box)
рендерится ПРЯМО на детали: календарь виден сразу, кнопка брони (она же
открывает попап контактов) появляется только при выбранном времени — это уже
поведение `_buybox.html` (`sellable.buybox_ready`). Отдельная страница
`/termin/leistung/<pk>/` остаётся (на неё ведут письма, QR и старые ссылки) и
показывает тот же пикер.

Контекст пикера извлекается из `service_slots` в общий помощник и зовётся обеими
вьюхами; `?box=1` (fetch-своп без перезагрузки) обслуживает обе.

## 3. Украинский: ярлык «UA», код остаётся `uk`

Владелец: «Украинский обозначение не uk а ua». В переключателе показываем **UA**
— меняем ТОЛЬКО отображаемый ярлык (витрина + кабинет).

Внутренний код остаётся `uk`: это ISO 639-1 для украинского, на нём завязаны
`locale/uk/LC_MESSAGES/`, `.po/.mo`, `settings.LANGUAGES`, сохранённые у тенантов
`active_locales` и `Accept-Language` браузеров. Переименование в `ua` (это код
СТРАНЫ, не языка) обнулило бы переводы и настройки существующих тенантов.
