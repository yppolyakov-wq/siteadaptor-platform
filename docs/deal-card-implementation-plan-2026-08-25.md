Источник правды по виду — дизайн-канвас `docs/design/deal-card-2026-08-25/`
(15 архетипов, утверждён владельцем 2026-08-25 вместе с правками «статус в рейл»,
«номер одной строкой», «скидка между позициями и суммой», «шахматка у сделок со

## 1. Волны

**DC-1 «Один скелет» (без миграций).** Требование владельца 2026-08-25:
*«базовые функции и блоки должны иметь общие настройки — меняется один, меняются
все сразу»*. Поэтому не «похожие шаблоны», а ОДИН базовый шаблон
`core/deal_card_base.html`, от которого четыре карточки наследуются через
`{% extends %}`; общие блоки (голова, статус, клиент с чатом, связанные сделки,
календарь) живут в нём и в партиалах `core/_deal_*.html` — правка в одном месте
меняет все карточки. Порядок: голова (номер · внешний номер · бейджи · мета одной
строкой) → состав → **скидка** → суммы → оплата и счёт; рейл: **статус** → клиент
с чатом → доставка → связанные сделки. Только рендер: вьюхи, приёмники, FSM не
трогаем. Замки-характеризации ДО правок.

**DC-2 «Календарь» (без миграций).** Требование владельца: *«если есть календарь —
открывается сразу ниже сетки»* — то есть развёрнутым блоком во всю ширину ПОД
основной сеткой карточки, а не свёрнутым и не в узком рейле. Источник данных —
существующие движки: stay — занятость номера (Belegungsplan), booking — день
мастера/ресурса (Tagesplan), order — дни выдачи, когда слоты используются.
У заявок и билетов календарного движка нет — блок не показываем (честно).

**DC-3 «Статус выпадающим списком + вопрос об уведомлении».** Кнопки → меню
(паттерн `_row_status_menu`), в форме — чекбоксы «клиента» / «команду».
Сервер обязан уважать флаг: сегодня письма уходят всегда → сквозной параметр
`notify` через `transactions.apply_action` в доменные `enqueue_*`. Средний риск,
идёт отдельным инкрементом со своими замками.

**DC-4 «Внешний номер везде» (⚠️ миграции).** `external_code` у брони, записи,
заявки, билета — аддитивные поля + поиск сделок (`sales_page`) + карточка.

**DC-5 «Скидка везде» (⚠️ миграции).** Ручная скидка владельца у job/stay/booking
по образцу `Order.discount_cents` + пересчёт итога тем же хелпером, что промокод.
Область действия (позиция / вся сделка / доставка) — как в макете.

**DC-6 «Счёт из брони и записи» (⚠️ миграция или сервис).** `invoice_from_*`
по образцу `invoice_from_order`; выбор языка — существующий `doc_langs`.

**DC-7 «Карточка билета»** — экран, которого нет вовсе (новый URL + шаблон).

## 2. Порядок

DC-1 → DC-2 → DC-3 → DC-4 → DC-5 → DC-6 → DC-7. Первые три без миграций и
дают владельцу ровно тот вид, который он утвердил; остальные добавляют
недостающие поля по одному, каждый со своим деплоем.

## 3. Инварианты волны

- Только рендер, пока волна не помечена «⚠️ миграции»; FSM/приёмники/URL целы.
- W0: скрытие — CSS, поля остаются в DOM (форма не должна терять значения).
- Характеризационные замки ДО перестановки блоков (прецедент UA3-1/_buybox).
- Новые классы Tailwind → `npm run build:css` в том же коммите.
- Новые msgid → пять каталогов (`scripts/i18n_quickcheck.py` перед пушем).
