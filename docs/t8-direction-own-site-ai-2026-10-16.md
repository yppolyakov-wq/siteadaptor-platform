## 1. Короткий ответ

1. **Да — открыть вход для бизнесов со своим сайтом как ступень «−1 · Nur Eintrag»**
   (перед «Nur Aktionen»). Это не урезанный тариф, а крючок плотности: главный риск
   каталога — пустота (все городские площадки умерли на 30–60 продавцах), а порог
   «заведи наш сайт» отсекает тех, у кого Instagram и Google-профиль уже есть.
2. **Рынок DACH сошёлся на одной схеме:** листинг бесплатен или дёшев · плата — за
   результат (новый клиент, выданный пакет) · **свой канал бизнеса — всегда без
   комиссии** (Treatwell, OpenTable, Too Good To Go, eBay «Deine Stadt»). Мы должны
   повторить ровно это.
3. **Три механики, все без переезда бизнеса:** **импорт с его собственного сайта по его согласию** (ИИ извлекает →
   владелец проверяет → каталог ведёт на его сайт), **не наш виджет у него**. Чужие сайты
   без согласия не скрейпим — фото/тексты это Urheberrecht, цена без воли продавца —
   UWG/PAngV; свой сайт, отданный владельцем, — другое дело.
4. **ИИ:** три ставки `t8-ai-layer` рынок подтвердил (данные важнее протоколов,
   ИИ-ввод владельца, синк с Google). Сверх них две дешёвые: «источник правды для
   ассистентов» (свежесть данных) и «ИИ-проверка перед публикацией» (PAngV/UWG/LMIV).

## 3. Предложение: ступень «−1 · Nur Eintrag» — импорт с сайта клиента

**Уточнение владельца (2026-10-16):** речь не о нашем виджете на чужом сайте, а о том,
чтобы **взять данные с сайта клиента, положить их в каталог и вести посетителя на его
сайт**. ИИ извлекает, владелец проверяет и правит, затем публикует. Это и есть
«интеграция в наш сайт» для тех, кому полный функционал не нужен.

| Ступень | У бизнеса есть | Мы даём | Цена |
|---|---|---|---|
| **−1 · Nur Eintrag** (новое) | свой сайт / Instagram / GBP | карточка бизнеса + его предложения в каталоге, **собранные с его сайта ИИ и подтверждённые им**; переход → на его сайт; акции через ассистент 3 экрана | 0 € до 5 активных акций (Р-5) |
| 0 · Nur Aktionen | ничего | визитка на нашем поддомене + всё выше | 0 € |
| 1–4 | — | как в `t8-aktion-start-lite-analysis §9.2` | 39 €+ |

### 3.1 Как работает импорт (T-8.27)

1. **Вход.** На `/aktion-starten/` вариант «Ich habe schon eine Website» → URL + e-mail.
   Согласие на обработку — он сам даёт нам свой сайт, это не скрейпинг чужого
   (юридическая разница с §2: право на тексты/фото у него, он подтверждает их чекбоксом).
2. **Сбор.** Наш fetcher (уже есть SSRF-гард `apps/core/ssrf.py`) берёт главную +
   страницы «Angebote/Speisekarte/Preise/Öffnungszeiten/Kontakt/Impressum» (≤ ~20 страниц,
   по ссылкам с главной, robots.txt уважаем). Фото — ссылки, копируем только после его
   подтверждения.
3. **Извлечение ИИ** (первый реальный потребитель общего интерфейса провайдера, который
   нужен и T-8.10): **структурированный JSON** по нашей схеме — название, адрес, район,
   часы, телефон/WhatsApp, категория каталога города (справочник T-8.13a) + признаки,
   описание ≤300 знаков, список предложений {название, цена, единица, фото, срок?}.
   Правило `t8-ai-layer`: **модель готовит черновик, не публикует.** Температура низкая,
   схема валидируется кодом; что не сошлось — пусто, не выдумано.
4. **Проверка владельцем.** Один экран «Prüfen & veröffentlichen»: карточка слева,
   предложения чекбоксами, каждое поле правится, цена обязательна к подтверждению.
   Публикация → листинги `business` + `product`/`service` (виды T-8.11 уже есть),
   `detail_url` = его страница. Атрибуция `?ch=portal` цела.
5. **Поддержание свежести.** Раз в N дней повторный сбор → **диф** («цена изменилась»,
   «страница пропала») → письмо «Bestätigen» одной кнопкой; без подтверждения через M
   дней позиция гаснет (то же автопротухание, что нужно не-акциям). Это закрывает
   главный риск отчёта — мёртвый каталог.

### 3.3 Ограничения и риски именно этого пути

- **PAngV на импортированных ценах:** истории цен у чужого сайта нет → **никаких «statt»
  и процентов** у импортированных позиций (SF-7 их не прикроет); только цена «ab …».
  Снижения — только через нашу акцию (ассистент), где история ведётся.
- **Фото:** на сайте клиента могут быть стоковые фото, лицензированные ему, а не нам →
  чекбокс «Ich habe die Rechte» + хотлинк не используем, копия только после подтверждения.
- **Качество извлечения** на сайтах Jimdo/Wix с меню в картинках/PDF — ИИ вытащит мало;
  честный фолбэк: карточка бизнеса без предложений + ассистент акций.
- **ИИ-стоимость:** ~20 страниц × 1 запрос на бизнес при входе, далее дифы по хешу
  страницы — бюджет копеечный, лимит по IP/бизнесу обязателен.
- **EU AI Act ст. 50:** на экране проверки — «Vorschlag automatisch erstellt».

## 4. ИИ-будущее: что сверх `t8-ai-layer`

Очередь отчёта сохраняется: **T-8.10a/c (ИИ-ввод владельца) → GBP-синк → T-8.10d (поиск
фразой) → T-8.10f (MCP только чтение) → оплата через агентов — заморожена.** Дополнения:

1. **T-8.28 «источник правды для ассистентов».** Ассистенты верны в 48–56 % ответов о
   местных бизнесах. JSON-LD/фид/llms.txt у нас есть (T-8.8); не хватает **честной
   свежести**: «проверено владельцем <дата>», автопротухание не-акций, `lastmod` только
   при реальном изменении (T-8.26 это уже держит для снимков).
2. **T-8.10e ИИ-проверка перед публикацией — поднять приоритет.** SF-7 закрыл
   арифметику; остаётся текст («garantiert», превосходные степени, «bio» без кода,
   аллергены) — подсказка, не блокировка. Единственная ИИ-функция, за которую
   микробизнес в Германии платит уже сейчас (страх абмахнунга).
3. **Подписка на намерение** — после T-8.7 и T-8.20 остался один шаг: сохранённый
   запрос → сверка SQL при активации акции; ИИ нужен один раз.
4. **T-8.10b ассистент владельца в Telegram** — ниша в DE пуста; привязка владельца
   есть (UD4-2), не хватает приёма команд.
5. **EU AI Act ст. 50 (с 02.08.2026):** пометка «создано с ИИ» на черновиках/ответах —
   заложить в общий интерфейс провайдера (T-8.10d) сразу.

**Не делать:** генерация фото товаров (решение AMP), оплата через агентов (свёрнута даже у
OpenAI), ставка на `llms.txt`, «ИИ-конструктор сайта» (<1 % трафика из LLM у Wix).
