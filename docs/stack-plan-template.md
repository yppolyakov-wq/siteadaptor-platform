# Образец плана стопки — с таблицей срезов, которую проверяет программа (T-14.2)

Скопировать в `docs/<задача>-stackNN-plan-<дата>.md`. Остальные разделы плана — как в
`docs/fb33-stack12-plan-2026-11-23.md` (макеты цитатами, что видно в коде, замки первого коммита,
прогноз эталонов и строк `.po`, исполнители и базы, ECC-прогоны, риски, ответы владельца, итог).

Обязательное — таблица ниже. До раздачи срезов: `uv run python scripts/plan_check.py <план>` — он
печатает волны (что можно вести параллельно) и расхождения. После кода, до свода:
`uv run python scripts/plan_check.py <план> --verify --base <коммит P0>`. Стопка берётся в работу
командой `uv run python scripts/work_map.py --set <N> "в работе"`.

Как заполнять:
- **Зависит от** — срезы этой же стопки, после которых можно начинать; «—» — можно сразу.
- **Свои файлы** — в бэктиках через запятую. Номера строк (`apps/core/detail_sections.py:137-141,213-216`)
  — ориентир, что правится. **Файл повторяется в двух срезах — срезы идут по очереди:** второй
  зависит от первого и берёт его ветку как базу (T-17). Разные строки не спасают: первый срез их сдвинет.
- **Одновременно — не больше трёх срезов.** Исполнители — главная строка расхода; шире волну
  `plan_check` не пропустит. Шаблон имени — `templates/tenant/_bw_*.html`.
  Нового файла ещё нет — с плюсом: `+apps/core/new_part.py`. Свои тесты (`tests/test_*.py`) не пишем.
- **Общие файлы** — только координатор на верхушке: `static/css/app.css`, общие эталоны окна, `.po`.
- **Эталоны** — сколько файлов эталонов изменит срез; `0`, если не задевает. Не знаешь — выясни
  прогоном до плана: «?» программа считает находкой.
- **Ветка** — заполняется, когда срез отдан; по ней идёт сверка после кода. Срез на ветке другого
  среза — диапазоном `ветка-предшественника..ветка-среза`, иначе ему достанутся чужие файлы.

## Исполнители и расход (T-16)
- Исполнитель: `uv run python scripts/preflight.py --slice` → пуш ветки `claude/<задача>-<срез>` → конец хода.
  Полный прогон среза — CI на этой ветке; его читает координатор. Долгих тестов в ходе агента нет.
- Находки ревью — одной пачкой на круг. Мелкая правка — свежему исполнителю (находка, файл, красный тест);
  сложная — прежнему.
- Задание исполнителю — со справкой `scripts/codemap.py --plan <план>` по его файлам, а не «прочитай модуль».
- Полный `preflight`, сборка `app.css`, общие эталоны, `.po` — координатор на верхушке, один раз.
- В конце — расход сессии в снимок (`--cost`, `--agents`).
