# FLT-4 — фильтры списков кабинета (план, 2026-11-04)

Третья часть волны FLT («портал → витрина → кабинет», порядок владельца). Портал —
`flt-portal-filters-plan-2026-11-04.md`, витрина — `flt3-storefront-filters-plan-2026-11-04.md`.

## 0. Разведка (что есть)
- Общего компонента фильтров в кабинете нет: каждый список собирает свою `<form method="get">`,
  13 шаблонов отправляют форму по `onchange` (WCAG 3.2.2), все строки фильтров — `flex-wrap`
  (на 390 px — 3–6 строк над списком, инструменты вперемешку с фильтрами).
- Правильная серверная форма уже есть у «Rechnungen»: `apps/finance/invoice_list.py`
  (белый список, счётчики, чипы через `query_with`). Пагинация — `paginate_queryset`
  (`QueryPage.total` даёт «N Treffer»), перенос состояния — тег `query_with` / `list_pager`.
- Шторка UX-D (`sf-drawer`) — fetch-фрагменты и POST-формы; фильтр-форма должна жить в
  странице и работать без JS → отдельный `<dialog id="flt-drawer" class="ui-drawer">`
  (CSS шторки переиспользуем, поведение — общий `static/js/portal.js`).

Найденные дефекты переноса состояния (чинятся первым инкрементом):
1. CRM внутри вкладки «Kunden» продаж: форма поиска и «Mehr anzeigen» не несут `tab=kunden` —
   поиск выкидывает из вкладки.
2. Sortiment: в режиме «Alle N» (`?art=`) форма поиска теряет `art`/`ansicht`.
3. Verkäufe › Liste заказов: форма поиска теряет `abholung`/`zahlung`.
4. `_PAGER_DROP` не снимает `drawer` — открытая шторка «прилипает» к ссылкам пейджера и чипов.

## 1. Компонент
- `apps/core/list_filters.py` — описание фильтров списка как данных: `FilterSpec(key, label,
  options | kind)`; `build(request, specs, keep=…)` → активные пилюли (подпись + ссылка «✕»
  без этого ключа и без `seite`), число активных, скрытые поля состояния (всё, что не правит
  шторка: `tab`, `view`, `art`, `ansicht`, `sort`…).
- `templates/core/_list_filter_bar.html`: строка = поиск (виден всегда) · «Filter · N» (открывает
  шторку) · сортировка с кнопкой «OK» (без автоотправки) · «N Treffer» (`role=status`); ниже —
  пилюли активных фильтров с ✕ и «Alle zurücksetzen». Шторка — одна GET-форма со всеми
  фильтрами списка, скрытые поля — остальное состояние; «Anzeigen» / «Zurücksetzen».
- Инструменты (CSV, KDS, Tisch-QR, «＋») — отдельной строкой, не в строке фильтров.
- Без JS: кнопка «Filter» — ссылка на якорь формы, форма видна обычным блоком (как портал).

## 3. Замки
- W0: шторка каждого списка переносит каждый параметр состояния (как портал).
- Пилюля ✕ снимает ровно свой ключ и сбрасывает `seite`; «Zurücksetzen» оставляет `tab`/`view`.
- Без автоотправки: в шаблонах с компонентом нет `onchange="this.form.submit()"`.
- Права: поиск по контактам — только с `kunden.kontakte` (как сейчас), счётчики не раскрывают
  чужие данные.
