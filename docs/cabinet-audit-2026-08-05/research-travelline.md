# RESEARCH: travelline

## SUMMARY
Веб-поиск и загрузка страниц работали (WebSearch/WebFetch). Кабинет TravelLine (secure.travelline.ru, «экстранет») — единый ЛК, в котором меню слева собирается из подключённых продуктов (TL: Booking Engine, WebPMS, Channel Manager, Reputation и т.д.). Операционные разделы («Помощник»/«Создать бронь», «Бронирования», Шахматка, «Служба приема») стоят сверху, конфигурация — в трёх настройковых кустах («Настройки гостиницы», «Управление номерами», «Управление отелем»), биллинг и права вынесены в отдельный «Портал клиента» под логином. Базовое отделено от продвинутого тремя механиками: вкладки «Основные настройки»/доп-настройки на карточках сущностей (тариф, канал), getting-started-чек-листы «обязательное vs дополнительное», ролевые срезы (менеджмент/ресепшн/хаускипинг + инструкции БЗ по ролям). Онбординг — self-serve чек-лист со ссылками на разделы + видеокурсы/вебинары/телеграм-канал + персональное сопровождение и поддержка 24/7. Хвалят: интуитивный интерфейс, шахматку как главный рабочий экран, автосинхронизацию каналов без овербукинга, быструю поддержку и обучение. Ругают: путаницу «где что» при множестве модулей и продуктового нейминга, отчёты раз в сутки без кастомизации, жёсткий биллинг (отключение за копеечный долг), непрозрачный вход в доп-модули, периодические глюки/нераспределённые брони. Оговорка: точный состав верхнего меню зависит от подключённых продуктов; структура реконструирована по путям меню, дословно цитируемым в инструкциях базы знаний (прямых скриншотов меню в открытом доступе мало; blog-статья о редизайне меню 2014 г. подтверждает только «меню слева, популярные разделы списком»).

## IA STRUCTURE
Личный кабинет TravelLine (экстранет, secure.travelline.ru) — меню слева, разделы → подразделы:

1. ОПЕРАЦИОНКА (верх меню)
├─ Помощник
│  └─ Создать бронь (встроенный модуль TL: Booking Engine — даты → тариф/категория → гость → способ оплаты → «Забронировать»)
├─ Бронирования — все брони из всех источников (сайт, каналы, шахматка, экстранет)
├─ Шахматка (TL: WebPMS) — ГЛАВНЫЙ рабочий экран: календарь броней; из брони — заселение/выселение, услуги, оплаты, счета, чеки
└─ Служба приема — сводка дня (заезды/выезды/проживающие, статусы номеров); позиционируется для объектов 40+ номеров

2. НОМЕРА И ЦЕНЫ («Управление номерами»)
├─ Категории номеров
├─ Тарифы — карточка тарифа с вкладками: «Основные настройки» (вкл. блок «Источники продаж»: сайт / шахматка / экстранет) + доп. правила
├─ Доступность номеров — квоты, открыть/закрыть продажи, «Доступность по умолчанию»
├─ Размещение детей (возрастные диапазоны × ценообразование)
└─ Ранний заезд / поздний выезд

3. PMS-КОНТУР («Управление отелем», появляется с TL: WebPMS)
├─ Номерной фонд — корпуса, этажи, физические номера
├─ Обслуживание номеров (хаускипинг, статусы уборки)
├─ Профили гостей (+объединение дублей)
├─ Справочник компаний (юрлица/партнёры)
├─ Кассы (смены, чеки, ККМ) · Финансовый учет
├─ Миграционный учет (регуляторный модуль РФ)
├─ Заметки и указания
└─ Настройки (WebPMS)

4. КАНАЛЫ (TL: Channel Manager)
└─ Управление каналами
   ├─ вкладка «Все доступные каналы» → «Подключить» (мастер: подтверждение договора → чекбоксы категорий/тарифов для выгрузки)
   └─ карточка канала: «Настройка канала» (активация, тарифный план по умолчанию, блок доступности, лимит номеров, период выгрузки, ID отеля) + «Сопоставление номеров и тарифов» (канал слева ↔ TL справа, авто-маппинг) → «Активировать канал»

5. ОТЧЁТЫ («Отчеты»)
├─ Отчет по броням (фильтры по источнику и т.д.)
└─ Документооборот / шаблоны документов (счета, акты)
   (расширенная аналитика — отдельный компонент «Аналитика», вход: логин в правом верхнем углу → «Аналитика»; + TravelDB)

6. НАСТРОЙКИ ГОСТИНИЦЫ («Настройки гостиницы»)
├─ Общие настройки — логотип, расчетный час, контакты, выходные, детские возрасты, ограничение позднего бронирования, политика перс. данных
├─ Банковские реквизиты
├─ Система налогообложения (НДС, ОСНО/УСН)
├─ Справочники — источники броней, способы оплаты
└─ Шаблоны документов

7. ПРОДУКТОВЫЕ МОДУЛИ (появляются в меню по мере подключения)
├─ TL: Booking Engine (модуль брони на сайт) · TL: Express (конструктор сайта)
├─ TL: Reputation (отзывы, AI-анализ) · TL: Rate Shopper (цены конкурентов) · TL: Price Optimizer
├─ TL: GMS (рассылки/CRM) · TL: Loyalty · TL: Order Management
└─ Интеграции (АСУ pull/push, amoCRM, 1С, публичные API/вебхуки)

8. ПОРТАЛ КЛИЕНТА (под логином, отделён от операционки)
├─ Документы (договор, счета TravelLine)
├─ Права и пользователи (доступ сотрудников)
└─ Профиль

9. МОБИЛЬНОЕ ПРИЛОЖЕНИЕ TL: Extranet — Панель управления, шахматка, репутация, push о новых бронях, 2FA

БАЗОВОЕ vs ПРОДВИНУТОЕ: (а) вкладка «Основные настройки» + отдельные «Дополнительные настройки» на карточке тарифа/канала; (б) getting-started-чек-листы делят шаги на обязательные (категории → доступность → тарифы → номерной фонд) и «дополнительные возможности» (финучёт, ККМ, шаблоны, справочник компаний); (в) 3 роли WebPMS — «Менеджмент» / «Служба приема и размещения» / «Хозяйственная служба» — режут и функции, и меню.

ОНБОРДИНГ НОВОГО ОТЕЛЯ: статья-хаб «Что нужно знать, чтобы начать работу» = последовательность: Настройки гостиницы (общие+реквизиты+НДС) → категории и тарифы → отчёт по броням/документооборот → номерной фонд WebPMS → интеграция АСУ → подключение каналов → опциональные продукты; каждая инструкция дублируется видео; + обучающие курсы, вебинары (регулярные + архив, «открытые уроки»), телеграм-канал, персональное сопровождение при запуске, поддержка 24/7 (8-800, support@).

## PATTERNS
- Операционка выше настроек: первый экран и верх меню — сегодняшняя работа («Помощник», «Бронирования», шахматка, «Служба приема»), конфигурация — внизу; владелец живёт в календаре, а не в настройках (наш аналог — Belegungsplan как entry «Verkäufe», подтверждение курса ST-5b)
- Календарь-шахматка = главный рабочий стол: все действия по сделке (заселение, услуги, оплаты, счета) делаются из карточки брони прямо в календаре, без ухода в другие разделы
- Раздел-«ассистент» с быстрым действием: «Помощник» → «Создать бронь» — ручная бронь создаётся тем же движком, что и клиентская с сайта (один флоу, паритет цен/квот) — совпадает с нашим принципом «кабинет зовёт штатные движки» (UD2/kanban_action)
- Двухуровневые настройки на карточке сущности: вкладка «Основные настройки» отдельно, «Дополнительные настройки» отдельно (тариф, канал) — не одна портянка; наш аналог — Einfach/Experte + аккордеоны W4
- Getting-started-чек-лист как хаб: обязательные шаги vs «дополнительные возможности», каждый шаг = ссылка прямо в раздел кабинета + видео (наш SETUP_STEPS/AB6 — тот же паттерн, стоит добавить деление обязательное/опциональное)
- Прогрессивное раскрытие по размеру бизнеса: сводка дня «Служба приема» подаётся как отдельный экран «для 40+ номеров» — мелкому объекту не показывают лишний слой
- Три понятные роли вместо гранулярных прав: Менеджмент / Ресепшн / Хаускипинг — роль режет и меню, и функции (наш core.Membership — держать столь же короткий список ролей)
- База знаний сгруппирована двумя осями: по продуктам И по ролям («Инструкции для администратора», «для отдела бронирования») — язык задач, а не таблиц БД
- Биллинг SaaS отделён от операционки: «Портал клиента» (документы, счета, права пользователей) живёт под логином, не засоряя рабочее меню
- Подключение интеграции как мастер с авто-маппингом: подтверждение договора → чекбоксы что выгружать → сопоставление «слева канал / справа мы» с авто-предзаполнением → явная кнопка «Активировать канал» (наш Channel/G11 — перенять этот степпер)
- Fail-safe дефолты в интеграциях: «Тарифный план по умолчанию» ловит брони по несопоставленным тарифам — ошибка маппинга не теряет бронь, а деградирует мягко
- Обучение как продукт: видео в каждой статье, регулярные вебинары + архив, телеграм-канал, персональное сопровождение запуска — снижает нагрузку на поддержку и страх «сложной системы»
- Мобильное приложение-компаньон: push о новых бронях + мини-шахматка + панель показателей — минимальный операционный срез, не весь кабинет

## ANTIPATTERNS
- Меню из бренд-названий продуктов (TL: WebPMS, TL: GMS, TL: Order Management…): пользователь должен выучить внутреннюю номенклатуру вендора; в отзывах — «сложно найти нужное среди множества опций» и «не сразу понятно, как подключить доп. модули»
- Три параллельных куста настроек с неочевидными границами: «Настройки гостиницы» vs «Управление номерами» vs «Управление отелем» (+«Настройки» внутри WebPMS) — тарифы в одном, номерной фонд в другом, реквизиты в третьем; исторический рост модулей без пересборки IA
- Отчёты обновляются раз в сутки и почти не кастомизируются — владельцы прямо жалуются; realtime-цифры и гибкие срезы должны быть базой, не премиумом
- Жёсткий биллинг: отключение кабинета за минимальную задолженность («даже за 10 копеек») — операционная система отеля гаснет из-за бухгалтерской мелочи, это разрушает доверие сильнее любого бага
- Скрытый апселл: доп-модули существуют, но входы в них из кабинета неочевидны — пользователь узнаёт о функции от менеджера, а не из интерфейса (наш ответ — карточки «Funktionen»/Integrationen-лендинг с явными входами)
- Ошибки синхронизации показываются пассивно: «нераспределённые брони» и «вечно какой-нибудь глюк» без явной очереди «требует внимания» — проблемные объекты должны всплывать сами (наш LS-6 «Problem — Kunde wartet» — правильное направление)
- Редизайн без миграции смысла: обновление 2014 г. поменяло только обёртку меню («структура разделов осталась прежней») — визуальный рестайлинг не лечит запутанную IA, а двухнедельный тумблер «старое меню» лишь откладывает боль (ср. наш classic_ui — использовать как мост, не как вечный костыль)
- Разрозненные точки входа в аналитику: основные отчёты в меню, продвинутая «Аналитика» — под логином в правом верхнем углу, TravelDB — отдельным сервисом; один вопрос «как идут продажи» размазан по трём местам
