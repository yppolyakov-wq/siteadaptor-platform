# FB-30 — план по фидбэку владельца 2026-11-15

План агента `planner` (разведка кода, без правок), на утверждение. Источник —
`docs/fb30-feedback-2026-11-15.md`. Макеты — `docs/design/fb30-2026-11-15/Entwuerfe.dc.html`.

## 0. Коротко

- Два настоящих бага баннера главной: текст библиотечного баннера не попадает ни в один вид,
  кроме слайдера; кнопка баннера без ссылки подменяется кнопкой «Sortiment».
- «Ширина» и вид баннера «ничего не меняют»: выбранный из библиотеки баннер всегда рисуется
  слайдером во всю ширину; одиночный блок ½ в списке структуры выглядит как блок во всю ширину.
- «Übernehmen» у «Willkommensbanner» остался, потому что форма настроек типа страницы не
  подключена к автоприменению.

## 1. Баннер

**Сейчас.** Форма — одна колонка (`templates/tenant/banner_form.html:7`). «Wo zeigen»: флажки
сохранённых мест, отдельная GET-форма поиска, результаты флажками. Виды мест —
`SHOW_ON_TYPES` (`apps/core/banners.py:586`): категория, товар, услуга, акция, номер, событие,
тур; главной нет. На главную баннер попадает только через строку «Banner» в «Seitenaufbau»
(`site_config["hero_banners"]["pick"]`, `site_schema.py:865`, `:1392-1416`) и только после
«Speichern» черновика.

**Баг текста.** `_hero.html:4` рисует слайдер с текстом баннера только при
`site.hero_banners.pick and slides`. Остальные ветки (split, fullscreen, bento, фото, accent,
plain) выводят `site.hero_title|default:request.tenant.name`, старый `hero_text` и кнопку
главного раздела (`_hero_cta.html:6-7`); фото берут из `site.hero_image` / `slides.0.image` /
`site.heroes.0.image`. Состояния, когда баннер в библиотеке есть, а на главной не его текст:

- S1 — не выбран для главной: текст из старых полей, фото из старого слайда (того же, что
  перенесён в библиотеку).
- S2 — выбран, но выключен или вне срока: `slides` пуст, срабатывает ветка вида.
- S3 — выбран только в черновике «Seitenaufbau» без «Speichern».
- S4 — выбран, но у кнопки нет ссылки: слайдер показывает «Sortiment» (`_hero_slider.html:17-18`).
- S5 — выбран и активен: вид баннера игнорируется, всегда слайдер (замок
  `test_fb29_banner_pick.py:170`).

**FB-30.1.** Один источник: при заданном `pick` заголовок, текст, кнопку, ссылку и фото
первого живого баннера получают ВСЕ виды; слайдер — только при двух и более живых баннерах.
Кнопка без ссылки — подпись баннера, адрес главного раздела. При пустом `slides` и заданном
`pick` фото из старых `heroes` не берём. Старые поля не удаляем — запас, пока `pick` пуст
(откат `undo_legacy` цел). В Студии над текстом, который ведёт баннер, нет
`data-edit="hero_title"`. В форме и списке баннеров — строка состояния («auf der Startseite» /
«nur im Entwurf» / «ausgeschaltet» / «außerhalb des Zeitraums»).

**FB-30.7 (макет 1).** Форма в две колонки; «＋ Ort hinzufügen» → вид страницы → список этого
вида (`place_search` с фильтром по виду; без JS — GET `?art=`). «Startseite» — вопрос 2.

## 2. «Seitenaufbau»

- **(a) «Übernehmen» у баннера.** Плитки вида — настройка типа страницы
  (`_schema_settings.html:13-18,46`, `op=setting`); `aufbau.js:20` автоприменяет только
  `[data-schema-fields],[data-schema-list]` и ставит `op=update` (`:63`). **FB-30.2:**
  `[data-schema-setting]` в автоприменение с сохранением `op`; без JS кнопка остаётся. Действие
  одно — «Speichern» страницы.
- **(b) Примеры видов баннера.** Миниатюры у `home_hero` нет (`page_settings._thumb`
  `:433-438`). Готовое: сетка плиток с миниатюрой `_schema_settings.html:32-41`,
  `_pagelayout_thumb.html`, `_cardform_thumb.html`, `_schema_thumb.html`. **FB-30.6 (макет 2):**
  `_herostyle_thumb.html` — пять схем.
- **(c) «Breite» ничего не меняет.** У строки баннера главной есть «Ganz / Randlos»
  (`site_schema.py:1155-1159`), но слайдер и фото-виды всегда `w-screen`. Одиночный узкий блок в
  списке структуры — `flex: N 1 0%` (`site_schema.html:141`): он один в ряду и растягивается на
  100 %, половина видна только значком «½». Правка уходит в черновик — сайт меняется после
  «Speichern». На телефоне доли не действуют по замыслу. **FB-30.3:** убрать ширину у баннера
  главной; узкий блок в списке занимает свою долю; подсказка «sichtbar nach Speichern».
- **(d) Панель «Kategorien».** У источника категорий способы «Welche»: `regel` (всегда) и
  `kategorie` = «Unterkategorien von» (`list_panel.py:267-271`, `:153-163`); у `regel` полей
  для категорий почти нет (`:358-362`, `:300-301`) — он ничего не меняет. Заголовки групп —
  голые «Welche» / «Wie» (`:434`, `:441`). Двойное «Wie» чтением кода не воспроизведено —
  искать на стенде. **FB-30.4:** способ без полей не показывается; единственный способ — без
  кнопок; найти и убрать второе «Wie». **FB-30.5 (тексты, макет 3):** заголовки по источнику —
  «Welche Kategorien gezeigt werden» / «Wie Kategorien aussehen»; способы «Automatisch», «Aus
  einer Kategorie», «Von Hand»; неверная подсказка «nach Übernehmen» (`:345`).
- **(e) Ширина как раскладка.** Рядов в данных нет: ряд вычисляется из подряд идущих узких
  блоков и `newline` (`siteconfig.group_block_rows` `:669-686`). Перетаскивание понимает
  горизонтальный ряд (`aufbau.js:219-226`), но бросок «рядом» не делает блок узким и не следит
  за суммой долей. **FB-30.8 (макет 4):** редизайн, ключи JSON те же, миграций нет.

## 8. Вопросы владельцу (рекомендация в скобках)

1. Кнопка баннера без ссылки ведёт в главный раздел с подписью баннера? (Да, плюс подсказка в форме.)

5. Ширину у приветственного баннера убрать? (Да: он всегда во всю ширину.)
6. Зоны курьера и пункты самовывоза перевести на ряды вместе с весом? (Да.)
7. Можно ли выключать «оплату на месте»? (Да — для заказов с доставкой и при другом включённом способе.)
8. Какие страницы, кроме главной, нужны в предпросмотре дизайна? (Главная, список, страница товара.)

`label(code, kind, fulfillment, tenant)`. Подвид «Vor Ort» и переключатель «Vor Ort bei
Lieferung» — `site_config["payment_on_site"]` (регистрировать в `normalize`), без миграции.

### 12b — экран «Zahlung» карточками (2026-11-15, до кода)

- Только экран `payment_settings` (вкладка «Zahlung»); слайд мастера остаётся на
