# T-8.30 «Mein Laden в Telegram» (Mini App) — план (2026-10-20)

Составлен агентом planner по `t8-29-30-integrations-miniapp-plan-2026-10-20.md §2` и решениям
владельца Р-1…Р-5 (§4 того же дока). Без миграций: токены, набор «уже видели», билеты выбора —
в Redis; флаг сессии — в существующей cache-сессии.

## 0. Опорные факты (проверены по коду)
- `links.active_links(uid)` уже фильтрует активные/не заблокированные; `links.is_owner`,
  `links.still_owner(tenant)`, `links.select(uid, link_id)`; Art. 18 — `rights.is_restricted(uid)`.
- Токен бота — `platform_bot.config.token()`; `bots.platform_bot()` = None, когда бот выключен;
  `config.apply_webhook()` ставит вебхук и команды — сюда добавим кнопку меню.
- Одноразовый вход e-mail — `core/owner_login.py`; его `consume_token` не атомарен, атомарный
  образец — `platform_bot/connect.py` (возврат `cache.delete`). Для Telegram — свой модуль.
- Сессии — cache backend; `SESSION_COOKIE_AGE` по умолчанию 2 недели; язык кабинета —
  `session["cabinet_lang"]`.
- Прод: `X_FRAME_OPTIONS=DENY`, CSP нет, Sentry `send_default_pii=False`, но тело запроса при
  ошибке уходит.
- `{% block lite_chrome %}` ещё не существует.

## 1. Решения
1. **Вход** `GET https://<base>/tg/app/` — отдельная страница: SDK telegram.org (только здесь),
   `POST /tg/app/auth/` c `init_data`. Без initData — «Bitte über den Bot öffnen». Эндпоинты
   `auth`/`waehlen` — `csrf_exempt`: аутентификация = HMAC initData (или серверный билет), плюс
   проверка Origin, тип тела, размер ≤ 4 КБ, лимиты по IP и uid; сессию на публичном хосте не
   создают. Telegram Web (iframe): страница входа кадрируется только `web.telegram.org`
   (`frame-ancestors`), переход — `openLink` в браузер (куки поддомена в iframe не уйдут).
2. **Проверка initData** `platform_bot/webapp_auth.py::verify`: строгий разбор, ключ =
   HMAC("WebAppData", токен), `compare_digest`, `auth_date` ≤ 300 с (+30 с на часы), повтор —
   `cache.add` по хешу; initData никогда не логируется (Sentry `before_send` чистит `/tg/app/`).
3. **Сопоставление** uid → активные связи → тенант → владелец (`owner_user_pk` только если он
   OWNER и активен; иначе единственный OWNER; иначе — вход по e-mail) + `still_owner`. Art. 18 —
   отказ. 0 связей — «сначала подключите бизнес в боте»; несколько — выбор (билет 120 с,
   атомарно, `links.select`).
4. **Передача** на поддомен — `core/tg_login.py`: токен 60 с, одноразовый, привязан к схеме,
   внутри `user_pk`+uid (не e-mail; e-mail-токен и tg-токен взаимно не принимаются).
   `tg/start/<token>/`: GET — автосабмит-форма (не расходует), POST — расход, повторная проверка
   владельца/связи/Art. 18, вход, ПОСЛЕ входа `session["tg_lite"]={uid, exp}` и
   `set_expiry(12 ч)`, язык кабинета из бота. Приёмник `user_logged_in` снимает флаг при любом
   другом входе (e-mail-вход в том же окне = полный доступ).
5. **Граница** `TelegramLiteScopeMiddleware` (process_view): истёк `exp` или пропала
   связь/владелец/появилось ограничение → выход + «Mini App neu öffnen»; разрешённый
   `view_name` — пропуск; кабинетный префикс вне списка → 302 на «Diese Seite ist in der
   Telegram-App nicht verfügbar» (+ «Mit E-Mail anmelden»), fetch → JSON 403; прочие
   защищённые экраны видят анонима. Список `TG_LITE_VIEWS` — лёгкие экраны, ассистент и
   превью акции, полная форма акции и товара (решение Q1), фото; НИКОГДА — оплата/подписка,
   команда, право, настройки, интеграции, свой бот, домены, импорт, Studio, палитра.
   «Sichtbarkeit» в tg-сессии прячет форму токена и активацию бота.
   Р-5: `lite_cabinet.is_lite_request(request)` — tg-сессия видит лёгкий кабинет и у полного.
6. **Бот:** `setChatMenuButton` («Mein Laden», web_app) в `apply_webhook`; кнопка
   «📱 Mein Laden öffnen» в меню, после публикации акции и в `/kabinett`.
7. **Хром:** флаг `tg_lite` в контексте, `{% block lite_chrome %}` прячет шапку/сайдбар/палитру,
   таб-бар остаётся; на страницах бизнеса SDK НЕ грузим — inline-шим `postEvent`
   (ready/expand/close), кнопка «Schließen» только при наличии моста.
8. **Ops владельца:** в @BotFather ничего обязательного — кнопки `web_app` и кнопка меню
   работают без `/newapp`. После деплоя: админка «Telegram platform bot» → «Webhook setzen»
   (поставит и кнопку меню). Юр.: фраза о Mini App в Datenschutz §8.

## 2. Решения по вопросам плана (по рекомендации, как Р-1…Р-5)
- **Q1** — полная форма акции и товара (+ фото) входят в Mini App (на них ведут «Bearbeiten»
  и «Fotos ergänzen»); варианты, категории, прочие виды — только по e-mail.
- **Q2** — кассовые экраны (сканер купонов, список резервов) — отдельным T-8.30e после стенда;
  в v1 — страница-объяснение.

## 3. Инкременты
- **30a** проверка initData + страница входа (публичный хост).
- **30b** передача + сессия с ограничением (тенант) + Р-5.
- **30c** кнопки бота + хром Mini App + i18n.
- **30d** стенд Playwright 390 px (лёгкое демо + полный кабинет + свой домен) → django +
  security ревью → CI → main.

## 4. Тесты до кода
Эталонный вектор HMAC (фиктивный токен, хеш зафиксирован и сверен независимой реализацией),
перестановка ключей и `signature`, подделки (поле/дата/лишнее/пропуск/чужой ключ/алгоритм
Login Widget), битый ввод, окно времени, повтор, отсутствие initData в логах; вьюхи: бот
выключен, Origin, лимиты, без связи, Art. 18, владелец понижен, два владельца, выбор (свой/чужой/
повтор/истёк), кадрирование; сессия: GET не расходует, POST входит, 12 ч, одноразовость, TTL,
чужая схема, перекрёстные токены, понижение владельца; список: разрешено/запрещено (вкл. POST
активации бота и подключения токена), JSON 403, аноним вне префиксов; замок полноты (каждая
ссылка лёгких шаблонов — в списке или «🔒»); истечение, отзыв связи, e-mail-апгрейд, обычные
сессии не тронуты, Р-5; кнопки бота и кнопка меню.

## 5. Риски
Подделка/утечка initData · кража токена передачи · выход за границу (deny-by-default + замок
полноты) · устаревшие права (проверка на каждый запрос) · флаг сессии между входами ·
сторонний JS на домене кабинета (только шим) · кликджекинг входа (frame-ancestors) ·
csrf_exempt (HMAC/билет + Origin + лимиты). Отложено: SDK на витрине грузить только при
initData (пред-существующее, roadmap).
