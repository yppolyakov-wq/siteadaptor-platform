# Батч D пилота — KA-P4a (пагинация «N von M») + KA-P4b (поиск клиента в счёте), 2026-10-23

План — агент planner (полный отчёт — в истории сессии); источник — `pilot-wave-plan §Батч D`,
`ka-7-desktop`, `ka-11 §3 P4`.

## Находки разведки
1. Доска режет 50 на ВЕСЬ вид сделки, а не на колонку: колонка «Neu» могла показывать «12» и
   ни одной карточки (done/cancelled съели лимит).
2. Пейджер CRM на вкладке «Kunden» продаж терял `tab=kunden`.
3. Тот же класс «201-го не выбрать»: композер Sofort-Angebot (200), справочник компаний сделки
   (200), складская опция (200).
4. `payment_summary` недосчитывает «offen» при >500 сделок.
5. Мусорный id клиента в POST формы счёта → 500.

## Решение
Offset `?seite=N`, 50 на страницу (счётчик «1–50 von 312», сквозная нумерация, nullable- и
составные сортировки — keyset их не держит); CRM остаётся keyset. Общие `pagination.paginate_queryset`
+ тег `{% list_pager page %}` (переносит все GET кроме `seite/box/cursor/next`) + партиал
`core/_list_pager.html`. Доска — лимит на колонку (Window RowNumber по статусу) + «+N weitere →»
в Liste с фильтром статуса. Sortiment — обзор 50 на вид + «Alle M anzeigen» (`?art=`), с `?art` —
пейджер.

## Инкременты
- **P4a-1:** ядро + Liste заказов + generic-Liste + доска + Sortiment + счета.
- **P4a-2:** входящие, отзывы, журнал, расходы, ваучеры, Reservierungen, Lieferungen, Zahlungen
  (+ `payment_summary`), «+N» в Auftragsbuch/Heute/CRM 360, пейджер CRM.
- **P4b:** поиск клиента в счёте (JSON `finance:customer-search`, фолбэк без JS, валидация UUID);
  P4b-2 — композер, компании, складская опция.

## Риски
Главная кабинета рендерит то же тело продаж — пейджер там ведёт в `verkaeufe`. Итоги журнала и
оплат — за весь период, не за страницу. Смена фильтра сбрасывает страницу.
