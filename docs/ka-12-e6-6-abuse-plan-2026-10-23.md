# KA-12 E6.6 — злоупотребление купонами/резервами, лимит 5 акций без гонки (план, 2026-10-23)

Источник: `ka-5fg-handwerk-lite-2026-10-23.md` L9/L10. **Без миграций** (настройки — `Promotion.metadata`
и `settings`). Решения Р-1…Р-4 приняты по рекомендации (владелец: «по рекомендации»).

## 0. Сверка с кодом
- **L10.** `limits.activate` = `can_activate()` (count) → `apply()` без блокировки. Через `activate` идут
  кнопка кабинета, ассистент и Telegram B-1 (`quick.publish_built`), ▶ в Telegram, `/aktion-starten/`.
  Beat (`roll_due_promotions`) — отдельная пара `can_activate` + `apply` → гонка и там.
- **L9 резерв.** Контакт не проверяется; остаток и лимит штук списываются уже в `pending` на TTL до 24 ч;
  лимит частоты только IP×акция → одна сеть прокси «выкупает витрину». `max_per_customer` без
  блокировки; телефоны «+49 171…»/«0171…» — разные клиенты.
- **L9 купон.** Два параллельных POST одного e-mail → два купона; «1 на человека» обходится новой
  кукой/адресом/пустым контактом; телефон без нормализации. Погашение уже однократное под блокировкой.

## 1. Решения
- **Р-1** проверку контакта для «Zurücklegen» НЕ вводим (бронь без аккаунта; телефон без SMS-канала).
- **Р-2** неподтверждённый резерв держит товар ≤ `PROMO_PENDING_HOLD_HOURS=4` ч; подтверждение
  владельцем продлевает до полного TTL (не дальше конца акции); `auto_confirm` — сразу полный TTL.
- **Р-3** опция акции «Coupon nur per E-Mail» (`metadata["coupon_delivery"]="email"`, выкл. по
  умолчанию): e-mail обязателен, код только письмом, браузер видит маску, кука не ставится.
- **Р-4** потолки в settings: резервов в сутки с IP по бизнесу 10; открытых резервов на контакт по
  бизнесу 3; купонов в сутки с IP на ограниченную акцию 3.

## 2. L10 (первым)
`limits.activate` — `transaction.atomic()` + `pg_advisory_xact_lock(hashtext('promo-limit:<schema>'))`
(только если лимит не None), `refresh_from_db(status)`, затем проверка и `apply`. `try_activate` →
bool для beat (каждая акция — своя короткая транзакция). Замок-скан: нет `apply(..., "active")` мимо
`limits` вне тестов/демо.

## 3. L9
1. `apps/core/contacts.py::phone_key` (цифры, `00`/`0` → `49`) — в поиске клиента и в
   `pickup_slots.contact_holds_too_many`.
2. `issue_coupon`: поиск+выпуск одной транзакцией под advisory `coupon:<schema>:<promo>:<customer>`.
3. `reserve`: advisory `resv:<schema>:<promo>:<customer>` вокруг `max_per_customer` + `_reserve_locked`;
   срок `pending` по Р-2, продление на `confirmed` в той же транзакции.
4. Потолки во вьюхах (`resv-day`, открытые на контакт, `coupon-day`), `ratelimit.refund` при отказе
   без побочного эффекта.
5. Р-3 во вьюхе купона + галочка в форме акции.
6. Бейдж «unbestätigt · läuft HH:MM ab» в списке резервов.

## 4. Замки (до кода)
`apps/promotions/tests/test_ka12_e66_abuse.py`: параллельная активация 5-й/6-й → ровно 5; beat против
кабинета ≤ 5; `try_activate` False; платный тенант без блокировки; скан `apply(..."active")`;
`phone_key`; параллельный купон одного e-mail → один Voucher; параллельный резерв при
`max_per_customer=1` → один; срок pending/продление; `resv-day`; 3 открытых на контакт; `coupon-day`
только на ограниченной; `coupon_delivery=email`; refund при невалидной форме; `isolated_ratelimit`.
