# Фидбэк владельца по витрине (2026-08-07) — план

Четыре замечания на демо `restaurant-demo`. Ниже — что показала разведка (факты,
а не догадки) и что делаем.

## FB-A. «Зачем кнопка Подробнее в меню? Тем более неработающая»

**Разведка.** Кнопка «Mehr ▾» — это overflow-дропдаун: `fitNav` в `_base.html`
прячет непомещающиеся пункты и показывает их копии в панели. Проверено в
браузере: панель **раскрывается** и по наведению, и по клику (тач-сценарий), в
ней лежат «Unser Team», «Über uns», «Kontakt». То есть механика не сломана.

Сломана **причина её появления**: контейнер шапки — `max-w-7xl`, меню получает
788 px и НЕ растёт с шириной экрана (замер: 1280/1440/1920 → одинаковые 788 px,
занято 659). А меню демо-ресторана я в этой же сессии раздул до **9 плоских
пунктов** — хвост честно уехал в «Mehr».

**Решение.** Не трогаем механику overflow (она страховка для длинных меню
владельцев) — убираем причину: второстепенные пункты демо-китов складываем в
осмысленную группу-дропдаун (тип `group` уже поддержан меню), напр. «Über uns» →
Galerie / Bewertungen / Unser Team / Kontakt. В строке остаётся 5–6 пунктов,
«Mehr» не появляется, а разделы никуда не деваются.

**Замок.** У каждого кита число пунктов ВЕРХНЕГО уровня ≤ 7 (эмпирический предел
для 788 px при средней длине немецкой подписи).

## FB-B. `/sortiment/` «выглядит непонятно, откуда-то взялось комбо-меню»

**Разведка.** Первым блоком страницы каталога идёт тизер комбо-наборов
(`combos_teaser`, `products.html` строки 24-41) — раньше категорий и раньше
товаров. Для гостя это «зачем мне это первым».

**Решение B1.** Тизер комбо уезжает ПОД сетку товаров; сверху остаётся уже
существующая компактная ветка-ссылка «🍔 Смотреть наборы и меню →» (она в
шаблоне есть и включается, когда тизера нет).

**Решение B2 — категории картинками.** `Category.images` уже есть (FB-6,
`catalog/0016`), но каталог рисует текстовые чипы. Делаем плитки с фото и
подписью; **фолбэк на чипы**, если у категорий нет фото (иначе у тенантов без
фотографий станет хуже, чем было).

**Решение B3 — размер картинок из Studio.** Новый ключ раскладки категорий
каталога (по образцу существующих `*_layout`, presence-minimal, чтобы golden
не поехал) + селектор в билдере: S / M / L. Правим только показ, данные не
трогаем.

## FB-C. «Диеты — часть параметров, должны быть в фильтрах»

**Разведка.** Диет-чипы (`Alle Diäten / Vegan / Vegetarisch / Glutenfrei`) —
отдельная строка НАД кнопкой «Filter», хотя цена/наличие/размер живут внутри
панели фильтров. Непоследовательно.

**Решение.** Диета переезжает в панель фильтров как обычный фасет; строка чипов
убирается. Проверить: `?diaet=` продолжает работать (ссылки из писем/поиска).

## FB-D. `/aktionen/` «выглядит незаполненной»

**Разведка.** Страница группирует акции по `group`, каждая группа — отдельная
секция с сеткой на 4 колонки. У ресторана 6 акций разложены на 5 групп → в
каждой строке одна карточка и три пустых места. Отсюда ощущение пустоты.

**Решение.** Группа получает свою секцию только если в ней достаточно карточек
(иначе акции идут общей сеткой); фильтр по группам остаётся чипами сверху —
он уже есть и работает. Порог и поведение — на реальных данных всех 14 китов,
чтобы у `aktionsmarkt` (17 акций, 4 группы) вид не сломался.

## Порядок и гейт

D → C → A → B (от дешёвого к дорогому; B несёт новый ключ конфига).
Каждый инкремент: локальный гейт (ruff + затронутые тесты + `i18n_gap`) →
браузерный стенд на демо → push → зелёный CI → FF-мерж в `main`.
