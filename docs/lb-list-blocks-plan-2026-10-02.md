## 1. Как это устроено сегодня

### 1.1. Три параллельные системы выводят списки

| Система | Где живёт | Сколько раз на странице | Что настраивается |
|---|---|---|---|
| **Фикс-секции главной** (`SECTIONS`: акции, товары, категории, услуги, номера, события, туры, блог, отзывы…) | только главная | каждая — один раз | заголовок/интро, лимит, раскладка (сетка/лента/колонки/ряды), стиль (`SECTION_STYLES`), у товаров — источник (новые/избранные) |
| **C-блоки** (`REPEATABLE_BLOCKS`: текст, фото, кнопка, …, `promo` — одна акция, `promo_list` — акции одного типа) + ссылочные `*_ref` | главная (в общем списке `sections`) и **любая** страница (`page_blocks[хост]`) | сколько угодно | у `promo_list` — только тип, заголовок, лимит; ВИД берётся у типа (экран «Aktionstypen») |
| **Листинг-страницы** (`/sortiment/`, категория, `/aktionen/`, `?gruppe=`, `/termin/`, `/unterkunft/`, `/veranstaltung/`, туры, наборы, Merkzettel, лукбук, отзывы, блог) | свой URL | один основной список | шаблон страницы (композиция), сетка/лента, форма карточки, сортировка, размер страницы; **поиск, фильтры, сортировка и пагинация живут в адресе** (`?q=`, `?farbe=`, `?sort=`, `?seite=`) |

Блоки страницы выводятся **только ПОСЛЕ** основного списка (`{% block listing_after %}`
в `listing.html`) — поставить блок над списком сегодня нельзя.

### 1.2. «Шаблон страницы» уже сам состоит из нескольких списков

Пример — `/aktionen/` без фильтров (`promotions_list.html`), сверху вниз:

1. шапка (обычная или фото-шапка «Kopfbild»);
2. чипы групп / вкладки / указатель (зависит от шаблона), системные чипы, поиск;
3. таблица («Preisliste») **или** крупная первая акция («Schaufenster»);
4. полоса **«Endet bald»** (≤4, заканчиваются в ближайшие 3 дня);
5. **«Vorschau»** — запланированные акции по бакетам начала;
6. **секции по типам** (у каждого типа — свой шаблон/сетка/форма карточки, PT-волна)
   **или** плоская сетка;
7. блоки страницы (`page_blocks["promos"]`) — в т.ч. те же `promo_list` по типам.

Каталог (`products.html`) так же собран из 10+ кусков: плитки категорий, чипы
подборок, полки, вкладки, первая позиция, сетка или прайс-лист, полоса наборов,
блоки страницы.

### 1.3. Где именно конфликт

* **Один и тот же список настраивается в двух местах.** Секция «Акции» на главной имеет
  свою сетку и стиль; страница `/aktionen/` — свою (`promo_index_layout`); тип акции —
  свою (`promo_groups[тип]`); блок `promo_list` берёт вид у типа. Товары: сетка секции
  главной ≠ `catalog_layout`.
* **Шаблон страницы решает, КАКИЕ списки есть на странице** (Endet bald, Vorschau, секции
  по типам) — и владелец этим не управляет: нельзя убрать «Vorschau», переставить «Endet
  bald», поставить свой блок между ними.
* **Блок не может встать над основным списком.**
* **Форма карточки — один ключ сайта на все виды** (`site_defaults.card_style` рисует
  товары, услуги, номера, наборы, туры), у блока своей нет.

Итог: «шаблон страницы» сегодня — это одновременно (а) структура основного списка,
(б) набор дополнительных списков вокруг него, (в) частично внешний вид. Поэтому
добавленный блок с ним и спорит.

## 2. Главное различие, на котором держится решение

Есть два принципиально разных вида «списка на странице»:

| | **Основной список** страницы («Hauptliste») | **Блок-список** («Liste», витрина) |
|---|---|---|
| Сколько на странице | ровно один, только на листинг-странице | сколько угодно, на любой странице и на главной |
| Что выводит | всё по адресу: фильтры, поиск, сортировка, страницы из URL | фиксированную выборку: источник + фильтр + сортировка + лимит |
| Зачем | найти нужное («каталог») | показать нужное («витрина», «подборка») |
| Ссылка «Все →» | не нужна | ведёт на основной список с тем же фильтром |
| SEO | каноническая страница раздела | часть страницы, где стоит |

Основной список **нельзя** превратить в «просто ещё один блок»: фильтр `?farbe=sand`,
поиск и пагинация должны знать, какой список они фильтруют, а поисковик — какая
страница каноническая. Зато всё ОСТАЛЬНОЕ (Endet bald, Vorschau, секции по типам,
«Новинки», «Хиты») — это блоки-витрины.

## 3. Предлагаемая модель

### 3.1. Страница = упорядоченный список блоков (как главная уже сегодня)

Главная **уже** так устроена: фикс-секции и C-блоки лежат в одном упорядоченном списке
`sections`. Расширяем это на все страницы:

```
страница /aktionen/ = [
  Liste «Endet heute»       (источник: акции, фильтр: заканчиваются сегодня, вид: лента)
  ★ Hauptliste              (все акции; поиск/фильтры/сортировка/страницы; вид = композиция)
  Liste «Räumung»           (источник: акции, тип: Räumung, вид: кольца, 4 колонки)
  Text-Block «Wie es funktioniert»
]
```

* `Hauptliste` — особый блок: ровно один на листинг-странице, не удаляется, **двигается**
  (блоки можно ставить над ним и под ним).
* Если владелец список страницы не трогал — `Hauptliste` неявно первая, блоки после неё:
  **ровно сегодняшний вид, байт-в-байт**, никакой миграции данных.

### 3.2. Блок «Liste» = ЧТО × КАК

```
data = {
  source:  promotions | products | categories | services | stays | events | tours | combos | reviews | blog
  filter:  по источнику — тип акции (тот же ключ, что ?gruppe=), категория, подборка,
           «новинки», «избранное», «со скидкой», «заканчиваются сегодня», «скоро»…
  sort:    ключи провайдера фасетов этого источника (FacetProvider.sort_keys)
  limit / rows
  title, intro, show_all («Все →» = основной список с тем же фильтром)
  view: {
    composition: сетка | лента | «Schaufenster» (крупная первая + сетка) | полки по
                 подгруппам | прайс-лист | …  (только применимые к источнику — гейт
                 `requires`, как у шаблонов страниц сегодня)
    layout:      колонки/мобильные/ряды/лента/скорость/хвост — тот же normalize_layout
    card:        форма карточки из реестра card_forms для вида сущности
  }
}
```

Это ровно **три оси волны LAY** (композиция · сетка · форма карточки), которые уже
заведены для страниц, — блок становится ещё одной «поверхностью» тех же реестров, а
не новой системой. Рендер карточек — общий контракт `SellableEntity` + `sellable_card`
(товар/услуга/номер/событие/набор), у акций — `_promo_card`; фильтр и сортировка —
`provider_for(kind)` (UB2-1), у акций — `promo_types.apply_type` (PT-1).

### 3.3. Откуда блок берёт вид: наследование, а не дубль

Чтобы «одна настройка — одно место» (правило PT-5/STU) не сломалось:

```
вид блока  →  вид по умолчанию его источника/типа  →  вид по умолчанию сайта
(своё)        (напр. promo_groups[тип], catalog_layout)  (site_defaults)
```

В панели блока — та же пилюля охвата, что уже есть в Студии: **«Für alle (Typ/Quelle)
· Nur dieser Block»**. Пустое значение у блока = «как у всех», и панель показывает,
откуда пришло действующее значение.

### 3.4. Что становится с «шаблоном страницы»

Предположение владельца «тогда общий шаблон имеет смысл только как тема» — верно
наполовину. Шаблон распадается на три ясные вещи:

| Было «шаблон страницы» | Становится |
|---|---|
| цвета, шрифты, рамки карточек, форма фото | **Тема** — уже есть: «Design des Shops» (Look) |
| как устроен основной список (полки, вкладки, навигатор, Kopfbild, прайс-лист) | **вид блока Hauptliste** — те же коды композиций, что сегодня |
| какие ещё списки есть на странице (Endet bald, Vorschau, секции по типам) | **пресет**: одноразово заполняет страницу блоками (как уже работают сборки главной и `apply_page_preset`) — после этого владелец двигает/удаляет/добавляет сам |

Пресет — **не живая привязка**: он один раз записывает список блоков. Поэтому
конфликта «шаблон против блоков» больше нет: истина одна — список блоков страницы.

## 4. Как не сломать (принципы перехода)

1. **Presence-minimal.** Новый тип C-блока `list` добавляется в реестр; ни одного нового
   материализуемого ключа → golden-эталоны normalize не меняются.
2. **Нет списка — прежний вид.** Пока у страницы нет явного порядка с маркером
   `Hauptliste`, рендер идёт прежним путём (блоки после основного списка).
3. **`promo_list` не мигрируем, а читаем** как `list(source=promotions, filter.type=…)`:
   живые конфиги и демо-киты продолжают работать, рендер — общий.
4. **Шаблоны страниц не удаляются.** `catalog_page_style`, `promo_page_style`,
   `page_styles.*`, `promo_groups` читаются как раньше — это вид `Hauptliste` и вид по
   умолчанию типа.
5. **Фикс-секции главной не конвертируем на первом этапе.** От их ключей зависят
   golden, 19 демо-китов и 27 сборок дизайна. В Студии они показываются той же панелью,
   что блок-список (фасад), а конвертация — отдельным решением позже.
6. **Замки класса — до кода.** Уже есть (добавлен сегодня): «каждое поле строки
   редактора C-блока переживает Save и попадает в черновик». Новые: «каждый источник
   блока имеет провайдер фильтра/сортировки и карточку», «каждая композиция блока
   применима к своему источнику (гейт `requires`)», «страница без маркера рендерится
   байт-в-байт как раньше» (характеризационные замки ДО правок).
7. **Производительность:** один запрос на блок, кап блоков-списков на страницу
   (например 8), `select_related` у источников; блоки читают сохранённый конфиг, а
   черновик — только в превью Студии.
8. **Переводы:** заголовок/интро блока — в реестр переводимых ключей (LAY-6), иначе
   редактор в языке ru писал бы их в немецкую базу.

## 8. Решения владельца (2026-10-02) и навигация по странице акций

**Принято:** Р-2 (а) — вид у каждого блока, с наследованием «блок → тип → сайт» и
переключателем охвата · Р-3 (а) — первый этап: акции и товары · Р-4 (а) — шаблон страницы
= тема + вид основного списка + одноразовый пресет.

**Р-1 уточнён владельцем:** «особый блок — да, но акции выводить БЛОКАМИ, каждый тип
отдельно, со своими настройками каждого блока. Как навигировать, если фильтр не
используется? Шаблон вывода каждого типа может быть разным». Предложение:

### 8.1. У страницы акций три состояния — и они не спорят

| Состояние | Когда | Что на экране | Чей вид |
|---|---|---|---|
| **Обзор** | `/aktionen/` без параметров | блоки по типам (каждый своим видом) + свои блоки владельца + «Weitere Aktionen» | каждого блока (по наследованию — его типа) |
| **Страница типа** | «Alle →» у блока или чип типа → `?gruppe=<тип>` | один тип целиком | шаблон страницы ТИПА (DL-20/PT-2, уже есть) |
| **Результаты** | поиск или фильтр (`?q=`, «−30 %», «Endet heute»…) | основной список: всё найденное одной сеткой, у карточки — метка типа; «Alle Filter löschen» → обзор | вид основного списка |

Разные шаблоны типов не конфликтуют, потому что никогда не показываются в одном списке:
в обзоре у каждого типа свой блок, на странице типа — один тип, а результаты смешивают
типы и поэтому выводятся единообразно.

### 8.2. Навигация без фильтра

* **Sprungleiste** — липкая полоса под заголовком: чипы с именами блоков страницы
  (автоматически из блоков, в их порядке, со счётчиками), клик прокручивает к блоку,
  текущий подсвечивается при прокрутке. В той же полосе справа — поиск и «Filter»: это
  вход в состояние «Результаты». На телефоне чипы листаются, поиск — одна кнопка.
* **«Alle N →»** в шапке каждого блока (только когда показаны не все — правило SF-5) ведёт
  на страницу типа; там — чипы соседних типов и «← Zur Übersicht».

### 8.3. Основной список в обзоре = «всё, что выше не показано»

Блок «Hauptliste» в обзоре показывает остаток: типы, у которых нет своего блока, — секциями
по типу (их видом, как сегодня), и акции без типа — «Weitere Aktionen». **Пока владелец не
добавил ни одного блока, это ровно сегодняшняя страница** (переход без поломок). Новый тип
не теряется: он сам появляется в остатке, а Студия подсказывает «у типа ещё нет своего
блока — ＋ Block anlegen». При поиске/фильтре тот же блок показывает результаты.

## 9. LB-1 — план инкремента (разведка 2026-10-02)

Разбит на два среза, чтобы каждый проверялся отдельно: **LB-1a** — сам блок (данные,
рендер, редактор, Save, черновик, библиотека, демо), **LB-1b** — пилюля охвата
«Nur dieser Block · Für den Typ» (запись вида в настройки типа).

### 9.1. Данные блока `list` (плоский `data`, как у остальных C-блоков)

Плоские поля — потому что редактор шлёт `cb_<id>_<поле>`, черновик собирает их одним
перебором (`CB_DATA_FIELDS`), а замок класса `test_cblock_field_roundtrip` сверяет
ровно такие имена (`[a-z_]+`).

| Поле | Значения | Чей |
|---|---|---|
| `source` | `promotions` · `products` (пусто/мусор → `promotions`: легаси-блок источника не знал) | обязательно |
| `type` | ключ типа акции — тот же, что `?gruppe=` (рубрика или `sys:*`); пусто = все | акции |
| `endet` | `heute` · `woche` | акции |
| `rabatt` | 20 · 30 · 50 (как чипы `/aktionen/`) | акции |
| `category` | слаг категории (с прямыми детьми, KAT-1) | товары |
| `only` | `featured` · `sale` · `available` | товары |
| `sort` | ключи провайдера: акции `endet`/`rabatt`/`preis`, товары `newest`/`price_asc`/`price_desc` + `featured` («empfohlene zuerst», как секция главной) | оба |
| `limit` | 1…24 | оба |
| `title`, `intro` | текст (≤120 / ≤300), переводимый | оба |
| `out` | `grid` · `slider` | вид |
| `cols` | 1…6 (десктоп) | вид |
| `rows` | 1…6 (сетка — сколько рядов, лента — строк в слайде) | вид |
| `card` | форма карточки из `card_forms` для вида сущности (акция/товар) | вид |

Presence-minimal: пустые поля не пишутся; поля чужого источника normalize отбрасывает.
Новых ключей верхнего уровня нет → golden-эталоны не меняются.

### 9.2. Легаси: «Aktionen eines Typs» читается как `list`

`promo_list` уходит из `REPEATABLE_BLOCKS`, остаётся входным псевдонимом
(`LEGACY_CBLOCK_ALIASES = {"promo_list": "list"}`): normalize на всех трёх входах
(главная, страницы, сохранённые шаблоны блоков) переписывает ключ, данные
`{type, title, limit}` подходят без преобразования (источник по умолчанию — акции).
Приёмники Save/вставки/шаблона принимают псевдоним — старая вкладка Студии,
открытая до деплоя, не уронит блок при Save.

Осознанное изменение поведения: легаси-блок с ПУСТЫМ типом раньше не рисовался,
теперь показывает все акции (у нового блока «нет фильтра» = «всё»). Мусорный тип
по-прежнему даёт пустую выдачу — блок исчезает.

### 9.3. Рендер и наследование вида

Логика — в новом модуле `apps/core/list_blocks.py` (тестируется без шаблона), тег
`{% list_block block as lb %}`, партиал `sections/_block_list.html`.

* **Выборка.** Акции: `status=active` → `PromoFacets.apply({gruppe, endet, rabatt})` →
  `sort` провайдера (иначе новые первыми) → срез. Товары: `is_active` + `select_related
  ("category")` → `CatalogFacets.apply({kategorie, sale, nur_verfuegbar})` + `is_featured`
  → сортировка → срез. Провайдеры принимают обычный dict — запрос/URL не нужен.
* **Оформление карточек** — теми же хелперами, что листинги: акции —
  `_attach_lowest_30d` (§11 PAngV; блок PT-6 этого не делал — на его карточках не было
  «Niedrigster Preis der letzten 30 Tage»), товары — `price_layer.attach_promos` + рейтинг
  `reviews.bulk_summary` (как в каталоге). Без N+1 — у выборки акций; у товаров ценовой
  слой сам спрашивает варианты по одному товару (см. §9.9).
* **Вид:** база по источнику → поверх свои оси блока:
  акции с типом — `promo_groups[тип].layout/card` → `promo_index_layout` → дефолт
  секции акций (3 колонки); акции без типа — `promo_index_layout` → дефолт; товары —
  `catalog_layout` (если это сетка) → дефолт секции товаров (4 колонки); форма карточки —
  блок → тип → дефолт сайта (`promo_card` / `card_style`), а своя форма у самого
  объекта (DL-19) по-прежнему сильнее всех.
* **Сколько показывать:** `limit` → `cols × rows` (только сетка) → 12; потолок 24.
* **«Alle N →»** — только когда показаны не все (правило SF-5): выборка берёт
  `limit + 1`, итог `N` считается одним COUNT только в этом случае. Цель — основной
  список с тем же фильтром: тип → страница типа (`/aktionen/?gruppe=…`, N-4),
  «endet/rabatt» → результаты `/aktionen/?endet=…`, категория → `/sortiment/<slug>/`,
  «reduziert» → `?sale=1`, «verfügbar» → `?nur_verfuegbar=1`, сортировка → `?sort=`.
* Хвост неполного ряда — `spread` (блок контент не прячет), лента — слайдер-примитив
  DL-16.1. Маркеры прежнего блока сохранены: `data-sf-promo-type`, `data-promo-strip`.

### 9.4. Редактор (строка C-блока в панели Студии)

Группы как у секций (STU-12e): **Inhalt** — источник, заголовок, вступление, фильтр
источника (поля обоих источников в DOM, чужие скрыты — W0), сортировка, «Höchstens»;
**Darstellung** — «Ausgabe» (Raster/Slider), «Spalten», «Reihen», «Kartenform»;
у пустого пункта подпись показывает, ОТКУДА придёт значение («wie der Typ: Slider»).
Save — ветка `list` в `_read_cblock_data`; черновик — новые имена в `CB_DATA_FIELDS`
(замок класса проверит оба). Селекторы: типы акций (`promo_types_for_blocks`, уже есть),
категории (`categories_for_blocks`, новый, fail-safe).

### 9.5. Переводы

`title`/`intro` переводимы; кодовые поля (`source`, `endet`, `only`, `sort`, `out`,
`card`, `category`) — в `NON_TRANSLATABLE_FIELDS`, иначе смена источника в редакторе
на ru уехала бы в русский оверлей (класс LAY-6). Обход демо-переводов
(`_CBLOCK_TEXT_FIELDS`) += `intro`.

### 9.6. Библиотека, пресеты, демо

Карточка библиотеки «Liste» вместо «Aktionen eines Typs»; пресеты вставки
(`CBLOCK_VARIANTS["list"]`): Aktionen · Endet heute (лента) · Neu im Sortiment ·
Empfehlungen · Reduziert. Демо `aktionsmarkt`: оба блока PT-8 переводятся на `list`
(вид прежний — по типу) + блок «Neu im Sortiment» лентой.

### 9.7. Замки — ДО кода

1. normalize `list`: поля по источнику, мусор отброшен, presence-minimal; легаси
   `promo_list` → `list` на трёх входах; golden целы.
2. Рендер: акции (тип / endet / rabatt / сортировка), товары (категория / featured /
   sale / сортировка); «Alle N →» только при обрезке, с правильной целью; пустая
   выдача — блок исчезает, в превью — пунктирный якорь.
3. Наследование: пустой вид блока = вид типа; свой вид блока бьёт тип; своя форма
   объекта бьёт блок.
4. §11 PAngV на карточках акций блока; выборка акций без N+1 (число запросов `resolve` не
   растёт с числом карточек — замок на выборке, не на странице, см. §9.9).
5. Save и черновик — замок класса (обновлённый санити-ассерт) + сквозной сценарий.
6. Кодовые поля не уезжают в перевод.
7. Каждый пресет вставки проходит normalize (уже есть замок для всех типов).
8. Блок работает на каждом хосте `PAGE_BLOCK_HOSTS`.

### 9.8. LB-1b — пилюля охвата (следующим срезом)

У блока акций с выбранным типом в группе «Darstellung»: «Nur dieser Block · Für den Typ
«…»». Во втором режиме те же контролы пишут `promo_groups[тип].layout/card` (то же
хранение, что экран «Aktionstypen» и страница типа), а у блока оси очищаются — единая
функция применяется и в Save, и в черновике, поэтому превью показывает изменение на
всех блоках типа сразу. У товаров «для всех» = вид страницы каталога — его меняют там.

### 9.9. Итог LB-1a (2026-10-02)

Сделано по §9.1–9.7 целиком, БЕЗ миграций. Отклонения от плана и находки:

* **Темп ленты** (`speed`) добавлен в данные блока — без него «Slider» был бы без
  автопрокрутки, хотя у страниц она настраивается (ось LAY-3b).
* **«Letzte Reihe»** (хвост ряда) у блока не выводится: блок контент не прячет
  (`spread`, как листинги) — контрол был бы обещанием без смысла.
* **Наследованные «Reihen» выдачу не режут**: на странице типа они значат «строк в
  слайде», поэтому «сколько показывать» режут только СВОИ ряды блока.
* **N+1 на карточках — пред-существующий.** `Product.has_variants` — некешируемое
  свойство; его зовут карточка товара, `Promotion.grundpreis` и `price_layer.attach_promos`
  — по запросу на товар на ВСЕХ поверхностях (главная, каталог, `/aktionen/`). Замок
  «без N+1» поэтому стоит на выборке блока, а лечение — отдельный перф-инкремент
  (кандидат: предвычисленный признак вариантов на инстансе, который читает свойство).
* **Пустой тип легаси-блока** = все акции (раньше блок не рисовался) — осознанно, см. §9.2.
* **Форма карточки задаёт минимальную ширину плитки** (стенд): горизонтальные «Ценник» и
  «Deal» в ленте 15rem ломались → лента даёт им плитку шире; «Deal» в сетке из трёх
  колонок тоже нечитаем → унаследованные колонки для него ужимаются до двух (на телефоне
  до одной), явный выбор владельца не трогается.
* **Модуль источника выключен** → блок не рисуется (у выключенных акций нет `/aktionen/`,
  «Alle →» вёл бы в 404 — урок hero-плиток).


## 10. LB-1b — пилюля охвата: спецификация (2026-10-02)

**Хранение — ничего нового.** «Den ganzen Typ» пишет `promo_groups[тип].layout/card` — то
же хранение, что экран «Aktionstypen» и страница типа. `scope` — служебное поле формы, в
конфиге не живёт никогда (normalize его и не знает).

**Одна функция на оба пути — `list_blocks.apply_type_scope(cfg)`.** Зовётся в Save
билдера (после сборки `sections`/`page_blocks`, до разборки перевода LAY-6b) и в живом
черновике (до финального normalize) — превью и сохранение не расходятся. Для каждого
блока `list` с `scope=type`, источником «Aktionen» и непустым типом:

* **Раскладка.** Слой раскладки у типа «всё или ничего»: `base_view` берёт раскладку
  типа ЦЕЛИКОМ и страницу уже не читает. Поэтому при любой заданной оси (`out`/`cols`/
  `rows`/`speed`) раскладка типа = **действующая раскладка страницы + заданные оси
  поверх**. Иначе пустое «Spalten» с подписью «wie die Seite: 4» дало бы 3 из дефолта
  нормализации, а «Raster» поверх ленты страницы был бы невыразим вовсе (у типа без
  раскладки нет способа сказать «сетка»). Все четыре оси пустые → у типа раскладки нет,
  он снова живо следует за страницей.
* **Форма карточки** → `promo_groups[тип].card`; пусто → своей формы у типа нет.
* **Оси блока очищаются** — блок следует за типом, как и все остальные блоки этого типа.
* **Шаблон страницы типа** (`style`) не трогается. Чужие типы не трогаются.
* Два блока одного типа в режиме «Den ganzen Typ» с разными значениями — побеждает
  последний по порядку обхода (главная, затем страницы). Сценарий редкий; честнее, чем
  молча смешивать оси двух блоков.

**Редактор.** В группе «Darstellung» — строка «Ansicht gilt für» с пилюлей «Nur diesen
Block · Den ganzen Typ» (видна при источнике «Aktionen» и выбранном типе) и подписью, на
что она влияет. Отдельный msgid, а не «Gilt für»: тот уже занят карточкой цели акции
(DL-16.3), и в tr он переведён «товар, к которому относится» — в пилюле это была бы
неправда. В режиме типа контролы показывают значения ТИПА (карта `lb-type-views` —
один JSON на страницу), пустые пункты — подписи страницы («wie die Seite: …»); возврат в
«Nur diesen Block» возвращает значения блока; смена типа в режиме типа подгружает
значения нового типа. Канва показывает изменение на всех блоках типа сразу (черновик).
Ограничение v1: подписи «wie der Typ: …» у СОСЕДНИХ блоков того же типа обновятся после
Save — канва при этом уже правдива.

**Попутный дефект LB-1a/PT-6 (класс W0).** Селектор типа строился только из ЖИВЫХ
типов (у которых есть активные акции). У блока, чей тип сейчас без акций (закончились,
ещё запланированы), селектор показывал «Alle Aktionen» — и первый Save молча превращал
блок «Räumung» в блок «все акции». То же у категории: неактивная → «Alle Kategorien».
Фикс: текущее значение блока всегда есть в списке, с пометкой «(derzeit leer)» /
«(inaktiv)».

**Экран «Aktionstypen» (класс W0).** `promo_type_save` пересобирает раскладку типа из
трёх своих полей — темп ленты, заданный из блока, стирался бы при Save экрана. Фикс:
оси, которых у экрана нет (`speed`, `tail`, `page_size`), переносятся как были.

**Замки — до кода.** apply: перенос осей, очистка блока, `style` цел, чужой тип цел ·
пустые оси → тип наследует страницу · без типа и у товаров — игнор · `scope` не хранится
· материализация от страницы (пустые колонки = колонки страницы; «Raster» поверх ленты
страницы) · Save билдера: второй блок того же типа меняется тоже (рендер витрины) ·
черновик · строка редактора несёт пилюлю, карта видов — один раз на страницу · орфан-тип
и орфан-категория переживают Save · экран типов сохраняет `speed`.

## 11. LB-2 — «Hauptliste»: блоки над и под основным списком (спецификация, 2026-10-02)

Решение владельца Р-1(а): основной список листинг-страницы — особый блок, один,
двигается, не удаляется. Разведка точек изменения — ниже; БЕЗ миграций.

### 11.1. Что есть сегодня

* Все одиннадцать листингов (`/sortiment/` и страницы категорий, `/aktionen/`,
  `/termin/`, `/unterkunft/`, `/veranstaltung/`, `/touren/`, `/kombi/`, `/lookbook/…`,
  `/merkzettel/`, `/blog/`, `/bewertungen/`) стоят на каркасе `listing.html` и выводят
  свои C-блоки ОДНИМ вызовом `{% page_blocks "<хост>" %}` в слоте `listing_after` —
  то есть всегда ПОД основным списком. Поставить блок над списком нельзя.
* Порядок блоков страницы — значения `order_cb_<id>` строк панели (видимое поле
  «Position»), перетаскивание на канве (`movePageBlock`) меняет только значения;
  `collect()` черновика сортирует по ним; Save пересобирает хост из `pb_id`-строк.

### 11.2. Данные

* Маркер основного списка — псевдо-элемент `{"key": "main"}` в `page_blocks[<хост>]`.
  Разрешён ТОЛЬКО на хостах листингов (`MAIN_LIST_HOSTS` + хосты категорий
  `catalog:<slug>`), не больше одного, не входит в кап блоков, данных у него нет.
* **Presence-minimal:** маркер первым = «блоки под списком» = сегодняшний вид, поэтому
  в таком положении он НЕ хранится (normalize его отбрасывает). Конфиги живых сайтов,
  демо-киты и golden не меняются; хранится только осмысленное «есть блоки над списком».
* Хост без блоков маркер не хранит тоже (переставлять нечего).

### 11.3. Рендер

* Тег `page_blocks` получает `part`: `"before"` — блоки до маркера, `"after"` (по
  умолчанию) — после него, без маркера — все. Пунктирный якорь пустого хоста в превью
  рисует только `after` (иначе на пустой странице было бы два «＋»).
* Каркас `listing.html` получает слот `listing_before` — после шапки страницы (и шапки
  композиции), ДО указателя/фильтров/строки инструментов: блоки над списком — часть
  страницы, а не часть списка, и фильтры остаются вплотную к сетке, которой управляют.
  Каждый листинг кладёт туда `{% page_blocks "<свой хост>" part="before" %}` (у каталога —
  ещё хост категории). Внутри `data-listing-root` (KAT-5: смена вида каталога
  перерисовывает и их — сервером, инлайн-скриптов у блоков нет).
* Основной список получает обёртку `data-pb-main="<хост>"` — цель перетаскивания на
  канве (блок, брошенный на верхнюю половину списка, встаёт над ним).

### 11.4. Студия

* В «Content blocks on this page» листинга — строка «★ Hauptliste» на своём месте среди
  блоков: поле «Position» (как у блоков), без «Sichtbar»/«Entfernen», подсказка «Blöcke
  davor erscheinen über der Liste, danach unter ihr. Aussehen der Liste — oben: Vorlage,
  Raster, Kartenform.» Нумерация строк считает маркер всегда (неявный — первым), и
  вставка без перезагрузки нумерует так же (`_add_block_fetch_response`).
* Save: `pb_id`-цикл принимает тип `main` на листинг-хостах; черновик — штатно
  (`collect()` уже сортирует по «Position»).
* Канва: dragover/drop на `[data-pb-main]` = `movePageBlock(блок, маркер, выше/ниже)` —
  тот же value-based путь, оптимистичного переноса между контейнерами нет (сверяющий
  рендер черновика поставит блок на место).

### 11.5. Чего НЕ делаем в LB-2

* Шаблон страницы не превращаем в «вид основного списка» ПЕРЕКЛАДКОЙ панели: контролы
  вида листинга уже живут в области «эта страница» (STU-8) прямо над строками блоков —
  строка «Hauptliste» ссылается на них подсказкой. Перекладка — по фидбэку.
* Пресеты, заполняющие страницу блоками («Endet heute», «Vorschau», секции по типам) —
  это LB-3 (сначала `/aktionen/`).

### 11.6. Замки — до кода

1. normalize: маркер на листинг-хосте сохраняется не первым; первым — отбрасывается;
   на не-листинг хосте и второй экземпляр — отбрасываются; данных у маркера нет; кап
   блоков маркер не съедает; golden целы.
2. Рендер: без маркера страница байт-в-байт прежняя (характеризационный замок ДО
   правок по каждому листингу); с маркером блок до него — над сеткой, после — под ней;
   якорь «＋» в превью один.
3. Каждый листинг-хост выводит `part="before"` (замок по реестру, как
   `test_every_declared_block_host_is_actually_rendered`).
4. Save билдера: строка `main` с позицией между блоками → маркер сохранён там; позиция 1 →
   маркера нет; на не-листинг хосте строка `main` игнорируется.
5. Черновик: payload с маркером → превью рендерит блок над списком.
6. Панель: строка «Hauptliste» есть на листинг-хосте с блоками, её «Position» учтена в
   нумерации; вставка без перезагрузки нумерует с учётом маркера.

### 11.7. Найдено разведкой: переводы C-блоков привязаны к ПОЗИЦИИ (класс I18N-11)

Оверлей перевода `i18n[<локаль>]["sections"]` и `[…]["page_blocks"][<хост>]` мёржится
позиционно (`_deep_overlay`: i-й перевод поверх i-го блока). Save в базовом языке
пересобирает список в новом порядке, а оверлеи не трогает — значит, любая перестановка,
удаление или вставка блока в середину сдвигает переводы на ЧУЖИЕ блоки (у посетителя на
ru заголовок «Бета» оказывается над блоком «Альфа»). Save в языке перевода этого не
делает — там `split_translation` сопоставляет блоки по личности (id/key), — но и он
выравнивает только СВОЮ локаль, остальные остаются по позициям.

Маркер основного списка — тоже элемент списка, и каждое его перемещение сдвигало бы
переводы. Поэтому LB-2 начинается с починки: **`realign_block_overlays`** — переводы
блоков едут за своим блоком по личности (id C-блока, key фикс-секции, `key:main` у
маркера) во всех путях, которые меняют состав или порядок: Save (базовый язык — все
локали; язык перевода — все, КРОМЕ сохраняемой: её выравнивает `split_translation`),
вставка «＋» и вставка шаблона блока. Замки: перестановка, удаление и вставка в
середину не переносят перевод на чужой блок — на главной и на странице.

## 12. LB-3 — `/aktionen/`: обзор блоками (спецификация, 2026-10-02)

Решения владельца: N-1 (A) Sprungleiste · N-2 (A) результаты одной сеткой с меткой типа ·
N-3 (A) основной список в обзоре = остаток · N-4 (A) «Alle →» → страница типа · Р-5 (а)
встроенные списки `/aktionen/` → блоки пресета. БЕЗ миграций.

### 12.1. Что есть сегодня (разведка)

Обзор без параметров (`promotion_list`): шапка → чипы типов (ведут на страницы типов) +
системные чипы + поиск → «Ending soon» (до 4, ≤ 3 дней) → «Vorschau» (запланированные,
бакетами по старту) → секции по своим рубрикам (порог `MIN_GROUP_SECTION`, «More offers»
в конце) или плоская сетка; плюс композиции обзора (Schaufenster/Tabs/Navigator/Kompakt/…).
Любой фильтр/поиск/сорт → плоская сетка (у карточки уже есть метка типа
`data-promo-group` — N-2 выполнено ПРЕДЫДУЩИМИ волнами). Блоки страницы (`promos`)
выводятся на ВСЕХ состояниях, в т. ч. на странице типа.

### 12.2. «Режим блоков» и что он заменяет

Страница строится из блоков, как только у хоста `promos` есть хотя бы один блок «Liste»
с источником «Aktionen». **Без таких блоков — сегодняшняя страница байт-в-байт** (переход
без поломок). Встроенное заменяется только РАВНОЗНАЧНЫМ блоком — «блок, показывающий то
же самое, заменяет встроенное»:

| Встроенное | Гаснет, если на странице есть блок… |
|---|---|
| «Ending soon» | `list` с фильтром «Endet» (`heute`/`woche`) без типа |
| «Vorschau» | `list` с новым фильтром «Demnächst» (`phase=upcoming`) |
| секция рубрики X | `list` с типом X |

Так владелец, поставивший один блок «Räumung», не теряет «Ending soon» и «Vorschau», а
секция «Räumung» из основного списка уходит (N-3: остаток — типы без своего блока + «More
offers»). Новый тип без блока сам появляется в остатке.

### 12.3. Новый фильтр блока «Demnächst»

`phase=upcoming` у источника «Aktionen»: акции в статусе `scheduled` со стартом в будущем,
по старту; карточки — превью («ab <дата>», без покупки и счётчика), тем же `preview=True`,
что у встроенной «Vorschau». Фасеты «Endet»/«Rabatt» к ним не применяются (у будущих их
нет). «Alle →» у такого блока не выводится (страницы «будущих» нет).

### 12.4. Состояния страницы

* **Обзор** (без фильтров и типа): блоки + основной список-остаток + Sprungleiste.
* **Страница типа** (`?gruppe=`) и **Результаты** (фильтр/поиск/сорт): блоки «Liste» с
  акциями НЕ выводятся — это композиция обзора, на странице типа они дублировали бы его
  содержимое. Прочие блоки (текст, кнопка, …) — как раньше.

### 12.5. Sprungleiste (N-1)

Только в режиме блоков. Липкая полоса под шапкой: чипы по порядку страницы — блоки «Liste»
над списком → секции остатка → блоки под списком; подпись = заголовок блока/секции,
счётчик — число показанных акций. Клик — плавная прокрутка к якорю (`id` у секции блока и
у секции остатка), текущий чип подсвечивается при прокрутке (IntersectionObserver), на
телефоне полоса листается. Справа — поиск (тот же `?q=`): вход в «Результаты». Чипы типов
(ведут на страницы типов) в режиме блоков заменяются полосой — входы на страницы типов
остаются у «Alle N →» блоков и у чипов на самой странице типа.

### 12.6. Студия и пресет (LB-3b)

* Пресет «Prospekt (Blöcke)» для `/aktionen/` — один раз заполняет страницу блоками:
  «Nur noch heute» (Endet heute, лента), «Demnächst», по блоку на каждую живую рубрику.
  Блоки владельца целы (идемпотентная замена по префиксу id, как `apply_page_preset`).
* Подсказка в панели страницы акций: «у типа ещё нет своего блока — ＋ Block».
* Демо aktionsmarkt: обзор собран пресетом — видно новую страницу целиком.

### 12.7. Замки — до кода

1. Без блоков «Liste» страница байт-в-байт прежняя (характеризационный замок ДО правок:
   «Ending soon», «Vorschau», секции рубрик, чипы типов на месте).
2. Блок с типом X: секции X в основном списке нет, остальные секции и встроенные полосы
   на месте; блок endet → «Ending soon» гаснет; блок «Demnächst» → «Vorschau» гаснет.
3. «Demnächst»: только будущие запланированные, превью-карточки, без «Alle →».
4. Страница типа и результаты: блоков «Liste» нет, текстовый блок есть.
5. Sprungleiste: только в режиме блоков; чипы в порядке страницы с подписями и счётчиками;
   якоря существуют; поиск несёт `?q=`.
6. Пресет: создаёт ожидаемые блоки, идемпотентен, блоки владельца целы.

### 12.8. Уточнения разведки (2026-10-03, до кода)

* **«Равнозначный» блок = та же выборка.** Блок заменяет встроенное, только если
  показывает то же множество акций (лимит и сортировка не в счёт — у обрезанного блока
  есть «Alle N →»):
  * секция рубрики X ↔ блок `{type: X}` без `endet`/`rabatt`/`phase`. Блок
    «Räumung · endet heute» секцию НЕ гасит — иначе остальные акции рубрики пропали бы
    из обзора, а «Alle →» такого блока ведёт в узкую выборку;
  * «Ending soon» ↔ блок с `endet` (heute|woche) без типа и без `phase`;
  * «Vorschau» ↔ блок с `phase=upcoming` без типа;
  * при группировке «по времени» (DL-13 C3) блок `endet=heute` гасит бакет «Endet
    heute», `endet=woche` — оба бакета «heute» и «woche» (фильтр «7 дней» включает
    сегодняшние);
  * блоки встроенных типов (`sys:*`) ничего не гасят: встроенный тип пересекает
    рубрики (mystery-акция лежит в «Wochenangebote»), секций по ним нет и сегодня;
  * блок без фильтра («Die stärksten Rabatte» — только сортировка) ничего не гасит:
    это витрина-подборка поверх обзора, дубль карточек с секцией ниже — норма.
* **Режим блоков** включает только ВКЛЮЧЁННЫЙ блок `list` с источником «Aktionen» на
  хосте `promos` (над или под основным списком). Блок товаров его не включает.
* **«Demnächst» в редакторе** — пункт селекта «Zeitraum» (рядом с «Endet heute/diese
  Woche»): одно поле, одно имя (`cb_<id>_endet`), поэтому приёмники Save/черновика и
  замок класса не меняются. Хранение — отдельный ключ `phase: "upcoming"`:
  `_clean_list_block` переводит `endet="upcoming"` в `phase` (и принимает `phase`
  напрямую — пресеты, демо); `endet`/`rabatt`/`sort` у такого блока не хранятся, тип —
  хранится (будущие акции одного типа). `phase` — в `NON_TRANSLATABLE_FIELDS`.
* **Одна выборка на запрос.** Чипам Sprungleiste нужны подписи и счётчики блоков, а
  блоки потом рисует тег. Чтобы не считать выдачу дважды, `list_blocks.resolve_for`
  кэширует результат на `request` по данным блока; тег `list_block` и вьюха зовут одну
  функцию. Конфиг у них один и тот же (черновик при `?preview=1`, локализация).
* **Якоря.** У секции блока — `id="lb-<id блока>"` (на `<section>`: у обёртки
  `display:contents` нет бокса, прокрутка к ней не работает), у секции остатка —
  `id="aktionen-<n>"`, у «Ending soon» и «Vorschau» — свои. `scroll-mt-*` + сдвиг в JS
  на высоту липкой шапки сайта и самой полосы.
* **Состояние «Результаты»/«страница типа»** = `has_filters` вьюхи (тип, фильтр, поиск,
  сорт). Вид «Liste» (`?ansicht=liste`, шаблон «Preisliste») — это вид ОСНОВНОГО
  списка, а не фильтр: блоки остаются, таблица = остаток.

### 12.9. Итог (2026-10-03) — сделано целиком, БЕЗ миграций

* **Режим блоков** (`list_blocks.overview_blocks`) — правила §12.8 как есть; «Ending soon»

  концов страница теряла бы полосу). Основной список = остаток (рубрики с блоком уходят

* **«Demnächst»** — пункт селекта «Zeitraum», хранение `phase: "upcoming"`; выборка

* **Страница типа и результаты** — тег `page_blocks` по флагу вьюхи
