# MX — Мастер-план исполнения (утверждён владельцем 2026-08-21: «приступай автономно, после зелёного мержи»)

**Стратегия:** `mx-anchor-strategy` (4 якоря, способ продажи на карточке) +
`mx-anchor-details` (§5b: опция = цена + трекер) + `mx-archetype-classification`
(проверено владельцем; тиры moto → переквалифицировать).
**Правила исполнения:** один инкремент = ветка `claude/multi-sale-archetypes-x5l7d1`
→ локальные гейты (ruff format/check, pytest затронутых аппов `--reuse-db`,
`--create-db` при миграциях, i18n_quickcheck, template_comments) → пуш батчем →
**зелёный CI → мерж в main** (git-only FF). Миграции аддитивные; после мержа с
миграциями — деплой владельцем. build-log + task-catalog в том же коммите.

## MX-0 — денежная гигиена + id опции (БЕЗ миграций) — фундамент всего
1. `core/extras.py::snapshot` → строки `{id, label, price_cents, unit_cents, per_night}`
   (line-total остаётся в price_cents — потребители не меняются); новый
   `retotal(snap, nights)` — пересчёт per-night строк по unit_cents (легаси-строки
   без unit_cents — как были, fail-safe).
2. id в снимок модификаторов (`orders/services.py:252`) и состава набора
   (`catalog/combos.py::combo_snapshot`).
3. `stays/services.py::move_stay(reprice=True)`:
   а) `booking.extras = retotal(...)` + "extras" в update_fields (фикс недосчёта 45 €);
   б) `auto_discount(..., unit=unit, departure=departure, extra=stay_promo(unit, arrival))`
      — как book_stay (фикс потери Lücken/промо; FK promotion — атрибуция, не трогаем);
   в) депозит: если `payment_state == PENDING` и тариф даёт `prepayment_cents > 0` —
      пересчитать по новому итогу (PAID не трогаем — доплата это MX-3).
4. Освобождение койки — единый узел: `events/services.py::release_linked_stay(ticket)`
   (статус-гейт pending/confirmed, идемпотентно; письмо гостю НЕ шлём — внутренняя
   companion-бронь без промо/ваучера, семантика прежних вьюх-хелперов сохранена);
   вызовы: `TicketSM.on_transition(dst=cancelled)` + зеркало в
   `status_effects.restore_stock_for(kind=ticket)`; оба `_cancel_linked_stay`
   (views + public_views) удаляются. Замок КРАСНЫМ ДО фикса: отмена через
   `core_transactions.apply_action` освобождает койку.
5. Кабинетная карточка записи: итог С доп-услугами + список допов
   (`templates/booking/booking_detail.html` — сейчас платит price_eur без extras).
6. Тесты: пере-снятие моего пробника (продление 2→5 ночей = 575 €), сохранение
   промо-скидки при move, release через apply_action + через вьюху + кастом-cancel,
   id в трёх снимках, экран записи показывает итог.

## MX-1 — Расходы → раздел ERP (миграция аддитивная)
1. `ExpenseEntry` += `ref_kind`/`ref_id` (generic-объект затрат; `event` FK остаётся
   легаси-полем), `vat_rate` реально проходит в defaults.
2. Экран `/dashboard/finance/ausgaben/`: список + фильтры период/категория + ручной
   ввод (сумма, категория, дата, ставка, заметка); удаление — только manual-записей.
3. Закупка пишет расход: приёмка строки PO → `ExpenseEntry(source=purchase,
   source_ref=<pk StockMovement приёмки>)` — идемпотентность даром.
4. «Finanzen» = вкладки Einnahmen · Ausgaben · Ergebnis (выручка − расходы за период);
   nav: записи в реестр (advanced в хабе board) — якоря сайдбара НЕ трогаем (мораторий).
5. i18n: все новые msgid × 5 каталогов.

## MX-2 — Опции с трекерами на все якоря (миграция аддитивная)
1. `core.Extra` += `entity_kind`/`entity_id` (адресность; пусто = scope-wide как сейчас),
   `tracker` (""=надбавка | pool | stock | purchase), `pool_size`, `product` FK
   (для stock), `supplier` FK (для purchase), `vat_rate`.
2. Витрина: buy-box сущности показывает scope-wide + адресные её опции (5/5 kind,
   включая товар/заказ — у заказа появляются опции сделки).
3. Кабинет: управление опциями из формы сущности + прежний `/dashboard/extras/`.
4. **«Zusatzverkäufe»** — вкладка в Verkäufe: строки проданных опций по id из снимков
   (extras броней/билетов + модификаторы заказов), фильтры тип/день/направление;
   у закупаемой — кнопка «→ заказать у поставщика» (создать SupplierBooking, MX-4).
5. Ёмкостной/расходуемый трекеры: v1 — информативно (счётчик в Zusatzverkäufe);
   enforcement пула и списание рецептом — отдельный слайс 2e по плану-доку.
6. Переквалификация moto (решение §3.1): демо-кит — тиры «участие» + опция «аренда
   Enfield» (pool), ops-пометка на пересев.

## MX-3 — Редактирование состава сделки + доплата
1. stays: «Buchung bearbeiten» += чекбоксы допов (текущий выбор из снимка по id) →
   пересборка снимка + reprice; booking (Termin): то же на карточке записи.
2. ticket: изменение допов из кабинета (событийный экран).
3. Деньги: PAID + итог вырос → дельта и «Jetzt bezahlen» (реюз /bezahlen/ B2);
   итог упал → пометка «зачёт/возврат вручную» (частичный Stripe-возврат — external).
4. orders: v1 — добавление строки (custom_line/каталожная, склад штатно) + сторно
   строки с restore; полноценный пересбор позиций — отдельным решением.

## MX-4 — Закупка от опций
1. `SupplierBooking.event` → nullable + `ref_kind`/`ref_id` (жить может у любой сделки
   и без сделки); `sync_expense` — по generic-ссылке.
2. Из Zusatzverkäufe: создание с префиллом qty = продано опций (по id) на дату/заезд,
   поставщик = из опции.
3. Кабинетный список закупок вне туров (вкладка в Einkauf или у логистики — решить
   план-доком шага).

## MX-5 — Способ продажи на карточке
1. `Product.primary_action` (""=cart | request) — «торт на заказ» без модуля jobs;
   buy-box уже умеет обе ветки (реюз GK-14).
2. Event/Tour: тумблер «Private Anfrage» (генерализация moto-CTA).
3. `Service.pricing_mode` (per_booking | per_person) + поле «человек» в форме брони
   слота + цена × людей — режим Tripster «за человека» у Работы.
4. Реестр PURCHASE_MODE остаётся дефолтом модуля; карточка переопределяет.

## MX-6 — Карточка Впечатления над датами
1. Оживить `series_id`: листинг событий группирует серию в одну карточку
   («ближайшая дата + ещё N терминов»), деталь — переключатель дат.
2. Категории событий: владелец может добавить свои (пресет + свои значения).
3. Агрегатор: листить карточку (тур/серию) с ближайшей датой вместо каждого заезда —
   правка sync-задач, план-доком шага.

## MX-7 — Цифровые Вещи и Offer в общий учёт (choices-миграции)
1. Выручка: `RevenueEntry.SOURCES` += gift/pass; хуки в вебхуках оплаты сертификата
   и абонемента (идемпотентно по объекту).
2. «Sortiment»: строки PassPlan + Gutschein-конфиг (read + переход к родным формам).
3. `Offer` виден: Ctrl+K + фильтр-чип на вкладке заказов Verkäufe.
4. Гейт: цифровые Вещи не попадают в товарный фид/агрегатор.
