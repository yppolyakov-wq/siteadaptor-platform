# T-8.10d — замер поиска, подписка на набор фильтров, ИИ «фраза → фильтры» (2026-10-19)

Родитель: `docs/t8-10-rest-plan-2026-10-19.md §3`. Разведка и план — агент planner (сверено с `main`).
Запрос владельца (2026-10-19): подписка по набору фильтров, выбранных жителем (район, магазин,
«овощи» или конкретно «помидоры», марка), и подписка на конкретную компанию с теми же сужениями —
чтобы житель не получал лишнего. **Делаем обобщением «Folgen» (T-8.7), а не второй системой.**
Миграция одна: `aggregator/0032` (SHARED, аддитивная). D-0 и D-2 — без миграций.

## 1. Что есть (по коду)

- `FollowSubscription` (`aggregator/models.py:674-742`): цели business | section | district,
  `target_key` CharField(100), unique `follow_uniq(user, kind, key, city, channel)`, CHECK «Sofort
  только у бизнеса». `FollowDigest` — дедуп против ПРОШЛЫХ писем; **внутри одного письма дедупа нет**
  (листинг двух подписок придёт дважды), `MAX_FOLLOWS_PER_MAIL=20` молча режет лишние подписки,
  лимита подписок на жителя нет.
- `follow.py`: `parse_target` понимает `?unternehmen|bereich|stadtteil`; DOI-токен подписан, без
  строк в БД; `items_for` = `listings_for(include_demo=False)` + `created_at > since`; `scope_url` —
  ссылка «Alle anzeigen».
- Поиск `search.py`: `SearchFilters`/`FILTER_PARAMS`/`parse_filters` (белый список)/`carry`;
  `execute(track=False, fuzzy=False)` не пишет журнал; намерение из текста (`query_intent`) выводит
  цену/дату/«открыто»/размер/район. «Tomaten» уже находит «Kirschtomaten» (стеммер + часть слова).
- **Марки в каталоге города нет** (`Product.brand` есть, в `AggregatorListing`, индексе и построителях —
  нет). **Фильтра «по бизнесу» в поиске нет** («Von <Firma>» — только группировка). Без `q` портал
  показывает только акции/номера/события/наборы — товаров нет (`portal_views.py:332`).
- Страница результатов не кэшируется, главная и район — кэшируются (P0-1): кнопки — ссылки/GET-формы.

## 2. Дизайн D-1

- **Цель `query`**: канонический набор `{"v":1,"p":[[ключ, значение], …]}` (белый список, сортировка),
  `target_key = sha256`. Белый список: `q` (= остаток после разбора намерения, ≤ 60, `pii.scrub`),
  `kat` ≤ 3, `merkmal` ≤ 3, `stadtteil`, `preis_von/bis`, `verfuegbar`, `groesse`, `kind`, **`marke`**,
  **`unternehmen`** (хранится schema, в ссылку — слаг), флаг `roh=ort`. **Не храним**: дату, «открыто»
  (относительны ко дню), сортировку, радиус и координаты (ПД), курсор, каналы, MEN-параметры.
  Пустой набор → кнопки нет. Набор ровно из одного «старого» условия → прежняя цель (без дублей,
  без миграции старых строк); категория (не раздел) остаётся запросом.
- **Модель** (`aggregator/0032`): `TARGETS += query`, `FollowSubscription.query` JSONField,
  CHECK «у query непустой набор»; `AggregatorListing.brand` CharField(120) default "".
  Индексы на марку/JSON в v1 не нужны (фильтр всегда в паре с городом).
- **Марка в каталоге**: через `_neutral_v2v4` (все 8 построителей), товар — своя марка, акция —
  марка товара-цели, **кроме mystery/surprise**; индекс (вес B + `search_text`), фильтр `?marke=`
  (iexact), ссылка «Alle von <Marke> in <Stadt>» на странице предложения.
- **Фильтр `?unternehmen=<slug>`** в поиске + одно правило вида `default_kind` (при марке/бизнесе
  без `q` видны товары); ядро `_district_pool` — общей функцией (портал и письмо одним путём).
- **Выборка письма** — та же цепочка, что у страницы по «Alle anzeigen» (⊇ по построению),
  `include_demo=False`, `track=False`, без записи в журнал. «Новое» = новые предложения (как Folgen).
- **Сводка**: дедуп ВНУТРИ письма (листинг двух подписок — один раз, под самой узкой подписью),
  порядок секций бизнес → запросы → раздел/район, подпись «Suche: „Tomaten“ · Obst & Gemüse ·
  Ohligs · Marke X · bei Bäckerei Y».
- **DOI**: вход `/folgen/?art=suche&…`; токен несёт набор, подтверждение заново канонизирует и
  проверяет бизнес (демо/скрытый → отказ). GET ничего не меняет, POST подтверждает.
- **Интерфейс**: ссылка «🔔 Benachrichtigen, wenn es so etwas gibt» + человеческая строка набора на
  результатах портала и `/entdecken/` (при городе); на странице бизнеса — GET-форма «Nur bestimmte
  Angebote?» (категория/слово/марка из листингов бизнеса); управление и `/konto/` — подписи и
  «Ansehen»; `/folgen/` честно пишет, какие фильтры не переносятся.

## 3. D-0 `search_log_report` (без миграций)

Только чтение агрегатов `SearchQueryLog`: доля пустых, «только опечатки», многословных, с выведенными
фильтрами, «только фильтры»; топы пустых и многословных малых выдач **только при `searches ≥ 2`**
(одиночные бывают с именами); разрез по языку/поверхности; счётчики подписок по видам. Порог для
D-2 — в отчёте.

## 4. D-2 (контур, за `AI_SEARCH_ENABLED=False`, после D-0)

Многословный остаток + пустая/малая выдача → ИИ (ЕС) предлагает фильтры из допустимых значений →
канонизация белым списком → пилюли «KI-Vorschlag» ССЫЛКАМИ (выдачу не подменяем); кэш 24 ч, потолки;
флаг выключен → путь байт-в-байт.

## 6. Решения владельца

- **Р-1** максимум подписок: рек. 20 всего, из них ≤ 10 запросов.
- **Р-2** чип марок в панели фильтров: рек. v1 нет (марка — поиском, ссылкой с предложения, селектом
  на странице бизнеса).
- **Р-3** «Sofort» для запросов: рек. v1 нет (daily/weekly).
- **Р-4** сужение подписки на странице бизнеса в v1: рек. да.
- **Р-5** подписка с `/entdecken/`: рек. да, только при выбранном городе.
- **Р-6** «новое» = новые предложения; «подешевело» — v2.
- **Р-9** порог включения ИИ (D-2): рек. ≥ 10 % многословных пустых/малых выдач при ≥ 500 поисков
  за 30 дней.

**Решения владельца 2026-10-19: Р-1…Р-6 и Р-9 — все по рекомендации** (20 подписок, из них ≤ 10 поисков; чипа марок и «Sofort» для поисков в v1 нет; сужение у компании и подписка с `/entdecken/` — да; «новое» = новые предложения; порог ИИ ≥ 10 % при ≥ 500 поисков).

## 7. Риски

`FEED_PARAMS ⊇ FILTER_PARAMS` (новые ключи — только в `FILTER_PARAMS`) · правило вида без `q` ·
расхождение письма и ссылки из-за намерения (храним остаток + выведенные фильтры + `roh`) · кэш P0-1
(только ссылки/GET) · DOI GET без эффектов · `isolated_ratelimit` в тестах · декоратор «съеден»
хелпером в `follow_views.py` · марка у всех построителей через `_neutral_v2v4` · `brand` в
`INDEXED_FIELDS`/`refresh().only()` (ops: `sync_aggregator` → `rebuild_search_index`) · журнал не
трогаем · демо никогда · нагрузка сводки (кап 10 запросов) · строка в Datenschutz платформы.
