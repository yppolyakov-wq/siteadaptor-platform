# KA-12 E6.1 — кнопка владельца для запросов DSGVO (Art. 15/17/20) — план (2026-10-23)

Источник: `ka-12-master-plan-2026-10-23.md` (E6.1). План — агент planner, факты сверены с кодом.
Без миграций.

## Что есть
`promotions/management/commands/dsgvo_customer.py` (`_export_payload`/`_erase`) — общая точка с ЛК
клиента (`account/views.export_data`/`delete_account`), но выгрузка тонкая (нет заказов/броней/
билетов/заявок/предложений/счетов/сообщений), удаление проверяет только резервы и забывает
`birthday`. Автоочистка `purge_due_customers` уже знает «открытые сделки» — переиспользуем её.

## Решение
- `apps/crm/dsgvo.py` — одна реализация: `export_customer`, `erasure_blockers` (общий с автоочисткой
  предикат), `erase_customer` (одна транзакция, блокировка клиента). CLI и ЛК — тонкие обёртки.
- Политика по моделям (`ERASURE_POLICY`): клиент — анонимизация (строка остаётся, на неё ссылаются
  сделки); заметки/Telegram/ожидания/сообщения — удаление; сделки — суммы остаются (GoBD/HGB § 257),
  адреса/заметки чистятся у закрытых; счета и журнал выручки — без изменений; Meldeschein (§ 30 BMG,
  1 год) и подписанный отказ участника — остаются с указанием основания; отзывы/подарочные
  ваучеры по e-mail — анонимизация.
- Экран владельца на карточке клиента: выгрузка ZIP (`daten.json` Art. 20 + `uebersicht.html`
  Art. 15 + `README.txt` «что сохранено и почему»), удаление POST с подтверждением, запись в журнал
  аудита без персональных данных. Только владелец.
- Вне охвата — данные платформы (портал, подписки жителей, боты): отдельный контролёр.

## Замки ДО кода
Только владелец; GET на удаление = 405; без подтверждения — без изменений; **замок покрытия**:
каждая модель с FK на клиента есть в выгрузке и в политике; выгрузка содержит сделки всех видов и
не содержит чужих; номер документа Meldeschein скрыт; открытая сделка блокирует удаление; после
удаления счёт байт-в-байт, журнал выручки цел, клиент анонимизирован (вкл. день рождения);
сбой шага откатывает всё; повтор идемпотентен; ЛК-удаление тоже отказывает при открытом заказе.
