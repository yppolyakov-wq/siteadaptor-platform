# Цикл инкремента (siteadaptor-platform)

Источник правды — `CLAUDE.md` §5 и `docs/pitfalls.md` §6; здесь — порядок действий и то, на чём
цикл чаще всего ломался. Дата у грабли — последнее срабатывание (правила ведения —
`docs/skill-feedback.md`).

## Когда грузить
В начале инкремента, перед планом; перед пушем стопки; при красном CI; при своде веток.

## Порядок шага
1. **ID** — строка в `docs/task-catalog.md` §3 ДО план-дока (подзадача — через точку, новых
   семейств не заводить).
2. **Разведка** — раздел своей темы в `docs/project-memory.md` §3 и тематический скилл `sa-*`.
   Любое «X не используется / не читается» в плане — только с grep вызовов.
3. **План-док** в `docs/` + раздел «ECC-прогоны» (таблица `docs/pitfalls.md` §0): какие скиллы
   до кода, какие агенты на каком шаге. Переработка UI — сначала варианты на утверждение.
4. **Ревью плана до кода** — пройти `docs/review-checklist.md` (32 вопроса по классам прежних
   находок) и «Грабли» тематического скилла по плану; каждое «риск есть» — будущий замок.
5. **Замки до кода** — красный тест отдельным коммитом (где поведения ещё нет — strict xfail),
   потом реализация.
6. **Код** — звать единую точку из памяти, не заводить второй список или писатель.
7. **Гейт** — `uv run python scripts/preflight.py` (`--plan` — посмотреть набор). Он сам берёт
   ruff целиком, i18n, свежесть `static/css/app.css`, замки шаблонов и pytest нужных приложений.
8. **Ревью ECC** по разделу плана (`django-reviewer` всегда); в промпт агенту — «пройди
   `docs/review-checklist.md` по каждому вопросу». Находка → замок → правка →
   строка в `docs/skill-feedback.md` + правка скилла в том же коммите.
9. **Стопка** — связные шаги отдельными коммитами, один пуш, один прогон CI на верхушке.
10. **Чекпоинт с владельцем** → FF в `main` (git-only; PR не создавать без просьбы).
11. **Доки тем же коммитом:** хронология → `docs/build-log.md`; статус → `docs/task-catalog.md`;
    новая единая точка или решение владельца → `docs/project-memory.md`; грабля →
    `docs/pitfalls.md`; в `CLAUDE.md` — только две-три строки §3.
12. **Ретро стопки** — `uv run python scripts/dev_stats.py --write` (доля «правок ревью» по
    шагам, находки по классам) и строка в таблицу «Тренд» журнала находок.

## Единые точки
- Финальный гейт — `scripts/preflight.py::plan, pytest_command` (таблица «путь → проверки»;
  замок `apps/core/tests/test_preflight_plan.py`). Новое правило гейта — туда, не в `CLAUDE.md`.
- Коммит-хук — `.githooks/pre-commit` (ruff и i18n по индексу, свежесть CSS); ставит
  `scripts/install-git-hooks.sh` из `.claude/hooks/session-start.sh`.
- i18n на лету — `.claude/hooks/i18n-watch.sh`; быстрый гейт — `scripts/i18n_quickcheck.py`,
  сканер необёрнутых строк — `scripts/i18n_untranslated.py`.
- CI — `.github/workflows/ci.yml`: три группы (g1 core/billing/aggregator/catalog, g2 tenants,
  g3 остальное), `-n auto`; отмена устаревшего прогона ветки.
- Состояние миграций — команда `migration_state` (шаг `scripts/deploy.sh`); деплой — только им.
- Бюджеты: `apps/core/tests/test_claude_md_budget.py` (45 КБ),
  `apps/core/tests/test_claude_rules_budget.py` (правила), `apps/core/tests/test_project_skills.py`.

## Нельзя
- Хотфикс прямо в `main` (исключение — деньги, данные, закон; тем же циклом).
- Force-push; после rebase запушенной ветки — пуш под новым именем.
- `migrate <app> zero`, `--fake`, `makemigrations --merge`, удаление миграций — без владельца.
- `ruff format` по ЯВНОМУ пути миграций (обходит exclude — переформатирует старые).
- Пропускать, отключать или ослаблять тест ради зелёного CI.
- Два pytest на одной тест-БД (параллельный срез — `DB_NAME=platform_<срез>`).
- Восстанавливать снесённое (classic_ui, режим Простой/Эксперт, рейка Студии, `studio_scope`).
- Идентификатор модели и секреты — в артефактах репозитория.

## Грабли
- Не править worktree, пока по нему идёт pytest (ленивые импорты ловят полуготовый код); ждать
  конца прогона по ` in [0-9.]+s`, не по «passed» (ruff пишет «All checks passed!») · посл. 2026-11-22.
- Предпосылка плана по старому комментарию, а не по grep → пункт «убрать» ломает витрину молча
  · посл. 2026-11-16.
- Красный только локально → сначала сверить окружение с `uv.lock`
  (`uv sync --frozen --extra dev --inexact`), потом искать дефект · посл. 2026-11-14.
- Широкий локальный прогон с `-x` прячет остальные падения — гонять без `-x` · посл. 2026-11-11.
- Правка `apps/core` при зелёном прогоне одного ядра роняет третью группу CI: ядро зовут все
  приложения — preflight добавляет импортёров сам · посл. 2026-11-21.
- Срез гоняет эталоны выборочно и получает красный CI (трижды за стопки 8–10): гейт при правке
  шаблона сам гонит все тесты с `golden`; параллельный срез — со своей `DB_NAME`, гейт чужой
  pytest на другой базе не считает помехой · посл. 2026-11-23.
- Правка шаблона без пересборки CSS / без замков шаблонов (многострочный `{# #}`) → красный CI
  · посл. 2026-11-20.
- `.mo` не в git, gettext локально нет: эталоны не на немецком снимать только со свежими `.mo`
  (компиляция через polib), иначе ложные падения · посл. 2026-11-20.
- Тест с месяцем/днём — по местному времени (Europe/Berlin), не UTC · посл. 2026-11-20.
- Сверка «до == после» рендером идёт мимо кэша страниц только с непустой сессией · посл. 2026-11-18.
- `str.replace(a, b)` с вычисленным пустым `a` вставляет `b` между всеми символами · посл. 2026-11-18.
- Нестабильные при `-n 4`: `test_migration_state`, `test_async_signup` — перепроверять отдельно.
- Параллельные срезы от одной базы не правят общие доки, `app.css` и общие эталоны — это один
  раз на верхушке; стыки срезов — отдельным коммитом с тестами · посл. 2026-11-21.
- Worktree агента создаётся от `main`, а не от ветки стопки: срез начинает с
  `git merge --ff-only <коммит P0>` и `uv sync --frozen --extra dev --inexact` (иначе нет плана,
  якорей `.po` и dev-зависимостей) · посл. 2026-11-22.
- Отчёт исполнителя «измерено / сильнее / не задевает» без замера — предпосылка: сверить
  (специфичность CSS, права превью под подменой) · посл. 2026-11-22.
- Срез с `node_modules` коммитит пересобранный `static/css/app.css` вместе с шаблоном (так требует
  pre-commit хук); координатор всё равно пересобирает его на верхушке · посл. 2026-11-23.
- Координатор правит в своём worktree со своей `DB_NAME`, пока в основном дереве идёт гейт верхушки
  · посл. 2026-11-23.
- `main` ушёл вперёд — сверить до свода; свой дубль снять целиком, оставить реализацию `main`.

## Что гейтить
`uv run python scripts/preflight.py` перед каждым пушем стопки; при новых миграциях он сам
ставит `--create-db`. Локально не проверяются `scripts/i18n_gap.py` и `msgfmt --check-format`
(нет gettext) — их закрывает CI, поэтому новый msgid сразу писать во все пять `.po`.

## Агенты ECC
`planner` — план и ревью плана; `django-reviewer` — всегда; `security-reviewer` — ввод,
авторизация, деньги, внешние вызовы; `database-reviewer` — миграции и тяжёлые запросы;
`silent-failure-hunter` — деньги и внешние вызовы; `e2e-runner` — JS и вёрстка;
`a11y-architect` — только при новых элементах интерфейса; `doc-updater` — в конце фазы.
Агент получает `CLAUDE.md` и правила заново — звать по разделу плана, не «на всякий случай».
