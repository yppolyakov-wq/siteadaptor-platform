# Ревью, агенты и безопасность — правила проекта

Сжато из общих правил ECC (T-13.0, 2026-11-21) — только то, чем проект реально пользуется.
Рабочий цикл, гейты и конвенции — `CLAUDE.md` §5; расхождения с ECC — `project-overrides.md`.

## Агенты
- Агенты лежат копией в `.claude/agents/`, имена без префикса `ecc:`. Кого и когда звать —
  таблица `docs/pitfalls.md` §0 и раздел «ECC-прогоны» плана инкремента.
- Независимые проверки запускать параллельно, одним сообщением.
- **Делегировал — собери результат.** Итоговое сообщение агента и есть результат; нельзя
  заканчивать ход словами «жду фоновых агентов». Не дробить задачу, которая помещается в
  один контекст.
- Агенту давать код и вопрос, а не готовый вывод. Агенты ECC про проект не знают — ревьюеру
  в промпт: «пройди `docs/review-checklist.md` по каждому вопросу» (и по плану, и по диффу).

## Ревью
- Уровни: **CRITICAL** (безопасность, потеря данных/денег) — блокирует мерж; **HIGH** (ошибка,
  заметный дефект) — чинить до мержа; **MEDIUM** — по возможности; **LOW** — на усмотрение.
- Находка ревью → сначала замок (красный), потом правка; строка в `docs/skill-feedback.md`.
- Мерж — без CRITICAL и HIGH. Чинить реализацию, а не тест (кроме неверного теста); тест
  падает странно — сначала проверить изоляцию тестов.
- `security-reviewer` — ввод, авторизация, деньги, а также сырые запросы к БД, файловая
  система, внешние вызовы, криптография. Смотреть N+1 и запросы без ограничения выборки.

## Безопасность — перед коммитом
- Секретов в коде нет; ввод пользователя проверен на границе (формы, `parse_amount`, `ssrf.py`).
- Запросы — через ORM или с параметрами; HTML пользователя — через `richtext.py`.
- CSRF включён; права проверены (`permissions.py` / `view_perms.py`); на перебор — лимиты.
- Сообщения об ошибках не раскрывают внутреннее; ошибки не глотать молча — логировать.
- Нашлась уязвимость — остановиться, агент `security-reviewer`, сменить засвеченные секреты,
  поискать тот же класс по всей кодовой базе.
- Флаг `dangerously-skip-permissions` не использовать.

## Код
- Пишем как окружающий код (Django-идиомы); KISS, DRY, YAGNI — без абстракций «на вырост».
- Ранний выход вместо глубокой вложенности; пороги и лимиты — именованными константами.
- Отладочных `print` в коде приложения нет — `logging`.
